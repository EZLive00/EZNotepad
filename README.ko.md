# EZNotepad

> **5MB** 크기의 데스크톱 소형 도구: Markdown 작성 + 텍스트 읽기·쓰기 + 파일 비교.
> 포터블, 오프라인 동작, 더블클릭으로 바로 사용.
> UI는 9개 언어를 지원하며 기본적으로 시스템 언어를 따르고, '설정 → 언어'에서 수동으로 전환할 수도 있습니다.

## 다운로드 및 설치

[Releases](https://github.com/EZLive00/EZNotepad/releases)에서 다운로드:

| 산출물 | 적합한 사용자 |
|---|---|
| `EZNotepad_<版本>_x64-setup.exe` | **설치 버전**: 설치 마법사 + 파일 연결, `.md` / `.txt` 더블클릭으로 바로 열기 |
| `EZNotepad_<版本>_x64-portable.zip` | **포터블 버전**: 아무 디렉터리에 압축 해제 후 `EZNotepad.exe` 더블클릭으로 사용 |

- 둘 다 코드 서명이 없어 첫 실행 시 SmartScreen이 한 번 차단합니다: '추가 정보' → '실행' 클릭
- 포터블 버전은 시스템 WebView2 런타임에 의존(Win10 / Win11에 내장), 레지스트리에 쓰지 않고 파일 연결도 등록하지 않음
- 현재는 Windows x64 빌드만 제공

## 세 가지 모드 (하나의 드롭다운, 파일 형식에 따라 자동 전환)

| 모드 | 하는 일 | 단축키 |
|---|---|---|
| **WYSIWYG** | `# ` 입력 시 제목으로, `**굵게**` 입력 즉시 굵게 표시 | `Ctrl+1` |
| **편집 모드** | 원본 Markdown / 소스 보기, 줄 번호·구문 강조·접기 지원 | `Ctrl+2` |
| **미리보기 모드** | 읽기 전용 렌더링, 집중해서 읽기에 좋음 | `Ctrl+3` |

**지원 파일 형식**: `.md`(세 가지 모드 모두 사용 가능), `.json`(검증 + 하이라이트 + 오류 위치 표시),
`.txt` `.log` `.csv`, 일반적인 코드 파일(`.js/.ts/.py/.rs/.go/.html/.css/.sql/.yml/...`).
**새로 만들 때는 먼저 형식을 선택합니다**(Markdown / 일반 텍스트 / JSON / CSV / 코드). Markdown이 아닌 파일은
'편집 / 미리보기'만 열려 일반 텍스트 편집기처럼 사용합니다.

## 편집 모드는 CodeMirror 6 기반

`<textarea>`를 얹은 수준이 아닙니다. 진짜 코드 편집기다운 것들을 갖췄습니다:

| | 설명 |
|---|---|
| **구문 강조** | JS/TS/JSX, Python, Rust, Go, Java, C/C++, JSON, CSS, HTML, SQL, YAML, Shell, INI, Markdown, 증분 파싱 |
| **줄 번호 / 현재 줄** | 줄 번호 거터, 현재 줄 배경색, 괄호 매칭, 코드 접기 |
| **실행 취소** | CM6 자체 트랜잭션 단위 history, 브라우저의 contenteditable보다 신뢰할 수 있음 |
| **대용량 파일** | 보이는 줄만 렌더링. 실측 5만 줄 열기 49ms, 10만 줄 20ms, DOM에는 100여 줄만 유지 |
| **들여쓰기** | Tab은 선택 영역이 있으면 해당 구간 전체, 없으면 현재 줄 들여쓰기; Shift+Tab은 내어쓰기; Enter는 윗줄의 들여쓰기를 따름 |
| **괄호 자동 완성** | `(` 입력 시 `)` 자동 보완, 따옴표도 동일; 커서가 괄호 쌍 사이에 있을 때 닫는 괄호를 입력하면 삽입하지 않고 '건너뜀' |
| **테마** | 밝은/어두운 두 세트가 앱과 함께 전환, 구문 색상은 미리보기와 동일한 CSS 변수 공유 |

색상은 `styles.css`의 `body[data-theme]`에 한 번만 정의되며, 편집기와 미리보기 렌더러가 각각 가져다 쓰므로
두 곳의 색상 값이 어긋나는 문제가 없습니다.

지원하지 않는 옵션은 자동으로 회색 처리됩니다 — JSON 파일을 열면 'WYSIWYG'가 회색으로 바뀌어 잘못 누를 수 없습니다.

## 화면 구성 (각 기능의 진입점은 하나뿐)

```
┌──────────────────────────────────────────────┐
│ ▣ 파일 편집 서식 보기 도구 도움말  欢迎.md  － □ ✕│ ← 제목 표시줄(40px)
├──────────────────────────────────────────────┤
│ 欢迎.md × │ test.json × │ +         편집▾ ⌕ 저장 │ ← 탭과 도구가 같은 줄
├────────┬──────────────────┬──────────────────┤
│        │                  │                  │
│ 개요   │   편집 / WYSIWYG │      미리보기        │
│        │                  │                  │
├────────┴──────────────────┴──────────────────┤
│ 줄 1,열 1 │ 36줄 │ 243자 │ Markdown │ LF │ UTF-8 │ 저장됨 │
└──────────────────────────────────────────────┘
```

내용 영역 위에는 두 줄만 있습니다: 제목 표시줄(메뉴 + 문서 제목 + 창 버튼), 그리고 탭과 도구가 합쳐진 한 줄
(왼쪽 탭, 오른쪽에는 **모드 전환 / 찾기 / 저장** 세 가지 고빈도 동작만 배치하고 나머지는 모두 메뉴에 두어 중복 배치하지 않음).
창이 좁아지면 도구는 아이콘만 남습니다.

창에는 시스템 제목 표시줄이 없습니다(`decorations: false`): 메뉴, 문서 제목, 창 버튼이 모두 맨 위 한 줄에 있고,
가운데 빈 공간을 드래그해 창을 이동할 수 있으며 더블클릭으로 최대화 — VS Code, WorkBuddy 같은 앱과 동일합니다.
창 네 모서리는 Win11의 DWM 원형 라운드 모서리를 사용하며, 가장자리를 드래그하면 크기 조절이 가능합니다.
'보기 → 제목 표시줄에 파일 이름 표시'에서 제목 텍스트를 끄고 메뉴와 버튼만 남길 수 있습니다.

- **개요** — 탐색 전용
- **사이드바** — 두 페이지: 개요(스크롤에 따라 현재 섹션 하이라이트)／파일(디렉터리 트리 + 전체 디렉터리 내용 검색)
- **도구 행** — 모드, 찾기, 저장 세 가지 고빈도 동작만 두고 그 외 명령은 모두 메뉴로
- **본문 영역** — 편집 전용
- **상태 표시줄** — 정보 표시 전용, 인코딩과 줄바꿈 문자는 클릭해 변경 가능
- **메뉴** — 전체 명령의 진입점
- **설정** — `Ctrl+,` 하나의 패널: 테마, 글자 크기, 인터페이스, 자동 저장, 작업 폴더
- **비교 센터** — 독립된 전체 화면 패널, 편집기와 섞이지 않음

### 사이드바 '파일' 페이지: 디렉터리 트리와 파일 간 검색

- 한 층 펼칠 때 한 층 읽기(지연 로딩), 대형 저장소를 열어도 수만 개 파일을 미리 읽어들이지 않음
- **오른쪽 클릭으로 바로 수정**: 임의 디렉터리에서 파일/폴더 새로 만들기, 파일 이름 변경 또는 삭제
  - 삭제는 **시스템 휴지통**으로 이동하므로 잘못 눌러도 되살릴 수 있음; 폴더는 빈 폴더만 삭제하고 통째로 지우지 않음
  - 이름 변경 또는 삭제 시 이미 열려 있던 탭도 함께 따라감 (옛 경로를 가리킨 채 다시 쓰지 않음)
- 검색은 Rust에서 스캔하며 바이너리와 4MB 이상 파일은 건너뛰고 최대 200건 반환
- 검색창의 `.*`는 정규식 전환, `Aa`는 대소문자 구분
- 결과는 파일별로 그룹화되어 줄 번호와 조각이 함께 표시되며, 클릭하면 열고 해당 줄로 이동
- **파일 간 바꾸기**: 검색창 아래에 '바꿀 내용'을 입력하고 '모두 바꾸기' 클릭. 디스크를 수정한다고 먼저 한 번 물어봅니다;
  각 파일을 수정하기 전에 히스토리 스냅샷을 하나 남겨 문제가 생기면 되살릴 수 있습니다
- 마지막으로 연 폴더를 기억; 설정 패널에서 변경하거나 비울 수 있음

### 찾기 (`Ctrl+F` / `Ctrl+H`)

하나의 플로팅 패널에 두 가지 상태: 맨 왼쪽 화살표를 클릭하면 '찾기 + 바꾸기' 두 줄로 펼쳐지고, 접으면 찾기만 남습니다.
`Ctrl+F`는 포커스만 이동(이미 펼쳐진 바꾸기 줄을 접지 않음), `Ctrl+H`는 바로 펼칩니다.

| 기능 | 설명 |
|---|---|
| **WYSIWYG에서 제자리 찾기** | 찾으려고 편집 모드로 전환할 필요가 없음; 하이라이트는 렌더링 레이어에 그려지고(CSS Highlight API) 본문에 마커를 삽입하지 않음 |
| **모드 스위치** | 입력창 오른쪽의 네 개 작은 사각형: `Aa` 대소문자 구분, `.*` 정규식, `전체 단어`, `선택 영역`. 활성화 시 accent 색 사용 |
| **전체 단어** | 검색 문자열 양끝이 영어 단어 문자일 때만 경계를 추가 — 중국어에는 단어 경계가 없어 `\b`를 억지로 적용하면 영원히 매칭되지 않음 |
| **선택 영역 내** | 선택한 구간 안에서만 찾기/바꾸기, 선택이 없으면 이 항목은 회색 |
| **줄바꿈** | 입력창 오른쪽 끝의 `↵`(또는 `Ctrl+Enter`)로 줄바꿈을 삽입하면 입력창이 스스로 높아짐; 줄바꿈이 없는 검색은 여전히 문단을 넘어 잘못 매칭하지 않음 |
| **바꾸기** | 매칭이 같은 텍스트 구간 안에 있으면 **바로 수정**, 팝업 없음; 굵게/링크 같은 서식 경계를 넘을 때만 '편집 모드로 전환할지' 물어봄 |
| **파일 간** | 사이드바 '파일' 페이지의 검색창, 파일별로 매칭 줄을 그룹화해 표시 |

## 가장 많이 쓰는 기능들

### WYSIWYG: 진짜 편집기로 쓸 수 있습니다

'`# ` 입력 시 제목으로 변환'만이 아니라 블록 수준 구조를 모두 직접 조작할 수 있고, Markdown 문법과 WYSIWYG가 양방향으로 일치합니다. 마커는 **줄 머리**에만 있으면 되고 줄 끝에 쓸 필요가 없습니다 — 글을 먼저 쓰고 나중에 줄 머리에 `## `을 보충해도 같은 방식으로 제목으로 승격되며, 마커 뒤의 텍스트(굵게, 링크 포함)는 그대로 유지됩니다:

| 기능 | 사용 방법 |
|---|---|
| **제목 / 본문** | 줄 머리에 `# `~`###### ` 입력(이미 있는 텍스트 앞에 보충해도 됨); `Ctrl+Alt+1~3`으로 단계 변경, 한 번 더 누르면 본문으로 |
| **글머리 기호 / 번호 / 작업 목록** | 줄 머리에 `- ` / `1. ` / `- [ ] ` 입력; `Tab`으로 하위 항목 들여쓰기, `Shift+Tab`으로 한 단계 내어쓰기 |
| **중첩 목록** | 최대 6단계, 번호/글머리 전환 시 단계가 사라지지 않고 번호는 자동 재정렬 |
| **인용** | 줄 머리에 `> ` 입력; `Tab`으로 인용 단계 추가, 빈 줄에서 Enter로 종료 |
| **코드 블록 / 구분선** | 줄 머리에 ` ``` ` / `---` 입력; 코드 블록 안에서 Enter 시 자동 줄바꿈, 두 칸 들여쓰기 |
| **표** | `Ctrl+Shift+T`로 3×3 삽입, 또는 '서식 → 표 삽입(크기 지정)' |
| **표 편집** | `Tab` / `Shift+Tab`으로 셀 사이 이동(끝에서 자동으로 행 추가), `Enter`로 다음 행 같은 열로 이동, 오른쪽 클릭으로 행/열 추가·삭제 및 열 정렬 |
| **인라인 스타일** | `**粗**`, `*斜*`, `~~删~~`, `` `码` ``, `[文字](链接)` 입력하면서 바로 변환 |
| **수학 수식** | 인라인 `$a^2+b^2=c^2$`, 블록 `$$ … $$`(여러 줄 가능), 미리보기에서 KaTeX가 조판 |
| **목차** | '삽입 → 목차…'로 제목을 훑어 클릭 가능한 목록 생성, `Ctrl+클릭`으로 해당 섹션으로 이동 |
| **이미지 삽입** | 캡처 후 바로 `Ctrl+V`, 이미지 파일을 창으로 드래그, 또는 '삽입 → 이미지…': 모두 문서와 같은 디렉터리의 `assets/`에 복사되어 상대 경로로 참조; 네트워크 주소를 직접 입력할 수도 있음 |
| **이미지 크기** | WYSIWYG에서 이미지 오른쪽 아래 모서리를 드래그해 너비를 직접 변경(드래그 후 자동으로 alt 접미사에 기록); `![说明\|300](a.png)`으로 너비 제한, `![说明\|300x200](a.png)`으로 너비·높이 제한을 직접 쓸 수도 있음; 쓰지 않으면 원본 비율로 표시(최대 320px) |
| **백스페이스 의미** | 제목 줄 머리에서 백스페이스 시 먼저 `###`이 드러나고 한 단계씩 지워짐; 목록 항목 시작에서 백스페이스 시 먼저 강등 후 문단으로; 문단 시작에서 백스페이스 시 윗줄과 병합; `Delete`는 반대 방향으로 동일 |
| **붙여넣기** | 여러 줄 텍스트가 Markdown으로 파싱되어 진짜 제목/목록/표 블록으로 변환, 뭉개지지 않음 |

**줄 머리 블록 핸들**: 커서나 마우스가 있는 줄의 왼쪽에 `+`와 `⋮⋮` 두 개의 작은 버튼이 떠오릅니다(글자를 가리지 않고 선택도 되지 않음).
`⋮⋮`로 이 블록을 다른 타입으로 변경(본문 / 제목 1~3 / 목록 / 인용 / 코드 블록), `+`는 아래에 새 블록을 삽입합니다.
상단 '서식' 메뉴와 같은 명령 세트를 실행하며, 진입점을 손닿는 곳으로 옮겨 온 것뿐입니다.

제목의 `###`은 단계를 바꿀 때만 나타납니다: 줄 머리에서 백스페이스를 한 번 누르면 마커가 드러나고(본문은 한 글자도 그대로), 다시 누르면 `#`이 하나 지워지며, 모두 지워져야 본문으로 돌아갑니다 — 백스페이스를 잘못 눌러도 단계와 글자가 함께 사라지지 않습니다. 커서를 이 줄에서 옮기거나 Enter를 누르면 마커는 자동으로 접힙니다.

마커가 인식하는 위치는 줄 끝 전체가 아니라 '커서 바로 앞의 짧은 구간'이므로 세 가지 쓰기가 모두 동일합니다: `## `을 먼저 입력하고 제목 쓰기, 제목을 쓴 후 줄 머리에 `## ` 보충, 일반 텍스트 문단을 제목으로 승격. 마커만 남은 경우(`## ` 바로 뒤에 공백)에만 인식하므로 본문의 `#话题`가 제목으로 잘못 변환되지 않고, 커서가 줄 머리에 없을 때 `- `을 입력해도 문장이 목록으로 쪼개지지 않습니다.

모든 블록 수준 작업은 **'서식' 메뉴**와 **오른쪽 클릭 메뉴**에도 있으며, 쓸 수 없는 항목은 자동으로 회색 처리됩니다(예: 커서가 표 안에 없으면 표 관련 명령은 모두 회색).

### 수학 수식

- 인라인 `$a^2 + b^2 = c^2$`, 블록 `$$ … $$`(여러 줄 허용, 행렬과 다단계 유도도 한 줄에 욱여넣지 않아도 됨)
- 렌더링은 **미리보기 쪽에서만** 발생: KaTeX는 '진짜 수식을 만났을 때만 로드'(약 546 KB), 수식 없는 문서는 비용을 전혀 내지 않음
- WYSIWYG에서는 수식을 렌더링하지 않고 배경색만 추가 — contenteditable에 KaTeX의 DOM을 넣으면 백스페이스로 지워지지 않고 커서가 끼는 등 대가가 이득보다 큽니다. 보려면 `Ctrl+3`, 또는 두 창 모드로 미리보기를 옆에 둘 것
- 수식 구간은 강조 문법을 파싱하기 **전에** 보호되므로 `$x_1 * y$`의 `_`와 `*`는 아래첨자와 곱셈 기호이며 기울임으로 취급되지 않음

### 집중 모드 (`F9`, `Esc`로 종료)

탭 행, 사이드바, 상태 표시줄, 메뉴가 모두 접히고 본문만 남습니다. 제목 표시줄은 거의 보이지 않을 만큼 흐려졌다가 마우스를 올리면 복구됩니다 — 창은 테두리가 없어서 제목 표시줄마저 사라지면 드래그도, 최소화·닫기도 할 수 없어 스스로 쓴 문서에 갇히는 꼴이 됩니다.

### 더블클릭으로 바로 열기 / 창은 하나만

설치 프로그램 설치 후 `.md` `.markdown` `.txt` `.log` `.json` `.csv` 모두 파일 연결이 등록되어,
파일 탐색기에서 오른쪽 클릭 '연결 프로그램'에서 'EZNotepad'를 찾을 수 있습니다.

같은 프로그램의 창은 하나만 있습니다: 파일을 다시 더블클릭해도 두 번째 프로세스가 시작되지 않고,
경로를 이미 열려 있는 창에 전달해 열립니다(최소화 상태면 다시 불러옵니다).
두 창이 동시에 같은 파일을 수정하고 서로 덮어쓰는 일은 근원적으로 사라졌습니다.

> **설치 버전**만 연결을 등록합니다. 포터블 버전과 `cargo build`로 만든 날것 exe는 레지스트리에 쓰지 않습니다.

### 파일 변경 감시

열려 있는 문서는 실시간으로 감시됩니다(백엔드는 시스템의 `ReadDirectoryChangesW` / `inotify` 사용, 파일이 있는 디렉터리 한 층만 감시하고 허용 목록에 있는 파일 이름만 통과). 다른 프로그램이 파일을 변경하면:

- 파일이 **현재 탭**: 수정한 적이 없으면 조용히 다시 로드하고 알림; 저장되지 않은 수정이 있으면 먼저 물어봄
- 파일이 **백그라운드 탭**: 팝업으로 방해하지 않고 탭에 주황색 작은 점이 뜨며, 전환할 때 물어봄

직접 저장할 때는 스스로 반응하지 않습니다(저장 후 수정 시간이 이미 동기화됨). 설정에서 전체적으로 끌 수 있습니다.

### 원클릭 서식 정리 (파일 형식별 스마트 처리)

| 형식 | 하는 일 |
|---|---|
| **JSON** | 검증 + 들여쓰기 재정렬; 전각 따옴표·불필요한 쉼표·주석 자동 수정; **문법 오류 시 파일을 수정하지 않고 'X행 Y열' 팝업 표시** |
| **Markdown** | 제목 앞뒤 빈 줄 보충, 목록 기호 통일, 줄 끝 공백 제거, 빈 줄 압축 |
| **TXT / 로그 / 코드** | 줄바꿈 문자 통일, 줄 끝 공백 제거, 연속 빈 줄 압축 |

서식 정리 후 원클릭 '실행 취소'로 원래대로 돌아갈 수 있습니다.

### 버전 기록 (파일 → 버전 기록…)

저장할 때마다 **저장 전** 내용이 스냅샷으로 남고, 로컬 앱 데이터 디렉터리에 보관됩니다(문서 디렉터리에는 아무것도 넣지 않음).
원클릭 서식 정리, 정렬·중복 제거, 일괄 바꾸기 후 후회할 때 `Ctrl+Z`로는 못 돌릴 수도 있습니다. 여기가 마지막 보루입니다.

- 파일당 최대 60개, 총량 20MB, 초과하면 가장 오래된 것부터 정리
- '보기'는 해당 버전을 읽기 전용 새 탭으로 열고, '복원'은 편집기에 다시 씁니다 — **둘 다 직접 `Ctrl+S`를 눌러야 디스크에 반영됩니다**
- 파일 비교, 3방향 병합과 같은 원칙: 롤백이 원본 파일을 직접 덮지 않음

### 웹페이지 내보내기 (파일 → 웹페이지 내보내기…)

현재 문서를 **단일 파일 HTML**로 저장: 스타일 내장, 이미지는 data URI로 변환,
다른 사람에게 보내거나 정적 사이트에 넣어도 바로 열리며 '그림이 다 깨지는' 일이 없습니다.
4MB를 넘는 이미지는 내장하지 않고(원본 주소 유지), 내보내기 알림에 몇 장을 내장했는지 표시됩니다.

### 명령 팔레트 (`Ctrl+Shift+P`)

메뉴에 있는 백여 개 명령을 몇 글자 입력으로 찾을 수 있습니다: `집중`, `서식`, `바꾸기` 모두 가능,
`↑` `↓`로 선택, `Enter`로 실행, `Esc`로 닫기. 목록은 메뉴 트리에서 직접 생성되므로 메뉴에 새 명령이 추가되면 여기에도 자동으로 생깁니다.
현재 상태에서 쓸 수 없는 명령은 회색으로 표시되고, 누르면 이유를 알려줍니다.

### 단축키 직접 변경 (설정 → 단축키)

설정 패널에 단축키가 있는 모든 명령이 나열되어 있고, '변경'을 누른 후 새 조합키를 직접 누르면 됩니다(`Ctrl` / `Alt`를 포함하거나
`F1`–`F12` 단독 사용), `Esc`로 취소. 사용자 지정 키가 기본 키보드보다 우선하며, 잘못 바꾸었으면 '복원'으로 돌아오고,
'기본 설정 복원'이 함께 지웁니다.

### 텍스트 비교 (`Ctrl+D`)

- 좌우 나란히, **줄 단위 + 문자 단위** 이중 하이라이트(실제로 바뀐 몇 글자만 표시)
- 공백 무시 / 대소문자 무시
- `F7` / `F8`로 차이 사이 이동
- 각 차이 블록에 **→** 버튼이 있어 한 번에 왼쪽 블록을 오른쪽에 동기화
- 원클릭 HTML 비교 보고서 내보내기

### 폴더 비교

두 디렉터리를 재귀적으로 비교하여 **왼쪽만 / 오른쪽만 / 수정됨 / 동일함**을 표시, 한 줄을 클릭하면 해당 파일의 텍스트 비교로 바로 이동.

### 3방향 병합 (도구 → 3방향 병합)

'기준 버전 + A측 + B측'을 선택하면 양쪽 변경을 자동 병합하고 충돌 목록을 만듭니다.
**결과는 새 탭에서만 열리며, 절대 원본 파일을 덮지 않습니다.**

### 인코딩과 줄바꿈 문자

상태 표시줄 오른쪽 아래 `UTF-8`을 클릭해 인코딩을 바꿔 저장할 수 있습니다(UTF-8 / GBK / UTF-16, BOM 추가 가능);
`LF`를 클릭하면 CRLF로 전환. GBK로 된 오래된 txt도 열 때 글자가 깨지지 않습니다.

## 데이터와 프라이버시

- 모든 파일은 사용자 컴퓨터에서만 읽고 쓰며, **네트워크 연결 없음, 업로드 없음**
- 임시 저장(초안)은 로컬 앱 데이터 디렉터리에 보관되어 창을 닫아도 사라지지 않음: 저장되지 않은 **모든** 탭이 저장되며,
  다음 시작 때 함께 복구할지 물어봅니다(마지막 것만 저장하는 것이 아님)
- 히스토리 스냅샷도 이 디렉터리의 `history/`에 있으며, 문서 디렉터리와 완전히 분리됨
- 처음 열 때 저장되지 않은 초안이 감지되면 복구 여부를 물어봄

## 알려진 제한

- PDF 내보내기는 시스템 인쇄 대화상자를 사용('PDF로 저장'), 레이아웃은 인쇄 결과 기준
- 3방향 병합은 반자동 버전: 자동 병합 + 충돌 목록, 4칸 시각화 병합기는 없음(복잡한 충돌은 텍스트 비교로 블록별 처리 권장)
- 각 플랫폼 설치 패키지는 해당 시스템에서 빌드해야 함(자세한 내용은 `构建说明.md`)
- 파일 간 검색은 기본적으로 문자 그대로, 대소문자 구분 없음, 정규식 전환 가능; 상한 200건
- 파일 간 바꾸기는 **UTF-8** 파일만 처리: GBK 등은 그대로 건너뛰며 파일 전체 인코딩을 몰래 바꾸지 않음
- 파일 트리의 삭제는 시스템 휴지통으로 이동; **폴더는 빈 폴더만 삭제 가능**, 재귀 삭제하지 않음
- 파일 **트리** 자체는 감시하지 않음: 다른 곳에서 만들거나 삭제한 파일은 빈 곳을 오른쪽 클릭 '새로 고침'하거나 디렉터리를 다시 펼쳐야 함(열려 있는 문서는 실시간 감시됨, 위 내용 참조)
- 수학 수식은 미리보기 쪽에서만 렌더링되고 WYSIWYG에서는 소스가 표시됨; Mermaid 다이어그램은 아직 미지원
