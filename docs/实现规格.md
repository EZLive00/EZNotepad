# EZNotepad · 实现规格

> 读者：要从零做出一个**行为一致**的 EZNotepad 的人；要把这程序搬到另一个平台
> （比如 macOS + 原生框架）的人；要判断「这个改动会不会破坏兼容性」的人。
>
> 这份文档回答的是**施工问题**：数据长什么样、算法怎么走、磁盘上写什么、失败时退到哪。
> 《功能设计.md》回答「对用户承诺什么、边界在哪、为什么这么选」，两份互为表里：
> 承诺在这里变成可执行的判据，判据在那边有理由。**冲突时以《功能设计》为准**，
> 因为那是写给用户的承诺；本文只是它的实现映射。
>
> 《架构设计.md》讲现有代码怎么分层、有哪些不变量；本文不假设任何既有代码结构，
> 只描述**必须有**的东西 —— 所以它既是重写指南，也是换平台的移植指南。
> 唯一例外是 §10.4：那一节反过来，从本仓库现有实现出发，逐项列出搬到 mac / Linux
> 要改哪几行、改完什么表现、哪一条不改会丢数据。

## 0. 怎么用这份文档

### 0.1 三条使用路径

| 你要做的事 | 读法 |
|---|---|
| 同栈重写（还是 WebView + 某个系统语言） | §1～§9 顺序读，§12 的里程碑当排期；附录 A/B 当单测用例 |
| 换语言但不换形态（比如 Rust + WebView、Swift + WKWebView） | 同上，但 §1.3 的平台能力清单必须先对齐 |
| 换平台 + 换形态（macOS 原生 AppKit/SwiftUI） | 先读 §1.3 与 §10，把「必须自研」和「可交给平台」切开；再回 §2～§9 逐章对应 |
| 把**现在这份 Windows 版**搬到 mac / Linux | 直接读 §10.4 的 A/B/C/D 清单（带改动量与验收），按 §10.7 的 M1～M6 推进；§10.1～§10.3 只在「要不要另写原生版」时用 |

### 0.2 「一样」分四级，别混着验收

| 级别 | 内容 | 怎么验 |
|---|---|---|
| **L1 数据一致** | 同一份 Markdown 进、出来还是同一份字节；设置/会话/历史能互读 | 附录 A 的往返向量全绿；用同一份 `settings.json` 两边互开 |
| **L2 行为一致** | 同一串按键，光标落点、块结构、存盘结果相同 | 附录 B 的差异向量 + §12 每步的验收清单 |
| **L3 视觉一致** | 骨架尺寸、颜色语义、圆角、动效时长一致 | 截图逐项比对（§9 的尺寸表就是清单） |
| **L4 手感一致** | 启动时间、输入延迟、滚动、大文档不卡 | §9.7 与 §6.7 的性能门槛 |

**只做到 L1 的移植是「能读写同一个文件」，不是「一样的程序」**。用户能感到不同的是 L2 和 L4。

### 0.3 记号

- `✅ 必须` / `⛔ 禁止` / `⚠️ 有条件`
- 伪代码用 `js` 代码块（读起来最省力，**不是**在指定实现语言）
- 路径一律写相对仓库根的路径；三平台差异单独列在 §3.1
- 所有尺寸单位是 CSS px（原生实现按 1x 逻辑点换算）

## 1. 系统轮廓

### 1.1 进程与窗口

```
一个进程（单实例）
├── main 窗口
│   ├── UI 层：标签条 / 菜单 / 侧栏 / 编辑器 / 预览 / 状态栏
│   └── 服务层：文件读写、编码、监听、历史、图片落盘、对话框
├── compare 窗口（按需创建，独立上下文）
└── foldercmp 窗口（按需创建，独立上下文）
```

**三个窗口不共享内存**。跨窗口只有两条数据通道，任选其一实现即可：

| 通道 | 语义 | 何时用 |
|---|---|---|
| 一次性请求对象（宿主侧存、工具窗启动时取走） | 「打开工具窗时把初始参数带过去」 | 冷启动路径。**不要走 URL query**：中文路径双重编码后与磁盘路径对不上 |
| 事件推送（工具窗已存在时） | 「窗口已开着，把新数据推进去」 | 复用路径。事件名就是契约，两边必须同时改 |

窗口标签固定为 `main` / `compare` / `foldercmp`，工具窗被 `main` 再次唤起时**复用**，不新建。

### 1.2 必写组件（10 个，按依赖顺序）

| # | 组件 | 职责 | 参考规模 |
|---|---|---|---|
| 1 | 状态与持久化 | 标签对象、设置、会话、草稿、最近 | 100 行 |
| 2 | 平台服务桥 | 文件/目录/编码/历史/图片/窗口 的宿主调用 | 前端 140 + 宿主 1700 |
| 3 | Markdown 解析 | 文本 → 块；文本 → HTML（预览/导出） | 470 行 |
| 4 | 块序列化 | 块 → 文本；含增量缓存与组装规则 | 含在 3、5 里 |
| 5 | 所见即所得编辑器 | 块模型、输入规则、光标、撤销、粘贴、表格 | 4300 行 |
| 6 | 代码编辑器 | 基于现成组件的纯文本编辑（CM6/Monaco/自写） | 340 行 |
| 7 | 差异引擎 | 行对齐、词级 diff、三向合并（纯函数） | 360 行 |
| 8 | 对比窗 | 行模型、几何、折叠、预览条、编辑态 | 2900 行 |
| 9 | 外壳 | 菜单、标签、侧栏、大纲、设置、对话框 | 4400 行 |
| 10 | 样式 | 视觉系统（同色平面 + 1px 线 + 四值圆角） | 1500 行 |

**总规模参考：前端约 1.96 万行 + 宿主约 1700 行**。任何显著低于这个量级的实现，
大概率是把某块「复杂但看不见」的东西省掉了（最常被省掉的是：大文档窗口化、
跨块选区、增量序列化、撤销合并）。

### 1.3 平台能力清单（宿主必须提供）

核心逻辑**只依赖这 14 项原语**。换平台时先把这张表填满，核心代码一行不用动。

| # | 原语 | 语义要求 | Windows 现实现 | macOS 对应 |
|---|---|---|---|---|
| 1 | 读文件字节 | 返回原始字节，不做解码 | `fs::read` | `Data(contentsOf:)` |
| 2 | 写文件 | 目录不存在要建；失败要有可分类错误 | `fs::write` | `Data.write(to:options:.atomic)` |
| 3 | 文件信息 | 大小；目录要能识别出来并报错 | `fs::metadata` | `URL.resourceValues` |
| 4 | 修改时间 | 毫秒；文件不存在返回「无」而不是错误 | `fs::metadata.modified` | `URLResourceKey.contentModificationDateKey` |
| 5 | 目录列举 | 递归、有数量上限、跳过无权限不报错 | `walk`（20000 / 深度 24） | `FileManager.enumerator` |
| 6 | 目录监听 | 只监听**一层**、可换名单、事件带路径 | `notify` crate | `FSEventStream`（或 `DispatchSource`） |
| 7 | 原生对话框 | 打开文件 / 打开目录 / 另存为 | `tauri-plugin-dialog` | `NSOpenPanel` / `NSSavePanel` |
| 8 | 打开外部 | 用系统默认程序打开路径或 URL | `opener` | `NSWorkspace.open` |
| 9 | 删除到回收站 | 进系统回收站，不可用直接删代替 | `SHFileOperation` 族 | `FileManager.trashItem` |
| 10 | 建窗口 | 建窗、设尺寸、设位置、全屏/还原 | Tauri builder | `NSWindow` |
| 11 | 屏幕工作区 | 给定窗口 → 它所在屏的可用区域 | `MonitorFromWindow` | `NSScreen.visibleFrame` |
| 12 | 剪贴板写 | 写纯文本，同步返回成败 | `execCommand('copy')` | `NSPasteboard.general` |
| 13 | 导出 PDF | 把当前文档整篇转成 PDF 文件落盘（不弹打印面板） | WebView2 `ICoreWebView2_7::PrintToPdf` | `WKWebView.createPDF` |
| 14 | 应用数据目录 | 每用户、跨版本稳定的可写目录 | `app_data_dir` | `Application Support/<bundle-id>` |

⚠️ **第 6 项的语义要抄准**：只监听已打开文档所在的那一层目录，并在事件到达后按文件名过滤。
递归监听一个大目录会让事件洪水淹掉前端，这是「打开一个 md 不应该惊动整个盘」的具体落实。

⚠️ **第 11 项不能偷懒用「主屏工作区」**：多显示器下窗口会跳到主屏，最大化被打回原尺寸。
必须先问「窗口在哪块屏」，再取那块屏的可用区域，并且注意坐标系单位（逻辑点 vs 物理像素）。

### 1.4 建议的模块边界（违反会出诡异 bug）

1. **UI 不认识磁盘**：所有磁盘操作走服务桥，UI 只拿到字符串路径与内容。
2. **宿主不认识界面**：宿主只回**错误码**，句子由 UI 拼（否则多语言没法做）。
3. **差异引擎是纯函数**：不读文件、不碰 DOM，输入两段文本、输出操作序列。
4. **解析器不碰 DOM**（除构造块节点）：预览与编辑器复用同一份解析规则，不能各写一份。
5. **序列化只有一个出口**：`块 → 文本`，任何其他路径拼文本都是 bug 温床。

## 2. 数据模型

### 2.1 文档句柄（Tab）

一个标签 = 一份「内存里的文本 + 它来自哪 + 怎么存回去」。字段一个都不能少：

| 字段 | 类型 | 默认 | 谁写 | 谁读 | 说明 |
|---|---|---|---|---|---|
| `id` | int | 自增 | 创建时 | 全部 | 会话内唯一，不复用 |
| `path` | string \| null | null | 打开/保存 | 保存、监听、标题 | 绝对路径；未命名为 null |
| `name` | string | `未命名.md` | 打开/另存 | 标签、标题 | 文件名，不含目录 |
| `content` | string | `''` | 每次编辑 | 序列化、统计 | **唯一真相**，行尾已归一为 LF |
| `savedContent` | string | 同初始 content | 保存成功 / 载入 | 脏标记 | 与 content 逐字节比较 |
| `encoding` | string | `UTF-8` | 载入 / 另存 | 保存 | `UTF-8` / `UTF-16LE` / `UTF-16BE` / `GBK` |
| `bom` | bool | false | 载入 | 保存 | 是否写回 BOM |
| `eol` | string | `LF` | 载入 | 保存 | `LF` / `CRLF` / `CR`；只在写盘时还原 |
| `mode` | string \| null | null | 用户切换 | 渲染分流 | `wysiwyg` / `edit` / `preview`；null = 按类型自动 |
| `scrollTop` | number | 0 | 滚动（节流） | 恢复 | 每模式各自记忆 |
| `previewScroll` | number | 0 | 预览滚动 | 恢复 | 与 `scrollTop` 分开 |
| `caret` | object \| null | null | 光标移动 | 恢复 | 见 §2.1.1 |
| `readonly` | bool | false | 载入判定 | 编辑开关 | 二进制/超大/无权限时置真 |
| `external` | bool | false | 生成结果 | 保存流程 | 对比/合并结果：默认另存 |
| `quickNote` | bool | false | 速记 | 脏标记、会话 | 见 §3.5 |
| `mtime` | int \| null | null | 载入/保存 | 外部改动检测 | 毫秒 |
| `extChanged` | bool | false | 监听 | 标签小圆点 | 后台标签的外部改动待确认 |

**脏标记** = `content !== savedContent`，**唯一例外**：`quickNote === true` 永远算干净。
理由见 §3.5（它没有「保存」这个动作，否则每敲一个字标签就闪一下，等于把「不用保存」还给用户）。

#### 2.1.1 光标状态

```js
// 非表格块
{ blockIndex: number, offset: number }          // offset 以块内文本字符计
// 表格块
{ blockIndex: number, cell: number, offset: number }  // cell 是 th/td 的线性下标
```

⚠️ `blockIndex` 是**全文块下标**，不是「窗口内下标」。大文档窗口化时（§6.6）恢复光标
要先判断目标块是否在窗口里，不在就先搬家再落光标。

### 2.2 设置 schema

存一份对象，键名与默认值如下。**新增键不升版本号**，**改默认值必须升 `__v`**。

| 键 | 类型 | 默认 | 取值 | 说明 |
|---|---|---|---|---|
| `theme` | string | `auto` | `auto`/`light`/`dark` | auto = 跟随系统 |
| `lang` | string | `auto` | `auto` + 9 个语言码 | 见 §9.6 |
| `fontSize` | number | `13.5` | 11–24，步进 0.5 | 正文与编辑区共用 |
| `readWidth` | number | `800` | 560–1600，步进 40 | 正文最大栏宽 |
| `wrap` | bool | `true` | — | 行显示模式，**一个开关管四处**（见下） |
| `layout` | string | `single` | `single`/`split` | 单栏 / 左编辑右预览 |
| `outlineVisible` | bool | `true` | — | 侧栏大纲页 |
| `showToolbar` | bool | `true` | — | 标签行右侧三个快捷按钮 |
| `showWinTitle` | bool | `true` | — | 标题栏中间的文件名 |
| `lastMode` | object | `{}` | `{ 扩展名: 模式 }` | **只记手动切换**，见下 |
| `lastNewExt` | string | `md` | 10 种之一 | 「新建」上次选的类型 |
| `autoSave` | bool | `true` | — | 只对**有路径**的文档生效 |
| `folder` | string | `''` | 绝对路径 | 侧栏文件页打开的目录 |
| `side` | string | `outline` | `outline`/`files` | 侧栏当前页 |
| `zen` | bool | `false` | — | 专注模式 |
| `watchFiles` | bool | `true` | — | 是否监听外部修改（别的程序改了磁盘上的文件） |
| `keymap` | object | `{}` | `{ "mod+shift+k": "commandId" }` | 自定义键，优先于默认 |
| `__v` | int | `4` | — | 设置版本 |

**`wrap` 一处改、四处生效**：主窗口三种模式 + 对比窗口。实现方式两种都行 ——
CSS 侧只写「不换行」状态（`body[data-nowrap]`，用 `toggleAttribute`，不是 `dataset.nowrap=''`），
纯文本编辑器走组件的「热替换」通道（不能重建 state，否则撤销历史与选区一起没了）。

**`lastMode` 的写入时机是这套设计里最容易写错的一条**：只在用户**显式切换模式**时写，
按文件类型自动落位时**不写**。否则「打开过 cpp 文件」会把默认模式永久改成源码模式，
之后打开 Markdown 也不进所见即所得。

#### 迁移算法

```js
if (stored.__v !== DEFAULTS.__v) {
  // 1) 用新默认值覆盖「曾经改过默认值的键」
  settings.layout = 'single';
  settings.autoSave = true;
  // 2) 清掉已成粘滞值的记忆
  settings.lastMode = {};
  // 3) 新增键给一次默认值
  settings.lang = 'auto';
  save();
}
```

⚠️ 判断依据是 `!==`，不是 `<`：回退到旧版本再升级回来，也要重跑一次迁移。
⚠️ 迁移必须**幂等**（跑两遍结果相同），因为写盘可能失败。
⚠️ 「恢复默认」= `Object.assign(settings, DEFAULTS, { keymap: {}, lastMode: {} })` ——
两个记忆型字段要清空而不是沿用默认对象，否则用户的自定义键位会赖着不走。

### 2.3 块记录（大文档的模型）

超过阈值（§6.6）时，不再把整篇解析成界面节点，而是先扫成**记录数组**。一条记录的字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `type` | string | `p` / `h1`..`h6` / `li` / `bq` / `code` / `math` / `table` / `hr` |
| `md` | string | **原文切片**（含围栏、含 `$$`），不重写用户的文件 |
| `line` | int | 起始行号（0 基） |
| `nl` | int | 这块在原文里占几行（用于估高） |
| `gap` | int | 与前一块之间的空行数（**空行不建块**，只记间隔） |
| `li` | object | `{ kind: ul\|ol\|task, indent, text, num, start, checked }` |
| `indent` | int | 引用层级 |
| `callout` / `calloutTitle` | string | 提示块类型（已归一）与自定义标题 |
| `bqStart` | 1 | 与上一条引用之间有空行（独立引用） |
| `coFollow` | string | 提示块续行染色的类型（**纯视觉**，不参与序列化） |
| `lang` | string | 代码块语言 |

**为什么存原文切片而不是结构化字段**：载入 → 序列化往返天然逐字节一致，
省掉整篇重新拼装，也避免「解析器小改动让用户的文件被悄悄重排」。

⚠️ 记录里的 `gap` 是**唯一**记住空行的地方。渲染时用 `gapBetween(a,b)` 决定补几行：
`li→li`、`bq→bq`（不是提示块、不是 `bqStart`）取 0，其余取 1。

### 2.4 界面节点契约（DOM 契约）

如果目标平台还有 DOM，照抄下表即可与现有实现互换；如果换原生框架，这张表就是
「每个块要画成什么、要存什么属性」的说明书。

| 块 | 容器类名 | `data-*` | 可编辑正文宿主 | 非编辑装饰 |
|---|---|---|---|---|
| 段落 | `w-block w-p` | `type=p` | `.w-text` | — |
| 标题 | `w-block w-h` | `type=h1..h6` | `.w-text` | `.w-hash`（退格时显示的 `###`） |
| 列表项 | `w-block w-li [w-task]` | `type=li`, `list=ul\|ol\|task`, `indent`, `num`, `start`, `checked` | `.w-text` | `.w-li-marker`（`•` / `3.`）或 `input.w-check` |
| 引用 | `w-block w-bq` | `type=bq`, `indent`, `callout`, `callout-title`, `bq-start`, `bq-tail`, `co-follow` | `.w-text` | `.w-co-head`（提示块标题行） |
| 代码块 | `w-block w-codeblock` | `type=code`, `lang` | `.w-text.w-code` | `.w-codebar`（`.cc-lang` 名字 + `.cc-copy` 复制按钮） |
| 公式块 | `w-block w-mathblock` | `type=math`, `math-inline` | `.w-text.w-tex` | `$$` 由伪元素画，**不进节点** |
| 表格 | `w-block w-table` | `type=table`；内层 `table` 上 `data-aligns=",,"` | 每个 `th`/`td`（自成一格） | `data-align` 在单元格上 |
| 分割线 | `w-block w-hr` | `type=hr` | 无（`contenteditable=false`） | 一个 `<hr>` |

**四条不变式**：

1. ⛔ 可编辑正文永远在 `.w-text` 里；装饰层（语言条、编号、提示块标题）**绝不进** `.w-text`。
   序列化只读 `.w-text`，所以装饰层加多少东西都不影响存盘。
2. `data-*` 是序列化的**唯一**输入（正文文字以外）。加一个视觉属性到 `data-*` 上，
   序列化就会读到它 —— 这是「样式泄漏成语法」的常见入口。
3. 空块必须有占位（一个 `<br>` 或等价的「可落光标」标记），否则点不进去。
4. 图片是 `<img data-src="相对路径" src="可加载地址" alt="说明" [width] [height]>`：
   `data-src` 存原文，`src` 存渲染用地址。**只存一个地址会让「整目录拷走」或「本地显示」二者坏一个**。

### 2.5 三份「真相」的关系

| 层 | 存在的条件 | 谁是权威 | 同步方向 |
|---|---|---|---|
| 源文本 `content` | 永远 | 存盘与统计以它为准 | 编辑器 → 文本（防抖） |
| 块记录 `records` | 超过阈值才建 | 大文档下**它是权威** | 记录 ↔ 窗口内节点 |
| 界面节点 | 永远（可能只有一屏） | 从不权威 | 只作为渲染与输入的载体 |

⚠️ 常见错误：以为「界面节点是真相」。只要有一次「删除节点 → 从未同步回模型」，
大文档就会在存盘时丢内容。**所有结构修改都必须先改模型或先改节点并立刻同步**。

### 2.6 撤销模型

一份历史栈，存的是**快照**而不是补丁：

```js
snapshot = { md, caret }                       // 小文档：整篇文本
snapshot = { recs, trail, caret }              // 大文档：记录数组的浅拷贝
state    = { history[], hIndex, hLast, hBytes, hCoalesce }
```

| 参数 | 值 | 为什么 |
|---|---|---|
| 合并窗口 | **700 ms** | 连续打字合成一步，停手 0.7s 后另起一步 |
| 条数上限 | **200** | 小文档够用 |
| 字节上限 | **8 MB** | 长文档每份快照几十 KB，200 条会常驻十几 MB |
| 单份大小估算 | `recs ? recs.length*8+64 : md.length*2` | 记录快照只算指针 |
| 快照浅拷贝 | `records.slice()` | **零成本**：未改动的块是同一个对象（写时复制） |

**去重**：新快照与栈顶内容相同就不入栈（记录模式按**对象引用**逐项比较，几万次指针比较零成本）。
**裁剪**：超条数或超字节时从**最旧**开始丢，但至少保留 2 条（否则撤销立刻失效）。

⚠️ 撤销前必须先 flush 挂起的输入（停手 400ms 内按 Ctrl+Z，这几下会丢）。
⚠️ 撤销后要把「合并开关」关掉：否则用户撤销完接着打字，新内容会被合进刚恢复的那一步，
表现为「撤销不管用」。

## 3. 磁盘契约

### 3.1 数据目录树

```
<应用数据目录>/                      Windows: %APPDATA%\com.simple.notepad
                                    macOS:   ~/Library/Application Support/com.simple.notepad
                                    Linux:   ~/.local/share/com.simple.notepad
├── quicknote.md                    速记：固定位置、固定名字
└── history/                        历史快照
    └── <16 位十六进制>/              = fnv1a(绝对路径)，见 §3.4
        ├── name.txt                原文件名（只为在文件夹里认得出）
        └── <毫秒时间戳>.txt         一份「保存前」的内容
```

⚠️ 应用标识 `com.simple.notepad` **不能改**：一改，老用户的速记与历史就全部「消失」（其实是换了目录）。

### 3.2 键值清单

现有实现把「界面偏好 / 会话 / 草稿 / 最近」放平台的键值存储（WebView 的 localStorage，
键前缀 `snp.`）。**换平台时用什么介质都行**（一个 JSON 文件、NSUserDefaults、注册表），
但要保住三件事：**键名、值结构、写入时机**。

| 键 | 值结构 | 何时写 | 何时清 |
|---|---|---|---|
| `snp.settings` | 设置对象（§2.2） | 任何设置变更 | 恢复默认时覆盖 |
| `snp.session` | `[{path,name,mode,scrollTop,previewScroll,caret}]` | 标签切换/打开关闭后 400ms | 退出时保留（下次恢复用） |
| `snp.sessionActive` | string（`path` 或 `name`） | 同上 | 同上 |
| `snp.drafts` | `[{path,name,content,encoding,bom,eol,mode,scrollTop,caret,time}]` | 编辑停手 400ms | 恢复完 / 丢弃后立即删 |
| `snp.draft` | 旧版单份草稿 | 只读兼容 | 读到就升级并删除 |
| `snp.recent` | `string[]`（绝对路径，最多 12 条） | 打开/保存成功后 | 菜单「清除记录」 |

⚠️ `snp.session` **不含速记**。速记不是「上次打开的文档」，混进去还会把它的路径塞进
「最近打开」，两份列表都不再干净。

### 3.3 会话与草稿

这是「关掉再打开，刚才的活儿还在」的全部机制。两个概念必须分开：

| | 会话（session） | 草稿（drafts） |
|---|---|---|
| 记什么 | 打开了哪些文件、光标/滚动在哪、上次什么模式 | **未保存的正文** |
| 有路径的文档 | 记 | 内容与磁盘不同才记 |
| 未命名文档 | **不记**（没有路径） | 有字就记 |
| 恢复时问不问 | 不问，静默重开 | **要问**（「恢复 N 份未保存的内容」） |

#### 草稿存储预算算法

```js
const BUDGET = 4 * 1024 * 1024;          // 键值存储一般 5MB，给设置和会话留余量
let budget = BUDGET;
const list = [];
for (let i = dirty.length - 1; i >= 0; i--) {   // 从最新往回装
  const t = dirty[i];
  const size = (t.content || '').length * 2;    // UTF-16 粗算
  if (size > budget) continue;                  // 装不下的整份跳过，不截断
  budget -= size;
  list.unshift({ ...snapshotOf(t) });           // unshift 保持原顺序
}
```

**为什么不截断**：截断过的稿子存回去等于悄悄丢内容，用户下次恢复看到的是半个文件。
跳过整份至少是「这一份没保住」，语义诚实。

⚠️ **一份都没有时必须删键**，而不是存空数组：空数组会让「恢复草稿」的弹窗逻辑
在旧数据残留时误判。

#### 恢复流程

```
1. 读 drafts（含旧版单份 draft，读到就升级成数组）
2. 逐份校验：
   - 有 path：读磁盘，若「磁盘内容 == 草稿内容」（两边都归一 LF）→ 丢弃这份
     （说明其实已经存过了，不该再当成未保存）
   - 无 path：内容非空白才保留
3. 一份都不剩 → 删键，静默返回
4. 有剩 → 弹一次确认框（列出文件名与「上次关闭时间」）
   - 用户选「丢弃」→ 删键，全部不恢复
5. 逐份开标签，且 savedContent 必须填**磁盘上的内容**（不是草稿内容）
   - 否则一打开就是「已保存」，关窗时不提醒，等于把草稿又还回去了
   - 磁盘读不到（文件被删）就填空串 → 保持「未保存」状态
6. 恢复完删键，并立刻重写一次 session（恢复过程会覆盖它）
```

### 3.4 历史快照

**语义**：每次**写盘之前**，把「写盘前的磁盘内容」留一份。自动保存、一键格式化、
排序去重之后想反悔，撤销栈已经翻不回去了，这是最后一道。

**只写不读原文件**：回滚永远是「开成新标签」或「写回编辑器」，**绝不直接覆盖磁盘**。

```js
// 目录名 = 64 位 FNV-1a(绝对路径)，16 位小写十六进制
function fnv1a(s) {
  let h = 0xcbf29ce484222325n;
  for (const b of new TextEncoder().encode(s)) {
    h ^= BigInt(b);
    h = (h * 0x100000001b3n) & 0xffffffffffffffffn;
  }
  return h.toString(16).padStart(16, '0');
}
```

| 步骤 | 规则 |
|---|---|
| 内容为空 | 不存（空文件没有回滚价值，还会挤掉真正的快照） |
| 与最新一份相同 | 不存（自动保存会反复触发） |
| 文件名 | 毫秒时间戳 + `.txt`；时间戳为 0 的条目一律忽略（防御脏文件） |
| 保留 | 最近 **60** 份，且总量 **20 MB**，从最旧开始删 |
| 列表 | 按时间倒序返回；每项含路径、时间、大小 |

⚠️ 删除是**按排序后的顺序累加体积**再判断，不是「先删到 60 份再看体积」：
两个条件要同时生效，任一条越界就继续删。

### 3.5 速记

一份「不需要保存」的固定文件。它是这套设计里唯一**没有保存动作**的文档。

| 规则 | 值/做法 | 理由 |
|---|---|---|
| 位置 | `<数据目录>/quicknote.md` | 固定：不需要选位置、不需要另存，重开还是同一份 |
| 覆盖路径 | 环境变量 `EZNOTEPAD_QUICKNOTE` | **测试必须用它**，绝不能碰用户真正的速记 |
| 可开几份 | **只允许一份** | 再点「速记」= 切到已开的那份；`openPath` 遇到同一路径要改道 |
| 脏标记 | 永远 false | 见 §2.1：它随时写盘，弹「要保存吗」等于把「不用保存」还给用户 |
| 落盘时机 | 输入停手后短延迟 + **关闭标签 / 退出前强制 flush** | 「永远算干净」与「关前必须 flush」是一对，缺一个就丢字 |
| 另存为 | 只导出**副本**，不改 `path` | 改 path 会让速记从固定位置搬走，下次打开就找不到 |
| 会话 | 不进 session、不进 recent | 同 §3.2 |
| 监听 | 不监听 | 它由我们自己写，监听自己会把每次自动保存当成「外部改动」 |

### 3.6 最近打开

`recent` 存最多 **12** 条，菜单只显示 **6** 条 + 「清除记录」。
每项展示：文件名（主）、完整路径（提示）、末级目录名（右侧小字，截 16 字符）。

### 3.7 编码探测与写回

#### 读入：按顺序判定，第一个命中即返回

| 顺序 | 条件 | 结果 |
|---|---|---|
| 1 | 字节以 `EF BB BF` 开头 | UTF-8，`bom=true`，跳过 3 字节解码 |
| 2 | 字节以 `FF FE` 开头 | UTF-16LE，`bom=true`，跳过 2 字节 |
| 3 | 字节以 `FE FF` 开头 | UTF-16BE，`bom=true`，跳过 2 字节 |
| 4 | 严格 UTF-8 校验通过 | UTF-8，`bom=false` |
| 5 | 以上都不成立 | **GB18030** 解码，标记为 `GBK`（覆盖 GBK/GB2312） |

```js
function decode(bytes) {
  if (startsWith(bytes, [0xEF,0xBB,0xBF])) return { text: UTF8(bytes.slice(3)), enc: 'UTF-8',   bom: true  };
  if (startsWith(bytes, [0xFF,0xFE]))      return { text: UTF16LE(bytes.slice(2)), enc: 'UTF-16LE', bom: true };
  if (startsWith(bytes, [0xFE,0xFF]))      return { text: UTF16BE(bytes.slice(2)), enc: 'UTF-16BE', bom: true };
  if (isValidUTF8(bytes))                  return { text: UTF8(bytes), enc: 'UTF-8',   bom: false };
  return { text: GB18030(bytes), enc: 'GBK', bom: false };
}
```

⚠️ 第 5 条是**兜底而不是猜**：用 GB18030 解码任意字节都不报错（它是多字节全覆盖的），
所以「中文乱码」几乎不会发生，代价是非中文的二进制会被解成一片怪字 —— 由 §3.8 的
二进制判定先挡掉。

**行尾探测**：文本含 `\r\n` → `CRLF`；否则含 `\r` → `CR`；否则 `LF`。
**内存里永远是 LF**，`eol` 只作为「写回时用什么」的标记。

⚠️ 不做这个归一的话：打开一个 CRLF 文件、一个字没改，模式切换时序列化出 LF，
与 `savedContent`（CRLF）对不上 —— 文件立刻显示「未保存」。这是最容易被当成
「脏标记坏了」的假 bug。

#### 写回

```js
out = []
if (bom) {
  out += enc === 'UTF-16LE' ? [0xFF,0xFE]
      :  enc === 'UTF-16BE' ? [0xFE,0xFF]
      :                        [0xEF,0xBB,0xBF];
}
switch (enc) {
  case 'UTF-16LE': out += utf16le(content); break;
  case 'UTF-16BE': out += utf16be(content); break;
  case 'GBK':      out += gb18030Encode(content); break;   // 超过 512MB 报「文件过大」
  default:         out += utf8(content);
}
write(path, out);       // 目录不存在先递归创建
```

**原编码写回**是硬要求：用户拿 GBK 打开的文件，存回去必须还是 GBK。
悄悄转 UTF-8 会让同目录的其他工具（老 IDE、脚本）读成乱码。

### 3.8 二进制判定与写盘

| 规则 | 值 | 说明 |
|---|---|---|
| 二进制判定 | 前 **8192** 字节里出现 `0x00` | 命中直接拒绝打开，报「这是二进制文件」 |
| 单次写盘上限（GBK 路径） | 512 MB | 超了报「文件过大」，避免编码缓冲把内存吃穿 |
| 图片落盘上限（剪贴板） | 64 MB | 超了报错，不写半个文件 |
| 图片内嵌上限（导出 HTML） | 4 MB/张 | 超了保留原路径，在提示里说明 |
| 目录列举上限 | 20000 条 / 深度 24 | 超了**截断并明说**，不能让人以为「就这么多」 |

**原子性的现状与建议**：现有实现直接 `fs::write`（覆盖写）。换平台时
⛔ 不要用「先删再写」：中途失败会留下一个空文件。用平台的原子写
（`Data.write(options: .atomic)` / 临时文件 + rename）。

### 3.9 文件树的写操作

| 操作 | 前置校验 | 失败必须报清什么 |
|---|---|---|
| 新建文件/目录 | 父目录存在；名字非空；不含 `/ \ < > : " \| ? *`；不是 `.`/`..`；目标不存在 | 「已存在」「名字不能包含 …」 |
| 重命名 | 源存在；新名字同上校验；目标不存在（同名同路径视为成功） | 同上 |
| 删除 | 进系统回收站；回收站不可用时报错，⛔ 不要退化成永久删除 | 「无法移入回收站」 |

校验只做「单层名字」：任何带路径分隔符的输入一律拒绝，避免从侧栏越出当前目录。

#### 在文件列表中定位（`FileTree.reveal`）

```js
async reveal(path) {                       // → 'revealed' | 'already' | 'outside' | 'gone'
  if (!root || !path) return 'outside';
  if (p !== root && !p.startsWith(root + '\\') && !p.startsWith(root + '/')) return 'outside';
  for (const d of ancestorsBetween(root, path)) expanded.add(d);   // 只往集合里加
  if (加了新的 || body 里没有 .ft-row) await render();             // 重画一次，别自己拼 DOM
  const row = _rowOf(p); if (!row) return 'gone';
  row.scrollIntoView({ block: 'nearest' });
  row.classList.add('active');
  row.classList.remove('ft-flash'); void row.offsetWidth; row.classList.add('ft-flash');
  setTimeout(() => row.classList.remove('ft-flash'), 1100);
  return wasActive ? 'already' : 'revealed';
}
```

| 触发 | 顺序 |
|---|---|
| 页签右边的 `#sideLocate`（Lucide `locate`，`src/vendor/icons/lucide/locate.svg`） | ① `settings.outlineVisible = true` + `updateOutline()` ② `setSide('files')` ③ `tree.reveal(path)` |

⚠️ **三步顺序不能换**：目标在 `display:none` 的容器里时 `clientHeight` / `scrollTop` 都是 0，
`scrollIntoView` 等于没滚，函数却照样返回成功。同理，`expanded` 是「哪些目录开着」的唯一真相，
reveal 只往里加、再 `render()` 一次；自己补 DOM 会和 render 里那套「按层级深浅补开目录」漂移。

⚡ 闪烁只改 `background` / `box-shadow`（`@keyframes ft-flash`，320ms × 3），不动尺寸与位置 ——
一行要是在闪的时候抖一下，说明改的是 `padding` / `margin`，那是错的。

## 4. Markdown ⇄ 块

### 4.1 两个解析器，两套粒度

同一个文件要喂两个消费者，粒度不同，**必须写两份解析器**（共用分类正则，不共用组装逻辑）：

| | 编辑器解析器 | 预览/导出解析器 |
|---|---|---|
| 用途 | 文本 → 可编辑块 | 文本 → 阅读用 HTML |
| 段落粒度 | **一行一块**（回车就分块） | 连续非空行合并成一个 `<p>`（行尾两空格 = `<br>`） |
| 空行 | **不建块**，只记间隔 | 忽略 |
| 列表 | 一项一块（扁平 + `indent` 属性） | 真正嵌套的 `<ul>/<ol>` |
| 表格 | 整块，内部 DOM 表格 | 同左 |
| 引用 | 一行一块，`indent` 表层级 | 连续 `>` 行合并成一个 `<blockquote>`（可递归） |

⚠️ 把两份合成一份会立刻出问题：编辑器需要「一行一块」才能让光标有落点；
预览需要「合并段落」否则每个换行都成为段间距。

### 4.2 行分类器（优先级从上到下，第一条命中即返回）

```js
RE_FENCE      = /^\s*(`{3,}|~{3,})\s*([^\s`]*)\s*$/          // 围栏：标记 + 语言名
RE_HR         = /^\s*([-*_])\s*(?:\1\s*){2,}$/                // 分割线：同一符号 ≥3 次
RE_HEADING    = /^(#{1,6})\s+(.*?)\s*#*\s*$/                  // ATX 标题
RE_QUOTE      = /^\s*((?:>\s?)+)(.*)$/                        // 引用（前缀可重复）
RE_UL         = /^(\s*)[-*+]\s+(.*)$/                         // 无序项
RE_OL         = /^(\s*)(\d{1,9})[.)]\s+(.*)$/                 // 有序项（. 或 )）
RE_TASK       = /^(\s*)[-*+]\s+\[([ xX])\]\s+(.*)$/           // 任务项
RE_TABLE_SEP  = /^\s*\|?\s*:?-{1,}:?\s*(\|\s*:?-{1,}:?\s*)*\|?\s*$/   // 表格分隔行
RE_CALLOUT    = /^\[!(info|warning|danger|success|note|tip|important|caution)\]\s*(.*)$/i
```

判定顺序（**顺序本身是设计**，换序会改变语义）：

| # | 判据 | 为什么必须在这个位置 |
|---|---|---|
| 1 | 围栏 `` ``` `` / `~~~` | 围栏里的一切都算正文，必须先吃掉整段 |
| 2 | 行首 `$$` | 块级公式可跨行，必须整体吃掉 |
| 3 | 空行（只有空格/制表符） | 只记账（间隔），不产块 |
| 4 | 分割线 | **必须先于列表**：`---` 同时长得像无序项和 Setext 下划线 |
| 5 | 标题 `#{1,6} ` | 空标题**原地降级为段落**（见下） |
| 6 | 表格（本行含 `\|` 且下一行是分隔行） | 依赖下一行，所以放在单行规则之前 |
| 7 | 引用 `>` | 引用里的 `[!info]` 顺带升级为提示块 |
| 8 | 任务项 | **必须先于无序项**：`- [ ] x` 也匹配 `RE_UL` |
| 9 | 无序项 | |
| 10 | 有序项 | |
| 11 | 其余 | 段落（一行一块，去行尾空白） |

**空标题降级的理由**：标题下方会画一条装饰线。空标题留着，页面上就是一条没有文字的
横线（像凭空多出来的分割线），而且接着打字还是标题。所以解析时直接造段落。

⚠️ 段落的「一行一块」意味着：用户在源码模式里看到的三行一段，进所见即所得会变成三块。
这是刻意的 —— 每一块都要有独立光标位。

### 4.3 缩进层级：按「列」而不是按字符数

```js
const leadingCols = (ws) => {           // 制表符算 4 列
  let n = 0;
  for (const ch of ws) n += ch === '\t' ? 4 : 1;
  return n;
};

function makeLevelTracker() {           // 层级栈
  const cols = [];
  return (col) => {
    while (cols.length && col < cols[cols.length - 1]) cols.pop();
    if (!cols.length) cols.push(col);
    else if (col > cols[cols.length - 1]) cols.push(col);
    return Math.min(MAX_INDENT, cols.length - 1);      // 上限 6 层
  };
}
```

**为什么不用「缩进 ÷ 2」**：有人用 2 空格、有人用 3 或 4、有人混用制表符。
按列建栈之后，这四种写法都能读出正确的嵌套，序列化时再统一成规范列宽（§4.5）。

⚠️ 层级栈在遇到**非列表块**时要重置（`levelOf.reset()`），否则上一段列表的缩进会
污染下一个列表。

### 4.4 容器组装

#### 列表缩进列宽（序列化侧）

子项要缩进到**父项正文所在的列**，这样交给任何渲染器都不会散架：

```js
const cols = [];                       // cols[level] = 该层子项的起始列
// 对每个 li：
const lvl = min(indent, 6);
cols.length = lvl + 1;
const base = lvl === 0 ? 0 : (cols[lvl - 1] ?? lvl * 2);
const marker = kind === 'ol'   ? `${num}. `
             : kind === 'task' ? `- [${checked ? 'x' : ' '}] `
             :                   '- ';
line = ' '.repeat(base) + marker + text;
cols[lvl] = base + marker.length;      // 正文从这一列开始
```

`cols[lvl - 1] ?? lvl * 2` 的兜底很重要：层级跳跃（0 直接到 2）时没有父列可参考，
退回「每层 2 列」的常规写法，不能算出 `NaN`。

#### 引用分组

引用是**一行一块**，靠两个标记维持视觉与语义：

| 标记 | 何时打 | 作用 |
|---|---|---|
| `bq-start` | 本块是引用，且**紧邻的上一行不是引用行**（中间隔了空行） | 这是新的独立引用，序列化时要断开 |
| `bq-tail` | 下一块也是引用且没有 `bq-start` | 只用于视觉：上一行的框不封底（CSS 不能写 `:has(+ ...)`） |
| `co-follow` | 提示块之后连续出现的普通引用行 | 纯染色：它们属于同一个提示框，但**不重复写 `[!x]`** |

⚠️ 提示块的续行 ⛔ 不能序列化成新的 `[!info]` 行：原文只有一处标记，写重了往返就不等。
`co-follow` 只在渲染层存在。

#### 提示块类型归一

```
info / note          → info      图标 info
warning / important  → warning   图标 triangle-alert
danger / caution     → danger    图标 octagon-alert
success / tip        → success   图标 circle-check
```

键是小写；`[!NOTE]` 与 `[!note]` 等价。默认标题用当前语言的译名（「信息」「警告」…），
用户自定义标题优先。

### 4.5 序列化

#### 逐类型规则（`rawBlock`）

| 类型 | 输出 |
|---|---|
| `hr` | `---` |
| `table` | 表头行 + 分隔行 + 数据行（见 §4.5.1） |
| `code` | `` ``` `` + 语言名 / 正文 / `` ``` ``（语言名为空时是裸三个反引号） |
| `math` | `math-inline` 且正文无换行 → `$$x$$` 单行；否则 `$$` / 正文 / `$$` 三行 |
| `h1`..`h6` | `#`×级别 + 空格 + 行内源 |
| `li` | 只返回 `{type, text}`（标记与缩进要等组装时按 `cols` 拼） |
| `bq`（普通） | `'> '.repeat(indent+1)` + 行内源 |
| `bq`（提示块） | 前缀 + `[!type]` +（自定义标题）+ 换行 + 前缀 + 正文 |
| 其他 | 行内源 |

**行内源** = `inlineToMd(正文宿主)`：把 `<strong>`/`<b>` → `**`、`<em>`/`<i>` → `_`（**统一成下划线**）、
`<code>` → 反引号、`<del>` → `~~`、`<a>` → `[文字](地址)`、`<img>` → `![alt](data-src)` + 尺寸后缀、
`<br>` → 指定文本（表格里是 `<br>`，正文里丢弃）。

⚠️ **换块类型时搬文字必须用行内源，不能用纯文本**：用 `textContent` 会把 `**加粗**` 退成
普通字、把链接退成标题，换一次类型等于悄悄削掉一层格式。
⚠️ 提示块的自定义标题存在 `data-callout-title` 里、不在正文，换类型时要一起搬走，
否则「`> [!info] 我的标题`」转成代码块会变成一个空块，用户写的字就没了。

#### 4.5.1 表格

```
| 表头1 | 表头2 |
| :--- | ---: |
| 单元格 | 单元格 |
```

| 规则 | 做法 |
|---|---|
| 单元格分隔 | `\|`；内容里的竖线转义成 `\\\|` |
| 对齐 | `:---` 左 / `:---:` 中 / `---:` 右 / `---` 默认；存在 `table` 的 `data-aligns` 里 |
| 单元格内换行 | 存成 `<br>` 字面文本（GitHub/Typora 同款约定），解析时再还原成真换行 |
| 空单元格 | 只写一个 `\|` 之间的空位；⚠️ 占位 `<br>` **不是内容**，不能写出去 |
| 列数 | 以**表头**的列数为准；数据行多出的列丢弃，少的补空 |

⚠️ 「占位 `<br>` 不是内容」这条要判 `textContent` 去掉零宽空格与空白后是否为空，
不能看节点里有没有 `<br>`。

#### 4.5.2 组装（块间空行与首尾修剪）

```js
const tight = (prevType, cur) =>
     (prevType === 'li' && cur.type === 'li')                        // 列表项之间紧凑
  || (prevType === 'bq' && cur.type === 'bq' && !cur.co && !cur.bqStart);  // 同组引用紧凑

for (const c of chunks) {
  const isBlankBlock = c.lines.length === 1 && c.lines[0] === '';    // 空段落自己就是空行
  if (lines.length && prev && !tight(prev, c) && !isBlankBlock) lines.push('');
  lines.push(...c.lines);
  prev = c.type;
}
while (lines.length && lines[0].trim() === '') lines.shift();        // 首尾空行无意义
while (lines.length && lines[lines.length - 1].trim() === '') lines.pop();
```

三条容易漏的细节：

1. **空段落别再额外补空行**，否则每存一次盘就多一行（累积漂移）。
2. **首部空段落必须清掉**：把标题文字删光后它会留在最前面，存盘就多出两行空行。
3. **引用后面跟提示块必须断开**：不然两个 `[!xx]` 会进同一段引用，预览里第二个标记
   变成普通文字，往返一次就丢了类型。

#### 4.5.3 结尾换行

`trailingNewline` 是**文档级**标记：新文档默认「以换行结尾」（POSIX 惯例），
载入文件时按实际内容修正，保存时按它补。

⚠️ 不记这一位，会出现「打开文件立刻变脏」：原文没有结尾换行，序列化却补了一个。

### 4.6 增量序列化缓存（大文档必做）

每次击键都全量序列化，万行文档会明显卡顿。方案：**按块缓存 + 廉价指纹**。

```js
// 指纹覆盖「序列化会读到的全部输入」：
sig = dataset.type|indent|num|list|checked|start|lang|callout|calloutTitle|bqStart|mathInline
    + (table ? '|al' + table.dataset.aligns : '')
    + '|wt' + textHost.childNodes.length
    + (纯文本快路径 ? '' : 每个行内标签的计数 + 图片的 data-src/alt/width)
    + '\u0001' + 块.textContent
```

| 规则 | 说明 |
|---|---|
| 指纹不符 → 重算该块 | **唯一**的正确性依据 |
| 指纹相同 → 复用上次结果 | |
| 纯文本快路径 | 正文只有文本节点时，跳过 `querySelectorAll`（大多数段落走这条） |
| 组装永远全量 | 空行与缩进依赖邻居，成本只是逐块读类型 |

⚠️ 不要用「监听 DOM 变化」来失效缓存：实测会漏事件，漏一次就是存盘丢内容。
指纹校验慢一点，但不会错。

### 4.7 幂等性要求

`parse(serialize(parse(md))) === parse(md)`，且 `serialize(parse(md))` 对
**已经是规范形态**的 `md` 应当逐字节相等。违反这条的症状是「打开文件就变脏」。

具体的往返向量见附录 A —— 那 24 条是这套解析器的验收门槛，改解析器前先跑一遍。

## 5. 编辑器行为

这一章是「一样的程序」的主体。**每一条判据都对应一个用户会立刻察觉的差别**。

### 5.1 输入即转换

#### 触发点

```
input 事件
  → normalize(false, true)          // 只扫光标附近三块（§5.14）
  → applyBlockRule()                 // 段首语法糖；接管了就 return
  → applyInlineRule()                // 行内标记收尾
  → queueFlush()                     // 防抖序列化（约 60–300ms）
```

#### 块规则（光标之前那一小段文字匹配即换块）

**判据是「光标之前这一段」而不是整行**：光标可以停在已有文字正前方，只敲标记，
标记后面的文字原样留进新块。于是「先写内容再补 `#`」和「先打 `#` 再写内容」是同一件事。

| 判据（对 `mark` 匹配） | 变成 | 注意 |
|---|---|---|
| `^#{1,6}\s$` | 对应级别标题 | 空格是触发条件 |
| `^```([\w#+.-]*)\s$` | 代码块（带语言名） | ⚠️ **必须带空格**：不带空格时会在第三个反引号就转块，紧接着敲的语言名落进正文。不带空格的写法（`` ```js `` + 回车）由 Enter 接住 |
| `^>\s$` | 引用 | |
| `^\[!(info\|warning\|danger\|success\|note\|tip\|important\|caution)\]\s$` | 提示块 | 在引用行里敲也走这条 |
| `^([-*+])\s\[([ xX])\]\s$` | 任务项 | ⚠️ 必须先于下一条 |
| `^([-*+])\s$` | 无序项 | |
| `^(\d{1,9})[.)]\s$` | 有序项（序号取输入值） | |
| `mark === 整行` 且 `^(-{3,}\|\*{3,}\|_{3,})$` | 分割线 + **自动补一个空段落** | 只有整行就这些字符时才触发 |

前置条件：块是段落（引用行另有分支）、选区已折叠、光标在正文宿主内、`mark` 长度 **≤ 16**。

**长度上限 16 的理由**：长文档里有人写一整段以 `- ` 开头的文字，逐字符判定会误触发。
16 个字符足够容纳最长的那条（`` ```js `` 占 5 个）。

**搬运后半段的做法**（伪代码）：

```js
// 把光标之后的 DOM 片段（不是纯文本！）搬进新块
const frag = rangeFrom(caret, endOf(textHost)).extractContents();
for (const n of children(frag)) if (n.nodeName === 'BR') n.remove();   // 占位 <br> 不搬
if (hasRealContent(frag)) { newHost.innerHTML = ''; newHost.appendChild(frag); }
block.replaceWith(newBlock);
placeCaretStart(newBlock);
```

⚠️ 占位 `<br>` 必须摘掉：新块自己会补一个，多出来的一行高会把后续回车拆分算歪。
⚠️ 用 DOM 片段而不是 `textContent`：否则 `**粗体**`、链接、行内码在换块时被抹平。

#### 无序项升级为任务项

逐字输入时 `- ` 会先把段落变成无序列表，后面那截 `[ ] ` 再也碰不到段首规则
（此时块已经不是段落）。所以要有一条**补丁规则**：

```
块是 li 且 list=ul，光标前一段匹配 ^\[([ xX])\]\s$  →  原地换成同缩进的 task 项
```

没有这条，任务列表只能靠粘贴整行或菜单做出来，表现为「一个圆点后面跟着字面的 `[ ]`」。

#### 行内规则（输入收尾符时立刻变样式）

只处理**光标所在的那个文本节点**，且不在代码块/公式块里：

| 判据（对光标前的文本节点内容） | 变成 |
|---|---|
| `\*\*([^*\n]+)\*\*$` | 粗体 |
| `__([^_\n]+)__$` | 粗体 |
| `~~([^~\n]+)~~$` | 删除线 |
| `` `([^`\n]+)`$ `` | 行内代码 |
| `!\[([^\]\n]*)\]\(([^)\s]+)\)$` | 图片 |
| `\[([^\]\n]+)\]\(([^)\s]+)\)$` | 链接 |
| `(?<![*\w])\*([^*\n]+)\*$` | 斜体 |
| `(?<![_\w])_([^_\n]+)_$` | 斜体 |

**三条必须遵守的实现细节**：

1. 已经在该标签里就不再嵌套（`parent.closest(tag)` 命中则跳过），否则 `**` 套 `**` 会无限嵌。
2. **转换后必须在元素后面补一个零宽空格文本节点，把光标放进去**。否则紧接着输入的字符会
   继续塞进 `<strong>` 里，看起来像粗体没结束，序列化出来就是 `**粗 尾**`。
3. 浏览器在这个 input 事件收尾时还会再修一次选区 —— 要在微任务里**再摆一次**光标。

#### 单元格里的行内格式（`selInOneCell`）

表格单元格是「结构容器」：`<td>` 里套 `<mark>` / `<strong>` 合法且能往返
（`inlineHtml` 解析、`inlineToMd` 序列化两头都认），但 `extractContents` **跨格**取内容会把
`<td>` 一起搬进包装元素里，表格当场散架。

```js
selInOneCell() {                    // → 单元格 | null
  const cell = this.currentCell(); if (!cell) return null;
  const r = getSelection().getRangeAt(0);
  const elOf = (n) => (n.nodeType === 1 ? n : n.parentElement);
  if (!cell.contains(elOf(r.startContainer))) return null;
  if (!cell.contains(elOf(r.endContainer))) return null;
  return cell;
}
```

`toggleInline` / `toggleMark` **只拦跨格**（`if (currentCell() && !selInOneCell()) return`），
单格内的加粗 / 斜体 / 行内码 / 删除线 / 高亮照常生效。⛔ 不要再回到「见到单元格就整条返回」：
那正是「表格里的字选得中、却什么都加不上」的成因。

#### `/` 起插入面板（把 + 号搬到键盘上）

手柄的 `+` 只有鼠标能点。键盘入口是**行首或空白之后敲 `/`**。它不改块类型，
所以不放进上面的规则表；它等价于「点 + 号」，走的是同一张面板。

**触发判据（全部为真才接管）**：

| # | 条件 | 理由 |
|---|---|---|
| 1 | `e.key === '/'`，无 Ctrl/Alt/Meta | 单字符、无修饰 |
| 2 | `!e.isComposing && e.keyCode !== 229` | 组字中的标点归输入法 |
| 3 | 面板未打开，且当前是所见即所得 | 只有这个模式有块 |
| 4 | `currentBlock()` 存在、`currentCell()` 为空 | 表格单元格里的 `/` 是正文 |
| 5 | `block.dataset.type` ∈ `p` / `h1..h6` / `li` / `bq` | 代码块 / 公式块 / 分割线排除 |
| 6 | 选区折叠，偏移按**块口径**读（`caretOffsetInBlock()`：光标停在 `.w-block` 上时折算成 0 / 末位） | 有选区时 `/` 是替换；删空一行后光标就在块上，严格按 `.w-text` 读会得到 -1，面板再也唤不出来 |
| 7 | `text.slice(0, off)` 去掉 `\u200b` 后为空、或以空白结尾 | 日期 / 路径 / 分数不触发 |

顺序上**先确认面板能开、再 `preventDefault`**：`placeHandle(block)` 没落到这一块就
原样放行，字符照常落进正文。反过来写（先吞字符）会出现「`/` 没了、面板也没出来」。

**状态**（两个字段，都在 app 层）：

```js
slashAt = { block, off };   // 被拦下的 "/" 该回到哪里；off 是 .w-text 的字符偏移
bmFromSlash = true;         // 面板是不是从 "/" 长出来的
```

**关闭的三条路径，各自对 `/` 的处理**：

| 路径 | `/` 怎么办 | 备注 |
|---|---|---|
| 选中了某一项（`bmRun`） | **丢弃** | 触发符和菜单项一起被消费 |
| Esc / 点别处 / 滚动 / 敲了没分配的键 | **按 `off` 插回正文** | 光标还在原处就顺手推到斜杠后面 |
| 面板里再按一次 `/` | 插回一次，且这一下不再落字 | 面板消费 + `stopPropagation` |

第三行必须 `stopPropagation`：编辑区那层 `/` 监听若用「面板是否开着」判断，此刻它已经
关了，会当场把面板重新弹出来（表现为按 Esc 后菜单关了又开）。

**补回的实现要点**：

```js
const stick = caretOffsetInBlock(block) === s.off;   // 光标还在原处？（同一个块口径）
const p = textPosAt(t, s.off);              // 偏移 → {node, off}
rangeAt(p).insertNode(document.createTextNode('/'));
if (stick) collapseAfter(node);             // 否则别抢用户已经移走的光标
wys.flush();                                // 进撤销栈 + 打脏标记
```

⚠️ 不要「先插入斜杠再删除」：那会在撤销栈里多一条「删斜杠」，还得把光标搬来搬去。
`preventDefault` 掉按键、字符从没进过正文，是最省事也最不容易错的做法。

**选择键**（`blockKinds()` / `blockInserts()` 的 `key`，渲染进 `.bm-kbd`）：

| 键 | 项 | 键 | 项 |
|---|---|---|---|
| `0` | 正文段落 | `8` | 代码块 |
| `1` `2` `3` | 标题 1 / 2 / 3 | `9` | 信息提示块 |
| `4` | 无序列表 | `w` `d` `s` | 警告 / 危险 / 成功提示块 |
| `5` | 有序列表 | `t` `T` | 表格 3×3 / 表格（自定大小） |
| `6` | 任务列表 | `i` `l` `-` | 图片 / 链接 / 分割线 |
| `7` | 引用 | | |

分派写在面板已有的 `document` keydown（capture）里：`k.length === 1` 且无修饰 →
**先精确匹配 `dataset.key`、再退回大小写不敏感**（`t` 与 `T` 是两档，不能合并）。
命中就 `preventDefault` + `stopPropagation` + `click()`；没命中走原来那条
「收起面板、字符落进正文」。

**空段落复用**：从 `/` 进面板时若当前块是空段落，类型项**原地改这一块**，不在下面新建。
判据：`block.textContent` 去掉 `\s` 与 `\u200b` 后为空。否则用户看到的是
「斜杠没了，标题跑到下一行」，还白留一个空行。

**撤销**：斜杠被拦不产生历史；补回时 `flush()` 记一条，按 Ctrl+Z 能撤掉它。

### 5.2 Enter

```
Enter
├─ 在单元格里
│   ├─ Shift 按住        → 格内换行（插入一个 <br>）
│   └─ 否则              → cellEnter()（§5.9）
├─ 块是分割线 / 表格      → 在块下方插入空段落，光标落在里面
├─ 块是代码 / 公式        → codeNewline()（插入 <br> + 零宽空格）。**永远换行**，
│                           出块不在这里，走 → / ↓（§5.5）
├─ 块是段落且整行是 ``` + 语言名 → 原地换块（保留语言名）
└─ 其他
    ├─ hideHashes()      // 标题的 ### 收起来
    └─ splitBlock()      // 光标前留在原块，光标后进新块
```

| 情形 | 结果 | 为什么 |
|---|---|---|
| 空标题里回车 | 退回**段落** | 「在空标题里回车 = 我要写正文」 |
| 空列表项回车 | 缩进 > 0 则减一层；顶层则退回段落 | 连按两次 = 退出列表 |
| 空引用 / 空提示块里回车 | **续一行同组引用**（不退回段落） | 提示块的类型与配色会跟着一起丢；退出有行首退格和 → 两条路 |
| 代码块末行回车 | **仍是换行**，按几次就是几个空行 | 出块靠 → / ↓；「连按两次出块」还是会把想空一行的用户弹出去 |
| 表格 / 分割线 | 下方新段落 | 否则这两个块是死路：进得去出不来 |

⚠️ 代码块的 Enter **必须自己插 `<br>`**，不能往文本节点里塞 `'\n'`：
Chromium 下次输入会把行尾的 `\n` 规整掉，光标漂到换行前面。

### 5.3 Backspace / Delete

#### Backspace

```
有选区 → 交给浏览器删（返回）
在单元格里 → 交给浏览器（格内删字）
块是代码/公式
  ├─ 块为空且不是唯一的块 → 删掉整块
  └─ 否则 codeBackspace()：
       ① 光标在整块末尾、前一个字符是 \n（末尾空行）
          → 自己删掉那个 \n，光标落在新末尾
       ② 前一个字符是零宽空格（行首垫片）
          → 删掉它；若是行首还要摘掉前面的 <br> 并接回上一行
       ③ 光标在节点最前、前面是 <br> → 摘掉 <br> 接行
       其余 → 交给浏览器
块是表格 → 返回（格内删字走上面的分支）
光标不在块首 → 交给浏览器
块是列表项 → 缩进 > 0 减一层；顶层退回段落
块是引用   → 层级 > 0 减一层；
             否则：上一条是同组引用 → 并进上一行；否则退回段落
块是标题   → 有 ### 明文 → 删一个 #（降一级，删光退回段落）
             无 ###     → 先把 ### 亮出来（级别与正文都不动）
其他       → 上一块是分割线 → 删掉它
             上一块 needsLineBelow（表格/代码/公式）
               ├─ 当前块为空 → 删掉当前块，光标退回上一块末尾
               └─ 当前块非空 → 只送光标（先把字删完，再按一次才轮到删行）
             其余 → 与上一块合并（mergeBack）
```

**标题为什么要两次**：行首退格直接砍级别，用户会莫名其妙掉一级；先亮出 `###`
（此时它已经变成可删的字符），之后每按一次删一个 `#`，行为与纯文本一致。

**代码块退格的两个坑（都实现在 `codeBackspace()` 里）**：

- **末尾空行要自己删。** 初始渲染的代码块是 `textContent = "line1\nline2\n"`，
  `\n` 就是换行本身。光标停在最后一个 `\n` 后面按退格，Chromium 会跳过这个末尾换行、
  直接删掉上一行最后一个字（实测删掉的是 `2`）。所以「光标在末尾且前一个字符是 `\n`」
  这一支必须自己接管。
- **摘 `<br>` 之前先把前一个节点取出来。** `br.remove()` 加 `node.remove()` 之后，
  `node.previousSibling` 是 `null`、`node.parentNode` 也是 `null`，
  `caretToPrevLine()` 两个分支全落空 → 光标被浏览器重定位到 `w-code` 元素开头，
  用户看到的是「退格一下，光标跑到块上面去了」。

#### Delete

```
无选区、不在单元格、块不是代码/表格、光标在块尾、有下一块：
  下一块是分割线 → 删掉它
  下一块是表格/代码 → 不动（避免把结构吃掉）
  否则 → 把下一块并进当前块
```

#### 合并的实现（两个方向共用）

```js
// 去掉目标块尾部的占位 <br>
while (target.lastChild && target.lastChild.nodeName === 'BR') target.removeChild(target.lastChild);
const joinAt = target.textContent.length;        // 接缝位置
for (const n of children(source)) {
  if (n.nodeName === 'BR') continue;             // 源块里的占位 <br> 不搬
  target.appendChild(n);
}
source.remove();
ensurePlaceholder(target);                       // 空块必须留 <br>，否则行盒塌成 0 高
setCaretOffset(target, joinAt);                  // 光标停在接缝
```

⚠️ 接缝位置要在**搬之前**算（`textContent.length`），搬完再算就被源块内容拉长了。

⚠️ `ensurePlaceholder()` 不能省：两个空段落合并时，目标块尾部的 `<br>` 被第一段循环删掉、
源块的 `<br>` 又被 `continue` 跳过，`target` 会一个子节点都不剩、行盒塌成 0 高 ——
用户看到「一次删了两行」，下一次退格还会因为光标无处落脚被甩进更前面的块。
验收要量 `getBoundingClientRect().height ≥ 12`，只看 DOM 块数看不出塌陷（块还在，只是没高度）。

### 5.4 Tab

| 上下文 | 行为 |
|---|---|
| 单元格内 | 下一个单元格；到末尾自动加一行（Shift 反方向） |
| 列表项 | 缩进 +1（上限 6）；Shift 时 -1，已在顶层则退回段落 |
| 代码块 | 插入 **2 个空格** |
| 其他 | 插入 **4 个空格** |

⛔ 不要用「焦点切换」的默认 Tab：编辑器里 Tab 是缩进，焦点必须留在正文。

### 5.5 方向键与「出块」

`↓` 与 `→` 在**块内最后一个可编辑位置**上都要能把光标送出块外。

```js
function endsBounded(block) {          // 是不是「带边界的块」的最后一行
  const t = block.type;
  if (t === 'code' || t === 'math') return true;
  if (t === 'bq') return !block.dataset.bqTail;        // 组内还有下一行 → 不接管
  if (t === 'li') return !(next && next.type === 'li'); // 下一项还是列表 → 不接管
  return false;                                        // 表格靠单元格分支处理
}
```

| 块 | 为什么需要出口 |
|---|---|
| 代码块 / 公式块 | 光标被包在结构里，走到末尾之后块内没有下一个位置 |
| 表格 | 最后一格右下角，↓/→ 没有下文 |
| 引用 / 提示块 | 组末行之后是块外 |
| 列表 | 最后一项之后是块外 |

⚠️ **组内还有下一行时不接管**：交给浏览器，它知道折行、知道要不要顺手滚动。
自己插一手只会更差（会跳过折行）。

⚠️ **`isCaretAtEnd` 要忽略尾部两类「看不见的尾位」**：

```js
isCaretAtEnd(block) {
  const t = textEl(block);
  const raw = t.textContent;
  let end = raw.length;
  while (end > 0 && raw[end - 1] === ZWSP) end--;   // 垫脚用的零宽字符不算内容
  // 代码块 / 公式块正文末尾那个 \n 在 pre-wrap 下不生成可点击的行：
  // 浏览器把行尾点击映射到它前面，end 必须也退到那里。只退一个。
  const type = block.dataset.type;
  if ((type === 'code' || type === 'math') && end > 0 && raw[end - 1] === '\n') end--;
  return offsetIn(t) >= end;
}
```

- 代码块末行、空单元格末尾垫着 `\u200b`。按 `textContent.length` 判时，光标停在最后一个
  可见字符之后只算「差 1」，于是 → 被放行给浏览器 —— 它只是跨过那个看不见的字符。
  用户看到的是「按一下没反应，按两下才出去」。`test/wysiwyg.html` 里
  `caretBeforeTrailingZWSP()` 专门造这个位置，`caretEndOf()` 落在零宽字符之后，测不出来。
- 代码块正文末尾带一个真换行（写完代码顺手回车、粘贴带尾部换行）时，`pre-wrap` **不给
  最后一个 `\n` 生成行**：光标最多停在它前面（`offsetIn === end - 1`）。旧判据把它算进
  `end`，于是这个代码块永远被判成「光标不在末尾」，`↓ / →` 不接管、浏览器原生把光标
  甩进下一块。这就是 1.2.6 里「代码块后面有内容时出不了块，别的块都行」：表格 / 引用 /
  列表的正文是 `<br>` 或单元格边界，`textContent` 里没有裸 `\n`。
  **只忽略末尾这一个**：再往前的每个 `\n` 都对应一条看得见的空行，光标能站上去，
  全剥掉会让用户在倒数第二行按 → 也被弹出块。`caretBeforeTrailingNewline()` 造这个落点。

⚠️ **方向键绝不改文档**。出块只移动光标并记一次性的「块后待插入」(`gapAfter`)；
用户按下回车 / 打字 / 输入法组字 / 粘贴时才兑现：插一个真段落、`flush()` 对齐
records / 序列化 / 撤销 / 脏标记。1.2.6 之前是「出块即插行」，方向键一下就让标签变脏、
撤销栈多一条 —— 用户明确判定这种擅自新增不符预期。现在既不会因移动光标改文档，
又保住了「出块后回车就能加一个空行」：下一块哪怕是表格 / 代码块，这一下回车也由
`gapAfter` 接管到块后，不会变成在下一块内部加行。「临时占位块」会在窗口化重铺时消失，
把 Range 悬在子节点间隙假装有一行则会在 WebView2 里吞掉回车，都不许用。

`gapAfter` 是**一次性状态**：只在「真的要写入」时消费 —— `keydown` 里的 `Enter` /
可打印键、`beforeinput` 的 `insertParagraph` / `insertLineBreak` / `insert*`、`compositionstart`、
`paste`。点击、其它方向键、Tab / 退格 / 快捷键、失焦、`render()` 一律清空，
不让它残留到别的操作上。

⚠️ `→` 必须**显式派发**到箭头处理函数：只拦 ↑↓ 的话，表格右下角与代码块末行
按 → 没有任何反应。

⚠️ 表格里 `↑`/`↓` 是上一条「组内还有下一行时不接管」的**例外**：这两个键必须
**无条件 `preventDefault()`**，包括格内真有 `Shift+Enter` 换的行。放行给浏览器时它按
阅读顺序跨格（横向跳），而不是做格内行移动。落点由 `cellLines()` 按 `<br>` 切出的
字符区间自己算，末尾那个空段要丢掉（空格子的占位 `<br>` 与 `tableToMarkdown()`
同一口径）；表头是 `tableInfo().rows[0]`，进出表头走的也是同一条路径。

#### 落点选择

```js
// 方向键：只移动光标 + 记状态，绝不改 DOM
function caretAfterBlock(block) {
  const next = block.nextElementSibling;
  // 块后已经空着一行：复用，绝不重复开行
  if (next && (next.dataset.type || 'p') === 'p' && isEmptyBlock(next)) {
    gapAfter = null;
    placeCaretStart(next); return;
  }
  gapAfter = { block };                       // 一次性的「块后待插入」
  // 后面有能站人的块就落到它开头；文末或紧跟分割线则保持光标不动
  if (next && next.dataset.type !== 'hr') placeCaretStart(next);
}

// 用户真的要写入时才调用：插真段落、flush 对齐模型
function materializeGap() {
  const gap = gapAfter; gapAfter = null;
  if (!gap || !gap.block.isConnected) return null;
  const p = insertEmptyAfter(gap.block);      // 正好插在两块之间
  placeCaretStart(p);
  flush();
  return p;
}
```

⚠️ **不要无条件新建空段落**：下面本来就有一个空行时要复用，否则文档末尾越按越长。
判重只认「空的 `p`」，其它类型一律记待插入。Markdown 解析会吃掉两个块之间的空行，
所以「源码里看着有一行」不代表 DOM 里有空段落 —— 判重只看 DOM，别拿源码猜。

⚠️ **下一块是带边界的块也不能例外**：`next` 是引用 / 表格 / 另一个代码块时，
`gapAfter` 照样要记，回车照样要在两块之间插空段落。放任回车按光标落点走默认行为，
它就只会在那个块内部加行（表格加一行、代码块内换行、引用续一行），插不出空段落。
`handleKey` 必须在 `handleEnter` 之前把这一下回车接管过来。

**→ 与 ↓ 共用同一个落点**：走到头的下一步就是出去。让其中一个键做别的事，
等于给同一个动作两种结果。分割线不在此列 —— 见下。

**分割线的特殊处理**：分割线自己**没有光标位**。光标停在它上面那一行末尾按 ↓ 时，
线下面有正文就直接 `placeCaretStart()` 落进去（既不插空行也不记状态），线在文末才走
`caretAfterBlock(hr)` 记下「线后待插入」，回车才在线下开一行。穿过一条线不是
「在线后面接着写」，不该改文档。

#### 出块提示线：`gapAfter` 只有一个写入口（1.2.9）

⛔ 禁止再散落 `this.gapAfter = null`。每多一处，就多一个「状态没了线还在」的漏点：

```js
setGapAfter(block) { this.gapAfter = block ? { block } : null; this.syncGapHint(); }
clearGapAfter()   { this.setGapAfter(null); }
```

`syncGapHint()` 只画视图：拿 `gapAfter.block.getBoundingClientRect().bottom`，减去
`.edit-wrap`（`gapHint.parentElement`）的 `getBoundingClientRect().top` 写成 `top`；
`left` 取块的左沿；`width` 取 `max(块宽, 标签宽 + 24px)` —— 双栏窄编辑区里文字标签
可能比块还宽，线用 `flex:1 1 auto` 占剩余宽度，不把容器撑开的话线会被挤成 0。
先 `display:flex` 才量得到标签宽度，量完再定 `top` / `left` / `width`。
以下三种情况直接 `display:none`：

1. `!block.isConnected || block.parentElement !== root` —— 被窗口化重铺 / 整篇重渲染；
2. 块滚出视口（`r.bottom < host.top || r.top > host.bottom`）—— 状态留着，滚回来自己出现；
3. `gapAfter === null`。

root 的 `scroll` 监听里跟着调一次 `syncGapHint()`，出块后滚屏线不能留在原地。
⛔ 常驻线与 hover 线必须**两个 DOM 元素**：`hoverInsertLine()` 每次 `pointermove` 都可能
`hideInsertLine()`，共用一条线的话用户随手挪一下鼠标提示就没了。两者都挂在 `.edit-wrap`
（`position:relative`），⛔ 别挂进 root —— 块遍历 / 序列化都假定 root 的孩子全是 `.w-block`。

#### Ctrl/Cmd+Enter：一步到位，只在块末尾

```js
// handleKey 的 Ctrl 分支，必须放在通用 return 之前
if (k === 'enter') { e.preventDefault(); this.insertLineBelow(); return; }

insertLineBelow() {
  const cell = this.currentCell();
  if (cell) {
    const info = this.tableInfo();
    if (!info || !this.atTableExit(info)) return false;   // 只有右下角那一格
    return this.forceGapAfter(info.block);
  }
  const block = this.currentBlock();
  // endsBounded：code / math / 引用组末行 / 列表末项；普通段落与标题不在内
  if (!block || !this.endsBounded(block) || !this.isCaretAtEnd(block)) return false;
  return this.forceGapAfter(block);
}

forceGapAfter(block) {
  const next = block.nextElementSibling;
  if (next && isEmptyPara(next)) { this.clearGapAfter(); this.placeCaretStart(next); return true; }
  const p = this.insertEmptyAfter(block);
  this.clearGapAfter(); this.placeCaretStart(p); this.flush();
  return true;
}
```

⚠️ 不在末尾时**也要 `preventDefault()`**：不拦的话 WebView2 会把 `Ctrl+Enter` 当一次普通
换行写进代码块，变成「按了却悄悄改了文档」。
⚠️ 别注册进 `setupKeys()` / `keyRows()`：全局命令会被编辑模式、查找输入框一起吃到，
也没法做「只在块末尾」的判定。块手柄面板里 `kbd: 'Ctrl+Enter'` 只落在
`title` / `aria-keyshortcuts`。
⚠️ `bmRun('blank')` 单独分支：它必须永远 `insertEmptyAfter(block)`，不能走
`/` 面板的「空块复用」（那一支在空段落里等于没做事），并且要 `flush()` 对齐模型。

### 5.6 光标工具集（API 契约）

| 函数 | 语义 | 实现要点 |
|---|---|---|
| `offsetIn(host)` | 光标在 host 内的**字符**偏移 | 用 Range 的 `toString().length`，不要累加节点长度（会漏 `<br>`/实体） |
| `setCaretOffset(host, n)` | 把光标放到第 n 个字符处 | 遍历文本节点累加；越界落到最后一个文本节点末尾 |
| `firstTextNode` / `lastTextNode` | 首/末文本节点 | ⚠️ **选区边界必须落在文本节点上**，落在元素上会让「全选」把自己吃掉 |
| `placeCaretStart/End(block)` | 块内首/末 | |
| `isCaretAtStart/End(block)` | 是否在首/末 | 与 `offsetIn` 配合，注意末尾要 `>=` 而不是 `===` |
| `isEmptyBlock(block)` | 正文去零宽空格后为空 | 图片不算空 |
| `caretOnEmptyLastLine(block)` | 在末尾且最后一个 `<br>` 之后无可见字 | 代码块判 Enter 用 |
| `ensurePlaceholder(host)` | 空块补一个 `<br>` | 没有它点不进去 |

**零宽空格（ZWSP）的角色**：它是「光标落脚点」，不是内容。三个地方必须用它：

1. 行内转换后（§5.1）—— 把光标从 `<strong>` 里引出来；
2. 代码块换行后（`<br>` 之后再垫一个）—— 否则接着输入会跑回上一行；
3. 原文粘贴后（末尾垫一个）—— 否则以换行结尾的粘贴会让光标停在 `<br>` 上。

⛔ 序列化时必须剥掉 ZWSP，且**不能**把它当字符计数（高亮偏移换算要逐字符跳它，见 §5.13）。

### 5.7 结构操作

| 操作 | 语义 | 关键点 |
|---|---|---|
| `splitBlock(block, batch)` | 回车拆分 | 光标后的**片段**（保行内样式）进新块；`batch` 时不做收尾重排（批量粘贴用） |
| `nextBlockFor(block)` | 新块的类型 | li 续同 kind 同缩进；bq 续同缩进；其他一律段落 |
| `mergeBack` / `mergeForward` | 合并 | 见 §5.3 |
| `removeBlock` | 删块 | 光标落到上一块末尾（没有上一块就落到下一块） |
| `bqGroupOf(block)` | 引用组 → 逻辑块 | 非 bq 返回 `[block]`；bq 往前走到 `bqStart` 或「前一块不是 bq」为止，再往后收到下一个 `bqStart` / 非 bq 之前。手柄、`convertBlock`、`deleteBlock` 都拿它归一 |
| `deleteBlock(block)` | 块级删除 | 删整组；光标落到 `first.previousElementSibling \|\| last.nextElementSibling` 末尾，删光了补空段落并站进去 |
| `toParagraph` | 换类型为段落 | 原地换节点，保留行内内容与光标偏移 |
| `insertEmptyAfter` | 块后插空段落 | 返回新块 |
| `insertAfter` / `insertMarkdown` | 在光标处插结构 | 多行走解析器 |
| `convertBlock(type)` | 换块类型（菜单入口） | 用**行内源**搬运文字（§4.5）；源文本取 `group.map(blockMarkdownText).join('\n')`，替换时整组一起摘掉 |

⚠️ 归一必须落在 `convertBlock()` 里，不能只做在 `placeHandle()`：右键 / 命令面板不经过手柄，
只归一手柄的话，在续行上点「标题」仍会只转那一行、留下半截引用。`group` 只有一块时与
原实现逐字等价（单块 `map().join('\n')` 就是 `blockMarkdownText(block)`，删 `group[1..]` 是 no-op）。
**块内退格仍按行**（§5.3 的引用分支），块级删除不许伸进去改它。

⚠️ 所有结构操作末尾都要三件事：**重编号**（有序列表序号、引用组标记）、
**关掉撤销合并**（`hCoalesce=false`）、**立刻序列化一次**（`flush`）。

**块菜单键盘导航（`app.js`）**：`bmRows` 只收**可键盘导航**的项。
`item(it, checked, navigable = true)` 在 `navigable=false` 时不 push、不绑
`mouseenter → bmHot`，改绑 `mouseenter → bmHover(-1)`。「删除这一块」按这个接法：
仍是 `.bm-item` + `role=menuitem`、仍可鼠标点、仍有 hover 反馈，但 ↑↓ / Home / End
的循环里没有它，`End` 的落点保持是最后一个转换类型。只「不给盲打字母键」不够，
`End + Enter` 同样是盲按；鼠标移上去还要清掉别处 `.hot`，否则 Enter 会执行那个
「别处的项」。

**编辑区行号槽（`editor/theme.js`）**：`.cm-gutters` 必须
`backgroundColor: 'var(--bg-panel)'`。CM6 自带 `sticky + zIndex:200`，透明底会让
不换行横向滚动的长行从行号条底下透出来。⚠️ `theme.js` 是**运行时源码**
（`plain-editor.js` 直接 import），不在 `build-cm6.mjs` 的入口里，改它不必重生成
`src/vendor/cm6.js`；但改完要 `cargo build` 重新内嵌前端。验收量 computed
`backgroundColor` 的 alpha 并与 `.editor-pane` 对色（`test/editor.html`、
`probe-app.mjs` G 段），光看 DOM 结构看不出来。
少一件的典型症状：序号错位、撤销把两步并成一步、存盘少最后一步改动。

**编辑区的三层视图提示**：互不依赖，**都不写 `t.content`**。

| 层 | 实现 | 状态存哪 | 什么时候作废 |
|---|---|---|---|
| 当前行 | `.cm-activeLine` → `var(--active-line-bg)` | CM6 自己算 | 光标一移动就换行 |
| 选区匹配 | `highlightSelectionMatches({ minSelectionLength: 1, maxMatches: 300 })`，由 `cm6-entry.js` re-export 进 `src/vendor/cm6.js` | 插件内部 | 选区变了重算，折叠即清 |
| 非 md 的高亮 | `viewMarksField`（`StateField`）+ `Decoration.mark({ class: 'cm-view-mark' })`；`setViewMarks` 是 `StateEffect` | `t.viewMarks`（标签级） | `docChanged` 时 `deco.map(tr.changes)`；`plain.load()` 重建 state 后由 `setMode()` / `activate()` 重放 |

⚠️ `highlightSelectionMatches` 的 `getDeco` 只给 `from >= range.to || to <= range.from` 的命中挂装饰，
**主选区自身不挂**（那一处已有选区底色）；所见即所得的 `sn-same` 则把选中那处也算进去。
三个「红」选第一个，断言分别是「编辑模式 2 处 / 所见即所得 3 处」，⛔ 别用同一个数字卡两边。

`toggleViewMark(from, to)` 先剔掉与选区相交的旧区间，再按「剔没剔掉」判这一次是加还是减；
`hasViewMark()` 只查区间集合，⛔ 不扫源码字符串（Python 的 `a == b` 会被误判）。
`onEditorInput()` 把映射后的 `plain.viewMarks` 写回 `t.viewMarks`，否则下一次切标签装饰就丢了。
`cm6-entry.js` 一改必须重跑 `pnpm build:cm6` 并提交产物；`theme.js` 是运行时源码，
不必重生成 vendor，但两种改法都要 `cargo build` 重新内嵌前端。

**所见即所得那一侧（`selmatch.js`）**：`wysiwyg.js` 在 `selectionchange` 上挂一个 rAF
去抖，调 `updateSelMatch(root, sel)`；用 `TreeWalker` 收文本节点拼成一条扁平字符串，
命中按字符偏移切回多个 `Range`，交给 `CSS.highlights.set('sn-same', ...)`。跳过
`.w-code` / `.w-tex` / `pre` / `code` / `.katex`（那里已有代码着色）。`_render()`
与 `app.js` 的 `clearView()` 调 `clearSelMatchNow()`：取消未执行的 rAF **并**注销全局高亮，
否则 `CSS.highlights` 这张全局表会跨标签留一片灰底。

⚠️ 忽略大小写时 `hay`（全文）与 `key`（选区文字）**必须一起折叠**：`İ → i̇` 这类字符
`toLowerCase()` 会变长，只把 key 退回原文、却继续在小写全文里搜，命中偏移会整体错位。
两边长度只要有一个对不上，就整段退回原文匹配 —— 宁可少标几个，也不把灰底涂到别的字上。

### 5.8 粘贴（按宿主分派）

⛔ 这是「粘贴为什么行为不一致」的唯一正确答案：**先看粘在哪，再决定怎么落**。

| 剪贴板里是 | 落点 | 做法 |
|---|---|---|
| 图片文件 | 任意 | 交给外层落盘（`assets/`），完成后插入图片；**不要**读文本 |
| 文本（单元格内） | 单元格 | 只取第一行，换行换成空格 |
| 文本（代码块/公式块内） | 原始正文 | `insertRawText`：原文进块，换行落 `<br>`，末尾垫 ZWSP，空块先摘占位 `<br>` |
| 文本（列表项/引用行内，多行） | 容器 | `pasteLinesInContainer`：等价于逐行回车续行 |
| 文本（单行） | 任意 | 直接插入文本 |
| 文本（多行） | 段落 | **整段按 Markdown 解析成块**，顶替当前空块或插到其后 |

#### insertRawText 伪代码

```js
if (host 只有一个占位 <br>) { host.textContent = ''; 光标归位到开头; }
range.deleteContents();
const frag = fragment();
lines.forEach((ln, i) => { if (i) frag.append(<br>); if (ln) frag.append(text(ln)); });
frag.append(text(ZWSP));           // 末尾落脚点
range.insertNode(frag);
光标放到 ZWSP 之后;
```

⚠️ 「先摘占位 `<br>`」不能省：空代码块粘内容会在前面多一个空行（那个 `<br>`
在序列化时就是一次换行）。
⚠️ 走 Markdown 解析那条路会让空代码块被**整块换掉**（代码块凭空消失），
非空块则把段落插到块**外面**（内容跑到代码块下方）。这两条都实测发生过。

#### pasteLinesInContainer

```js
items = lines.filter(s => s !== '');        // 空行不占一项
silent = true;                              // 期间别让每行都跑一遍规范化
range.deleteContents(); insertText(items[0]);
for (i = 1..) { splitBlock(cur, true); cur = currentBlock(); insertText(items[i]); }
silent = false;
renumber(); hCoalesce = false; flush();
```

**为什么空行不占一项**：容器里「一行 = 一项」，而空列表项在模型里存不住
（序列化直接丢掉）。真去造一个空的 li/bq 只会留下一块看不见的空位。
代价是粘多段文本进引用会并成一个引用组 —— 比「空行把引用断成两截、后面几段全变正文」好解释。

### 5.9 表格编辑

| 操作 | 规则 |
|---|---|
| Tab / Shift+Tab | 线性遍历 `th,td`；越过末尾自动加一行；到开头则停在第一格 |
| Enter（格内） | 整行**都空**时退出表格（下方新段落）；否则跳到下一行同一列，末行则先加行 |
| Shift+Enter | 格内换行（`<br>`，序列化写成字面 `<br>`） |
| 加行 | 位置 `above`/`below`/`end`；落到表头行时**统一插进数据区**（表头上方插一行没有意义） |
| 加列 | 每行同位置补一格，`data-aligns` 同步补位 |
| 删行/删列/删表 | 删表 = 整个块删除 |
| 对齐 | 写 `table[data-aligns]` 的第 i 段，同时改该列每个单元格的 `data-align` 与 `text-align` |

⚠️ 单元格在模型里是**线性下标**（`th,td` 顺序），不是 (row,col)。光标状态里存的是
这个线性下标，恢复时按同一顺序取。

### 5.10 链接、图片、公式、提示块

| 动作 | 步骤 | 边界 |
|---|---|---|
| 插入/编辑链接 | 有选区则用作文字，否则用输入框文字；`<a href>` 里**不放 `target`**，点击行为由应用决定 | Ctrl/⌘+点击才打开；直接点是放光标（否则改链接文字没法下手） |

### 5.12 查找替换

```js
flags = 'g' + (区分大小写 ? '' : 'i');
if (正则模式) re = new RegExp(query, flags);            // 无效正则 → 视为无输入
else {
  let src = escapeRegExp(query);
  if (整词) {
    if (/^\w/.test(query)) src = '(?<!\\w)' + src;     // 只有头是 ASCII 单词字符才加
    if (/\w$/.test(query)) src += '(?!\\w)';
  }
  re = new RegExp(src, flags);
}
```

⚠️ **整词边界只对 ASCII 加**：中文没有词边界，「标题」匹配到「副标题」是正常行为。
硬套 `\b` 会让中文查询永远匹配不到。

| 模式 | 命中怎么算 | 高亮怎么做 |
|---|---|---|
| 所见即所得（普通文档） | 在 DOM 上遍历文本节点 | CSS Custom Highlight API（不插节点，不破坏选区） |
| 所见即所得（大文档） | 在**块模型**上算（DOM 里只有窗口） | 跳转时把块搬进窗口再算 |
| 源码 / 预览 | 纯文本扫描 | 同上或预览层标记 |

⚠️ 改字之后旧的高亮区间已错位：停手 **300ms** 重算一次，不要边走边重算。

### 5.13 代码块高亮（不许碰 DOM）

⛔ **不能往代码块里插 `<span>`**：光标会被踢出、撤销记录失效、序列化前提被破坏。
用 CSS Custom Highlight API（或平台等价能力）给**文本区间**上色。

#### 区间从哪来

复用**预览用**的高亮器输出，在离屏节点里走一遍，把每个 token 的文本节点换算成源码偏移：

```js
// HTML → [{start, end, cls}]
walk(node, stack):
  text node  → 若 stack 非空，push({start: off, end: off+len, cls: stack.top}); off += len
  element    → 若 className 匹配 /^tok-(\w+)$/，压栈 → 递归 → 出栈
```

```js
// 源码偏移 → 节点位置：逐字符记下标，因为两种节点长度语义不同
segments(host):
  for node in host.childNodes:
    if 文本节点: pos = [该字符不是 ZWSP 则记下它的下标]; off += pos.length
    if <br>:    off += 1                    // 占一位，但没有文本节点
    if 其他元素: off += codeText(该元素).length   // 只推进偏移，不给它建区间
```

⚠️ 这张 `pos[]` 是**唯一**能把「源码第 k 个字符」映射到「节点第几个字符」的东西。
直接用 `textContent.length` 当偏移，症状是「颜色涂在别的字上」。

| 参数 | 值 |
|---|---|
| 单块上限 | **40000** 字符（超过不上色；hljs 40k 约 40 ms，见 §6.7 门槛） |
| 高亮类 | `key` `str` `num` `comment` `punc` `fn` `tag` `attr` `type`（hljs 的几十个 scope 收敛到这 9 个） |
| 重算时机 | 内容变化后 **120ms** 防抖 |
| 不支持该 API 时 | 静默退化为纯文本（语言条照常显示） |

#### 语言自动识别（`detectLang`）

底层是 highlight.js 的 `highlightAuto`。**不要自己写特征正则表** —— 那套东西只在
写它的人挑的样本上正确（见《架构与经验》§15 第 49 条）。

```
detectLang(code):
  s = code.trim()
  if s.length < 8: return ''                       // 太短，怎么判都不靠谱
  if s[0] in '{[' and JSON.parse(s) 成功: return 'json'   // 唯一能「验算」的语言
  best = hljs.highlightAuto(code, SUBSET)
  if best.language == 'plaintext' or best.relevance < 8: return ''
  return normalizeLang(best.language == 'xml' ? 'html' : best.language)
```

**SUBSET = 已注册语言 − {plaintext, css, scss, less, dart, kotlin, csharp, scala, objectivec, vbnet}**

剔除的理由是实测的（`run-units` 12 条判据守着）：

| 剔除 | 不剔会怎样 |
|---|---|
| css / scss / less | CSS 的「属性: 值;」几乎匹配任何带冒号的代码 —— `interface Foo { a: string }` 判成 CSS，Go 的 `key: value` 也判成 CSS |
| dart / kotlin / csharp / scala / objectivec / vbnet | 都是 C 家族，彼此长得一样，也长得像 Java/Go —— Python 会被判成 dart |
| plaintext | 它是「没认出来」的兜底，不该参与竞争 |

**门槛 8 分的来历**：`relevance` 随命中关键字数量线性增长，同一个 `SELECT … FROM`
两行时 5 分、二十行时 12 分。实测 2~7 分的赢家经常是错的，8 分以上基本稳定。
所以短片段（三四行）通常**不上色**，这是刻意的取舍：错色比无色难查，还会让语言条
显示错名字。识别结果**只用于着色与语言条，绝不写回 Markdown**。

### 5.14 规范化要做的六件事

每次输入后跑一遍（只扫光标块与左右邻块；载入/粘贴时全量）：

1. **顶层游离节点包成段落**（浏览器偶尔会造出裸 `div`/`br`/文本）。
2. **补齐正文宿主**（缺 `.w-text` 就造一个）。
3. **装饰层归位**：编号、语言条、`###`、提示块标题、复选框留在块里，其余游离内容搬进正文。
4. **空标题降级为段落** —— 只降「光标所在的那个」，避免同一个空标题在别处打字时被悄悄吃掉。
5. **清掉空的行内包裹**（`<strong></strong>` 这种）。判空**必须忽略零宽空格**：
   有它在 `textContent` 就不为空，于是删光重打还是粗体。
6. **相邻同标签合并**，避免序列化出 `**a****b**`。

⚠️ 第 5 步删掉的元素如果正夹着光标，光标会悬空 —— 记得把它放回块首。

### 5.15 语言表与格式化引擎

#### 5.15.1 一张表回答「这个扩展名是什么」

`src/js/langs.js` 的 `LANGS` 是唯一真源，每条七个字段：

| 字段 | 含义 | 例句 |
|---|---|---|
| `label` | 显示名（中文源串，取用时过 `tt()`） | `'JSON Lines'` |
| `exts` | 扩展名（不含点） | `['jsonl','ndjson']` |
| `files` | 没有扩展名的整文件名 | `['Dockerfile']` |
| `hljs` | highlight.js 语言名（预览 / 导出 / 代码块） | `'json'` |
| `cm` | CodeMirror 语言工厂名（编辑区） | `'json'` |
| `fmt` | prettier parser 名（格式化） | `null` = 只做保守清理 |
| `kind` | 文档大类 `md/json/code/txt/data` | `'code'` |

四个使用方全部查表，不许各自维护副本：

| 使用方 | 用法 |
|---|---|
| 新建文档网格 | `newDocTypes()` 按表顺序取前 28 条 |
| 编辑区着色 | `LANGS[id].cm` → `plain-editor.js` 的 `CM` 工厂表 |
| 预览分流 | `detectKind(name)` → `LANGS[id].kind` |
| 格式化 | `LANGS[id].fmt` → 严格 parser，失败查 `format.js` 的 `LOOSE_CHAIN`，再失败 `format-loose.js` |

`normalizeLang(x)` 接受扩展名 / 别名 / 各引擎的语言名（`bash`、`python`、`plaintext`、
`xml`…），认不出返回 `''` —— **不再原样返回输入**，否则调用方会拿 `'foobar'` 去问引擎。

加一门语言的完整步骤（业务代码零改动）：`langs.js` 加一条 → `vendor-entry/syntax.js`
注册 hljs 语法 → `cm6-entry.js` export + `plain-editor.js` 的 `CM` 加一行 →
`node scripts/build-syntax.mjs && node scripts/build-cm6.mjs`。

#### 5.15.2 格式化（`formatByKind`）

```
formatByKind(kind, text, fileName):
  id  = langForFile(fileName) || (kind == 'md' ? 'md' : kind == 'json' ? 'json' : '')
  def = LANGS[id]
  if not def?.fmt: return formatPlain(text, kind)          // 统一 LF / 去行尾空格 / 压空行
  { formatText } = await import('../vendor/format.js')      // 2.2 MB，首次才加载
  for parser of [def.fmt, ...(LOOSE_CHAIN[def.fmt] || [])]:
      try   return { text: await formatText(text, parser, OPTS),
                     notes: parser != def.fmt ? [tt('已按宽松规则')] : [],
                     loose: parser != def.fmt, forced: false, error: null }
      catch e: firstError ||= e
  fallback = INDENT_SENSITIVE.has(def.fmt) ? formatPlain(text, kind).text
                                           : formatLoose(text)
  return { text: fallback, notes: [tt('原文有语法错误，仅调整空白')],
           loose: false, forced: true, error: formatError(firstError, id) }
```

| 项 | 值 |
|---|---|
| prettier 版本 | 3.x（standalone + 7 个插件；`PLUGIN_SETS` 登记 13 个 parser 名） |
| 严格 parser | `markdown` / `json-stringify` / `babel` / `typescript` / `css` / `scss` / `less` / `html` / `yaml` |
| 宽松回退链 | `json-stringify → json → jsonc → json5`；`babel` / `typescript → babel-ts` |
| ⚠️ parser 名 | 必须是插件 `parsers` 表导出的名字，**不是插件名**。`prettier/plugins/postcss` 导出 `css` / `less` / `scss`，写 `postcss` 会 `Couldn't resolve parser` |
| `printWidth` / `tabWidth` | 100 / 2 |
| `proseWrap` / `endOfLine` | `preserve` / `lf` |
| 语法错误 | **不抛错、不弹框**；`e.loc.start` 只作为 `error.line/col` 报给用户，不 `gotoLine`（排版后行号已变） |
| 兜底 `format-loose.js` | 只增删 ASCII 空白；按括号深度缩进、结构边界换行；字符串 / 模板串 / 注释原样；硬校验 `stripWs(out) === stripWs(src)`，不满足就返回原文；> 30 万字符放弃 |
| 缩进敏感 | `yaml` / `markdown` 落兜底时改走 `formatPlain`，⛔ 不重排缩进（缩进是语义） |
| 加载方式 | 动态 `import()`；只有**引擎本身加载失败**才 reject（上层弹框），不因文本内容报错 |

⛔ **不要写「自动修复」**（全角引号改半角、删尾逗号、删注释、补括号）。这类正则补丁只在它
见过的坏法上有效，改错了是**静默的数据损坏**：`"价格：1"` 里的全角冒号会被改掉，字符串里的
`//` 会被当注释删掉。解析不了就退到「只重排空白」——那一级有逐字符校验兜着，最差只是排版
难看，绝不会动用户的数据；结果一律可撤销（`undoToast`）。

## 6. 视图几何

### 6.1 折行：按「半角单元」算，不按字符数

```js
const unitsOf = (s) => {
  let n = 0;
  for (const ch of s) n += /[\u1100-\u115F\u2E80-\uA4CF\uAC40-\uFFDC]/.test(ch) ? 2 : 1;
  return n;              // 全角 = 2，半角 = 1
};
```

**为什么不是字符数**：中文一折就错位，而中文正是这类窗口最主要的用途。
等宽字体 + `word-break: break-all` + `line-break: anywhere` 之后，断点严格按字符走，
于是「算出来的行数」与浏览器排出来的高度一致。

```js
// 一行能放几个半角单元
function wrapCols() {
  const lnW = readCssVar('--cmp-ln-w', 54);
  let cols = 0;
  for (const side of [left, right]) {
    const avail = (canvas.clientWidth || scroller.clientWidth || 0) - lnW - 14;  // 14 = 右侧内边距
    const c = Math.floor(avail / CHAR_W);
    if (c > 0 && (cols === 0 || c < cols)) cols = c;      // 取更窄的一侧
  }
  return Math.max(8, cols || 80);
}
```

| 参数 | 值 | 说明 |
|---|---|---|
| `CHAR_W` | 实测（10 个数字宽度 ÷ 10），兜底 **7.6** | 字号变了要重测 |
| 行号列宽 `--cmp-ln-w` | 兜底 **54** | ⚠️ 读 CSS 变量，**不要量 DOM**：首帧画布是空的，量不到会算错一截 |
| 右侧留白 | **14** | 与样式表一处对齐 |
| 最小列数 | **8**，默认 **80** | 极窄窗口下不能算出 0 或负数 |

⚠️ **不要逐行 `getBoundingClientRect`**：两万行就是两万次强制重排，滚动直接卡死。
折几行是**算**出来的，不是量出来的。

### 6.2 行位：前缀和 + 四个查询函数

```js
// layout()：只在 key 变化时重算
key = `${viewRows}:${contentVer}:${cols}:${rowH}`;

y  = Float64Array(n + 1);     // 每行顶边（最后一项 = 总高）
hh = Float64Array(n);         // 每行高度
if (!wrap) { y[i] = i * ROW_H; hh[i] = ROW_H; }
else for each view row vi:
  lines = max(1, ceil(uL[mi] / cols), ceil(uR[mi] / cols));   // 两栏取高的一侧
  hh[vi] = lines * ROW_H;
  y[vi] = acc; acc += hh[vi];
y[n] = acc;
```

| 函数 | 语义 | 实现 |
|---|---|---|
| `rowTop(vi)` | 第 vi 条视图行的顶边 | 读 `y[vi]`，越界退回 `vi * ROW_H` |
| `rowH(vi)` | 该行高度 | 读 `hh[vi]` |
| `rowAtY(y)` | 内容坐标落在哪条视图行 | 在 `y` 上二分（`y[mid] <= y` 取右） |
| `totalHeight()` | 内容总高 | `y[n]` |

**五条不变式**（违反任何一条都会出现「点错行」「跳错位置」「滚动条长度不对」）：

1. 行位一律走 `view` 下标，⛔ 不许拿模型行下标当行位（折叠后两者不是一回事）。
2. 换行模式下 ⛔ 禁止 `下标 × ROW_H`：行高不等。
3. 切换换行/字号/栏宽/折叠之后，必须**保住视口顶部那一行**：
   `keep = rowAtY(scrollTop)` → 重算 → `scrollTop = rowTop(keep)`。
4. `y` 的长度必须等于 `view.length + 1`，否则所有二分都会越界。
5. `hh` 与 `uL/uR` 必须与 `rows` 同长（改行数时一起重建）。

### 6.3 折叠

```js
// 保留：所有差异行 + 每处差异前后各 foldCtx 行
if (!collapseEnabled || noDiffBlocks) view = identity;
else {
  keep = Uint8Array(total);
  for each row i where kind !== 'same':
    mark [i-foldCtx, i+foldCtx] in keep;
  if (editing && pin in range) keep[pin] = 1;              // 光标所在行必须留着
  if (find.on) keep[currentHit] = 1;                       // 当前命中行必须露出来
  view = indices where keep;
}
```

| 参数 | 值 | 为什么 |
|---|---|---|
| `foldCtx` | **3** | 只留差异行等于把「改了什么」从上下文里剥出来，读者反而要猜 |
| `pin` | 光标所在对齐行 | 把左边改成和右边一样，这一行变成「相同」随即被折叠 —— 光标当场消失，像键盘坏了 |
| 当前命中行 | 查找第 N 个 | 跳过去却看不到命中行本身，只看到一片接缝 |

⚠️ 编辑态**照样折叠**：「看一眼差异然后改」是主要用法。想改相同行的人关掉开关即可。

### 6.4 预览条（差异导航条）

| 元素 | 值 | 说明 |
|---|---|---|
| 栏宽 | **34** | 原先 22 太窄，三样东西抢十来个像素 |
| 轨道宽 | `clamp(w - 12, 10, 22)` | 居中 |
| 差异线宽 | **10**，1px 高，居中 | 铺满轨道会让连续几行粘成一根柱子，越密越糊 |
| 圆角 | 4 | |
| 视口框 | 半透明填充 + 1px 描边 + 上沿实线 | 回答「我在文件哪一段」，与「哪里不一样」是两件事 |
| 视口框抑制 | `contentH <= viewH * 1.12` 时不画 | 装得下一屏时整条轨道就是视口，画框没有信息量 |
| 逐行绘制条件 | 每行平均 ≥ **2.5px** 且差异行总数 ≤ **4000** | 否则按段并成一条 |

⚠️ 逐行标记是「每行 1px」，**不是「这一行有多高」**：折行之后一行可能有 80px，
按高度画就成了粗柱子，把「这是几行」糊掉了。
⚠️ 具体 y 位置一律按 `y[]` 换算，不能按平均像素画（折行会整体错位）。

### 6.5 大纲提取

只反映**结构**，不猜。按文件类型分四条路：

| 类型 | 判据 | 层级 |
|---|---|---|
| Markdown | `#{1,6} `（跳过围栏内） | `#` 个数；`[*_`~]` 去掉后为空显示「(空标题)」 |
| JSON | `"key":` 开头的行 | `min(3, max(1, floor(缩进/2)+1))` |
| 代码 | `def/function/class/fn/func/const/let/var/…` 定义名 | 类 = 1，函数 = 2；上限 **300** 条 |
| 纯文本 | 见下 | |

纯文本的规则（**这里最容易做成「每行都是大纲」**）：

```
1. Setext：整行是 === 或 ---（≥2/≥3），把**上一行**当标题（= 为 1 级，- 为 2 级）
   ⚠️ 上一行自己全是符号/空行时不算
2. `# 标题`（有人把 txt 当 Markdown 写）
3. 行首【…】（1–40 字，整行 ≤ 60 字，保留原样）
4. 第X章/节/条/款/篇/部 → 章篇部 = 1，节 = 2，条款 = 3
5. `一、` `二、` → 1 级
6. 阿拉伯编号：
   - 全文出现过任意一处 `1.1` 式编号 → 编号承担章节语义，层级 = 点号段数
   - 只有单级编号 → 要求它「孤零零成一条」（空行断组后组内只有它），否则当列表，一条都不收
7. 收完做一次「不许跳级」归一化：level = min(level, 上一级 + 1)
8. 上限 300 条；文本截 80 字
```

⚠️ 第 6 条是「猜结构」与「反映结构」的分界线。之前用「像标题的行」启发式，
结果一份带序号的清单会让**每行都成为大纲**，而且层级全被压平。
⚠️ `csv/tsv` **不提取**大纲（一行一条记录，硬凑等于把前 60 行抄一遍），
面板要说明「为什么没有」而不是只说「没有」。

### 6.6 大文档窗口化

两档降级，**阈值不同、手段不同**：

| 条件 | 手段 | 目的 |
|---|---|---|
| 块数 > **5000**（字符 ≤ 1MB） | 给块加 `content-visibility: auto`（CSS 跳过屏外布局） | 布局成本 |
| 字符数 > **1,000,000** | 走窗口化渲染（DOM 里只留视口附近） | 内存与解析成本 |

⚠️ `content-visibility` 在**可编辑**块上有选区副作用，所以只在非窗口化的那一档开启，
且载入期间临时摘掉 `contenteditable`（每次 DOM 变异 Chromium 都要整理选区）。

#### 窗口算法

```
records  = 全文记录数组（§2.3）
cum[i]   = 前 i 块的高度前缀和（末项 = 总高）
winStart / winCount = 当前摆在 DOM 里的范围
padding-top    = 32 + cum[winStart]                  // 编码的是绝对文档偏移
padding-bottom = cum[n] - cum[winStart + winCount]
```

| 步骤 | 规则 |
|---|---|
| 选窗口 | 从 `startIdx` 往后累加高度，直到覆盖 **4 屏**或 **600 块**（谁先到） |
| 建节点 | 逐条 `_materialize(rec)`：单块 parse，再补模型层标注（缩进、序号、bq 标记） |
| 实测 | 量窗口内每块真实高度，**只在真变了才置脏**（否则每趟都重算前缀和） |
| 顶高度 | 用 padding 顶出剩余空间，使 scrollTop 与文档位置对应 |
| 保锚点 | `keepAnchor` 时补 `cum[startIdx] - 高度修正前偏移` 的差，否则画面会跳 |
| 续长 | 滚到边界时**只往两端补**，不重建（重建会摘掉选区） |
| 拖选期间 | ⛔ 绝不搬家：搬家会 replace 掉锚点所在节点，浏览器随即丢掉整个选区 |
| 全选 | Ctrl+A 的语义是**整篇**，但 DOM 里只有窗口 —— 必须走「标记全文已选 + 模型层整篇替换」 |

**估高表**（未实测时用；只影响滚动条长度与跳转精度）：

| 类型 | 估算 |
|---|---|
| 代码块 | `22 × (行数+1) + 44` |
| 表格 | `34 × (行数+1)` |
| 分割线 | 30 |
| 公式块 | `24 × (行数+1) + 16` |
| 其他 | `max(1, ceil(文本长/44)) × 26 + 12` |

⚠️ 「4 屏」的取值是权衡：太小则每滚一屏就搬家（掉帧），太大则首次进窗口就要建几百个节点。
⚠️ 窗口里必须包含窗口边界前后的兄弟块：合并/拆分要用到相邻块。

#### 渐进载入

超大文件按空行切段，逐段 parse 后批量插入（每段约 512KB）。**三条切割禁令**（跨段会改语义）：

1. 围栏代码块内不切（正文会被当成代码，或反过来）。
2. `$$` 块级公式内不切（公式体会被拆碎）。
3. 空行后紧跟列表项不切（松散列表被拆成两段）；空行前是引用行不切（提示块染色跨组）；
   连续多个空行不切（第二个空行会合成空段落块，切开就丢）。

### 6.7 性能门槛

| 场景 | 门槛 | 超标时的症状 |
|---|---|---|
| 冷启动到可输入 | < 400 ms | 用户开始怀疑程序没启动 |
| 单次击键到画面更新 | < 16 ms（小文档）/ < 40 ms（10 万行） | 打字有拖影 |
| 打开 1MB Markdown | < 300 ms | 白屏 |
| 打开 10MB Markdown | < 2 s，且中途有进度 | 看起来卡死 |
| 对比 5 万行 × 2 | < 1.5 s | 窗口白屏 |
| 滚动 | 恒定 60fps，**不许**随行数变慢 | 「越用越卡」 |

`> 1MB`、`> 5000 块`、`> 3 万行`、`> 2000 条差异` 这几条线附近是最容易翻车的地方，
改任何渲染路径都要在这几个量级上各测一遍。

## 7. 差异引擎

纯函数，输入两段文本，输出操作序列。**不许读文件、不许碰界面**。

### 7.1 行对齐

```js
normalize(line) = 忽略大小写?(toLowerCase) + 忽略空白?(压缩连续空白为空格并 trim)

diffLines(aLines, bLines, opt):
  A = aLines.map(normalize); B = bLines.map(normalize);
  return lcsOps(A, B, 0, 0, depth=0);
```

`lcsOps` 分四步，**顺序不能换**：

```
1. 剥公共前缀 p、公共后缀 s        // 递归切出来的碎片多半同头同尾，剥掉能省整张 DP 表
2. 中间段 an × bn：
   - 任一侧为空 → 全 add 或全 del
   - an*bn <= 4,000,000 → 精确 DP（LCS）
   - depth >= 24 → 兜底「整段替换」
   - 否则 → 锚点切分后各自递归
3. 前缀输出 same（行号 = 原偏移 + k）
4. 后缀输出 same
```

| 参数 | 值 | 说明 |
|---|---|---|
| DP 单元格上限 | **4,000,000** | 4 字节/格 ≈ 16MB，超过就换锚点 |
| 递归深度上限 | **24** | 防病态输入把栈走穿 |
| 锚点 | 两侧都**恰好出现一次**的行 | 重复行（空行、表格分隔线）不当锚点：位置本来就多解 |
| 锚点取子序列 | 对「B 侧行号」求最长严格递增子序列 | 保证两侧顺序一致 |
| 兜底 | 整段 = 全删 + 全增 | 语义上是「这段被整体替换」 |

DP 的取边规则（决定差异块长什么样）：

```js
if (a[i] === b[j]) same;
else if (dp[i+1][j] >= dp[i][j+1]) del;      // 相等时优先「删左」
else add;
```

⛔ **兜底绝不能把不匹配的行标成 `same` 且 `b = -1`**：那会让行号错位，界面上看起来
像整页未改动（实际发生过：2000 行对 2000 行，右侧整页空白）。
退化得再快，也不能拿假结果冒充真结果。

### 7.2 词级 diff（段内高亮）

只对 `kind === 'chg'` 的行做，**按 token** 而不是按字符：

```js
tokenize = /[\u4e00-\u9fa5]|[A-Za-z0-9_]+|\s+|[^\sA-Za-z0-9_\u4e00-\u9fa5]/g
// 即：每个汉字一个 token、每个 ASCII 词一个 token、空白一段、其余每个符号一个 token
```

| 参数 | 值 | 说明 |
|---|---|---|
| 规模上限 | `n × m <= 250,000` | 超了整行标成「替换」（左右各一个 `<mark>`） |
| DP 存储 | `Uint16Array` | LCS 长度不会超过 65535 |
| 输出 | `{l, r}` 两段**已转义** HTML，差异部分包 `<mark class="rem">` / `<mark class="ins">` | |

**只把字标红**：⛔ 不铺底色、不画行边框、不给整段加背景。

### 7.3 行模型

```js
buildSideBySide(aLines, bLines, opt):
  ops = diffLines(...)
  连续 del/add 合成一段：
    len = max(dels.length, adds.length)
    第 x 行：L = dels[x] || null, R = adds[x] || null
    kind = L && R ? 'chg' : L ? 'del' : 'add'
  same 行两侧都有行号
→ { rows, blocks }        // blocks = 每处差异的起始行下标（导航用）
```

| 不变式 | 理由 |
|---|---|
| `same` 行两侧行号**必须都有效** | 否则「行号列」出现空洞 |
| 占位行（一侧为 null）**必须可写** | 写下去 = 在该侧插入一行；不可写的话，一侧贴完另一侧就动不了 |
| 跨行替换的边界**必须允许占位行** | 选区末端落在尾部占位行是常态（对面更长）。按行号取会整段放弃，表现是「全选后粘贴没反应」；两端一律换算成字符偏移 |
| `chg` 才做词级 diff | `add`/`del` 整行都是差异，词级没有意义 |

**占位行的插入位置** = 前面最后一个本侧行号 + 1。这个位置在建模时就算好存起来
（`fL`/`fR`），编辑时直接用。

### 7.4 三向合并

```js
hunks(base, x) =         // base → x 的改动块
  遍历 buildSideBySide(base, x).rows：
    same 行 → 结束当前 hunk，baseIdx++
    差异行 → 开 hunk；有 L 则 baseEnd++、baseIdx++；有 R 则把 R 的文本收进 lines

merge3(base, a, b):
  1. 两侧 hunk 合并成一个列表，按 baseStart 排序（同起点按 baseEnd）
  2. 区间重叠或「同点插入」的合成一组
  3. 逐组处理：
     - 只有 A 侧改动 → 用 A
     - 只有 B 侧改动 → 用 B
     - 两侧都有且**文本相同** → 用任一侧（算自动合并）
     - 两侧都有且不同 → 记一条冲突，**输出保留 A 侧内容**
```

⛔ 冲突处**不要写入 `<<<<<<<` 标记**：会污染文档，用户还得手动清理。
冲突以「区间清单」返回，由界面显示，让用户逐个决定。

### 7.5 文件夹对比

```
两侧各递归列目录（上限 20000，深度 24）→ 按「相对路径」建 map（相对各自根目录！）
键 = 两侧相对路径的并集，按**字节序**排序（不是语言相关排序）
逐键判定：
  只有左侧 → left（仅左）
  只有右侧 → right（仅右）
  两侧都有，大小不同 → mod（已修改）
  两侧都有，大小相同 → **maybe → 必须读内容比较**
```

⚠️ **「大小相同」不等于「内容相同」**：`3`→`5`、`一`→`二` 字节数一模一样，
只看大小会把改过的文件报成「相同」，而「只看差异」默认勾着 —— 等于把差异藏起来。
内容比较要**整批发一次**（一次调用比 N 次快得多）；读不了就按「已修改」报（宁可多报）。

| 参数 | 值 |
|---|---|
| 行数上限 | **4000**，超了截断并明说「只显示前 N 条」 |
| 默认视图 | 只看差异 |
| 排序 | 按相对路径的**码点序**（与 `localeCompare` 不同，保证跨语言一致） |
| 点击一行 | 用系统默认程序打开该文件（仅一侧存在时打开存在的那侧） |

## 8. 导出

### 8.1 导出 HTML（单文件）

目标：**双击就能看**的网页。两个决定：CSS 内嵌、图片转 data URI。

| 步骤 | 做法 |
|---|---|
| 1. 收集图片 | 正则找出所有 `![](...)`，跳过 `data:` / `http(s):` |
| 2. 内嵌 | 逐张读字节转 base64；MIME 由扩展名映射（png/jpg/jpeg/gif/webp/bmp/svg/avif/ico） |
| 3. 超限 | 单张 > **4 MB** 或读不到 → 保留原路径（图可能打不开，但文档还能看），提示里说明内嵌了几张 |
| 4. 渲染 | Markdown 走与预览同一套渲染器（高亮、公式、图片解析器都传进去） |
| 5. 内联样式 | 把当前文档所有样式表的规则文本拼起来（跨域取不到就跳过） |
| 6. 包壳 | 固定**浅色**主题 + 正文最大宽 **46rem** 居中 + `padding: 48px 20px 80px` |
| 7. 写盘 | UTF-8，无 BOM |

⚠️ 导出页必须**忽略用户的深色主题**：接收方多半在浅色环境下打开，且打印时深色底会全黑。
⚠️ 非 Markdown 文件（代码/纯文本/JSON）导出时走「预览渲染」，代码要保留等宽与换行。

### 8.2 导出 PDF（不提供打印）

用 WebView2 自己的 `PrintToPdf`，直接落盘；不打包 PDF 库（体积不涨），也不弹打印面板。

**为什么不是 `window.print()`**：嵌入式 WebView（不是独立浏览器窗口）里 `window.print()`
是空实现 —— 不弹框、不报错、不 reject，什么都收不到。这就是「唤不醒打印窗口」的全部原因，
不是权限问题、也不是被拦截。所以打印面板这条路在本产品里不存在，直接删掉，
只保留「导出 PDF」这一个明确动作。

```
前端（src/js/pdf.js）
1. pickSavePath() 拿目标路径；用户取消就返回
2. 把内容渲染进 #printRoot（复用预览渲染器，图先 await 画完）
3. 临时把 body 切到浅色主题（深色底导出会成黑纸），显示 .pdf-busy 遮罩
4. await be.exportPdf(path)            → invoke('export_pdf', { path })
5. 复原：清空 #printRoot、还原主题、撤遮罩；成对写在 try/finally 里

后端（src-tauri/src/lib.rs::export_pdf，仅 Windows）
6. with_webview 拿到 ICoreWebView2Controller → core 转 ICoreWebView2_7
7. environment 转 ICoreWebView2Environment6 → CreatePrintSettings
   · PageWidth/PageHeight = 8.27 × 11.69 英寸（A4）
   · 四边 Margin 全 0（页边距交给 CSS 的 @page，只给一次，否则双边距）
   · SetShouldPrintBackgrounds(true)（代码块底色、表格斑马纹要留）
8. PrintToPdf(path, settings, PrintToPdfCompletedHandler) → 结果通过 mpsc 回传
9. 回调里 hr.is_ok() && ok 才算成功；否则 pdf.failed
```

打印样式（`@media print`，全部在 CSS 里，JS 不写样式）：

```css
@page { size: A4; margin: 16mm 15mm; }
/* ⚠️ 第一条：屏幕布局是「一屏铺满」，打印必须整套撤掉，
   只撤 overflow 或只撤 height 都还会把整篇裁进第一个视口高度 */
html, body {
  height: auto !important; min-height: 0 !important; width: auto !important;
  overflow: visible !important; display: block !important;
}
body > *:not(#printRoot) { display: none !important }   /* 单容器模式 */
#printRoot { display: block !important; width: auto !important }
h1,h2,h3 { page-break-after: avoid; }                   /* 标题不落页尾 */
tr { page-break-inside: avoid; }                        /* 表格行不跨页 */
pre { white-space: pre-wrap; word-break: break-word; }
```

⚠️ **打印媒体不等于换一套布局**：`@media print` 里没有覆盖的规则会原样继承
`html, body { height:100%; overflow:hidden }` 与 `body { display:flex }`。三者
叠加时 Chromium 把 `#printRoot` 裁在 820px 的视口里，`PrintToPdf` 就只写 1 页，
后面的正文全丢。三条必须一起撤，验收见 `test/probe-app.mjs` 的「多页 PDF」断言。

⚠️ **单容器模式**是这里唯一的结构约定：所有要进 PDF 的东西先渲染进 `#printRoot`，
再用 `body > *:not(#printRoot){display:none}` 屏蔽其余一切。这样不用逐个隐藏
标题栏/标签条/菜单/状态栏，也不会漏掉后续新增的 UI。
⚠️ 页边距只能有一处来源。`PrintSettings` 四边设 0，`@page` 给 16mm/15mm；
两边都给会得到叠加后的双份边距，看起来像「内容挤在纸中间」。
⚠️ 非 Windows 平台（`#[cfg(not(target_os = "windows"))]` 的同名命令）返回
`pdf.unsupported` —— 不假装支持再静默失败（见 §10.5）。

### 8.3 打开 PDF（只读分流）

PDF 不是「不能打开」，是「不能按文本打开」。实现只有三处：

1. `format.js::externalFileKind()`：按扩展名认白名单（目前 `/\.pdf$/i`），**唯一真源**；
2. `app.js::openPath()`：命中就在读盘之前分流，调 `be.openExternal(path)` →
   `plugin:opener|open_path`（`capabilities/default.json` 已有 `opener:allow-open-path`），
   给一条带文件名的 toast，`addRecent()` 记一条，**不建标签、返回 `null`**；
3. `backend.js::fileFilters()`：打开文件对话框加 `{ name: 'PDF', extensions: ['pdf'] }`，
   否则对话框里根本点不到 PDF。

文件树 / 拖放 / 命令行 / 「最近打开」都汇到 `openPath()`，所以判定只有这一处。
⛔ 不要给 `tauri.conf.json` 的 `fileAssociations` 加 pdf：把 `.pdf` 的系统默认程序
设成本应用后，本应用又转手交给系统默认程序，会形成自循环。
⛔ 不要把 PDF 做成新的 `kind`：`t.content` 参与草稿 / localStorage、保存、格式化、
查找、外部改动重载，每个环节都得开特例，改动面大且容易串档。
程序内嵌 PDF 阅读器同理不划算：WebView2 内置 viewer 受 Edge 策略控制，用 pdf.js
自绘则要新增渲染引擎与 worker。

### 9.2 标签条

| 规则 | 值 |
|---|---|
| 标签最大宽 | **133** |
| 文件名最大宽 | **100**（超出省略号） |
| 关闭按钮 | 18×18，仅 hover / 激活时可见 |
| 相邻标签 | `margin-left: calc(var(--bw) * -1)`（共用一条边，避免双线） |
| 首/末标签 | 外侧边透明（不画出容器外的线） |
| 激活态 | `z-index: 1` + 字重 600 + 全亮 + 上下线断开；圆角恒 0 |
| 未保存点 | 7px 圆点（accent） |
| 外部改动点 | 5px 琥珀点（`--chg-fg`），与未保存点**分开**看 |
| 加粗防抖 | 用 `::before { content: attr(data-bold); height:0; visibility:hidden }` 预留粗体宽度，否则切标签时中文变粗会让整条抖动 |

**溢出三入口**（缺一个就有用户找不到标签）：

1. 滚轮横向滚动；
2. 拖到边缘自动滚（指针靠近左右边缘时按帧滚）；
3. 右侧「全部标签」按钮弹出完整清单（固定定位，不随滚动关闭）。

**标签右键（1.2.8）**：

```
b.oncontextmenu → contextMenu(x, y, [
    关闭 (Ctrl+W) / 关闭其他 / 关闭左侧 / 关闭右侧 / ──
    复制文件路径 / 在文件夹中显示
])
```

- `idx = tabs.findIndex(x => x.id === t.id)`；三个批量项分别按
  `tabs.length < 2` / `idx <= 0` / `idx >= tabs.length - 1` 置灰；后两项按 `!t.path` 置灰。
- 三个方向统一走 `closeMany(ids, keepId)`：`flushQuickNote`（待关名单里的速记）→
  收脏标签 → 一次 `dialog`（Y 全部保存并关闭 / N 不保存并关闭 / Esc 取消）→
  `saveAllQuiet(dirty)` → `dirty.filter(isDirty)` 持久化到 `snp.draftStash` →
  活动标签在待关名单时先 `persistCurrentView()` → `removeTab` → `activate(keepId)`。
- `saveDraft()` 每轮把 `draftStash` 并进 `drafts`；`restoreDrafts()` 的三个出口
  （无有效草稿 / 用户丢弃 / 恢复成功）都要 `LS.del('draftStash')`。
  ⛔ 别把 stash 做成 `activate()` 的一次性参数：输入防抖、`setMode`、`beforeunload`
  都会重调 `saveDraft()`，只写一次会被下一轮覆盖，兜底等于没有。
- `copyPath(p)` → `writeClipboard(p)` → toast `路径已复制` / `无法复制路径`。

**文件树行右键**：`_rowMenu()` 末尾在「在资源管理器中显示」之前插「复制文件路径」，
`_copyPath()` 走同一个 `writeClipboard`；目录行也复制自己的路径，多选时复制被右键那一行。
⛔ 两处都不要再用 `navigator.clipboard.writeText`（WebView2 抛 `NotAllowedError`）。

### 9.3 菜单

一级顺序固定（**速记与对比在最右边**，它们是高频动作，不是分类）：

```
文件 / 编辑 / 格式 / 插入 / 视图 / 工具 / 设置 / 帮助 / 速记 / 对比
```

四种表达手段，**按语义选，不能混用**：

| 手段 | 语义 | 例子 |
|---|---|---|
| `head` 小节标题 | 分组 | 「文件」里的「速记」小节 |
| `row` 横排 | 互斥单选，横排省空间且当前态一目了然 | 正文/H1/H2/H3 |
| `hidden` 条件隐藏 | 在该上下文里根本不适用 | 非 Markdown 时隐藏标题级别 |
| `note` 灰字说明 | 解释「为什么这项是灰的」 | 「标题与列表只在所见即所得模式下可用」 |

**一级项要么是下拉、要么是动作**：速记与设置都是**动作**（点一次直接执行）。
⛔ 不要再套一层「打开速记」。

菜单项该不该进工具栏的判据：**「效果取决于你选中哪一处」就不该进工具栏**
（对比窗口「复制到另一侧」的箭头因此在中缝里，不在工具栏）。

右键菜单五条关闭时机：点外部 / Esc / 滚动 / 窗口失焦 / 执行项。
⚠️ 滚动关闭要用**捕获**监听（任何元素滚动都触发），但锚在固定控件上的菜单必须
传 `stayOnScroll: true` —— 否则「刚滚过标签条就点按钮」会被迟到的 scroll 收掉菜单。
⚠️ 滚动事件是**排队派发**的，所以这个 bug 是间歇性的，别用 sleep 掩盖。

### 9.4 设置面板

四页：**外观 / 界面 / 文件 / 快捷键**。所有设置**即时生效**（没有「确定」按钮，
只有「完成」关闭）。左栏底部有「恢复默认设置」。

| 页 | 内容 |
|---|---|
| 外观 | 主题（跟随系统/浅色/深色）、字号（步进 + 当前 px + 重置）、正文宽度（同上） |
| 界面 | 语言（9 种 + 跟随系统）、显示侧栏、双栏 |
| 文件 | 自动保存、监听外部修改、工作文件夹（路径 + 选择…/清除） |
| 快捷键 | 按命令列出当前键位；逐条「更改」进录制、有自定义键时才出现「恢复」 |

### 9.5 对话框与提示

| 类型 | 用途 | 规则 |
|---|---|---|
| 信息框 | 需要用户确认的操作 | 标题 + 正文（可含少量 HTML 加粗）+ 两个按钮（主/次） |
| 输入框 | 重命名、插入链接/表格参数 | 单输入框 + 确定/取消；回车=确定 |
| toast | 操作结果 | 2–3 秒自动消失；同时只显示一条（新的顶掉旧的） |
| 空状态 | 侧栏/列表没有内容 | 必须说明**为什么没有**，不能只说「没有」 |

⚠️ 对话框渲染时容器还没挂到文档上，所以内部查询要用「在容器内查找」而不是全局 `getElementById`。

### 9.6 语言

9 种：`zh-CN` / `zh-TW` / `en` / `ja` / `ko` / `fr` / `de` / `es` / `pt`。

| 规则 | 做法 |
|---|---|
| 词条的键 | **简体中文原文**（`tt('保存')`），不是 `menu.save` |
| 取词函数名 | `tt`，⛔ 不叫 `t`（`t` 在业务代码里是「当前标签」） |
| 缺译 | 回退英文 → 再回退中文原文；**永不显示空白或键名** |
| 占位符 | `{name}` / `{n}` 形式，替换时缺参数就原样保留 |
| 顶层常量 | 带 `tt()` 的必须写成**函数**，否则切语言后卡在旧语言 |
| 语言检测 | 依次尝试 `navigator.languages`；`zh` 开头按地区判繁简（TW/HK/MO 或 Hant → 繁），其余按前缀匹配 |
| 静态节点 | 只能挂在 `data-i18n` / `data-i18n-title` / `data-i18n-ph` / `data-i18n-aria` 上；动态生成的节点直接调 `tt()` |
| `html lang` | 必须同步设置：影响断行规则（中日文不按空格断）、字体回退、屏幕阅读器 |

⚠️ 错误文案要**整句**翻译，不要拼「前缀 + 名词 + 后缀」：各语言语序不同，拼出来一定别扭。
后端只回**错误码**，句子由前端拼（见 §1.4）。

| `--bg-hover` / `--bg-active` | gray-4 / gray-5 | 同 | 悬停 / 按下 |
| `--line` / `--line-strong` | gray-6 / gray-7 | 同 | 细分隔 / 控件边 |
| `--fg` / `--fg-soft` / `--fg-faint` | gray-12 / gray-11 / gray-10 | 同 | 正文 / 次要 / 元信息 |
| `--accent` | tm-11 | tm-11 | 强调色**文字与图标** |
| `--accent-solid` / `-hover` | tm-9 / tm-10 | 同 | 实心填充（主按钮、当前标签点） |
| `--accent-soft` | tm-3 | tm-3 | 强调浅底（有未保存改动的按钮） |
| `--accent-fg` | `#fff` | `#1a0f0c` | 实心色上的字：深色下橙底配深字才不糊边 |
| `--danger-solid` / `-hover` / `-fg` | red-9 / red-10 / `#fff` | 同 | 危险按钮 |
| `--add-*` / `--del-*` / `--chg-*` | green/red/amber 的 3 + 11 | 同 | 增 / 删 / 改的底色与字色 |
| `--co-{info,warn,danger,ok}[-bg]` | blue/amber/red/green 的 11 + 3 | 同 | 提示块四色 |
| `--tok-*` | 九种语法类 | 同 | 预览与 CM6 共用一套着色 |
| `--mark-bg` | `#ffe9a3` | 半透明黄 | 文档高亮 `==文字==`；非 md 的 `.cm-view-mark` 复用同一份黄 |
| `--active-line-bg` | `color-mix(--fg 3%)` | `color-mix(--fg 5%)` | 当前行：中性，⛔ 不占状态色 |
| `--sel-match-bg` | `color-mix(--fg 10%)` | `color-mix(--fg 14%)` | 选区匹配 `.cm-selectionMatch` 与 `::highlight(sn-same)`；同时盖掉 CM6 `baseTheme` 的默认亮绿 |

⚠️ **三种视图提示都不进文档**：当前行是 `EditorView.theme()` 的一条规则，选区匹配是
`@codemirror/search` 的 decoration，非 md 的高亮是 `StateField` + `Decoration.mark`。
只有 md 的 `==文字==` 会写进 `t.content`。`.cm-selectionMatch` 必须在 `editor/theme.js`
里显式给 `var(--sel-match-bg)`：官方 `baseTheme` 自带亮绿底，样式优先级按 CM6 的
注入顺序走，光在 `styles.css` 里写一句盖不住。

⚠️ **深色下「纸面 / 灰面」的步进方向是反的**：Radix 暗色第 1 步最暗，所以纸面取 2 步、
灰面取 1 步，才能保住「纸面比侧栏亮」这个相对关系。照抄亮色的步号会让两块糊在一起。

⚠️ **`--bg-soft` / `--bg-well` / `--bg-chip` 必须分开**，别图省事合成一个：
深色下浮层在第 3 步，若控件也用第 3 步，设置面板里的分段控件、输入框、快捷键列表
会**整块消失**（只剩一圈 0.5px 线）。三者的分界是「在纸面上 / 在浮层上凹进去 /
在浮层上凸起来」，方向不同，只能各给一个值。

#### ③ 强调色只表示状态

当前标签、当前章节、焦点、未保存点、主按钮 —— 只有这五类。**悬停、选中行的底色
一律走灰阶**：满屏橙条会让「哪个是当前」这个信息直接失效。
`--accent-soft` 只给「有未保存改动」的保存按钮，`--accent-solid` 只给主按钮与标签点。

#### ④ 边框只有一种粗细：`--bw: 0.5px`

在 100% DPI 上它落成半像素覆盖，重量是 1px 的一半；同一色平面上，1px 会像用尺子划过，
0.5px 才是一条「分界」而不是「画框」。
- 分隔线（用 `height/width: 1px` 画的色块）也走 `var(--bw)`；
- 内描边（`box-shadow: inset 0 0 0 …`）同样走 `var(--bw)`；
- ⛔ 别再写 `1px`，包括 `outline`。

#### ⑤ 圆角两档 + 同心

`--r-1: 4px`（控件）/ `--r-2: 8px`（浮层与块）。
**嵌套时内层 = 外层 − 内边距**：菜单 8 − `padding: 4` = 菜单项 4；分段控件外层 8 +
`padding: 4` → 内层 4。两层弧线要平行，否则一眼看得出来是「套了个方框」。
⛔ `.tab` 必须 `border-radius: 0`：相邻标签共享同一条竖线，圆角会在接缝处露出缺口。

#### ⑥ 字号四档，12px 是下限

| 令牌 | 值 | 用途 |
|---|---|---|
| `--fs-1` | 12 | 元信息、标签、按钮、状态栏 |
| `--fs-2` | 13 | 界面正文、对话框 |
| `--fs-3` | 15 | 阅读与标题 |
| `--fs-editor` | 13.5（可被设置覆盖） | 编辑区 |

层级靠**字重、颜色、间距**去做，不靠「再缩半号」——12px 以下在 100% DPI 上就是糊的。
中文⛔ 不加 `letter-spacing`：四个字会散开，读起来比不加更慢。

#### ⑦ 浮层：线归线，影归影

浮层 = `border: var(--bw) solid var(--line-strong)` + **一层** `--shadow-float`
（`0 8px 20px -8px rgba(0,0,0,.18)`，暗色 `.62`）。
⛔ 别把边框画进 `box-shadow`（旧写法 `0 0 0 1px` 既是线又是影，改一处另一处跟着歪），
⛔ 也别叠第二层投影 —— 那会把扁平的界面拉回 2010 年。

#### ⑧ 动效只给「浮层出现」

`--dur: 250ms` + `--ease-out: cubic-bezier(0,.2,1)`，只有 `pop` / `fade` 两个关键帧。
悬停、切换、折叠、主题切换一律瞬变：工具类界面里，延迟反馈只会让人觉得卡。

#### ⑨ 焦点环

`outline: var(--ring)`（`2px solid var(--accent-solid)`）+ `outline-offset: 2px`。
用 `outline` 而不是 `box-shadow`：后者会被组件自己的阴影盖掉；`outline` 还会跟随圆角。
原生复选框 / 单选框 / `progress` 走 `accent-color: var(--accent-solid)`——
不写这一行，系统会塞一块**蓝色**进来，那是整套界面里唯一不来自色板的颜色。

#### ⑩ 不用「卡片彩边」表达分类

引用块、提示块、JSON 校验条、块公式、重复行、大纲当前项：**一律去掉左沿 2–3px 彩条**。
分类信息改用「底色 + 标题字色」表达；⛔ 左侧色条是最像 2010 年后台模板的那一种装饰。

#### ⑪ 其余

| 项 | 值 |
|---|---|
| 图标 | 统一挂 `.ico`（`fill:none; stroke:currentColor` 在样式表一处给）。不挂就是默认黑色实心块 |
| 光标 | 正文用**自绘 I-beam** `--cur-text`：系统 I-beam 只有 1px，且会按底色翻白 |
| 专注模式 | 只留标题栏与正文；标题栏 `opacity: .28`，hover 恢复 1 |
| 排版 | h1 `1.9em` / h2 `1.42em` / h3 `1.16em`；正文行高 1.7；正文宽 `var(--rw)`（专注模式 `calc(var(--rw) * .92)`，⛔ 不能自引用同一变量） |
| 层数上限 | 一个视图里最多三层底：纸面 → 浮层 → 浮层上的控件。再加第四层就说明该拆结构了 |

## 10. 移植到别的平台

这一章有两种用法，先分清自己在哪一条：

- **另写一份原生版**（不打算复用现有代码）→ 看 §10.1 ～ §10.3，选路线、定文本引擎、逐功能映射；
- **把这个 Windows 版本搬到 mac / Linux**（复用现有代码）→ 先看 §10.4 的 A/B/C/D 清单，
  再按 §10.7 的里程碑推进。

### 10.1 先选路线，再谈代码

| 路线 | 复用率 | 工作量 | 主要风险 | 什么时候选 |
|---|---|---|---|---|
| **A. 同一套前端 + WKWebView** | ≈95% | 小 | WebView 行为差异：选区跨节点、剪贴板异步、导出 PDF、`content-visibility` | 只想「上 mac」，功能与手感要和 Windows 一致 |
| **B. 原生外壳 + 编辑区仍是 WebView** | ≈70% | 中 | 两套 UI 语言拼在一起；菜单/窗口原生但编辑区不是 | 需要原生菜单栏/Dock/窗口管理，编辑区可以接受 Web |
| **C. 全原生（AppKit + TextKit 2）** | ≈20–30% | 大 | 编辑器行为要从零对齐；L4 手感最难保证 | 产品定位就是「原生质感」，愿意为此重写核心 |

⚠️ **C 路线最大的坑不是画界面，是文本引擎**：`contenteditable` 帮你做了大量脏活
（光标在嵌套行内元素里怎么走、选区跨节点怎么合并、输入法组合、拖放）。
原生实现必须**自己定义并实现**这些规则 —— 本文 §5 那一整章就是给这件事写的。

⚠️ A 路线的隐性代价：三个平台的内核不同（WebView2 / WKWebView / WebKitGTK），
同一段 DOM 代码在三者上的光标、滚动、字体度量、选中行为会有差异。
所以里程碑**每一档都要求先在目标机器上跑通再往下走**，不要一次改完再统一联调。

### 10.2 全原生：文本引擎的三个方案

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| C1 单个 `NSTextView` | 整篇一个属性化文本，块只是「段落样式 + 自定义属性」 | 光标/选区/输入法/撤销全部现成 | ⛔ 表格、代码块栏、提示块标题这些**非文本装饰**只能靠 attachment 或自绘；折叠、窗口化几乎做不了 |
| C2 每块一个文本视图 | 与 Web 实现一一对应：一个块一个 `NSTextView`（或 `NSTextField`），外层自定义容器负责布局与滚动 | 行为最容易对齐；表格/装饰/折叠都能按块做 | 跨块选区、方向键跨块、拖选都要自己实现（**这部分 Web 端也是自己实现的**，可直接照搬算法） |
| C3 TextKit 2 自定义布局 | 一个 `NSTextContentStorage` + 自定义 `NSTextLayoutFragment`，块装饰在 fragment 层画 | 性能与自由度最好 | 复杂度最高，等于自写排版器 |

**推荐 C2**：它和本文的模型（块 = 可编辑单元，容器负责几何）是同一个形状，
§5 的每条规则都能一对一落地；性能上「只给视口内的块建视图」正好复用 §6.6 的窗口化。

### 10.3 逐功能映射

| 功能 | Web 做法 | 原生做法 | 注意 |
|---|---|---|---|
| 文档模型 | Tab 对象 + 纯文本 | `struct Document` + `String`（同样「文本是真相」） | 别用 `NSAttributedString` 当真相：它会把样式和内容混在一起，序列化不可控 |
| 块结构 | DOM 节点 + `data-*` | `enum BlockKind` + `struct Block`（带 `indent`/`callout`/`lang`…） | 与 §2.4 的属性表一一对应 |
| 输入即转换 | `input` 事件 + 正则 | `NSTextViewDelegate.textDidChange` + 同一批正则 | 判据仍是「光标之前 ≤16 字符」 |
| 行内标记转换 | 拆 Range 插元素 | 改 `NSAttributedString` 属性 + 一个零宽空格落脚点 | 零宽空格的作用完全一样 |
| 光标工具 | Range/Selection API | `NSTextView.selectedRange()` + `layoutManager` 位置换算 | 「边界落在字符上」在原生侧天然成立 |
| 撤销 | 自己的快照栈 | 可用 `NSUndoManager`，但**建议照搬快照栈** | 我们要的是「700ms 合并 + 8MB 上限」，不是系统的 undo 分组 |
| 跨块选区 | 自建 Range 模型 + `setBaseAndExtent` | 自定义 `NSResponder` 选区模型（锚点 + 焦点 + 块内偏移） | 系统不支持跨 `NSTextView` 选区，必须自建（Web 端同样自建） |
| 语法高亮（代码块） | CSS Custom Highlight | `NSLayoutManager` 的临时属性（`.backgroundColor`/`.foregroundColor`） | ⛔ 不要改 `textStorage` 的属性：会进撤销栈、会被序列化看到 |
| 表格 | 真 `<table>` + 单元格可编辑 | `NSTableView` 或自定义网格（每个单元格一个文本视图） | Tab/Enter 的遍历规则直接照 §5.9 |
| 预览 | 自研渲染成 HTML | `NSTextView`（只读、属性化）或 `WKWebView` | 用 WKWebView 更省事，且公式（KaTeX）现成 |
| 公式 | KaTeX | 用 WKWebView 渲染成图，或 `NSImage` 缓存 | 转成图片后要处理 DPI |
| 大纲 | `#` 扫描 | 同一套扫描 + `NSTableView`（窗口化复用 §6.5 的 28px 行高） | |
| 标签条 | 自绘 + 溢出三入口 | 原生 `NSTabView` 不好控样式 → 自绘 `NSView` | 133/100/18/7px 这些值照抄 |
| 菜单 | 自绘菜单栏 | **必须**用 `NSMenu`（系统菜单栏） | 顺序照 §9.3；快捷键用 `keyEquivalent` + `modifierMask` |
| 快捷键 | `keymap` 表 + 拦截 | `NSMenuItem.keyEquivalent` + 局部 `NSEvent` 监听 | ⌘ 代替 Ctrl；注意与系统快捷键冲突（⌘Space、⌘Tab、⌘M、⌘H） |
| 设置 | 自绘四页面板 | `NSWindow` + 自定义视图（或 `NSPreferencePane`） | 即时生效、无「确定」 |
| 文件对话框 | 系统对话框 | `NSOpenPanel` / `NSSavePanel` | 允许目录选择要设 `canChooseDirectories` |
| 目录监听 | 一层目录 + 文件名过滤 | `FSEventStream`（目录级）或 `DispatchSource`（vnode） | FSEvents 有延迟合并，300/250ms 的节奏要重调 |
| 删除 | 回收站 API | `FileManager.trashItem(at:resultingItemURL:)` | 沙箱下也只能进废纸篓 |
| 导出 PDF | `PrintToPdf`（WebView2） | `WKWebView.createPDF(configuration:completionHandler:)`，纸型与边距由 CSS `@page` 决定 | 不要走 `NSPrintOperation`：那会弹打印面板，而本产品是「直接落盘」 |
| 剪贴板 | `execCommand('copy')` | `NSPasteboard.general.clearContents()` + `setString` | 读图用 `readObjects(forClasses:[NSImage.self])` |
| 编码 | encoding_rs | `String(data:encoding:)` **不支持 GB18030** | 用 `CFStringConvertEncodingToNSStringEncoding(kCFStringEncodingGB_18030_2000)` 或 ICU；探测顺序照 §3.7 |
| 图片落盘 | 复制到 `assets/` | `FileManager.copyItem` | 命名冲突规则照 §5.10 |
| 窗口几何 | 问窗口所在显示器 | `window.screen?.visibleFrame` | 多屏 + 缩放（Retina）都要按逻辑点算 |

### 10.4 若从本仓库移植出去：A/B/C/D 清单

**移植面比想象的小。** 业务逻辑（`src/js/` 约 1.4 万行）与平台无关，一行都不用改；
真正要动的集中在四处：

1. **打包配置**（`tauri.conf.json` 里写死了 Windows 目标）；
2. **Rust 里的 5 处系统调用**（圆角、工作区矩形、回收站、窗口铺满、浏览器参数）；
3. **macOS 独有的两个入口**（Finder 双击打开文件、系统菜单）；
4. **测试工具链的另一半**（真机套件是 Windows 专用）。

`additionalBrowserArgs` 被 wry 的 `#[cfg(windows)]` 包着，其它平台直接忽略、不报错；
`app_data_dir()` 由 Tauri 按平台给出；字体栈已写 `-apple-system` / `PingFang SC` /
`Noto Sans CJK`；`notify` 与 `encoding_rs` 都是纯 Rust + 各平台原生实现；
主题跟随系统用 `prefers-color-scheme`，三个内核都支持。

#### A 级：不改就跑不起来

**A1 打包目标写死 `nsis`。** NSIS 是 Windows 专属打包器，在 mac / Linux 上 `tauri build`
会直接报「target not supported」。改成 `"targets": "all"`，由 CI 显式指定
（`--bundles dmg` / `--bundles deb,appimage`），能按需只出某一种。同时补两块：

```jsonc
"macOS": {
  "minimumSystemVersion": "10.15",
  "entitlements": null,          // 不用 JIT / 摄像头时保持 null
  "signingIdentity": null        // CI 里用环境变量注入，别提交到仓库
},
"linux": {
  "deb": {
    "depends": ["libwebkit2gtk-4.1-0", "libgtk-3-0"]   // 空着能装上，但装完可能起不来
  }
}
```

⚠️ `depends` 空数组时要留意：装完缺 webkit2gtk 的表现是「双击没反应」，用户很难自己诊断。

**A2 系统依赖。** macOS 要 Xcode Command Line Tools（`xcode-select --install`，编译 Rust 与
bundler 都要）。Linux 要 `libwebkit2gtk-4.1-dev`、`libgtk-3-dev`、
`libayatana-appindicator3-dev`、`librsvg2-dev`、`build-essential`、`pkg-config`，
运行时还要 `fonts-noto-cjk`（否则中文全是豆腐块）。
⚠️ WebKitGTK 4.0 与 4.1 是两个 ABI，Tauri 2 只认 **4.1**，所以最低发行版是
Ubuntu 22.04 / Debian 12 —— 这一点必须写进文档，否则用户会在 20.04 上撞墙。

**A3 macOS 双击打开文件不通（最容易漏的一条）。** 现在打开文件的入口是命令行 `argv`。
Windows 和 Linux 都靠「把路径塞进命令行」，macOS **不是**：从 Finder 双击 → 系统发
**Apple Event**，`argv` 里没有路径；应用已在运行时 → 事件发给**已有进程**，根本不会启动
第二个进程，所以 `single-instance` 的回调也不会被调用。Tauri 把这件事包成
`RunEvent::Opened { urls }`，而且只有 macOS/iOS/Android 才编译这个变体。
空回调等于把这个事件丢了。

```rust
app.run(|app_handle, event| {
    #[cfg(target_os = "macos")]
    if let tauri::RunEvent::Opened { urls } = event {
        let files: Vec<String> = urls.iter()
            .filter_map(|u| u.to_file_path().ok())
            .map(|p| p.to_string_lossy().to_string())
            .collect();
        if files.is_empty() { return; }
        if let Some(w) = app_handle.get_webview_window("main") {
            let _ = w.unminimize();
            let _ = w.show();
            let _ = w.set_focus();
        }
        let _ = app_handle.emit("open-files", files);
    }
});
```

三个注意点：① 事件可能带**目录**，`emit` 前用 `Path::is_file()` 过一下；② 冷启动时
`Opened` 可能**早于**前端监听器就绪 —— 稳妥做法是同时存进 Rust 状态
（`Mutex<Option<Vec<String>>>` + `take_opened_files` 命令，照 `CompareRequest` 的做法），
前端初始化时先 take 一次再开始监听，**否则第一批文件会丢**；③ `--compare 左 右` 在 mac 上
写成 `open -a EZNotepad --args --compare a.md b.md`，`argv` 里能拿到，不受影响。

**A4 通用二进制。** `build:mac: tauri build --target universal-apple-darwin` 要求两个
target 都装好（`rustup target add aarch64-apple-darwin x86_64-apple-darwin`）。
只想出一个架构时（绝大多数用户是 Apple Silicon）只跑 `aarch64`，体积减半、构建快一倍。

#### B 级：会丢数据

**B1 删除文件在非 Windows 上是永久删除。** 界面上这个动作叫「删除（进回收站）」，
用户以为能捞回来。**这一条不改，移植版第一天就会被投诉。**
换成跨平台的 `trash` crate（Windows 走回收站 API、macOS 走 `NSFileManager.trashItemAtURL`、
Linux 走 freedesktop trash 规范），并删掉 `#[cfg(windows)]` 的 `delete_file_impl`
与 `windows-sys` 的 Shell feature：

```rust
#[tauri::command]
fn delete_entry(path: String) -> Result<(), AppError> {
    let p = PathBuf::from(&path);
    if !p.exists() { return Err(AppError::new("entry.missing")); }
    // 目录只删空的：递归删除风险太大
    if p.is_dir() {
        return fs::remove_dir(&p).map_err(|e| AppError::detail("dir.not_empty", e));
    }
    trash::delete(&p).map_err(|_| AppError::new("recycle.failed"))
}
```

⚠️ 错误码 `recycle.failed` 原来带 `rc` 变量，改完是固定文案，要同步改文案模板
（`run-i18n.mjs` 会把漏改的地方报出来）。
⚠️ Linux 的 trash 规范要求文件与回收站同挂载点，跨盘会退化成 copy+delete——不用特殊处理，
但要知道大文件删除会变慢。

**B2 编码回退一律当 GB18030。** Windows 中文环境下这个假设是对的（系统 ANSI 就是 GBK 系）。
到 mac / Linux 上，一个非法 UTF-8 的文件更可能是 Latin-1、Shift-JIS 或二进制误判，
用 GB18030 硬解会得到「看起来像中文的乱码」，用户会误存成 UTF-8 —— **原文件就毁了**。

两条路：① 用 `chardetng`（与 `encoding_rs` 同作者）做候选打分；
② **更省事的做法**：只把 GB18030 当成 Windows 的选项，其它平台回退到 `windows-1252`
（Latin-1 超集，永不失败、不会解出假中文），并在状态栏明确显示当前编码，
让用户自己用「以…编码重新打开」纠正。项目已有编码显示与重载能力，成本更低。

#### C 级：功能残缺

**C1 导出 PDF（已在本平台解决，移植时重做）。** Windows 上走
`ICoreWebView2_7::PrintToPdf`（见 §8.2），不需要用户交互、不需要打印面板。

移植时必须注意：**嵌入式 WebView 里 `window.print()` 一律不可依赖**。
Windows 上是空实现（不弹框、不报错、不 reject），macOS 的 WKWebView 也没有实现，
Linux 的 WebKitGTK 有实现但分页表现与 Chromium 不同。所以「新窗口 + `print()`
+ 让用户自己存 PDF」这条路三个平台都别走。

| 方案 | 做法 | 代价 |
|---|---|---|
| ① 原生落盘 | mac 用 `WKWebView.createPDF(configuration:completionHandler:)`（macOS 11+），Linux 用 WebKitGTK 的 `webkit_print_operation_*` | 中；每个平台一个 `#[cfg]` 分支，但用户体验与 Windows 一致 |
| ② 降级 | 该平台把「导出 PDF」改成「导出 HTML」+ 默认浏览器打开，让用户自己 ⌘P | 最小，但菜单项名不副实 |
| ③ 自带渲染 | 引入 PDF 生成库或 headless Chromium | 大，违背「5MB」原则 |

建议 ①：`pdf.js` 里已经有 `exportPdfTo(path, tab)` 这个与 UI 无关的入口，
平台差异只落在 `backend.exportPdf()` 后面那条命令上，前端一行都不用改。
⛔ **不要**用「命令返回成功但文件没生成」来假装支持 —— 非 Windows 现在直接回
`pdf.unsupported`，宁可说「这个平台还不支持」，也不给一个空文件。

**C2 拖文件进窗口（已解决，只需回归验证）。** 两个开关是连在一起的：
`dragDropEnabled: true` 时 `onDragDropEvent` 拿到的是**真实磁盘路径**；`false` 时处理器
不注册，文件落到页面上是普通 HTML5 `drop`，`dataTransfer.files` **有字节、没有路径**。
现在走原生通道（`app.js` 的 `setupDrop`）：图片复制进 `assets/` 并保留原名、其它文件开标签、
`enter`/`leave` 驱动 `.drop-hint`（这条通道下页面收不到 `dragover`）。
代价是 `AllowExternalDrop(false)` 是全局的，从别的程序往编辑区拖选中文字也会失效
（只能 Ctrl+C/V）。移植时保持 `true` 即可，三平台同一条通路。

**C3 无边框窗口。** `decorations: false` + 自绘标题栏是 Windows 的做法。

| 平台 | 问题 | 建议 |
|---|---|---|
| macOS | 交通灯在左上角、由系统画，自绘按钮在右上角 → 两边各一套 | `decorations: true` + `titleBarStyle: "Overlay"` + `hiddenTitle: true`，系统交通灯浮在自绘标题栏上；前端按平台隐藏 `.win-ctrl`，标题栏左侧留 ~78px |
| Linux | 多数 WM 下无边框窗口**不能拖边缩放** | 加 8px 边角热区，`mousedown` 时调 `startResizeDragging('East'...)`；补权限 `core:window:allow-start-resize-dragging` |

⚠️ `titleBarStyle: Overlay` **要求 `decorations: true`**：不能既 `decorations:false`
又要系统交通灯，只能二选一。选 Overlay 的代价（其实是好事）是圆角与阴影交回系统。

**C4 macOS 会出现两套菜单。** Tauri 2 在 `menu` 为空且 `enable_macos_default_menu` 为
true（默认）时，会自动建一套系统菜单，而本应用又自绘了一份画在窗口里 → mac 用户同时看到
两套。推荐收敛方式：mac 上改用系统菜单承接全部命令，窗口里那行只留「品牌 + 标题 + 交通灯」
（`body[data-os="mac"] .menubar { display: none }`），并用 Tauri 的 `Menu` API 建一套带
`accelerator` 的原生菜单 —— 这样 ⌘ 快捷键也能显示在系统菜单里。省事的方式是
`enable_macos_default_menu(false)` 只留自绘，代价是 ⌘Q / ⌘H / ⌘M 没有菜单归属
（仍可用，但不符合 macOS 习惯）。Linux 没有系统菜单栏，自绘就是对的。

**C5 快捷键显示是 `Ctrl`，行为却是 `⌘`。** 匹配逻辑已经兼容（`ctrlKey || metaKey` 折成
`mod`），所以 mac 上按 ⌘S 能存盘；坏消息是**显示文案全是硬编码 `Ctrl`**，约 130 处
（`app.js` 69、`welcome.js` 32、`i18n-dict-src.js` 15、其余模块 6、两个 html 8）。

改法（一次到位，别逐处 if）：数据层统一写 `mod+shift+s` 这种平台无关形式，
再加**唯一一个**认识平台的渲染函数：

```js
const IS_MAC = navigator.userAgent.includes('Mac');
export const kbdLabel = (combo) => String(combo).split('+').map((p) => {
  if (p === 'mod')   return IS_MAC ? '⌘' : 'Ctrl';
  if (p === 'alt')   return IS_MAC ? '⌥' : 'Alt';
  if (p === 'shift') return IS_MAC ? '⇧' : 'Shift';
  return p.length === 1 ? p.toUpperCase() : p;
}).join(IS_MAC ? '' : '+');   // mac 上不写加号：⌘S
```

i18n 词条里的 `Ctrl+…` 改成 `{kbd}` 占位符 + 运行时填，否则九种语言各写一遍平台相关文案。
这一项改动面不小，可以分两步：先让代码层（菜单、提示）正确，欢迎文档与词条留后面。

**C6 POSIX 绝对路径被当成相对路径。** `resolveDocImg` 的判据是
`/^[a-z]:[\\/]/i.test(src) || src.startsWith('//')`，于是 `/Users/me/notes/a.png` 既不匹配
盘符也不以 `//` 开头，被拼成 `/Users/me/notes//Users/me/notes/a.png`。改成：

```js
const isAbs = (s) => /^[a-z]:[\\/]/i.test(s) || s.startsWith('/')
                  || s.startsWith('\\\\') || s.startsWith('//');
```

其余同类写法（`app.js`、`backend.js`、`filetree.js`、`foldercmp.js`、`exporthtml.js`）
已经是 `[\\/]` 兼容的，不用改。

#### D 级：体验打磨

| # | 项 | 建议 |
|---|---|---|
| D1 | 圆角 | mac 本身圆角；Linux 无（可接受）。⛔ 不要为了 Linux 去开 `transparent`，会牺牲性能与阴影 |
| D2 | 铺满工作区 | mac/Linux 已回落 `maximize()`；**先实测它在无边框 mac 窗口上是否生效**，不生效就用跨平台的 `currentMonitor()` 按 `workArea` 算 `setFrame`，比 Win32 干净 |

### 10.5 平台差异（必须显式承认的）

| 项 | Windows | macOS | Linux | 处理 |
|---|---|---|---|---|
| 主修饰键 | Ctrl | ⌘（⌥⇧ 同族） | Ctrl | 用户可见的提示要跟着换（`Ctrl+S` → `⌘S`）；存储仍用 `mod` 抽象 |
| 窗口按钮 | 右上（自绘） | 左上交通灯（系统画） | 右上（自绘） | ⛔ 不要为「像素一致」把按钮画到右上，违反平台习惯 |
| 标题栏高度 | 34（自绘） | 系统 28（含交通灯） | 34（自绘） | L3 视觉**允许不同**；正文起始位置按实际可用区算 |
| 菜单栏 | 窗口内自绘 | 屏幕顶部系统菜单 | 窗口内自绘 | 原生版必须用系统菜单；§9.3 的顺序作为**结构**照搬 |
| 无边框缩放 | `WS_THICKFRAME`，系统处理 | `NSWindow` 边缘处理 | 常失效，需 `startResizeDragging` | |
| 圆角 | Win11 DWM；Win10 直角 | 系统 | 无 | |
| 删除到回收站 | 回收站 API | `NSFileManager.trashItem` | freedesktop trash 规范 | 见 §10.4 B1 |
| 双击打开文件 | `argv` | Apple Event → `RunEvent::Opened` | `argv` | 见 §10.4 A3 |
| 文件监听 | ReadDirectoryChangesW | FSEvents | inotify | 语义按「一层目录 + 文件名过滤」，延迟自己调 |
| 行尾习惯 | CRLF 常见 | LF 常见 | LF 常见 | 归一策略不变（§3.7），写回按原文件 |
| 默认编码 | GBK 常见 | UTF-8 常见 | UTF-8 常见 | 探测顺序不变，仍是「BOM → 严格 UTF-8 → GB18030」 |
| 默认字体 | Segoe UI / 微软雅黑 | SF / PingFang SC | Noto Sans CJK（需装） | 字体度量不同 → 行高与 ±1 行误差要重验 |
| 导出 PDF | WebView2 `PrintToPdf` | `WKWebView.createPDF` | WebKitGTK 打印操作 | 纸型/边距一律由 CSS `@page` 给，不读系统设置 |
| 应用数据目录 | `%APPDATA%\<id>` | `~/Library/Application Support/<id>` | `~/.local/share/<id>` | 目录布局照 §3.1 |
| 安装包 | nsis / 便携 zip | dmg / app | deb / AppImage（rpm 另配） | |
| 代码签名 | 可选（SmartScreen） | 必需（否则打不开） | 无 | |
| 沙箱 | 无（传统桌面） | App Sandbox（若要上架） | 无 | 见下 |

⚠️ **最后一行是最大的隐藏成本**：App Store 沙箱下，用户通过「打开」授权的文件在重启后
需要 security-scoped bookmark 才能再访问；而历史快照按「绝对路径哈希」建的目录，
在沙箱里会随 bookmark 变化。**如果目标是上架，历史功能要重新设计存储键。**

### 10.6 移植后必须重测的指标

性能数字**不能直接沿用**，三个内核的特征差得多：

| 指标 | 为什么必须在目标平台重测 |
|---|---|
| 单次击键延迟（600 段） | WebKitGTK 的 DOM 操作比 WebView2 慢，可能要重调视口窗口大小（`MAX_WIN = 600`） |
| 10MB 文档视口渲染 | WKWebView 的滚动事件节流策略不同，`_windowAt` 的补偿量要重新校 |
| 常驻内存 | 三个 WebView 的基线差 50～200MB |
| 冷启动 | mac 首次启动要过 Gatekeeper 校验，明显更慢（只在首次） |
| 字体度量 | `PingFang SC` 与 `Noto Sans CJK` 的行高不同 → 正文区高度、大纲定位的 ±1 行误差都要重验 |

对应地，`test/` 里的截图基线要按平台分开存（现在只有一套 Windows 基线）。

**测试工具链一半能直接跑，一半要重写**：

| 套件 | 组成 | 可移植性 | 移植时要做什么 |
|---|---|---|---|
| 离线行为套件 | `run.mjs`、`run-units`、`run-editor`、`run-menu`、`run-i18n`、`run-filetree` | **高**：静态服务 + headless Chrome + CDP，纯 Node | 三处小改，见下 |
| 真机套件 | `test/real/*.ps1`（UIA + SendInput + PrintWindow）、`gen-*.mjs` | **零**：Windows API 专用 | mac 用 AppleScript / `cliclick` / `screencapture`；Linux 用 `xdotool` / `import`；或整体改用 `@playwright/test` |

离线套件的三处改动：① `harness.mjs` 的 `CHROME_CANDIDATES` 已含 mac/linux 路径，
但 `killChromeWhere()` 在非 Windows 上直接 `return` → 上一轮残留的 Chrome 占着端口，
需要补 `pkill -f` 分支；② 以 root 跑 headless Chrome 要 `--no-sandbox`（容器 CI 常见）；
③ `test/real/` 里的坐标与窗口尺寸结论（那些 `-7, 0`）全是 Windows 实测值，
在 mac/Linux 上一条都不成立，必须重建。

建议把真机套件重构成两层，只重写「输入层」：

```
断言层：CDP（Runtime.evaluate 读状态 + Page.captureScreenshot）  ← 三平台通用
输入层：合成点击 / 按键 / 截图                                    ← 平台化，每平台约 100 行
```

这也是原项目最值钱的经验之一：**给每个复杂功能留一条绕过 UI 的直开通道**（`--compare 左 右`
就是），移植时它能让断言层完全不依赖窗口。

**CI 矩阵**。现在 `release.yml` 只有一个 `windows` job，扩成三个时注意：
`macos-latest`（arm64）要装两个 Rust target 并 `--target universal-apple-darwin`，
签名 + 公证需要 5 个 secrets（证书 p12、密码、App Store Connect 的 key/id/issuer）；
`linux` 必须 `runs-on: ubuntu-22.04`（才是 webkit2gtk-4.1），先 `apt-get install`
那五个 `-dev` 包加 `patchelf`。三条经验：① **发版仍以 tag 为唯一触发**，
版本号只从 `tauri.conf.json` 读，三个 job 复用同一个读取步骤；② 构建失败要用
`::error::` 注解把错误行吐出来（Actions 完整日志需要管理员令牌，注解不需要）；
③ 产物在三个 job 里各自 `upload-artifact`，Release 汇总单独一个 job，
否则某个平台失败会连累其它平台已经构建好的产物。

| 层 | 手段 |
|---|---|
| L1 数据 | 跑附录 A 的 24 条往返向量；两边互开同一份 `settings` / `session` 文件 |

### 10.9 哪些**不必**一致

以下差异是平台特性，追求一致反而是错的：

- 窗口装饰、交通灯位置、阴影与圆角半径（系统统一）
- 滚动条样式与滚动惯性
- 字体渲染（字形微调、抗锯齿）
- 菜单栏位置与系统级菜单项（服务、隐藏、退出）
- 系统文件对话框（打开/另存为）的样式与按钮顺序
- 快捷键前缀（⌘ vs Ctrl）与系统保留键

**另外两条「第一次会改写」的规范化，验收时别当成 bug**：

- **首块的缩进被归零**：层级是相对**第一次见到的缩进列**算的。文档第一块就是 `  - x` 时，
  缩进列栈里只有它一个，层级为 0，序列化后变成 `- x`。这是「按列建栈」的必然结果，
  好处是用户从别处拷来一段带 4 空格缩进的列表也能读对，代价是首块的绝对缩进不保留。
- **斜体统一成下划线**：`*文字*` 解析成斜体，序列化写出 `_文字_`。
  粗体一律写 `**`（`__文字__` 也变 `**文字**`）。

**关于第 6 条（重要，也是已知设计债）**：编辑器是「一行一块」，所以紧邻的两行正文
在第一次保存时会变成两段（中间加空行）。对「用空行分段」的文档没有影响，
但**硬折行的长段落**（每 80 列换行）会被改成每行一段。

要避免有两条路，都值得写进设计决策：

1. 解析时把连续非空行合成**一个块**，块内用 `<br>`/软换行表示行 —— 但这样光标在块内
   要跨行，且「回车 = 新块」与「文本里的换行」要怎么区分需要额外规则。
2. 保持现在的行为，但在首次保存前提示「这次保存会把硬折行段落展开成多段」。

现有实现选的是「保持行为 + 不做提示」，因为目标用户写的是**短段落**的 Markdown。
移植时如果目标用户群不同，这条要重新决定。

| 11 | 2000 行随机 vs 2000 行随机 | 同左 | **不许出现 `same` 且有一侧无行号** |
| 12 | 4M+ 单元格的两次大改 | 同左 | 走锚点，结果中 `add`+`del` 覆盖全部改动，无空白整页 |

第 11/12 条是回归重点：历史上就是这两类输入暴露了「假 same」的兜底 bug。

## 附录 C · 出错时的定位顺序

用户报「文件坏了」时，按这个顺序查，**不要凭直觉改代码**：

1. **先看是不是「打开就变脏」**：比对磁盘字节与内存文本的行尾、BOM、结尾换行。
2. **再看是不是「保存后多了空行」**：检查块间空行的组装（§4.5.2 的三条）。
3. **再看是不是「某类块消失了」**：多半是粘贴/换块走了错误的宿主分支（§5.8）。
4. **再看是不是「撤销回到很早以前」**：撤销合并窗口与字节上限（§2.6）。
5. **最后才怀疑解析器**：附录 A 的 24 条向量跑一遍，能定位到具体规则。

⚠️ 改任何一条规则之前，先跑附录 A + B；改完再跑一遍。
这两份向量是这套实现唯一能防止「修一个坏两个」的东西。
