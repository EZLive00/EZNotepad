# EZNotepad · 功能设计

> 读者：要改功能行为的人、要判断「这个需求该不该做」的人、接手后想知道「为什么是这样」的人。
>
> 四份文档的分工——**本文写业务规则**：每个功能对用户承诺什么、边界在哪、为什么不选另一种做法。
> 《架构设计.md》写结构与不变量（怎么做才不塌），《跨平台移植.md》写换系统的代价，
> 《构建说明.md》写环境与打包，《开发经验.md》写踩过的坑与排查手法。本文不重复代码结构，
> 只在与规则直接相关时引用【不变量 N】。

## 0. 这份文档怎么读

全文按**用户能感知的功能**分章，不按代码模块。每章尽量回答四个问题：

| 记号 | 含义 |
|---|---|
| **规则** | 必须成立的行为。改它之前先想清楚会破坏谁的预期 |
| **为什么** | 这个选择换来了什么、放弃了什么。没有理由的规则通常会被人「顺手优化」掉 |
| **边界** | 明确不处理的输入、上限、失败时的表现 |
| **文案** | 用户实际看到的字。按钮、提示、空状态都算 |

三个符号贯穿全文：

- ✅ 已承诺的行为，测试里有断言守着；
- ⛔ 明确不做，不是没来得及；
- ⚠️ 已知设计债，写在这里是为了不让人以为是 bug。

**一条总原则**：所有「说不通」的地方，优先改成用户不用想就能用的行为，而不是写一句提示让
用户去适应。提示只在**无法避免**时出现（比如格式限制、数据可能丢失），而且必须说清
「发生了什么、会有什么后果、下一步点哪儿」。

## 1. 产品定位与取舍

### 1.1 一句话

一个**不登录、不联网、打开就能写**的 Markdown / 纯文本编辑器，自带一套够用的文本与文件夹
对比工具。装完 2.6 MB，冷启动约 0.6 秒，常驻内存约 170 MB（其中一半是系统 WebView 的
GPU 进程）。

### 1.2 用户与场景

| 场景 | 具体动作 | 设计上的后果 |
|---|---|---|
| 写笔记 / 文档 | 新建 md、边写边看、插图、公式、目录 | 所见即所得必须是默认模式，且不能有「预览延迟」 |
| 改配置 / 看代码片段 | 打开 json / yaml / sh、看高亮、改两行 | 非 md 文件不该进所见即所得，编辑模式要有行号与缩进 |
| 比对两份东西 | 两份文本、两个目录、三份版本合并 | 对比要独立窗口（主窗口塞不下两栏），且能直接改 |

这三件事的频率远高于「管理一个知识库」。所以产品里没有工作区、没有数据库、没有索引、
没有后台进程 —— 打开一个文件就是打开一个文件。

### 1.3 需求筛子

任何新功能先过三问（写在《架构设计》§1，这里是执行口径）：

1. **每天都会用到吗？** 一年用两次的功能，占的是菜单位置和别人的注意力。
2. **能不联网、不登录做完吗？** 需要账号的功能一律不做 —— 它会把「打开就能写」变成
   「先验证邮箱」。
3. **会让「打开一个 md」变慢，或让安装包明显变大吗？** 这条是硬约束。

第 3 问有具体数字，不是感觉：主程序 ≤ 8 MB、安装包 ≤ 5 MB、冷启动 < 1 秒、
常驻 < 250 MB、600 段文档单次击键 < 12 ms。**任何一个功能把其中一项顶破，就要重新谈**，
而不是「先加上，以后再优化」。

### 1.4 明确不做

| 不做 | 原因 | 如果用户要 |
|---|---|---|
| Mermaid 图表 | 完整包 2.75 MB，是当时 exe 的 63%；裁成 core 也只是一堆带 hash 的分块，vendor 化后升级困难 | 用「代码块 + 外部截图」表达 |
| 图床 / 账号 / 云同步 | 违反第 2 问；同步冲突的复杂度远超这个产品的价值 | 用网盘同步文件夹 |
| 插件市场 | 插件 API 会把「零依赖、可复现」的架构变成平台工程 | — |
| 多窗口拆分编辑 | 单窗口 + 标签已经够；多窗口要处理布局持久化、焦点、快捷键归属 | 拖到第二个显示器开两个实例（单实例插件会拦住，属已知取舍） |
| 二进制对比 | 十六进制视图是另一个产品 | 用专门工具 |
| 跨文件批量替换 | 一次误点改几十个文件，撤销要按文件翻历史；真实需求极低 | 单文件内 `Ctrl+H`；确实要批量时用命令行 |
| 四栏可视化合并 | 交互复杂度高，维护成本与使用频率失衡 | 三向合并向导 + 两栏对比组合使用 |
| 表格的可视化网格编辑（像 Excel） | 见 §5.11：单元格已经能直接编辑，再加一层网格是重复投入 | 直接改单元格 |
| 孤儿图片清理 | 同目录多篇文档共用一个 `assets/`，判「没人引用」得先扫全目录，误删风险高 | — |
| 视口模式下的「模型级跨窗选区」 | 10 MB 文档里跨十万块拖选，选区落点与自动滚动都要重做；收益不足以支撑 | 分块复制，或用编辑模式全选 |
| CodeMirror 惰性加载 | 能省首屏 49 ms，但 `plain` 有 30 处同步调用，异步就绪会让首次读取拿到空内容 | 接受这 49 ms |
| 后台窗口降频 | Chromium 自己会节流；再叠一层要改动草稿保护与文件监听的边界 | — |

**不做的功能也要能被搜索到**：README 的「已知限制」列出它们，避免每次有人重新提议、
重新评估、重新否掉。

### 1.5 改过的决定（留档，防止走回头路）

| 曾经 | 现在 | 为什么改 |
|---|---|---|
| 三层底色（画布 / 面板 / 浅坑）区分区域 | **同色平面 + 1px 线** | 三层底色在深色下要差 12 级才看得出来；差不够就糊成一块，差够了又像补丁 |
| 激活标签底部伸一块「引脚」把边线顶断 | 无引脚，整条线连续 | 全域同色后，引脚本来是「连接标签与正文」的隐喻，底色一样时它只剩一个缺口 |
| 块尾插入指示线在「点在最后一块下方」时总亮 | 只在该块真的会补一行时亮 | 指示线的全部意义是预告「点这里会多一行」；行为收窄了它还亮，就是骗人 |
| 文本对比是主窗口里的浮层 | 独立窗口 | 两栏各需 600 px 起，浮层里永远不够宽；独立窗口还能有自己的最大化 |
| 对比窗口默认只读 | 默认直接可写 | 默认只读的代价是「点一下正文没反应」，用户会以为窗口坏了；误改有三层兜底（行脏标记 / 撤销 / 关窗确认） |
| 退出三选里有「存为草稿并退出」 | 去掉，只留「全部保存并退出 / 不保存退出 / 取消」 | 与「全部保存」语义重叠且低频；未命名文档仍由草稿兜底接住 |
| 「速记」是一级下拉，第一项叫「打开速记」 | 一级**动作**，点一次直接打开 | 用户的第一反应是「我已经点了速记」，不该再点第二次 |
| 设置塞在「工具」最后一项 | 顶级「设置」 | 工具是「处理文本」，设置是「配置软件」，两类东西不该共用一个菜单 |
| 格式化快捷键 `Ctrl+Shift+F` | `Ctrl+Alt+L` | 撞 Windows 繁简切换，`preventDefault()` 拦不住系统级热键 |
| 侧栏顶部有齿轮图标 | 删掉 | 它紧贴「大纲 / 文件」页签，看起来像「这一栏的设置」 |

## 2. 界面骨架与信息层级

### 2.1 五块

```
┌──────────────────────────────────────────────────────────────┐
│ 标题栏 34px  品牌 · 菜单栏 · 窗口按钮（拖动区）                 │
├──────────────────────────────────────────────────────────────┤
│ 标签行 33px  标签 … ＋ …………… 模式 / 查找 / 保存（右）        │  合计 68px
├────────────┬─────────────────────────────────┬───────────────┤
│ 侧栏        │ 编辑区（单栏或左半）             │ 预览（双栏时） │
│ 大纲 / 文件 │                                 │               │
├────────────┴─────────────────────────────────┴───────────────┤
│ 状态栏 27px  行列 · 行数 · 字数 · 类型 · 换行符 · 编码 · 草稿   │
└──────────────────────────────────────────────────────────────┘
```

**顶部只占 68px**（34 + 33 + 1 底边线）。这不是审美问题：笔记本 768 高的屏上，
每 10px 都是正文。曾经是「标题栏 40 + 标签栏 32 + 工具栏 35 = 107」，一次把工具栏并进
标签行、一次把标题栏压到 34，才有了现在的数字。

### 2.2 快捷按钮只留三个

标签行右侧只有**模式切换、查找、保存**。其余命令全在菜单里，理由有两条：

1. 同一命令摆两处，两处都要维护图标、禁用态、勾选态；
2. 菜单能表达「当前是什么」——「大纲开着」「主题是深色」「当前是双栏」，工具栏按钮
   只能表达「点我会怎样」。

**保存按钮兼作脏标记**：有未保存改动时整颗按钮淡蓝高亮。曾经在右上角做小圆点，实测会压在
「存」字上，弃用。

### 2.3 标签

| 规则 | 细节 |
|---|---|
| 宽度 | 单颗最大 133px，文件名最长 100px 后省略号 |
| 激活态 | 字重 600 + 全亮文字；**同一串文字的加粗版用 `::before` 占位**，否则中文一加粗就变宽，切换标签时整行标签左右抖 |
| 边框 | 每颗只有左右竖线，上下借用标签行的两条线；相邻标签 `margin-left:-1px` 共用一条，**不许用「左边框 + 最后一颗补右边框」的取巧写法**（有标签隐藏/重排就得重算） |
| 首末颗 | 最外侧那两条竖线置透明（不是宽度 0，否则差 1px 位移） |
| 激活层级 | `z-index:1`，否则共享的那条竖线会被右邻的浅色边盖掉一半 |
| 关闭 | 悬停出现 ×；中键直接关；`Ctrl+W` 关当前 |
| 拖拽换位 | 拖到标签左右半区决定插前/插后，落点画 2px 竖线 |
| 未保存 | 名字前一颗 7px 蓝点 |
| 被外部改过 | 名字后一颗 5px 琥珀点，与蓝点分开（见 §3.7） |
| 溢出 | 见 §2.4 |

**为什么不用「激活标签加底色块」**：全域同色之后，底色块要么和背景差不够（看不见），
要么差太多（像补丁）。字重 + 全亮 + 竖线断开已经足够表达「我在哪」，而且切换时不会闪。

### 2.4 标签溢出（十几个标签之后）

标签条能横滚，但滚动条被藏起来了（一条横向滚动条会把标签挤扁）。于是「后面还有标签」
既看不出来，也没有可抓的东西。三个入口都补齐：

| 入口 | 规则 |
|---|---|
| 滚轮 | `deltaY` 当横向位移；`deltaMode === 1`（按行）要 ×16，否则一格只动 3px |
| 拖标签贴边 | 指针距左右边缘越近滚得越快；**必须用 `requestAnimationFrame` 自循环**，指针不动就不会有第二个 `dragover`，靠事件驱动会停在半路 |
| 「全部标签」下拉 | 右侧按钮只在真的溢出时出现；清单带滚动条，当前项 ✓、脏项 ● |

**当前标签必须自动滚进视野**：新建的排在最后，不滚过去，界面上就是「点了新建没反应」。
判定用 rAF 合并，`renderTabs` 与 `resize` 各调一次。

### 2.5 状态栏

`行列 · 行数 · 字数 · 类型徽章 · [右] 换行符 · 编码 · 草稿状态`

- 字数统计口径：中日韩单字各算 1，ASCII 连续段算 1；行数 = 换行数 + 1。**单趟扫描**，
  10 MB 文档 39 ms（旧实现 `split('\n')` + 两次全局正则要 125 ms）。
- 类型徽章跟着当前标签变，不再是「打开第一个文件时算出来的那个」。
- 编码与换行符是**按钮**：点一下就能改，不用去菜单里找。
- 草稿状态只在有未落账编辑时显示「草稿同步中」，落盘后回到「草稿已同步」。

### 2.6 菜单栏

**顺序：文件 / 编辑 / 格式 / 插入 / 视图 / 工具 / 设置 / 帮助 / 速记 / 对比。**

排序依据是频率与性质，不是字母：

| 位置 | 内容 | 为什么在这儿 |
|---|---|---|
| 前 6 项 | 文件 / 编辑 / 格式 / 插入 / 视图 / 工具 | 编辑器惯例顺序，肌肉记忆 |
| 设置 | 单独一级、点一下直接开面板 | 它不属于「处理文本」 |
| 帮助 | 快捷键一览 / 关于 | 惯例放最后 |
| 速记 | **动作项**，点一次直接打开 | 高频；不套「打开速记」 |
| 对比 | 文本 / 文件夹 / 三向合并 | 高频；固定最右，伸手就到 |

两条硬规则：

1. **一级菜单只有两种形态：下拉，或动作。** 动作项点一次就执行，不能先展开再让人点第二下。
   键盘左右键要**跳过**动作项，否则光标会停在「没有面板」的项上，看着像卡死。
2. **同一个命令不在两处各列一遍。** 所以「工具」里不再有文本 / 文件夹 / 三向合并；
   命令面板仍然全部收得到，它是从菜单树现抽的。

菜单内部的表达手段：

| 手段 | 用途 | 例子 |
|---|---|---|
| 分组小标题 `head` | 一条线只说明「断了」，文字才说明「这是哪一组」 | 标题级别 / 文字 / 段落 |
| 一行多个 `row` | 互斥的单选题横排，当前项点亮 | 正文 / H1 / H2 / H3 |
| 按上下文隐藏 `hidden` | 不是变灰，是根本不渲染 | 不在表格里就不显示表格操作 |
| 说明行 `note` | 一句话解释「为什么这项是灰的 / 去哪儿找」 | 「标题与列表只在所见即所得模式下可用」 |
| 勾选 `checked` | 表达当前状态 | 大纲开着、主题是深色、双栏 |

**勾和图标共用一个 18px 槽**：有勾显示勾，没勾显示图标。否则带图标和带勾的两行，
文字左边缘会差一格，整列看起来是歪的。

### 2.7 右键菜单

右键菜单和主菜单共用一套渲染器，规则一致，另加：

- **定位必须量真实尺寸**：先以 `visibility:hidden` 挂上去，读 `offsetWidth/offsetHeight`，
  再四边夹取。早期按「项数 × 30」估高度，23 项的表格菜单估成 710px，窗口矮于 730 时
  `top` 被算成负数，菜单上半截永远在屏幕外——用户看到的是「靠上右键弹不出来」。
- 比窗口还高时给 `max-height` + 纵向滚动，不硬塞。
- **药丸**可以带 `checked`（点亮当前值）、`iconOnly`、`hint`（`title` 用完整说法，
  比如「本列取消对齐」）；`danger` 可以标在整行（`{lead:'删除', danger:true, row:[…]}`）。
- **关闭时机只有五种**：点别处（`document` mousedown 捕获）、Esc（捕获并阻止冒泡，
  防止同时触发「退出专注模式」这类全局 Esc）、滚动（捕获）、`resize`、`blur`。
  **鼠标移动永远不该关它**——曾经块菜单一挪鼠标就消失，根因是「菜单和按钮之间那 4px 缝」
  落在编辑区里，一次 `mousemove` 就把菜单收了。
- **锚在固定控件上的菜单要传 `stayOnScroll`**（标签条、工具栏）。滚动事件是排队派发的，
  「刚滚过标签条就点全部标签」会被迟到的 `scroll` 收掉，症状是「点了没反应」。

### 2.8 对话框与设置面板

- 通用对话框：标题 + 正文 + 按钮（主按钮一个，其余为次要 / 危险）。
- **设置面板没有「确定」**：所有改动即时生效，底部只有「完成」。省掉「改完忘了点确定」
  这一类挫败。
- 设置分四页：**外观 / 界面 / 文件 / 快捷键**，左侧分类、右侧内容，宽 760px。
  切页只切显隐，所有控件留在原处，不会因为切页丢焦点。
- Esc 关闭；点遮罩关闭（正在输入的重命名框除外）。
- **对话框内不要用 `document.getElementById` 找还没挂载的节点**：`box` 还没 append 到
  `#dlgBody` 时，全局查询拿不到，报 `Cannot set properties of null`；一律 `box.querySelector`。

### 2.9 空状态

空状态不是「没内容」，是「告诉用户下一步点哪儿」：

| 位置 | 文案 |
|---|---|
| 没有标签 | 自动建一份「未命名.md」（欢迎文档只在首次启动出现） |
| 侧栏文件页未选文件夹 | 「还没有打开文件夹」+「选择文件夹」按钮 |
| 大纲为空 | 按文件类型分别说明：md「用 # 写标题就会出现在这里」；txt「只识别章节标记，不会猜」；data「表格数据不提取大纲」 |
| 搜索无结果 | 「没有找到匹配的内容」+ 当前搜索范围 |
| 对比窗口未打开文件 | 两个空白编辑区 + 提示「把两段文本分别粘到左右两侧，或点上面的文件名打开文件」 |

**空状态里不放插画**。这个程序的用户是来干活的，一张大图只会让「正文从哪儿开始」更难判断。

## 3. 文件、标签与数据安全

这一章的所有规则都服务同一个目标：**用户的东西不能丢，也不能在用户不知道的时候被改。**

### 3.1 新建

- 入口：`Ctrl+N` / 文件 → 新建 / 标签行 `+`。
- 先弹**类型网格**（10 种：md / txt / json / csv / js / ts / py / html / css / sh），
  点一下直接开，回车开上次用过的类型（`settings.lastNewExt`）。
- 未命名文档自动编号：「未命名.md」「未命名 2.md」……连开三个不该都叫一个名字。
- 新建不写磁盘。第一次 `Ctrl+S` 才问路径。

**为什么先选类型**：新建一个 `.py` 却先得到 `未命名.md`、再让用户去另存为改扩展名，
是把自己的实现顺序（先有标签、后有类型）摊给用户看。

### 3.2 打开

| 入口 | 规则 |
|---|---|
| 对话框 | 过滤器覆盖 md / txt / 常见代码 / 数据文件；可多选，一次开多个标签 |
| 拖入 | 走 Tauri 原生拖放通道，拿得到**真实路径**；图片复制进 `assets/`，其它当文档打开；多选开多个 |
| 命令行 / 文件关联 | 双击文件或 `EZNotepad.exe a.md b.md`；已有实例时把路径交给它（单实例） |
| 最近打开 | 文件菜单里最多 6 条；localStorage 存 12 条，超出丢弃最旧 |
| 文件树 | 单击预览？不——单击即打开；多选后可「比较这两个文件」 |

**拖入必须是原生通道**（`dragDropEnabled: true`）。HTML5 `drop` 拿得到字节但**拿不到路径**，
而没有路径就没法「打开这个 md」。代价是从别的程序拖一段选中文字进来也会失效
（wry 会关掉外部拖放），这个取舍是明知且接受的。

### 3.3 类型与模式矩阵

| 类型 | 可用模式 | 默认 |
|---|---|---|
| Markdown（md / markdown） | 所见即所得 / 编辑 / 预览 | 所见即所得 |
| 其它一切（txt、json、csv、代码、日志…） | 编辑 / 预览 | 编辑 |

- 非 md 文件**不提供**所见即所得：它的结构不是 Markdown，硬套块模型只会改坏文件。
- 「预览」对非 md 不是「渲染成网页」，而是按类型分流：JSON 格式化 + 错误定位、
  代码语法高亮、CSV 按表格看、其余纯文本。
- 状态栏的类型徽章、预览分流、格式化策略、大纲提取策略，用的是同一套类型判定，
  不允许各写一份。

### 3.4 读盘：编码、BOM、换行、二进制

| 项 | 规则 |
|---|---|
| 编码探测 | UTF-8（含 BOM）→ 否则按 GB18030 尝试 → UTF-16LE/BE 按 BOM 认 |
| BOM | 读到就记住；保存时原样写回（不替用户「顺手去掉」） |
| 换行 | 读入后内存统一 `\n`，同时记住原文件是 LF 还是 CRLF，保存时还原 |
| 二进制 | 内容里出现 NUL 字节即判二进制，**拒读**并提示，不当文本硬解 |
| 新文件 | 默认 UTF-8 / 无 BOM / LF |

**内存统一 LF 是硬规则**：不统一的话，一个 CRLF 文件打开就「已修改」（DOM 里的 `\n` 与
磁盘的 `\r\n` 不等），用户按一次 `Ctrl+S` 会把整个文件的行尾翻一遍，diff 里全是噪音。

### 3.5 保存

- **原编码、原 BOM、原换行写回**：用户没要求转码，编辑器就不该转。
- 写盘用「临时文件 + 替换」的原子策略，避免写一半断电留下半个文件。
- 「另存为」之后，标签指向新路径。
- 外部生成的内容（对比结果、合并结果）没有原路径，保存时必须问路径，不能默默写到某个
  默认位置。
- 编码可以手动改（状态栏编码按钮 / 工具 → 文件编码）：UTF-8 / GBK / UTF-16LE 三选，
  另有「保存时写入 BOM」开关。改完提示「保存后生效」——它只影响下一次写盘，不立刻转码。

### 3.6 自动保存

| 项 | 规则 |
|---|---|
| 默认 | **开** |
| 生效范围 | 只对**已经有磁盘路径**的文件 |
| 时机 | 停手约 1.2 秒；连续输入会不断重置计时 |
| 提示 | 静默，不 toast、不闪状态 |
| 保存前 | 再比一次磁盘 `mtime`，被别人改过就先问（见 §3.7） |

未命名文档不自动保存：静默写盘会让文件管理器里凭空多出一堆 `未命名.md`。
它们走草稿（§3.8），退出时仍然有兜底。

### 3.7 外部改动

别的程序（或生成脚本）改了同一个文件，我们再保存就会把对方的改动默默抹掉 ——
这是记事本类软件最伤数据的一种 bug。

| 环节 | 规则 |
|---|---|
| 监听 | `notify` 只监听**文档所在目录的一层**（NonRecursive）；事件里拿文件名比对名单，不在名单里直接丢 |
| 事件过滤 | 只看 Modify / Create / Remove；`Access` 一律跳过（我们自己 stat/读文件也会产生） |
| 合并 | 前端 300 ms 合并一次变更，再等 250 ms 处理（Windows 上一次保存会拆成「截断 + 写 + 改属性」好几个事件） |
| 自激 | 保存成功后立刻同步 `t.mtime`，事件回来时时间相同即返回 |
| 内容未变 | 静默重载，不打扰 |
| 内容变了，且本标签没改 | 前台：提示「文件在磁盘上被修改，已重新载入」；后台：不弹窗，标签上冒琥珀点 |
| 内容变了，本标签也改了 | **必须问**：重新载入（丢本地改动）/ 保留我的（下次保存覆盖磁盘） |
| 保存前 | 无条件再比一次 `mtime`，包括自动保存 |

琥珀点和蓝点必须能分开看：蓝点是「我没存」，琥珀点是「别人改了」。两个都用蓝点，
用户会以为自己记错了。

### 3.8 会话恢复与草稿

两个不同的东西，别混：

- **会话**（`snp.session`）：上次开了哪些标签、各自什么模式、滚动到哪、光标在哪。
  只记路径，不记内容。
- **草稿**（`snp.drafts`）：所有**脏标签**的内容快照，用于「上次没保存就关了」的兜底。

规则：

| 项 | 规则 |
|---|---|
| 会话范围 | 全部标签（速记除外），按顺序重开，再回填模式/滚动/光标 |
| 草稿范围 | 只存脏标签；**干净标签不会清掉别人的草稿**（早期实现会 `LS.del('draft')`，一份干净标签就能抹掉所有未保存内容） |
| 容量 | 预算 4 MB，**从最新的脏标签往回分配**，最近改的一定保得住 |
| 恢复时判定 | 草稿与磁盘内容一致（都按 LF 比）→ 不算脏，不恢复；未命名文档必须**有字**才留 |
| 恢复交互 | 一个确认框，列出文件名与时间，二选一：全部恢复 / 丢弃 |
| 恢复后的脏状态 | 与**磁盘**比，不与草稿自己比；否则一恢复就是「已保存」，关窗也不再提醒 |
| 清空时机 | 恢复完立刻删草稿键，再写一次会话，避免下次重复询问 |
| 速记 | 不进会话、不进草稿、不进最近打开（见 §7） |

### 3.9 退出

关闭窗口有三条路：右上角 ×、Alt+F4、任务栏关闭。**三条都要拦**，所以守卫装在
`onCloseRequested`，不是装在按钮上。

有脏标签时三选：

| 选项 | 行为 |
|---|---|
| 全部保存并退出 | 逐个保存；有未命名文档就问路径；任何一个取消则中止退出 |
| 不保存退出 | 直接退，不写草稿，且用 `discardOnQuit` 标志挡住 `beforeunload` / `visibilitychange` 的草稿兜底（否则关窗瞬间又把草稿写回去，功能等于没做） |
| 取消 | 留在原地 |

**不再提供「存为草稿并退出」**：它和「全部保存」在用户心里是同一件事（都是「别丢」），
却要用户判断「我这次到底想不想留在磁盘上」。未命名文档本来就有草稿兜底。

### 3.10 文件树上的写操作

| 动作 | 规则 |
|---|---|
| 新建文件 / 文件夹 | 在当前目录下建；名字里的非法字符由后端拒绝并回错误码 |
| 重命名 | 就地输入；成功后**同步改掉所有打开着的、指向旧路径的标签** |
| 删除 | 进系统回收站（不是永久删除）；目录**只删空目录**；删之前确认，确认框里写清路径 |
| 删除后 | 关掉指向它的标签；如果标签有未保存改动，先问 |
| 刷新 | 监听事件驱动增量刷新，保留展开状态与滚动位置 |

### 3.11 最近打开

- 存 12 条，菜单只显示 6 条（超出的没有入口，纯属冗余）。
- 打开成功才记录；打开失败不写。
- 提供「清除最近记录」。
- 速记永远不进这个列表 —— 它是「随时能回去的地方」，不是「上次打开的文件」。

## 4. 视图模式与显示

### 4.1 三种模式

| 模式 | 快捷键 | 看见什么 | 数据形态 |
|---|---|---|---|
| 所见即所得 | `Ctrl+1` | 排版后的样子，直接改字 | 块 DOM ⇄ Markdown |
| 编辑模式 | `Ctrl+2` | 源码 + 行号 + 语法高亮 | 字符串 ⇄ 字符串（CodeMirror 6） |
| 预览模式 | `Ctrl+3` | 只读渲染结果 | Markdown → HTML |

- **默认**：md 进所见即所得，其余进编辑模式。
- `lastMode` **只记忆用户手动切换过的模式**。自动落位不写入 —— 早期把自动落位也存进去，
  导致「默认值」在第一次打开时就被粘滞成 `edit`，之后再改默认对老用户永远无效。
- 切标签、切文件后按类型回填上次模式；类型不支持该模式时回落到首个可用模式。
- 双栏（`Ctrl+Shift+L` 切换单/双栏）时，左边是当前编辑模式，右边固定是预览。

### 4.2 专注模式（F9）

- 隐藏：标签行、菜单栏、侧栏、状态栏。
- **保留标题栏**（无边框窗口没有标题栏就没法拖、没法关），但品牌与窗口按钮压到
  `opacity: .28`，悬停恢复。曾经设成 0，结果连关闭按钮都找不到。
- 正文宽度在用户设定值基础上再收 8%（`calc(var(--rw) * .92)`），长行更好读。
- `Esc` 退出。若查找条开着，先关查找条，再退专注 —— 一次 Esc 只做一件事。

### 4.3 行显示模式（soft wrap）

| 项 | 规则 |
|---|---|
| 开关 | `settings.wrap`，**默认换行** |
| 生效范围 | 编辑 / 预览 / 所见即所得 / 对比窗口，**一个开关管四处** |
| 入口 | 视图菜单（自动换行 / 不换行，互斥）、编辑区右键、所见即所得右键、预览右键、对比窗口工具栏 + 两栏右键 |
| 保存 | 进 localStorage，跨窗口共用 |

实现上的三条约束（用户看不见，但破坏任何一条都会丢数据或丢位置）：

1. **CSS 只写「不换行」这一侧**（`body[data-nowrap]`）。换行是浏览器默认行为，正面写
   `white-space: normal` 会和既有的 `pre-wrap` / `pre` 打架。
2. **CodeMirror 用 `Compartment` 热替换**，绝不重建 `EditorState` —— 重建等于把撤销历史
   和选区一起扔掉，用户只是改了显示方式，`Ctrl+Z` 却撤不回去。
3. **切换时保住视口顶部那一行**：先记 `rowAtY(scrollTop)`，重排后滚回 `rowTop(keep)`。
   在 2000 行文档的第 21 行上打开换行，屏幕跳到第 2 行，用户会以为文件被改了。

### 4.4 字号与正文宽度

| 项 | 规则 |
|---|---|
| 字号 | 默认 13.5px；`Ctrl+=` / `Ctrl+-` / `Ctrl+0`；设置面板显示当前 px |
| 正文宽度 | 默认 800px；范围 560–1600，步进 40；显示 px 不显示 rem（rem 要心算 16 倍） |
| 生效 | 宽窗口下正文居中收窄；窗口或分栏不够宽时自动退回两侧 54px 留白；专注模式再收 8% |

正文宽度用 `padding-left/right: max(54px, calc((100% - 宽)/2))` 居中，**不包一层
`max-width`**：包了以后滚动条会离开窗口右边缘，贴在正文框上，长文档横向找位置很别扭。

### 4.5 双栏

- 单栏（默认）/ 双栏，`Ctrl+Shift+L` 切换。
- 双栏 = 左编辑 + 右预览，中间可拖拽调宽。
- **预览侧不做视口化**：6.4 MB 文档双栏时预览会渲染约 220 万个节点，切布局/改宽度/换主题
  都会触发全树重排（实测 12.8 秒）。⚠️ 已知设计债，大文档建议单栏。

## 5. 所见即所得

这一章是整个产品的核心，也是最容易「看起来能用、实际处处别扭」的地方。所有规则围绕一句话：
**编辑器的行为要和人写纸稿时的直觉一致** —— 回车是换行、退格是往回删、方向键是往那个方向走。

### 5.1 模型：一行一块

| 规则 | 说明 |
|---|---|
| 一行 = 一个 `.w-block` | 块是最小编辑单元，块内不再有「段落」概念 |
| **空行不是块** | 空行是序列化概念，由块间分隔符表达；把空行建模成空块会污染结构（可被光标命中、可被退格合并） |
| 源文本是唯一真相 | DOM 只是 `t.content` 的投影；任何 DOM 改动都要落账（flush）成 Markdown |
| 块是只读记录 | 大文档下块记录视为只读，改动换新对象（撤销快照靠这一点零成本） |

**连续两个以上空行**才折算成 `n-1` 个空段落 —— 那才是用户真的按了两次回车想留空档。
文档开头的空行直接丢。

### 5.2 块类型总表

| 块 | Markdown 形态 | 可编辑位 | 特殊规则 |
|---|---|---|---|
| 段落 | 纯文本 | 整块 | 默认落点 |
| 标题 | `#` … `######` | 标题文字 | 哈希把手 `###` 是 `contentEditable=false`，只在退格时亮出来；空标题自动退回正文 |
| 无序列表 | `- 项` | 项文字 | 最多 6 层缩进；标记不参与编辑 |
| 有序列表 | `1. 项` | 项文字 | 编号由序号重排，不手改 |
| 任务列表 | `- [ ]` / `- [x]` | 文字 + 勾选框 | 勾选直接改模型，不用进源码 |
| 引用 | `> 行` | 整行 | 连续引用行 = 一个引用组；组首行打 `data-bq-start` |
| 提示块 | `> [!info] 标题` + `> 正文` | 正文；标题单独存 | 四型 + 别名；标题不进正文文本 |
| 代码块 | 三反引号 + 语言 | 整段原文 | 语言条 + 复制按钮；块内没有「行」概念（文本 + `<br>`） |
| 公式块 | `$$ … $$` | TeX 原文 | `$$` 用 CSS 伪元素画，不进 DOM |
| 表格 | GFM 表格 | 单元格 | 单元格是唯一编辑位；对齐存 `data-aligns` |
| 分割线 | `---` | 无光标位 | 不能点进去，靠上下行绕行 |
| 图片 | `![](path)` | 无 | 行内元素，独立成块时居中 |

**块类型只在编辑区里存在**。切到编辑模式看到的是原始 Markdown，切到预览看到的是渲染结果，
两边不共享 DOM。

### 5.3 输入即转换（打字就把块变过去）

在行首敲标记，当前块原地变成对应类型，不用去菜单：

| 输入 | 变成 | 备注 |
|---|---|---|
| `# ` … `###### ` | 对应级别标题 | 空格是触发键 |
| `- ` / `* ` / `+ ` | 无序列表 | 三种符号等价，序列化统一成 `-` |
| `1. ` | 有序列表 | 数字不必是 1，序列化按位置重排 |
| `- [ ] ` / `- [x] ` | 任务列表 | 逐字升级：敲到 `[` 就已经是待办 |
| `> ` | 引用 | 紧跟已有引用时打 `data-bq-start`（否则会粘进上面的框） |
| `[!info] ` 等 | 提示块 | 在引用行里敲也生效，光标后的文字当标题 |
| 三个反引号 | 代码块 | 后面跟的语言名进语言条 |
| `---` | 分割线 | 要求整行只有它（后面还有字不算） |
| `$$` | 公式块 | 回车后成为块级公式 |

三条判据细节：

1. **看「光标之前这一小段」，不看整行**。所以三种写法等价：先打标记再写字 / 写完回行首补标记 /
   把普通文字原地升级成标题。早期判据是「整行 = 标记」，只有空行上先打 `#` 才行，
   用户在已有文字前补 `##` 只会得到两个井号。
2. **前缀超过 16 个字符不判**：那更可能是一行正常文字里恰好有 `-`，不是想建列表。
3. **光标不在行首时不触发**（`- ` 打在句子中间就是普通字符）。

**转换是原地改属性/类名，不是 `replaceWith`**：换节点会让光标、块下标、撤销记录一起错位。
光标后的内容用 `Range.extractContents()` 搬 DOM 片段，不用 `textContent` —— 否则加粗、链接、
行内代码会在转换时被削平。

### 5.4 回车：每种块都有自己的「下一行」

| 块 | 回车做什么 |
|---|---|
| 段落 / 标题 | 在光标处拆成两块；空标题回车退回正文 |
| 无序 / 有序 / 任务列表 | 续一个同类型、同缩进的新项，编号接上；**空项回车 = 退出列表**，变回普通段落 |
| 引用 | 续一行同组引用；**空行回车 = 退出引用**，在下面开普通段落 |
| 提示块 | 续行仍属于这个提示块（打 `data-co-follow`，视觉同框）；空行退出 |
| 代码块 / 公式块 | **永远换行**；只有「空末行」再按回车才出块（即连按两次：第一下开空行，第二下出去） |
| 表格 | 格内 `Shift+Enter` 插 `<br>`；普通回车在当前格换行？不 —— 回车在单元格里只做一件事：整行全空时退出表格，否则留在格内 |
| 分割线 | 在它下方开一个段落 |

**代码块那条规则改过一次，值得记住**：最早按「光标在末尾就出块」，结果用户写完一行想换行，
光标刚好在行尾，一按回车就被弹出去了。正确的约定是 Typora 那一套 —— 块内回车永远是换行，
**只有空末行回车才是出口**。出口要两个动作，但每一步都符合预期。

### 5.5 退格与删除

| 场景 | 行为 |
|---|---|
| 空段落 / 空标题 | 与上一块合并（光标落在接缝处） |
| 标题行首退格 | **第一下只亮出 `###`，不降级**；第二下起每按一次删一个 `#`：h3 → h2 → h1 → 正文；标记消失后回正文 |
| 空标题 | 自动降级为正文（原地改类型，不换节点）；但正在亮标记时不降级 |
| 列表项行首 | 并回上一行；已是组首行则退回普通段落 |
| 引用行行首 | 同上；提示块的续行并回上一行，只有组首行退回段落 |
| 代码块行首 | 一次退格吃掉行尾的零宽空格 + `<br>`（两个节点），不能按两次 |
| 有选区 | **只删选区，绝不合并行**。三击选中一行后按退格，锚点在行首，早期实现会把整行并进上一行，选中的内容一点没删 |
| 标题里只有图片 | 不算空，不降级 |

**为什么标题退格要分两步**：在 `### 标题` 这一行按退格，用户想的是「把标题级别降一格」，
不是「删掉这个标题」。先亮出 `###` 是在告诉用户「这里有一个标记，下一下删的就是它」——
和 Obsidian 的实时预览同一个思路。标记是纯视觉层（`contentEditable=false` 的兄弟节点），
绝不进正文文本，序列化时不参与。

### 5.6 方向键：走到头就出去

| 位置 | ↓ / → | 说明 |
|---|---|---|
| 普通段落、标题 | 浏览器默认 | 段落本身就是出口的落点 |
| 代码块 / 公式块末行 | **出块** | 落到下一块开头，或新开一行 |
| 表格最后一格 | **出块** | 表格右下角必须有出口，否则只能动鼠标 |
| 引用 / 提示块的组末行 | **出块** | 组内还有下一行时交给浏览器（它会处理折行与滚动） |
| 列表最后一项 | **出块** | 同上 |
| 分割线上一行末尾 | **穿过分割线** | 分割线自己放不了光标；文末那条 `---` 否则是一道墙 |

出口落点按优先级取第一个成立的：

1. 紧邻的下一块 —— 空段落就停进去，别的块就停在它开头；
2. 后面确实什么都没有，才新开一个空段落。

**判重的关键在第 1 条**：以前无条件新建，表格下面本来就空着一行时按一下又冒一行，
连按就往下沉（空段落不进 Markdown，但屏幕上真真切切多一行）。

**↓ 和 → 在块内最后一个位置做同一件事不是偷懒**：走到头的下一步就是出去。让 `→` 在表格
右下角原地打转，才是违背直觉的。

### 5.7 鼠标

| 动作 | 行为 |
|---|---|
| 点字 | 光标落在点的位置 |
| 点块内空白（表格右侧、代码块下方留白） | 光标落到该块最后一个可写位置 |
| 点文末空白 | **把光标送回文末**，不是加一行。只有代码块 / 公式块 / 表格 / 分割线垫底时才补一行（它们把光标包在结构里），其余 `placeCaretEnd(末块)` |
| 拖选跨块 | 保留选区，不许在松手时被当成「点空白」 |
| 拖到窗口边缘 | 自动滚动并继续扩选 |
| 双击 | 选词 |
| 三击 | 选一行 |

**跨块拖选有个隐蔽陷阱**：`mousedown` 与 `mouseup` 落在不同元素上时，`click` 派发给两者的
**最近公共祖先**。选到两行以上，公共祖先就是编辑区根节点，和「点了正文空白」长得一模一样。
必须两道闸：①选区非空直接返回；②真要按空白处理时用 `elementFromPoint` 问一下这一点命中谁，
命中任何块就按「点在字上」处理。只做①，「从空白拖到空白」仍会误判。

#### 块手柄

行首悬停出现两个按钮：`⋮⋮`（换块类型）和 `+`（在下方插入）。

| 规则 | 说明 |
|---|---|
| 位置 | 挂在编辑区外层（`position:relative`），按当前块的矩形定位，**不能放进块里** —— 会被当成正文吸进去 |
| 常驻 | 锚点是「最后确定的那一行」，鼠标移到行间空隙、页边距、编辑区外都不消失；只有真的换到另一行才跟着挪 |
| 滚动 | 滚出视野只隐藏元素，不丢锚点，滚回来还是它 |
| 菜单关闭 | 只有点别处 / Esc / 滚动三种；**鼠标移动永远不关**（手柄和菜单之间有 4px 缝，落在编辑区里，一次 `mousemove` 就会收掉） |
| 键盘 | ↑↓ 环绕、Home/End、Enter 执行、Esc 关闭；字母 / 空格 / Tab / ←→ 收起菜单且不拦事件（焦点始终留在编辑区，打字才是意图） |
| 高亮 | 当前项用 `.hot` 类，不给真焦点（给焦点会丢正文选区） |
| `+` 的语义 | 在**下方**插一个新块；表格 / 图片 / 链接 / 分割线自己知道往哪插，不走这条路 |

菜单里每个图标要和「点了会发生什么」对得上：标题用 heading-1/2/3，表格用 table，链接用 link，
引用用 text-quote。曾经三级标题都画同一个 `type` 图标，一列看下来分不出谁是谁。

#### 块尾插入指示线

鼠标在最后一块下方空白移动时，显示一条细线，预告「点这里会多一行」。

- **只在真的会补行时亮**：判据和「点空白」共用 `needsLineBelow()`；
- 指示线挂在编辑区外层，不挂进块容器（否则会被遍历成幽灵空段落）；
- 点一下只补一行；补出来的空段落立刻成为新末块，再点也不会继续长。

### 5.8 粘贴：先看落在哪个宿主

同一个 `paste` 事件，落到不同块上语义完全不同：

| 落点 | 处理 | 不这么做的后果 |
|---|---|---|
| 普通段落 / 空行 | 多行 → 解析成块，顶替空行或插在块后 | 从别处粘一段带标题的笔记，结构全丢 |
| 列表项 / 引用行 | **在容器里续行**：每行等价于一次回车，li 续同 kind 同缩进、ol 编号接上、task 仍是待办 | 按段落插在块后会拦腰截断容器：`- 第二项` 之后冒出三个普通段落、每段还隔一个空行 |
| 表格单元格 | 只取第一行 | 多行会把表格结构塞进一个格 |
| 代码块 / 公式块 | **原文插入**：换行落 `<br>`、末尾垫零宽空格、先摘掉占位 `<br>` | 走 Markdown 解析时，空代码块会被整块替换（粘一段 JSON，块凭空消失），非空块则把段落插到块外面 |
| 图片（剪贴板里是位图） | 存进 `assets/`，回填 `![](assets/…)` | 不处理就是静默吞掉 |
| 文件（资源管理器拖入） | 图片复制进 `assets/`，其它当文档打开 | — |

代码块的三个细节必须一起做，少一个都会出现「光标跑错行」：

1. **换行用 `<br>`，不往文本节点塞 `\n`**：Chromium 下一次输入会把行尾那个 `\n` 吃掉，
   光标漂到换行前面；
2. **末尾垫零宽空格**：否则以换行结尾的粘贴会让光标停在 `<br>` 上，接着打字跑回上一行；
3. **先摘掉空块的占位 `<br>`**：不然粘进来的内容前面多一个空行。

**粘贴期间不逐行落账**：`splitBlock` 有批量模式，粘贴时置 `silent`，末尾统一 flush 一次。
逐行 flush 在万块文档上是一次几百毫秒的全量序列化。

**空行不占列表项**：空的 li / bq 在模型里存不住（序列化直接丢），造一个只会留下看不见的空位。
代价是「粘多段文本进引用会并成一个引用组」，这个代价接受。

### 5.9 拖放

- 走 Tauri 原生拖放通道（`dragDropEnabled: true`），拿到真实路径。
- 图片：复制进文档同目录的 `assets/`，保留原名，重名加 `-1`。
- 其它文件：直接开标签，多选开多个。
- 拖入期间显示一个提示层（`.drop-hint`）；原生通道下页面收不到 `dragover`，只能由 Rust 的
  enter / leave 事件驱动。
- 页面内拖拽标签换位走 HTML5 DnD，不受影响。

**未保存的文档拒绝插入图片**，提示「请先保存文档」。没有「同目录」可放 —— 存到临时目录
再让 Markdown 指过去，换台机器图就全断。

### 5.10 图片

| 规则 | 说明 |
|---|---|
| 存储 | 文档同目录 `assets/`；Markdown 里写**相对路径** |
| 双地址 | `data-src` 存原始相对路径（序列化用它），`src` 存 `convertFileSrc` 后的绝对地址（WebView 只认这个） |
| 尺寸语法 | `![说明\|300x200](assets/x.png)`；只写宽度也可以 |
| 拖拽改宽 | 右下角 14px 见方才可拖；只写 `width`、删 `height`（高度按比例）；最小 24px，上限正文宽 |
| 撤销 | 一次拖拽 = 一步撤销（拖拽期间不落账，松手才 flush） |
| 原生拖动 | `draggable="false"` + `dragstart` 拦一道，别和浏览器「把图拖出去」抢指针 |

**为什么 Markdown 里存相对路径**：整个目录拷到别处、提交进 git、换台机器打开，图都还在。
存绝对路径当场能看，文件一移动就全断。

### 5.11 表格

| 项 | 规则 |
|---|---|
| 插入 | `Ctrl+Shift+T` 插 3×3；「表格（自定大小）…」可以输行列 |
| 编辑 | 光标进格子直接改；`Tab` 下一格、`Shift+Tab` 上一格；末格 `Tab` 加一行 |
| 单元格内换行 | `Shift+Enter` 插 `<br>`；序列化与解析都按 `<br>` 往返，空单元格不写占位 |
| 行列操作 | 右键：上方/下方插行、左侧/右侧插列、删行、删列 |
| 对齐 | 右键药丸：左 / 中 / 右 / 取消；当前列的对齐会点亮 |
| 出口 | 最后一格末尾 `↓` 或 `→` 出表（见 §5.6） |
| 转换 | 表格**不参与**「换块类型」（没有可搬的文本），也不可拖拽 |
| 空行退出 | 一整行所有格子都空时按回车 = 退出表格，在下面开段落 |

**表格的阅读态与编辑态不同**：预览用完整 1px 网格（和所见即所得一致），编辑态保留极淡的
竖线用来定位光标。曾经预览用「横线表」（只留下边框），切到预览格子边界全消失，用户以为
边框没画。

### 5.12 链接

- `Ctrl` / `⌘` + 点击才打开，直接点仍是定位光标 —— 否则想改链接文字就下不了手。
- 外链交给系统浏览器；站内锚点（`#标题`）在文档内跳转。
- 相对路径按文档所在目录解析；`http(s)` / `mailto` 直接放行。

### 5.13 数学公式

| 项 | 规则 |
|---|---|
| 行内 | `$ … $` |
| 块级 | `$$ … $$`，独立成块，跨行也吃成一个 |
| 渲染 | KaTeX，**懒加载**：文档里没有公式就一分钱不付 |
| 往返 | 行内公式必须存**含 `$` 的完整匹配**，否则切回编辑模式 `$` 就丢了，公式退化成普通文字 |
| 下标 | `a_i` 里的 `_` 不能被当成斜体标记（先提公式，再处理行内语法） |
| 体积 | 只 vendor `katex.min.js` + `auto-render` + 一份 CSS + 20 个 woff2，合计约 546 KB；CSS 里 woff/ttf 的 url 必须删掉，否则字体三份副本撑到 1.2 MB |

**顺序死记**：行内处理必须先提行内代码、再提公式，最后统一转义。公式里 `<` 要原样进 KaTeX，
提前转义成 `&lt;` 就废了。

### 5.14 提示块（callout）

语法：`> [!info] 可选标题` + `> 正文`。

| 类型 | 别名（GitHub 命名收编） | 视觉 |
|---|---|---|
| info | note | 蓝 |
| success | tip | 绿 |
| warning | important | 琥珀 |
| danger | caution | 红 |

- 未知标记保持普通引用（不猜）。
- 标题存在 `data-callout-title`，不在正文里；标题行是 `contentEditable=false` 的独立节点
  （和代码块语言条同一套路），序列化时单独输出。
- 续行染同色（`data-co-follow`），视觉上是一个框；空行退出。
- **相邻两个提示块之间必须有空行**，否则会并进同一段引用，第二个 `[!xx]` 在预览里退化成
  普通文字 —— 这是「相邻 callout 往返丢类型」的根因。
- 把提示块转成别的块（或取消提示块）时，**标题文字要放回正文**，否则「我的标题」凭空消失。

### 5.15 换块类型

「插入新块」和「换类型」是两种语义。菜单「段落」组里的都是后者，五个入口全部走
`convertBlock()`：

- 能互转的是「一行文本」的块：段落 / H1–H6 / 列表项 / 引用 / 代码块 / 公式块；
- 表格与分割线没有可搬的文本，返回 false，调用方另起新块；
- **搬运取 Markdown 源**，不取 `textContent` —— 后者会把 `**加粗**` 削成纯字；
- 代码块 / 公式是多行的：转成逐行块要按 `\n` 拆开、一行一块（末尾空行是「空末行」的产物，
  丢掉）；反方向则整段塞进一块；
- 引用组边界双向都要管：自己转成引用时前一块是引用 → 自己打组首标记；后一块是引用且没标记
  → 给它打上（否则转完被紧凑规则吸成一个框）。

**为什么必须统一**：以前每个命令各写一套「只认某几种源类型」的判断，于是「在代码块上点引用」
静默无反应，「引用转代码块」在下面多出一个空代码块，换标题会把行内格式削平。同一个动作
在不同块上表现不一致，用户只能靠试。

### 5.16 序列化与幂等

| 规则 | 说明 |
|---|---|
| 两条实现 | DOM → md（`blocksToMd`）与记录 → md（`recordsToMd`）必须**逐字节一致** |
| 块间分隔 | 列表项之间、引用行之间用 `\n`（空行会让列表变 loose、把引用拆成两段）；其余用 `\n\n` |
| 空段落 | 自己就是空行，不再额外补一行 |
| 文末 | 只留一个换行；文档开头不留空行 |
| 改块类型 | 两个序列化函数 + 两个解析入口要同时改，这是最容易漏的一处 |

**每次改序列化都要验幂等**：读回来再写一遍，结果必须相同。否则每保存一次文件就漂一点，
几天后整篇文档的空行结构全变。

### 5.17 撤销

| 文档 | 快照 | 上限 |
|---|---|---|
| < 1 MB | 记录型快照 | 200 条 |
| ≥ 1 MB | `records` 数组浅拷贝（块对象写时复制） | 8 MB 总字节 |

- **入口唯一**：`Ctrl+Z`、工具行箭头、编辑菜单、命令面板，全部落到同一条 `editCmd('undo')`，
  按模式分派到各自的历史栈。
- **禁止 `document.execCommand('undo')`**：它操作浏览器原生栈，而所见即所得的 DOM 是受控
  重绘的，两套栈各记各的，混用会退到谁也没预期的位置（内容退一半、光标乱跑）。
- 纯文本走 CodeMirror 自己的历史；同一文档内替换内容（格式化、转大小写）保留历史，
  切换文档则重建 state，旧文档的历史不串到新文档。
- 到栈底按钮变灰。「点了没反应」是最差的反馈 —— 用户分不清是软件坏了还是自己记错了。

### 5.18 查找与替换

一个浮层，四个模式开关，替换行可折叠（IDEA 式）：

| 元素 | 规则 |
|---|---|
| 呼出 | `Ctrl+F` 只聚焦，**不收起**已展开的替换行；`Ctrl+H` 直接展开 |
| 折叠箭头 | 在输入框左侧，点一下展开/收起替换行 |
| 模式 | `Aa` 区分大小写 / `.*` 正则 / `全词` / `选区` |
| 整词 | **只在查询串两端是 ASCII 单词字符时加边界**。中文没有词边界，「标题」匹配到「副标题」是正常的，硬套 `\b` 会让中文查询永远匹配不到 |
| 多行 | 输入框是 `textarea`，`↵` 或 `Ctrl+Enter` 插换行，自动长高到四行 |
| 跨行命中 | 所见即所得里整篇一份索引、块间插 `\n`；显式分隔符保证不带换行的查询不会匹配「上段结尾 + 下段开头」 |
| 高亮 | CSS Custom Highlight API，不往 contenteditable 里插 `<mark>`（会毁行内结构与光标） |
| 替换一处 | 命中在同一文本节点内 → 就地改 + 落账；跨了加粗/链接等格式 → 问「切到编辑模式继续替换？」 |
| 全部替换 | 从后往前改（前面的偏移不失效）；跨格式的单独计数并如实告知 |
| 计数 | 「当前 / 总数」；无匹配时显示 `0/0`，不弹窗 |
| 关闭 | Esc；`Esc` 在专注模式下先关查找条（一次只做一件事） |

**选区模式只在真的选了东西时可用**：没选区时勾上也会自动取消，避免「勾了却搜整篇」的困惑。

### 5.19 一键格式化

快捷键 `Ctrl+Alt+L`（避开 Windows 繁改简的 `Ctrl+Shift+F`，系统级热键拦不住）。

| 类型 | 做什么 |
|---|---|
| Markdown | 标题 `#` 后补空格、标题前后补空行、列表符号统一为 `-`、去行尾空格、压缩连续空行、文末一个换行 |
| JSON | 解析后重新缩进 2 空格；**保守自动修复**：全角引号/冒号、尾逗号、`//` 与 `/* */` 注释；修不了就报出错行列，**原文一字不动** |
| 代码 / 纯文本 | 统一 LF、去行尾空格、压缩连续空行 |
| CSV / TSV | 不格式化（列对齐不是「修文本」，是「重排数据」） |

格式化的三条原则：**不丢内容、可撤销、语法错误时不改动原文**。

### 5.20 大文档（≥ 1 MB）

超过 100 万字符换一条路径：

| 项 | 规则 |
|---|---|
| 真相 | `records` 数组（每块存 Markdown 原文切片 + 结构标记） |
| DOM | 只放视口附近约 4 屏、上限 600 块；窗口外高度用前后伪元素撑出 |
| 不能用 padding | `clientHeight` 含 padding，会把滚动容器自己撑高 |
| 滚动锚定 | 必须 `overflow-anchor: none`，否则浏览器的锚定与自己的偏移补偿各补一次 |
| `Ctrl+A` | 走逻辑全选（标记整篇 + 拦截输入/复制/剪切）；原生全选只覆盖窗口，随后打字会把窗口外几万块当未选中删掉 |
| 载入 | 分段解析（512 KB 一段，围栏 / `$$` / 松散列表 / 连续空行 / 引用前五处不切），首段先显示，其余一次插入 |
| 分段失败 | 整篇重载兜底，绝不留半截文档 |
| 载入中 | 禁止把半截 DOM 序列化回 `t.content`（载入中途切标签或失焦会把残篇写进标签，自动保存再覆盖磁盘） |

实测 10.8 MB / 7.8 万块：打开约 1.14 秒、DOM 48 块、堆内存 32 MB、击键 1 ms、往返逐字节一致。
这些数字是这条路径存在的理由；如果某次改动让它掉到几百毫秒，先查是不是又退回了整篇渲染。

### 5.21 代码块：高亮、识别、复制、全选

| 能力 | 规则 |
|---|---|
| 编辑态高亮 | **不改 DOM**：用 CSS Custom Highlight API 给文本区间上色（区间由 `highlight()` 的输出换算成源码偏移）。往 `.w-code` 插 `<span>` 会同时毁掉光标、撤销记录和序列化 |
| 着色一致 | 与预览共用同一份分词输出，没有第二套实现 |
| 偏移换算 | `<br>` 占一位但没有文本节点；零宽空格有文本位但源码里没有 —— 必须逐字符记位置，用 `textContent.length` 硬算会整体错位 |
| 重算 | `MutationObserver` + 120 ms 防抖；单块超过 8 万字符放弃着色（流畅比彩色重要） |
| 自动识别 | 每种语言一组特征正则打分，≥ 3 分才认；JSON 先 `JSON.parse` 验算 |
| 识别写回 | **绝不写回 Markdown**。往用户文件里补一句语言名会让首次打开就标脏，存一次就改了人家的文件 |
| 语言条 | 显示 `data-lang` 或识别结果；没认出来显示 `code` |
| 复制 | 语言条右侧按钮，点一下整块进剪贴板，图标变对勾。走 textarea + `execCommand('copy')`（WebView2 里 `clipboard.writeText` 不可靠） |
| 块内 `Ctrl+A` | 第一次选**这一块**，第二次选整篇，第三次仍是整篇 |
| 复制按钮的焦点 | `pointerdown` 要 `preventDefault`，否则焦点被抢走，复制完光标不在原处 |

**`Ctrl+A` 为什么不由浏览器做**：实测「已选中一个内联块」之后再触发全选，WebView2 会把选区
整个吃掉（`execCommand('selectAll')` 返回 true，而选区是空的）。所以两步都自己算：第一下
用文本节点边界圈住本块，第二下自己从首块铺到末块。

## 6. 侧栏与导航

### 6.1 侧栏两页

- 「大纲」与「文件」两个页签，宽度可拖拽；当前页记在 `settings.side`，重开还原。
- **没有齿轮图标**：设置是软件级的，放在侧栏顶部会被读成「这一栏的设置」。
- 侧栏可整体隐藏（`Ctrl+Shift+O`），专注模式下自动隐藏。

### 6.2 大纲：只反映结构，不猜内容

| 类型 | 认什么 |
|---|---|
| Markdown | `#` ~ `######`（跳过围栏代码块内的 `#`）；Setext 的 `===` / `---`（文字在上一行） |
| 纯文本 | `#` / Setext / `【章节】` / `第X章·节·条` / 多级编号（点号段数 = 层级） |
| JSON | 缩进层级里的键 |
| 代码 | 函数 / 类 / 接口定义 |
| CSV / TSV | **不提取**（一行一条记录，提取出来就是几千行噪音） |

**单级编号必须「空行断组后只剩它一条」才算章节**：一份 `1. 2. 3.` 的清单不该把每行都变成
大纲；文件首尾天然缺一边邻居，所以不能按「前后都有空行」判。收完做一次「不跳级」归一化，
避免 h3 上面没有 h1/h2 时缩进悬空。

| 交互 | 规则 |
|---|---|
| 点击 | 标题**顶边贴基准线**（容器顶 + min(96, 高 × 0.3)），不是滚到视口中央 —— 滚到中央时高亮判据还停在上一节，用户会看到「点 A 亮了 B」 |
| 跟随 | 编辑 / 预览 / 所见即所得三套滚动容器各接一条路；CodeMirror 用 `lineAtViewportY()`，**不许自己累加行高**（折行会算错） |
| 滚到底 | 高亮让给最后一个标题（否则最后一节永远高亮不到） |
| 空状态 | 按文件类型分别说明，见 §2.9 |
| 大纲内定位 | 二分查找（标题位置单调递增） |

**大纲必须窗口化**：3 万个标题全铺，每次重排要 `classList.toggle` 4 万项，会把主文档的
视口渲染一起拖垮。只铺可见段（行高 28px、上下各多铺 12 行），未铺部分用**子元素 div 占位**
（绝不能用 padding，`clientHeight` 含 padding，会把盒子越撑越高）。首帧 `clientHeight`
不可信（可能等于内容高度），只采信 `(40, 4000)` 区间，超范围用 rAF 重试。

### 6.3 文件树

| 项 | 规则 |
|---|---|
| 打开文件夹 | 菜单 / 设置面板 / 命令行；一个文件夹一个根 |
| 懒加载 | 展开时才读这一层（`read_dir_shallow`），不递归；展开状态在刷新后保留 |
| 排序 | 目录在前、文件在后，同类按名称（中文按拼音） |
| 单击 | 打开文件；已打开则切到那个标签（不重复开） |
| 双击 | 同单击（没有「预览 vs 打开」两态，别让用户猜） |
| 右键 | 新建文件 / 新建文件夹 / 重命名 / 删除（进回收站）/ 在资源管理器中显示 |
| 多选 | `Ctrl` 点加选、`Shift` 点连选；选两个文件后可「比较这两个文件」 |
| 与标签联动 | 重命名 / 删除后同步已打开的标签；删除有未保存改动的标签先问 |

### 6.4 侧栏搜索：只搜不改

| 项 | 规则 |
|---|---|
| 范围 | 当前打开的文件夹，递归 |
| 模式 | 字面 / 正则；`Aa` 区分大小写；改开关要**立即重跑**并把按钮状态说清 |
| 结果 | 按文件分组，显示命中行；点击跳到该文件的那一行 |
| 上限 | 200 条；到了就明说「只显示前 200 条」 |
| 跳过 | 二进制（含 NUL）、大于 4 MB 的文件 |
| 替换 | **不提供**。文件侧栏只回答「在哪儿」，改内容回编辑区 |
| 空态 | 「没有找到匹配的内容」+ 当前范围与模式 |

⛔ **跨文件替换整体删除**（后端命令、`plan_replace`、面板行一起删）。这类功能一次误点改几十
个文件，撤销要按文件翻历史快照，而真实需求几乎不存在。侧栏搜索的价值是「定位」，
不是「批量手术」。

### 6.5 跳转

- `Ctrl+G` 跳转到行：输入行号，光标落到该行行首，视口把该行放到中央。
- 目录（`Ctrl+Shift+T` 之外的「插入 → 目录…」）按当前文档的标题生成锚点列表；锚点 slug
  由渲染和生成**共用同一个函数**，差一点链接就跳不过去。
- 站内链接 `#标题` 同样走 slug 匹配；重名标题按出现顺序加后缀，两边算法一致。

## 7. 速记

### 7.1 它是什么

一份固定在 `<app_data_dir>/quicknote.md` 的普通 Markdown 标签。不选位置、不按保存 ——
用来接住「先记一下，回头再整理」的那类内容。

### 7.2 与普通标签的三处不同

| 普通文档 | 速记 |
|---|---|
| 脏标记 = 内存 ≠ 磁盘 | **永远算干净**（`isDirty` 直接放行）—— 它没有「保存」这个动作 |
| 关窗时逐份问「要保存吗」 | 不问；关标签 / 退出前先 `flushQuickNote()` |
| 进「最近打开」、进会话恢复、进草稿 | 都不进 |

**「永远算干净」和「关前必须 flush」是一对**：打字到落盘是 350 ms 防抖，打完最后一个字就
关窗，`content` 里可能还差几个字。正因为不显示脏点、不弹确认框，沉默丢字的窗口必须由代码
自己关掉 —— 否则「不用保存」就成了「悄悄丢」。

### 7.3 只有一份

- 身份看标签上的 `quickNote` 标记，**不靠路径比较**（路径比较要在每个用到的地方重新问后端）。
- `openPath()` 命中速记路径时改道 `openQuickNote()`；文件树、拖放、最近打开都会走到这里。
- 两个标签写同一个文件，后保存的会把先保存的盖掉 —— 所以只允许一份。

### 7.4 「另存为」= 导出副本

对速记执行另存为，**不改 `t.path`**。改了之后自动保存会跟着副本跑，速记本身从此不再更新。

### 7.5 入口

- 菜单栏最右的「速记」是一个**动作项**，点一次直接打开。
- 辅助动作在「文件」菜单末尾的「速记」小节：插入当前时间 / 在文件夹中显示 / 复制路径 /
  清空…；小节末尾用一行小字写明速记文件的实际路径。
- `Ctrl+Shift+M` 打开。
- 清空前先存一份历史快照，给「手滑清空」留一条后路。

## 8. 设置

### 8.1 四页

| 页 | 内容 |
|---|---|
| 外观 | 主题（跟随系统 / 浅色 / 深色）、字号（步进 + 显示当前 px + 实际大小）、正文宽度（560–1600，步进 40，默认 800） |
| 界面 | 语言（跟随系统 + 9 种）、显示大纲/文件栏、双栏 |
| 文件 | 自动保存、监听磁盘改动、工作文件夹 |
| 快捷键 | 全部命令的键位列表 + 逐条「改」 |

「行显示模式」不在设置里 —— 它放在**视图菜单**和右键菜单，因为改的是「此刻怎么显示」，
不是一次性配置。

### 8.2 即时生效

面板没有「确定」按钮，改哪一项立刻生效并写 localStorage。底部只有「完成」。
省掉「改完忘了点确定」这一类挫败。

### 8.3 默认值与迁移

| 项 | 默认 |
|---|---|
| 主题 | 跟随系统 |
| 语言 | 跟随系统 |
| 字号 | 13.5 px |
| 正文宽度 | 800 px |
| 行显示 | 自动换行 |
| 布局 | 单栏 |
| 自动保存 | **开** |
| 磁盘监听 | 开 |
| 侧栏 | 显示，停在大纲页 |

**改默认值必须 bump `__v`**：老用户的 localStorage 里存着旧默认，光改 `DEFAULTS` 对他们无效。
当前 `__v = 4`，迁移做过四件事：布局回单栏、自动保存回开、清掉被粘滞的 `lastMode`、
语言回「跟随系统」。

**新增设置键不需要 bump**：`Object.assign({}, DEFAULTS, stored)` 会自动补上缺失的键。
bump 会顺带重跑上面那几条重置，属于误伤。

### 8.4 恢复默认

- 确认框写清「主题、字号、正文宽度、布局、自动保存都会回到出厂状态，文件夹设置也会清空」。
- 实现是 `Object.assign(settings, DEFAULTS, { keymap: {}, lastMode: {} })` —— 手抄字段
  加一项必漏；`keymap` / `lastMode` 必须换新对象，否则改动会污染 `DEFAULTS`。
- 测试或脚本要钉死设置时，写入的对象必须带 `__v: 4`，否则会被迁移改写。

### 8.5 自定义快捷键

- 设置 → 快捷键 → 某条命令「改」→ 直接按新组合键。
- 规则：必须带 `Ctrl` / `Alt`，或单用 `F1–F12`；`Esc` 取消。
- 自定义键位优先于默认键位；冲突时后设的覆盖前设的，并在列表里标出冲突。
- 存在 `settings.keymap`（`{ 'mod+shift+k': 'commandId' }`），与平台无关的 `mod` 在匹配时
  映射到 `Ctrl` / `⌘`。

## 9. 历史版本

| 项 | 规则 |
|---|---|
| 何时留 | **每次写盘之前**，把上一版磁盘内容留一份（内容为空不留；与最新一份相同则跳过） |
| 位置 | `<app_data_dir>/history/<fnv1a(路径)>/<时间戳>.txt`；目录里另存 `name.txt` 供人辨认 |
| 上限 | 每个文件最近 60 份，再按总量 20 MB 兜一道 |
| 面板 | 「文件 → 历史版本…」，列出时间（今天 / 昨天 / 月日 + 时分）与大小 |
| 动作一 | 在**只读标签**里打开这一版（可以对照、复制，不会误覆盖当前文件） |
| 动作二 | 写回编辑器（**不落盘**）—— 要不要保存由用户决定 |
| 不动作 | ⛔ 绝不「一键回滚并覆盖磁盘」 |

**为什么回滚不直接覆盖**：历史快照是兜底，不是版本控制。一键覆盖会让「我只想看一眼旧版」
变成「我的新版没了」。所有对比 / 合并 / 历史功能的共同原则是：**结果先落在编辑器里，
落不落盘由用户按一次 `Ctrl+S` 决定。**

### 10.1 导出网页（HTML）

## 11. 文本对比窗口

对比是这款软件的第二条腿。它的设计目标不是「功能对标 Beyond Compare」，而是
**「打开就能看、看完就能改、改完就能存」**。

### 11.1 形态与生命周期

- 独立窗口（`compare.html`），有自己的最大化 / 关闭；窗口标题带两侧文件名。
- 入口：菜单「对比 → 文本对比…」、`Ctrl+D`、文件夹对比里点一行、命令行 `--compare 左 右`。
- **窗口复用**：已经开着就推新数据（`compare:load` 事件），不再开第二个。
  因此「打开一对新文件」必须先把两侧重置干净（见 §11.3）。
- 关闭走 `onCloseRequested`，× / Alt+F4 / 任务栏三条路都过这里（见 §11.12）。

### 11.2 打开时给什么

| 情况 | 界面 |
|---|---|
| 什么都没带 | **两个空白编辑区**，光标在左侧第一行，`Ctrl+V` 就能用；顶部一行提示「把两段文本分别粘到左右两侧，或者点上面的文件名打开文件」 |
| 带一个文件 | 另一侧补成空白文本，两侧都能写 |
| 带两个文件 | 两侧都加载，直接进可写状态 |
| 一侧读失败 | 那一侧**清成空白可写区**，并说明失败原因；绝不保留上一轮的旧内容 |

**为什么不再有「选择左侧 / 选择右侧 / 粘贴两段文本」的浮层**：三个入口等于逼用户先选模式，
而最常见的用法就是贴两段文本比一比。直接给两个空白框，想比文件就点槽位上的文件夹图标
（有图标才看得出那里能点）。

**失败侧必须清空**：否则「新的超大文件没读进来」时，界面会拿旧左栏比新右栏，给出一个
看起来完全正常的错误结论。

### 11.3 上限

| 项 | 上限 | 超限表现 |
|---|---|---|
| 单文件大小 | 8 MB | **先问 `file_size`，超限不读**；正文上方可关闭的提示条写明文件名、实际值、上限、建议 |
| 单文件行数 | 50 000 行 | 同上 |
| 文件夹列举 | 20 000 个文件 | 提示已截断 |

引擎本身很快（5 万行约 160 ms），卡的是读入、每行一个对象的模型和导出报告。所以限制放在
**读之前**，不是读完再放弃。

### 11.4 行模型与对齐

- 两侧各是一个行数组；并排视图把两侧对齐成一张「对齐行表」，每行有左侧行号 / 右侧行号 /
  类型（相同 / 修改 / 仅左 / 仅右）。
- 短的一侧补**占位行**（`row.l` 或 `row.r` 为 `null`）。
- 占位行不是空白，是「这一侧缺了几行」的位置（见 §11.7）。
- 行级 diff 分档：段内 `n × m ≤ 4M` 走精确 LCS；更大就按「两侧都唯一出现的行」当锚点
  （LIS 保持顺序）切开递归；兜底只能报「整段替换」。
- **绝不允许输出 `same` 而某一侧行号无效**：这会让整栏空白、新增全堆到文末，用户拿到的
  是一个看似正常的错误结论。

### 11.5 差异怎么画

| 元素 | 规则 |
|---|---|
| 修改行 | 只有 `inlineDiff` 算出的那几段字变红；行本身不加底色、不加边框 |
| 仅左 / 仅右 | 整行文字红（行号也红） |
| 预览条 | 每一条差异行一根 1px 细红线，画在 22px 轨道正中；差异太密（每行不足 2.5px 或超过 4000 行）时退回按段合并 |
| 底色 | **一律不铺** |
| 删除线 | 不用（删除由「仅左」表达，不需要再把字划掉） |

**为什么只红字**：一屏几十处差异时，铺底色会让整页发红，反而看不出是哪几个字变了。
差异要一眼看见，但**看见的应该是字**。

### 11.6 预览条

| 项 | 规则 |
|---|---|
| 尺寸 | 栏宽 34px，槽宽 22px |
| 起点 | 对齐**滚动区顶部**，不是预览条自身顶部（每栏顶上还有 26px 的文件名条） |
| 高度 | `min(可视高度, 内容高度)`，短文档时只有几行高 |
| 颜色 | 只有两种：红 = 这一行有差异；灰框 = 正在看的范围 |
| 当前这一处 | **不额外上色**。差异位置本来就靠红线的疏密看出来，多一种颜色只会让人问「蓝色是什么」 |
| 视口框 | 内容只比一屏多一点时不画（否则整条轨道被染灰，像没画差异） |
| 交互 | 点击 / 拖动定位，换算与绘制共用同一个几何函数 |
| 说明 | 三种含义写进 `title`，九种语言 |

宽度从 22px 加到 34px 是因为「三样东西抢十来个像素，点起来像瞄靶」——用户的原话是
「预览条太窄，很不好用」。丢给正文 12px 换这些划算。

### 11.7 编辑

打开即可写，只读是主动选择。

| 项 | 规则 |
|---|---|
| 宿主 | 每行一个 `contenteditable="plaintext-only"` 单元 |
| 单行内编辑 | 交给浏览器（保住原生撤销粒度） |
| 行首退格 / 行尾删除 | 自己算：合并行（`mergeUp` / `mergeDown`） |
| 回车 | 在光标处拆行 |
| Tab / Shift+Tab | 行首插 / 删缩进 |
| 有选区时按退格 | **只删选区，绝不合并行**（三击一行的锚点在行首，只看锚点会把「选中一行」误判成「光标在行首」） |
| 占位行 | 可写；写下去 = 在**这一侧插入一行** |
| 占位行点击 | 按**对齐索引**定位，不按行号（空行号 `+'' === 0` 会被夹成第 1 行） |
| 视觉 | 占位行编辑态画极淡斜纹 + 行号位 `·`；只读时不画（不该暗示可写） |

#### 跨行选区

Blink 的选区**不许跨出一个 `contenteditable` 宿主**：拖到第二行就停住，`range` 设进去也会
被掐回第一行（实测设 201 行，读回来只剩 17 个字）。所以编辑态的跨行选区由我们自己管：

1. **先摘掉这一侧每行的 `contenteditable`**（`stripSide()`），文本仍可选，但 Blink 不再
   拿某一行当编辑宿主；
2. `Ctrl+A` 全选这一侧，拖选与 Shift+点击也走同一条路；
3. 接管期间渲染**只补行不重建**，否则选中节点会跟着 `innerHTML` 一起被摘掉；
4. 跨行选区上的按键自己落进模型：删除 → 删选区；打字 → 替换选区；粘贴 → 替换选区；
5. 下一次点击、切编辑态或重建 DOM 时惰性恢复可写属性。

重建选区一律用 `setBaseAndExtent(anchor, focus)`，**不要手工 `setStart` / `setEnd`**：后者只
表达正向区间，向上扩的那一次会把锚点悄悄换到点击处，再按 Shift+点击就扩不动了。

**Shift+点击**：从已有锚点直接扩到点击处，等价于「一次到位的拖选」。锚点必须在恢复可写
**之前**读 —— 一恢复可写，Blink 就把跨行选区掐回一行。

#### 粘贴

**不能自己读剪贴板。** `navigator.clipboard.readText()` 在 WebView2 里既不 resolve 也不
reject（1.2 秒后仍在等），用户看到的是「按了没反应」。唯一不依赖权限的读法是 `paste` 事件
里的 `clipboardData`，可没有编辑宿主浏览器根本不派发 `paste`。

所以两步接上：

1. `keydown` 里记下 `pendingPaste` 的区间 → 恢复可写 → 把光标摆到选区起点 →
   **放行这次按键**（拦了就没有 `paste` 事件）；
2. `document` 上的 `paste` 监听 `preventDefault()`，用 `clipboardData.getData('text/plain')`
   落进模型。

剪切同理，只是复制那一步交给 `execCommand('copy')`（选区是真的，不需要编辑宿主）。

### 11.8 复制到另一侧

| 项 | 规则 |
|---|---|
| 单位 | **一处差异**（不是一行，也不是整个文件） |
| 键盘 | `Alt+←/→` 推这一处；`Ctrl+Alt+←/→` 推完并跟到下一处（连续合并） |
| 方向 | 箭头指向哪一侧就推到哪一侧；键盘的方向看**光标所在侧** |
| 按钮 | 长在中间那道 26px 的缝里，跟着当前差异块上下走；只在「编辑态 + 两侧都有内容 + 真有差异」时出现 |
| 目标侧缺行 | 插到该对齐位置（用 `recompute()` 算好的插入点） |

**为什么箭头在缝里**：这是用得最多的动作，放在顶部等于让鼠标从正文跑回顶上再跑回来。
**为什么按钮方向固定、不随光标翻转**：一个按钮说两件事，两边都说不清；键盘的组合键已经
表达了方向。

### 11.9 撤销 / 重做

| 项 | 规则 |
|---|---|
| 粒度 | 打字 700 ms 内合并成一步；换行 / 合并 / 缩进 / 删选区 / 粘贴这些结构性编辑一次一步 |
| 落哪一侧 | 光标所在侧 → 最近一次改动侧（`lastSide`）→ 左边 |
| 同步之后 | 先试光标侧，没历史就落到另一侧（`undoEither`）——否则「刚同步完按 Ctrl+Z 没反应」 |
| 光标 | 先记位置再换内容；实时选区 → `lastCaret` 备份 → 第 1 行 |
| 滚动 | **不主动滚视口**；光标行不在屏幕上时夹到视口中央那一行 |
| 按钮 | 可用性从**真实历史栈**算（两侧 undo/redo 长度 + 排序快照），只读态一律灰 |
| 监听 | 挂在 `document` 上，不挂在画布上 —— 点过工具栏后焦点在按钮上，画布收不到按键 |

`focus()` 本身会把元素滚进视野，必须 `focus({ preventScroll: true })`，否则前面「不滚」白做。

### 11.10 折叠（只看差异）

- 默认开。相同行收起来，每处差异前后各留 3 行；2000 行 20 处改动 → 49 行。
- **进编辑态自动关掉折叠**（要改的地方得看得见）。
- 折叠时两个特例必须保留：**光标所在行**、**当前查找命中行**。把左边改成和右边一样，
  这一行就从「修改」变成「相同」、随即被折掉，光标当场消失，表现为「键盘不管用了」。
- 折叠后「哪一行在哪、有多高」一律走**可见行表**，不许再拿原始行数组的下标当行位。

### 11.11 查找与差异清单

**查找（`Ctrl+F`）**：

- 浮在文件名条那一行，不遮正文；`Enter` 下一个、`Shift+Enter` 上一个、`Esc` 关闭。
- **命中按对齐行去重**：同一条对齐行可能两侧都有，不去重的话「下一个」会在两栏之间原地打转。
- 高亮只做**行级**：差异行的内部已经是 `inlineDiff` 的高亮 HTML，再插 `<mark>` 会互相踩。
- 命中色是蓝、当前命中加左侧竖线，和差异红刻意分开 ——「哪里不一样」和「你找的词在哪」
  是两件事。

**差异清单**：

- 把每个差异块摊成一行：位置 / 类型 / 行数 / 摘要。
- 表头三列都能点，同一列再点切换升降序；第二排序键恒为位置升序（否则「按类型排」时
  同类型内部会反序）。
- 筛选：全部 / 修改 / 仅左 / 仅右。
- 超过 300 条只渲染前 300 条并明说「用 F8 继续浏览」，不假装全列出来。

### 11.12 保存、脏标记、关闭

| 项 | 规则 |
|---|---|
| 保存 | `Ctrl+S` 写回磁盘；没有磁盘目标（纯粘贴）时提示「这份内容还没有路径」，引导另存 |
| 脏标记 | 每侧与**打开时/存盘时的基线**逐行比（`slice()` 让未改的行共享字符串，8 MB 也不多存一份） |
| 撤销回原样 | 「未保存」必须自己消失，`Ctrl+S` 变灰 |
| 关闭守卫 | `onCloseRequested` 里先 flush 再判 `dirtySides()`；三选：保存并关闭 / 不保存 / 取消 |
| 无磁盘目标 | **不显示「保存并关闭」** —— 给一个按了也没用的按钮比没有按钮更糟 |
| 二次拦截 | 确认后置 `forceClosing = true` 再关，否则会被自己拦第二次 |

### 11.13 排序

- 把两侧的行按**字典序**重排，空行沉到末尾，行数不变。
- 比较器 `Intl.Collator('zh-CN', { numeric: true })`：中文按拼音（李 < 王 < 张），`a9` 在
  `a10` 前。码位序下中文既不可读，`a10` 还会跑到 `a9` 前面。
- 排序键跟着「忽略空白 / 忽略大小写」走，否则 diff 说相同的两行会被排到两处。
- 只读态点排序会**先自动进入编辑态**（否则内容变了但保存是灰的）。
- `Ctrl+Z` 一次还原**两侧**（只还原一侧会留下「一边排好一边没排」的中间态）。
- 排序后打字再撤销，不能跳回排序前把字一起抹掉 —— 任何写入模型的路径都要先清掉排序快照。

### 11.14 工具栏

`统计 · 当前序号 · 忽略空白 · 忽略大小写 · 只看差异 · 自动换行 · 上一处 · 下一处 ·
差异清单 · 查找 · 排序 · 撤销 · 重做 · 编辑 · 保存 · 导出报告`

- 单行 flex，**按真实溢出量降级**：先去掉两级文字（`.tight` 按钮只留图标，`.tighter`
  勾选项也收成方框），每次量 `scrollWidth > clientWidth`。
- **不按窗口宽度猜阈值**：九种语言宽度差 100px 以上，按像素猜的阈值必然在某种语言下把
  最右边的按钮静默裁掉（760px 窗口下「导出报告」曾经就这么消失过）。
- 调用时机：`resize`、`document.fonts.ready`（字体没就绪时量出来偏窄）、`updateMeta()`
  （统计文字长度会变）。
- 统计与当前序号允许收缩 + 省略号：**信息和动作抢地方时，动作优先**。

### 11.15 快捷键

| 键 | 动作 |
|---|---|
| `F7` / `F8` | 上一处 / 下一处差异 |
| `Alt+↑` / `Alt+↓` | 同上（笔记本没有 F 键时的替代） |
| `Alt+←` / `Alt+→` | 把这一处推到左 / 右侧 |
| `Ctrl+Alt+←/→` | 推过去并跟到下一处 |
| `Ctrl+Z` / `Ctrl+Shift+Z` | 撤销（`Shift` 仍是撤销，不是重做） |
| `Ctrl+Y` | 重做 |
| `Ctrl+F` / `Enter` / `Shift+Enter` | 查找 / 下一个 / 上一个 |
| `Ctrl+S` | 保存 |
| `Ctrl+A` | 编辑态选这一侧全部 |

### 11.16 行显示模式

对比窗口和主窗口共用 `settings.wrap`。它原来是**固定行高虚拟滚动**（满篇「下标 × 行高」），
换行后行高不等，于是全部改成前缀和几何：

- `S.y`（每行顶边，长度 = 行数 + 1）、`S.hh`（每行高）、`rowAtY()`（在 `S.y` 上二分）、
  `rowTop()` / `rowH()` / `totalHeight()`；全站收口到这几个函数。
- **折几行靠算不靠量**：等宽字体 + `word-break: break-all` + `overflow-wrap: anywhere`，
  一行能放几个字只取决于宽度；一次算好每行的半角单元数（全角算 2），「可用宽 ÷ 字符宽」
  向上取整就是折行数。
- 不许逐行 `getBoundingClientRect()`：滚动路径每帧都要行位，5 万行量一次就是几千次强制重排，
  而且虚拟滚动只摆一屏、屏幕外的行根本没有元素可量。
- 切换换行、改字号、改栏宽、切折叠 —— **凡是改变行高的动作都不能沿用像素偏移**，
  先记视口顶部那一行，重排后滚回它。

## 12. 文件夹对比

### 12.1 为什么是独立窗口

浮层只有一栏「状态 / 路径 / 大小」，看不出左右两侧各自是什么，也点不进两侧目录。
独立窗口里**左右各列自己那一侧的文件**，同一行就是同一对，一行行看过去就是
「谁多了、谁少了、谁改过」。

### 12.2 布局规则

| 决定 | 理由 |
|---|---|
| **一个滚动区里的两列**（`1fr 1fr`），不是两个各自滚动的列表 | 对齐是这扇窗存在的唯一理由；两边各滚一下就全错位了 |
| 中缝用一条渐变画到底 + 每行一条底边 | 只有几行时中缝不会断在半空 |
| 行内只存索引（`data-i`），路径不进 `data-*` | 路径里的 `& < "` 要转义好几层，索引是唯一不会出错的做法 |
| 单侧存在的格子画 -45° 淡斜纹 | 与文本对比窗口「这一侧没有内容」用同一套语言 |
| 差异只红字 | 与文本对比一致 |
| 行数超过 4000 截断并明说 | 2 万行 DOM 会卡住半秒，而「能不能看全」用户得知道 |

### 12.3 「相同」必须读内容

早期判据是「大小 + 修改时间（±1.5 秒）」。把「一」改成「二」字节数一样、时间又挨着，
于是被判成「相同」；而「只看差异」默认勾着，**改动直接从界面上消失**。

现在用 `compare_file_pairs` 整批比对内容（一次 IPC、256 KB 分块、首个不同块就返回），
**修改时间从判据里彻底删掉**。这是那扇窗里最要紧的一条规则。

### 12.4 点一行

| 情况 | 动作 |
|---|---|
| 两边都有 | 开文本对比窗口（复用） |
| 只有一边 | 在主窗口打开这个文件 |
| 目录 | 展开 / 收起？不 —— 不做递归逐层展开，用系统文件管理器 |

这扇窗只回答「差在哪儿」，改内容交给各自该在的地方。

⛔ 刻意不做：批量同步、三栏合并、目录递归逐层展开。做深了，维护成本会和「打开看一眼」
的价值迅速失衡。

## 13. 三向合并

- 输入：基准版本 + A 侧 + B 侧。
- 输出：自动合并结果 + 冲突清单；结果**另存为新文件**，绝不覆盖任何原文件。
- 不做四栏可视化合并器 —— 复杂交互交给已有的两栏对比，这里只解决「先合一遍看看」。
- 三个文件缺一个就不让开始，提示「请先选择基准、A 侧、B 侧三个文件」。
- 合并算法与行级 diff 共用（`merge3`），冲突块按「基准里的位置」排序，便于逐条看。

## 14. 快捷键体系

### 14.1 设计原则

1. **不碰系统级热键**。`Ctrl+Shift+F`（繁简切换）、截图、虚拟桌面这些由系统/输入法先截走，
   `preventDefault()` 根本轮不到我们。格式化因此改成 `Ctrl+Alt+L`。
2. **不碰窗口级热键**。`Ctrl+Shift+T/N/W` 在浏览器和很多应用里是标签操作，尽量不用。
3. **跟随编辑器惯例**：`Ctrl+N/O/S/W`、`Ctrl+Z/Y`、`Ctrl+F/H/G`、`Ctrl+1/2/3` 切模式。
4. **匹配用 `mod`**（`Ctrl` 或 `⌘`），展示文案目前写 `Ctrl`（⚠️ 见 §21）。
5. **功能键留给全局**：`F9` 专注、`F11` 全屏、`F3` 查找下一个、`F7/F8` 对比窗口专用。

### 14.2 主窗口

| 编辑 | `Ctrl+Z` / `Ctrl+Y` / `Ctrl+X` / `Ctrl+C` / `Ctrl+V` / `Ctrl+A` | 撤销 / 重做 / 剪切 / 复制 / 粘贴 / 全选 |
| 编辑 | `Ctrl+F` / `Ctrl+H` / `Ctrl+G` / `F3` | 查找 / 替换 / 跳转行 / 下一个匹配 |
| 标题 | `Ctrl+Alt+0`…`3` | 正文 / H1 / H2 / H3 |
| 文字 | `Ctrl+B` / `Ctrl+I` / `Ctrl+Shift+X` | 加粗 / 斜体 / 删除线 |
| 段落 | `Ctrl+Shift+8` / `Ctrl+Shift+7` / `Ctrl+Shift+9` / `Ctrl+Shift+Q` / `Ctrl+Shift+K` | 无序 / 有序 / 任务 / 引用 / 代码块 |
| 段落 | `Tab` / `Shift+Tab` | 增加 / 减少缩进（所见即所得里作用于块） |

| 对比 | `Ctrl+D` / `Ctrl+Shift+N` | 文本对比（两个入口都开同一个窗口） |
| 速记 | `Ctrl+Shift+M` | 打开速记 |
| 标签 | `Ctrl+Tab` / `Ctrl+Shift+Tab` | 下一个 / 上一个标签 |

查找条内还有一组 Alt 组合（只在查找条可见时生效）：`Alt+C` 大小写、`Alt+R` 正则、
`Alt+W` 整词、`Alt+A` 全部替换（仅替换行展开时）。这是 IDEA 的习惯，补上之后不用鼠标也够得着。

### 14.3 对比窗口

见 §11.15。它有一套自己的键位，因为它的主循环是「看下一处、推过去」，和编辑正文不是一回事。

### 14.4 自定义

- 设置 → 快捷键 → 「改」→ 按新组合。
- 必须带 `Ctrl` / `Alt`，或单用 `F1–F12`；光按字母会误吞输入，直接忽略。
- `Esc` 取消；`Backspace` 清空回默认。
- 自定义优先于默认；冲突时列表标红并提示被谁占用。

## 15. 多语言与文案

### 15.1 九种语言

简体中文（源）、繁体中文、英、日、韩、法、德、西、葡。默认跟随系统：

- 读 `navigator.languages`，取第一个匹配；
- `zh` 按地区判：`TW` / `HK` / `MO` → 繁体，其余 → 简体；
- 没有匹配 → 英文。

### 15.2 词条结构

| 文件 | 角色 |
|---|---|
| `i18n-dict-src.js` | **唯一手写源**。键 = 简体中文原文，值 7 列（en/ja/ko/fr/de/es/pt） |
| `i18n-dict.js` | 生成物，**不许手改**。繁体列由 `tools/build-i18n-dict.py` 用 OpenCC `s2twp` 生成 |
| `i18n.js` | `tt()` 取词、`applyDom()` 刷静态文案、`detectLang()` |

- 键用中文原文（gettext 思路），代码里 `tt('保存')` 一眼知道上下文。
- 取词函数必须叫 `tt`，不能叫 `t` —— `t` 是「当前标签」，会被局部变量遮住。
- 带 `tt()` 的**顶层常量必须写成函数**（`const menuTree = () => [...]`），否则模块加载那一刻
  就求值了，切语言不生效。
- 新增词条后跑 `node test/run-i18n.mjs`：查覆盖率、列数、占位符、缺键回退。

### 15.3 不能挂 `data-i18n` 的节点

凡是 JS 会赋值 `textContent` 的节点，**绝不能**挂 `data-i18n`，否则切语言那一刻会被刷回
静态词。已知名单：对话框标题、草稿状态、文件树路径、对比窗口的两侧文件名与统计、预览标题。

切换语言的流程是「就地刷新」，不是重建界面：

```
setLang → applyDom → 菜单 update（不是重建，重建会叠 document 监听）
        → 模式标签 / 预览标题 / 大纲 / 状态栏 / 文件树 / 预览重排
```

### 15.4 错误文案

后端只说三样东西：`code`（稳定错误码）、`vars`（模板参数）、`detail`（系统原文）。
前端 `errors.js` 把码映射成一条**完整句子**：

| 规则 | 原因 |
|---|---|
| 整句做成一条词条，**不用「前缀 + 冒号 + 细节」拼** | 中日全角冒号、法语冒号前有空格，拼接每种语言都错 |
| `detail` 原样透传 | 它本来就是 Windows 按自己的语言给的，不归我们翻 |
| 未知码显示 `[io.foo] detail` | 宁可露出来，也不静默吞掉 |
| 翻过的 `Error` 不再翻第二遍 | 判据是「有 message、没有 code」 |

`run-i18n` 做双向对账：`ERR_TEXT` 的每条模板都在词条表里；Rust 里出现的每个错误码前端都有
模板。新增错误码不补文案，测试会红。

### 15.5 语气

- **说清后果，不吓人**：「上次关闭时还有没保存的内容：a.md、b.md。是否全部恢复？」
- **给下一步**：「替换需要编辑模式。这一处匹配跨越了加粗、链接这类格式……切到编辑模式继续？」
- **不甩锅**：不说「非法输入」「操作失败」，说「文件名里不能有 `\`」「文件已被其他程序修改」。
- **不用感叹号**。这个程序不激动。
- 数字与路径用 `<b>` 突出，长列表用「、」连接。

### 15.6 术语表（跨语言必须一致）

| 中文 | 英文 | 说明 |
|---|---|---|
| 速记 | quick note | 固定位置、不用保存的那份 |
| 对比 | compare | 文本对比窗口 |
| 提示块 | callout | `> [!info]` |
| 大纲 | outline | 侧栏结构导航 |
| 正文宽度 | reading width | 设置项，不是「页面宽度」 |
| 行显示模式 | soft wrap / no wrap | 统一用 soft wrap，不用 word wrap |
| 只看差异 | differences only | 折叠开关 |
| 差异清单 | difference list | 不是「变更列表」 |
| 换块类型 | change block type | 不是「转换」 |
| 一键格式化 | format document | — |

## 16. 视觉与交互规范

### 16.1 同色平面 + 1px 线

- 标题栏、标签行、侧栏、状态栏、正文**同一个底色**（浅色纯白 / 深色 `#191b20`）。
- 区域分界只靠 1px `--line-strong`；不再用「画布 / 面板 / 浅坑」三层底色。
- **理由**：三层底色在深色下要差 12 级才看得出，差不够就糊成一块，差够了又像补丁；
  同色之后「大纲和编辑区之间像有阴影」的问题直接消失。

### 16.2 浮层

- 不写 `border`，轮廓由 `--shadow` 给：`0 0 0 1px rgba(...)` + 大扩散。
- 深色下浮层必须比内容面**亮一档**（`--bg-float: #282c34`），否则菜单和正文同色，
  只能靠阴影硬撑。
- 菜单、下拉、右键、查找条、弹窗、抽屉全部用同一套。

### 16.3 圆角

只有四个值：`--r-sm: 0`、`--r-md: 2px`、`--r-lg: 3px`、`50%`（圆点）。

- 控件级（按钮、标签、菜单项、输入框、徽章、行内代码、滚动条）一律直角；
- 浮层留 2–3px（压到 0 时 1px 描边在斜角会露锯齿，看着像渲染坏了）；
- 不再出现「左直角右圆角」这类写法（大纲项、引用块都归零）。

**目标不是「现代感」，是「硬朗的工具感」**：这个程序每天开几十次，圆角多了会显得软。

### 16.4 排版

| 项 | 值 |
|---|---|
| 字号阶梯 | h1 1.9em / h2 1.42em / h3 1.16em |
| 段距 | 0.85em（早期 0.32em，段落粘在一起） |
| 标题上边距 | 1.5–1.85em（给足「新一节开始」的呼吸） |
| 中文 `letter-spacing` | 0.02em（中文加大字距会散架） |
| 正文行宽 | `--read-measure`，默认 800px，专注模式 ×0.92 |
| 正文左边距 | `max(54px, calc((100% - 宽)/2))`，不包 `max-width` |

h2 不加下划线：中文里那条横线会把标题压成「分节条」，显旧。

### 16.5 颜色语义

| 颜色 | 含义 | 不许用于 |
|---|---|---|
| 蓝（accent） | **当前态**：激活标签、选中项、焦点 | 装饰、普通链接排版 |
| 红 | 差异（修改片段、增删行）、危险操作 | 普通强调 |
| 琥珀 | 外部改动提示、警告提示块 | 未保存（那是蓝点） |
| 绿 | 成功提示块 | 「已保存」（那用文字） |
| 灰阶 | 其余一切 | — |

同类颜色不重叠：预览条里红=差异、灰框=视口，**不再给「当前差异」第三种颜色**。

### 16.6 图标

- 全部来自 Lucide（ISC），只 vendor 用到的；`scripts/build-icons.mjs` 编译成内联 sprite。
- 引用 `<svg class="ico"><use href="#i-x"/></svg>`；**绘制属性（fill/stroke/线宽）由 CSS 给**，
  symbol 里只留路径，天然跟随 `currentColor`。
- 图标尺寸 13–16px；**16px 下默认 1.75 的线宽只有 1.17px**，需要更实的图标（抓手、提示块）
  要单独把 `stroke-width` 提到 2–3，否则六个圆点糊成一层灰。
- 新图标下载后要验证内容（`grep` 路径数）；曾经 `curl` 没跟随 302，把「Redirecting…」
  当 svg 编译进 sprite，表现为所有图标隐形。

### 16.7 正文光标

系统 I-beam 只有 1px，且 Chromium 会按背景明暗自动翻色（深底白、浅底黑）——两种配色都细，
浅色底翻白时几乎看不见。

- 自绘 SVG：2px 竖线 + 1px 对比晕，热区必须在竖线正中（`7 12`），否则点击落点偏移。
- 只写在容器上靠继承（`.wysiwyg` / 预览正文 / CodeMirror 内容 / `textarea` / 文本框），
  **不要写 `*`**，否则会盖掉链接、复选框、拖拽把手自己的 cursor。
- `cursor: var(--cur-text), text`：变量里只放 `url(...) 7 12`，`text` 兜底留在规则里，
  图加载失败也不会变箭头。

### 16.8 动效

- 只保留「出现/消失」的即时切换，不做位移与缩放动画。
- 唯一的时间感来自 toast 的淡入和菜单的展开，均 ≤ 100ms。
- 滚动、输入、切标签不做过渡 —— 编辑器里任何延迟都会被读成「卡」。

## 17. 数据、隐私与安全

### 17.1 数据落在哪

| 数据 | 位置 | 说明 |
|---|---|---|
| 设置 / 草稿 / 会话 / 最近打开 | `localStorage`（前缀 `snp.`） | 由 WebView 的 profile 目录承载 |
| 历史快照 | `<app_data_dir>/history/<hash>/*.txt` | 一个文件一个目录，目录名是路径哈希；`name.txt` 存原名 |
| 速记 | `<app_data_dir>/quicknote.md` | 固定一份 |
| 粘贴 / 拖入的图片 | `<文档目录>/assets/` | 相对路径引用，换机器不断链 |
| 临时探针数据 | `%TEMP%\eznotepad-probe` | 只在测试时；绝不碰用户真实数据 |

`app_data_dir` 由 Tauri 按平台给出，代码里没有硬编码路径。

### 17.2 不联网

- 没有账号、没有遥测、没有自动更新检查、没有 CDN 依赖（KaTeX、CodeMirror、图标全部
  vendor 进仓库）。
- 打开外链是唯一会发起网络请求的动作，且由用户显式点击（`Ctrl+点击`）。
- 这条不是「暂时没做」，是产品承诺：断网、内网、隔离环境里必须完整可用。

### 17.3 删除

- 文件树删除、清理速记等**一切删除进系统回收站**（Windows `SHFileOperationW` +
  `FOF_ALLOWUNDO`），不是永久删除。
- 目录只删空目录。
- 删除前确认，确认框写清路径与「进回收站」。
- ⚠️ 非 Windows 分支目前是 `fs::remove_file`（永久删除），与产品语义不符（见《跨平台移植》B1）。

### 17.4 数据保护的分层

| 层 | 防什么 |
|---|---|
| 自动保存 + 草稿 | 忘记保存 / 崩溃 |
| 退出三选 | 关窗时丢掉未保存内容 |
| 保存前比 `mtime` | 覆盖别人刚写的内容 |
| 历史快照（60 份 / 20 MB） | 保存错了还能找回上一版 |
| 原子写盘 | 写一半断电留下半个文件 |
| 对比窗口关闭守卫 | 改完直接 Alt+F4 |

**每一层都只解决一种失效**，不能互相替代。加新功能时先问：它会绕过哪一层？

### 17.5 测试与构建不留垃圾

用户对「回收站被构建产物塞满」有明确要求，所以定成硬约定：

- 测试代码里**一行删除都不写**：Chrome profile 按端口固定并复用、夹具覆盖写、不放 `unlink`；
- 探针的 WebView2 数据目录固定在 `%TEMP%`（安全软件不备份 TEMP），绝不写用户真实配置；
- 每次构建后跑 `.workbuddy/tools/purge-build-trash.ps1` 只清本项目 target 下的条目；
- 这条约定写在《构建说明》的「零垃圾约定」，有实测数字。

## 18. 性能预算与降级

### 18.1 指标

| 指标 | 目标 | 现状（Windows） | 怎么测 |
|---|---|---|---|
| 主程序 | ≤ 8 MB | 约 5 MB | 二进制大小 |
| 安装包 | ≤ 5 MB | 2.63–2.68 MB | 构建产物 |
| 冷启动 | < 1 s | 约 0.6 s | 人工 / 日志 |
| 单次击键（600 段） | < 12 ms | 9.1 ms | 页面内打点 |
| 常驻内存 | < 250 MB | 约 170 MB | `WorkingSetPrivate`（不是 `PrivateMemorySize64`，后者虚高 60 MB） |
| 大文档 | 10 MB 可编辑 | 10.8 MB / 7.8 万块可用 | 生成夹具 |

### 18.2 输入路径纪律

1. **禁止全量重算**：normalize 只扫光标块 ±1；
2. 大纲 250 ms 防抖 + 结构签名；
3. 标签栏先比签名，没变就返回；
4. 大纲定位用二分；
5. 判「结构变化」只看块类型，不看文本 —— 纯文本编辑不重排块间距；
6. 序列化按块缓存（签名校验），纯打字不 renumber；
7. 字数统计 150 ms 节流、单趟扫描。

这七条是「600 段文档从 18.6 ms/字降到 9.1 ms」留下的，任何一条被「顺手简化」都会退回去。

### 18.3 降级阶梯

| 触发 | 降级 |
|---|---|
| 文档 ≥ 100 万字符 | 视口渲染（records + 窗口 DOM） |
| 代码块 > 8 万字符 | 不上色 |
| 文档 > 5000 块 | 给容器加 `content-visibility: auto` |
| 对比单文件 > 8 MB 或 5 万行 | 拒绝加载，先提示 |
| 对比差异 > 4000 行 | 预览条按段合并 |
| 文件夹对比 > 4000 行 | 截断并明说 |
| 搜索命中 > 200 条 | 截断并明说 |
| 递归列举 > 2 万文件 | 截断 |
| 查找命中 > 5000 处 | 停止继续收集 |
| 大纲 > 数万标题 | 列表窗口化 |
| 预览双栏 + 大文档 | 不降级，⚠️ 已知会卡（12.8 秒） |

**降级的共同要求：用户必须知道。** 截断要说「只显示前 N 条」，拒绝加载要说上限和建议，
不上色不提示（它不影响正确性）但也不能报错。

### 18.4 主动放弃的优化

- **CM6 惰性加载**：省 49 ms，但 `plain` 有 30 处同步调用，异步就绪会让首次读取拿到空内容；
- **后台降频**：Chromium 已经节流，再叠一层会动到草稿保护与文件监听的边界；
- **滚动性能调优**：后台窗口 rAF 被节流，测出来的数不可信，不拿它当依据改 CSS。

## 19. 平台差异

当前只正式支持 Windows。平台相关行为集中在四类，完整清单见《跨平台移植》：

| 类别 | Windows 做法 | 移植时要注意 |
|---|---|---|
| 窗口外观 | DWM 圆角（Win11）、无边框 + 自绘标题栏、最大化靠 `SetWindowPos` 铺满工作区 | macOS 用 `titleBarStyle: Overlay`；Linux 用 GTK 最大化 |
| 工作区 | `MonitorFromWindow` + `GetMonitorInfoW().rcWork`，按窗口所在屏算 | 三平台都要问「窗口在哪块屏」 |
| 删除 | 回收站 | 非 Windows 目前是永久删除（债） |
| 浏览器参数 | `additionalBrowserArgs`（`--disable-gpu-sandbox` 修全黑窗口） | wry 只在 Windows 编译该字段，其它平台忽略 |
| 拖放 | 原生通道拿真实路径 | macOS / Linux 需实测 |
| 文件关联 / 单实例 | 安装器注册 + 插件 | macOS 双击走 `RunEvent::Opened`，不是 argv |

**WebView 内核不同，性能数字不能照搬**：这三个平台上必须重测 §18.1，
尤其「10 MB 可编辑」和「GPU 进程内存」。

## 21. 已知设计债（产品视角）

结构与移植层面的清单在《架构设计》§13；这里只列**用户能感觉到**的：

1. **快捷键文案写死 `Ctrl`**（约 130 处）。macOS 上能用（匹配 `⌘`），但显示错。
2. **双栏 + 大文档会卡**：预览侧没有视口化，6.4 MB 文档切布局约 12.8 秒。
3. **视口模式的选区跨不出窗口**：10 MB 文档里拖选只能覆盖当前窗口内的块；
   全选走逻辑全选，但「拖到窗口外」不是。
4. **大文档撤销深度 = 1 步**（8 MB 历史上限，10 MB 文档一份快照就占满）。
5. **非 Windows 删除是永久删除**，与界面文案（进回收站）不符。
6. **打印依赖 `window.open`**，mac/Linux 待实测。
7. **标签的 `readonly` 字段基本没派上用场**：目前只在插入图片时检查，真正只读态在对比窗口。
8. **macOS 菜单会重复**（系统一套 + 自绘一套），移植时必须二选一。
9. **Mermaid / 孤儿图片清理 / 跨文件替换**是明确不做，不是欠账；但用户提起来时需要解释。
10. **对比窗口「编辑」按钮的 `title` 写了按 `E` 切换，代码里没有这个绑定**。要么补键位
    （但 `E` 是普通字母，得先判焦点不在可编辑行，容易误吞输入），要么把 `title` 里的
    「（E）」去掉。现在属于「文案承诺了、行为没做到」，优先改文案。

## 附录 C · 一次交互的完整状态（自查用）

改一个功能时，至少把这五件事过一遍：

1. **入口**：键盘、菜单、右键、按钮 —— 有没有漏一处？
2. **禁用态**：不可用时是变灰、隐藏，还是点了给提示？三种语义不能混。
3. **失败态**：读不到、写不进、格式不支持时，用户看到什么？下一步能做什么？
4. **持久化**：刷新 / 切标签 / 重启之后，这个状态还在吗？该在的要在，不该在的不能粘住。
5. **可撤销**：这一步改内容，`Ctrl+Z` 能回去吗？回去之后光标和视口在哪？
