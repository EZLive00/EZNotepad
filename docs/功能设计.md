# EZNotepad · 功能设计

> 读者：要改功能行为的人、要判断「这个需求该不该做」的人、接手后想知道「为什么是这样」的人。
>
> 四份文档的分工——**本文写业务规则与落地细节**：每个功能对用户承诺什么、边界在哪、
> 为什么不选另一种做法，以及做界面时的确切取值（像素 / 颜色 / 阈值）与踩过的坑。
> 《架构设计.md》写结构与不变量、以及这一路踩过的坑；《实现规格.md》写算法判据、磁盘格式、
> 常量与测试向量（**要照着重写一份时看它**）；《构建说明.md》写环境与打包。
> 本文不重复代码结构，只在与规则直接相关时引用【不变量 N】。

## 0. 这份文档怎么读

全文按**用户能感知的功能**分章，不按代码模块。每章尽量回答四个问题：

| 记号 | 含义 |
|---|---|
| **规则** | 必须成立的行为。改它之前先想清楚会破坏谁的预期 |
| **为什么** | 这个选择换来了什么、放弃了什么。没有理由的规则通常会被人「顺手优化」掉 |
| **边界** | 明确不处理的输入、上限、失败时的表现 |
| **文案** | 用户实际看到的字。按钮、提示、空状态都算 |
| **取值** | 尺寸、颜色、阈值。章末以「落地：……」小节集中给出，做界面或移植时照抄 |

三个符号贯穿全文：

- ✅ 已承诺的行为，测试里有断言守着；
- ⛔ 明确不做，不是没来得及；
- ⚠️ 已知设计债，写在这里是为了不让人以为是 bug。

**一条总原则**：所有「说不通」的地方，优先改成用户不用想就能用的行为，而不是写一句提示让
用户去适应。提示只在**无法避免**时出现（比如格式限制、数据可能丢失），而且必须说清
「发生了什么、会有什么后果、下一步点哪儿」。

## 1. 产品定位与取舍

### 1.1 一句话

一个**不登录、不联网、打开就能写**的 Markdown / 纯文本编辑器，自带一套够用的文本与文件夹
对比工具。装完 2.6 MB，冷启动约 0.6 秒，常驻内存约 170 MB（其中一半是系统 WebView 的
GPU 进程）。

### 1.2 用户与场景

| 场景 | 具体动作 | 设计上的后果 |
|---|---|---|
| 写笔记 / 文档 | 新建 md、边写边看、插图、公式、目录 | 所见即所得必须是默认模式，且不能有「预览延迟」 |
| 改配置 / 看代码片段 | 打开 json / yaml / sh、看高亮、改两行 | 非 md 文件不该进所见即所得，编辑模式要有行号与缩进 |
| 比对两份东西 | 两份文本、两个目录、三份版本合并 | 对比要独立窗口（主窗口塞不下两栏），且能直接改 |

这三件事的频率远高于「管理一个知识库」。所以产品里没有工作区、没有数据库、没有索引、
没有后台进程 —— 打开一个文件就是打开一个文件。

### 1.3 需求筛子

任何新功能先过三问（写在《架构设计》§1，这里是执行口径）：

1. **每天都会用到吗？** 一年用两次的功能，占的是菜单位置和别人的注意力。
2. **能不联网、不登录做完吗？** 需要账号的功能一律不做 —— 它会把「打开就能写」变成
   「先验证邮箱」。
3. **会让「打开一个 md」变慢，或让安装包明显变大吗？** 这条是硬约束。

第 3 问有具体数字，不是感觉：冷启动 < 1 秒、常驻 < 250 MB、
600 段文档单次击键 < 12 ms —— **这三项是硬约束，顶破了就要重新谈**，
而不是「先加上，以后再优化」。

体积单独说，因为它的口径变过：原来是「主程序 ≤ 8 MB、安装包 ≤ 5 MB」，现在是
**「不为体积砍功能，20 MB 以内都算小」**（见 §1.5）。判断依据是：真正影响「打开就能写」
的是冷启动与内存，而不是下载那 3 MB。所以体积只要没到几十 MB 的量级，按平常心处理。

### 1.4 明确不做

| 不做 | 原因 | 如果用户要 |
|---|---|---|
| Mermaid 图表 | 完整包 2.75 MB，是当时 exe 的 63%；裁成 core 也只是一堆带 hash 的分块，vendor 化后升级困难 | 用「代码块 + 外部截图」表达 |
| 图床 / 账号 / 云同步 | 违反第 2 问；同步冲突的复杂度远超这个产品的价值 | 用网盘同步文件夹 |
| 插件市场 | 插件 API 会把「零依赖、可复现」的架构变成平台工程 | — |
| 多窗口拆分编辑 | 单窗口 + 标签已经够；多窗口要处理布局持久化、焦点、快捷键归属 | 拖到第二个显示器开两个实例（单实例插件会拦住，属已知取舍） |
| 二进制对比 | 十六进制视图是另一个产品 | 用专门工具 |
| 跨文件批量替换 | 一次误点改几十个文件，撤销要按文件翻历史；真实需求极低 | 单文件内 `Ctrl+H`；确实要批量时用命令行 |
| 四栏可视化合并 | 交互复杂度高，维护成本与使用频率失衡 | 三向合并向导 + 两栏对比组合使用 |
| 表格的可视化网格编辑（像 Excel） | 见 §5.11：单元格已经能直接编辑，再加一层网格是重复投入 | 直接改单元格 |
| 孤儿图片清理 | 同目录多篇文档共用一个 `assets/`，判「没人引用」得先扫全目录，误删风险高 | — |
| 视口模式下的「模型级跨窗选区」 | 10 MB 文档里跨十万块拖选，选区落点与自动滚动都要重做；收益不足以支撑 | 分块复制，或用编辑模式全选 |
| CodeMirror 惰性加载 | 能省首屏 49 ms，但 `plain` 有 30 处同步调用，异步就绪会让首次读取拿到空内容 | 接受这 49 ms |
| 后台窗口降频 | Chromium 自己会节流；再叠一层要改动草稿保护与文件监听的边界 | — |

**不做的功能也要能被搜索到**：README 的「已知限制」列出它们，避免每次有人重新提议、
重新评估、重新否掉。

### 1.5 改过的决定（留档，防止走回头路）

| 曾经 | 现在 | 为什么改 |
|---|---|---|
| 三层底色（画布 / 面板 / 浅坑）区分区域 | **同色平面 + 1px 线** | 三层底色在深色下要差 12 级才看得出来；差不够就糊成一块，差够了又像补丁 |
| 激活标签底部伸一块「引脚」把边线顶断 | 无引脚，整条线连续 | 全域同色后，引脚本来是「连接标签与正文」的隐喻，底色一样时它只剩一个缺口 |
| 块尾插入指示线在「点在最后一块下方」时总亮 | 只在该块真的会补一行时亮 | 指示线的全部意义是预告「点这里会多一行」；行为收窄了它还亮，就是骗人 |
| 文本对比是主窗口里的浮层 | 独立窗口 | 两栏各需 600 px 起，浮层里永远不够宽；独立窗口还能有自己的最大化 |
| 对比窗口默认只读 | 默认直接可写 | 默认只读的代价是「点一下正文没反应」，用户会以为窗口坏了；误改有三层兜底（行脏标记 / 撤销 / 关窗确认） |
| 退出三选里有「存为草稿并退出」 | 去掉，只留「全部保存并退出 / 不保存退出 / 取消」 | 与「全部保存」语义重叠且低频；未命名文档仍由草稿兜底接住 |
| 「速记」是一级下拉，第一项叫「打开速记」 | 一级**动作**，点一次直接打开 | 用户的第一反应是「我已经点了速记」，不该再点第二次 |
| 设置塞在「工具」最后一项 | 顶级「设置」 | 工具是「处理文本」，设置是「配置软件」，两类东西不该共用一个菜单 |
| 格式化快捷键 `Ctrl+Shift+F` | `Ctrl+Alt+L` | 撞 Windows 繁简切换，`preventDefault()` 拦不住系统级热键 |
| 侧栏顶部有齿轮图标 | 删掉 | 它紧贴「大纲 / 文件」页签，看起来像「这一栏的设置」 |
| 有「打印」，靠隐藏窗口 + `window.print()` | **只留「导出 PDF」**，走 WebView2 `PrintToPdf` 直接落盘 | 嵌入式 WebView 里 `window.print()` 是空实现：不弹框、不报错、不 reject。「打印」这个功能在本宿主上根本不存在，不是配置问题，留着只会让人反复点、反复没反应 |
| 「导出 PDF / 导出网页 / 历史版本」后面带 `…` | 去掉 | `…` 表示「点了会先弹框让你填」，这三个里只有 PDF 会弹保存框（那是系统行为，不是问参数）。两个相邻项一个带一个不带，用户只能挨个试 |
| 速记下拉里有「插入当前时间 / 保存在 …（路径提示）/ 在文件夹中显示 / 复制路径」 | 全删，只留「清空速记」；「在文件夹中显示」提到「打开文件夹」下面、对所有文件生效 | 时间戳在正文里直接打得比菜单快；路径提示用省略号截断后反而不知道在哪，而且「在文件夹中显示」本来就能回答它；复制路径在标签右键里已有。这一栏除了「清空」全是重复入口 |
| 体积是硬预算（主程序 ≤ 8 MB / 安装包 ≤ 5 MB），并为此砍过功能 | **不砍功能，20 MB 以内都算小**；仍然「能小则小」，但不再为几百 KB 改方案 | 集成 mermaid 后 exe 5.1 → 7.56 MB、安装包 2.63 → 4.58 MB，本来准备裁剪图类型把体积收回去。判断改成：用户真正在意的是「打开一个 md 快不快」，不是下载那几 MB。把预算挪到冷启动（< 1 s）与常驻内存（< 250 MB）上，那里才是手感 |
| 不支持 ```mermaid | **支持**（写 mermaid 出图），不做拖拽式画图 | 引擎 5.12 MB 但**只在有 mermaid 块时才加载**，实测渲染两张图 JS 堆 +21 MB —— 都在「体积不明显增加、内存 50 MB 以内」的预算里，且无图文档零成本。图形编辑器不做：凡是「能画出来」的都必须能写回源码，拖拽式编辑器做不好这一层反而制造两份真相 |

## 2. 界面骨架与信息层级

### 2.1 五块

```
┌──────────────────────────────────────────────────────────────┐
│ 标题栏 34px  品牌 · 菜单栏 · 窗口按钮（拖动区）                 │
├──────────────────────────────────────────────────────────────┤
│ 标签行 33px  标签 … ＋ …………… 模式 / 查找 / 保存（右）        │  合计 68px
├────────────┬─────────────────────────────────┬───────────────┤
│ 侧栏        │ 编辑区（单栏或左半）             │ 预览（双栏时） │
│ 大纲 / 文件 │                                 │               │
├────────────┴─────────────────────────────────┴───────────────┤
│ 状态栏 27px  行列 · 行数 · 字数 · 类型 · 换行符 · 编码 · 草稿   │
└──────────────────────────────────────────────────────────────┘
```

**顶部只占 68px**（34 + 33 + 1 底边线）。这不是审美问题：笔记本 768 高的屏上，
每 10px 都是正文。曾经是「标题栏 40 + 标签栏 32 + 工具栏 35 = 107」，一次把工具栏并进
标签行、一次把标题栏压到 34，才有了现在的数字。

### 2.2 快捷按钮只留一排

标签行右侧只有 **模式切换（下拉）、撤销、重做、查找、保存**。其余命令全在菜单里，理由有两条：

1. 同一命令摆两处，两处都要维护图标、禁用态、勾选态；
2. 菜单能表达「当前是什么」——「大纲开着」「主题是深色」「当前是双栏」，工具栏按钮
   只能表达「点我会怎样」。

**为什么撤销/重做留在上面**：它们是仅有的两个「打字打到一半会去点」的命令，
而且变灰本身就是信息（没得可撤的时候，看菜单才知道自己要按几下）。其余动作
（新建/打开/单栏双栏/大纲/格式化/对比/主题）都只在菜单里，且带勾选状态。

**保存按钮兼作脏标记**：有未保存改动时整颗按钮淡蓝高亮。曾经在右上角做小圆点，实测会压在
「存」字上，弃用。

### 2.3 标签

| 规则 | 细节 |
|---|---|
| 宽度 | 单颗最大 133px，文件名最长 100px 后省略号 |
| 激活态 | 字重 600 + 全亮文字；**同一串文字的加粗版用 `::before` 占位**，否则中文一加粗就变宽，切换标签时整行标签左右抖 |
| 边框 | 上下借用标签行的两条线；**一条缝只画一条线** —— 每颗只画左边框，两颗之间的线归后一颗所有，最后一颗额外画右边框收口。⛔ 不许再给每颗画左右两道再用负 margin 压 |
| 首末颗 | 最左颗的左边框置透明（宽度留着，避免 1px 位移）；**最右颗的右边框要画出来**，标签区右端得有收口 |
| 状态色 | 悬停 / 激活只改那颗左右两条边的颜色；右边那条属于右邻的左边框，用 `+ .tab` 兄弟选择器同步，⛔ 不靠 `z-index` 抬层盖住另一条 |
| 关闭 | 悬停出现 ×；中键直接关；`Ctrl+W` 关当前 |
| 拖拽换位 | 拖到标签左右半区决定插前/插后，落点画 2px 竖线 |
| 未保存 | 名字前一颗 7px 蓝点 |
| 被外部改过 | 名字后一颗 5px 琥珀点，与蓝点分开（见 §3.7） |
| 溢出 | 见 §2.4 |

**为什么改回「左边框 + 最后一颗补右边框」**：旧约定怕标签隐藏 / 重排时得用 JS 重算
哪颗是最后一颗，其实 `:last-child` 由选择器引擎自动维护，`renderTabs()` 全量重建也照样
对。而原来「每颗左右各一道 + `-0.5px` 负 margin」在 WebView2 里是实打实的粗线：
`--bw` 被取整成 1px，两道 1px 只错开半像素，接缝宽 **1.5px**（用户反馈「中间的
分割线比较粗，好像两边的边框都显示了」）。一条缝只画一条线才是正解；最右那道边框
由用户要求补回，不再置透明。

**为什么不用「激活标签加底色块」**：全域同色之后，底色块要么和背景差不够（看不见），
要么差太多（像补丁）。字重 + 全亮 + 竖线断开已经足够表达「我在哪」，而且切换时不会闪。

### 2.4 标签溢出（十几个标签之后）

标签条能横滚，但滚动条被藏起来了（一条横向滚动条会把标签挤扁）。于是「后面还有标签」
既看不出来，也没有可抓的东西。三个入口都补齐：

| 入口 | 规则 |
|---|---|
| 滚轮 | `deltaY` 当横向位移；`deltaMode === 1`（按行）要 ×16，否则一格只动 3px |
| 拖标签贴边 | 指针距左右边缘越近滚得越快；**必须用 `requestAnimationFrame` 自循环**，指针不动就不会有第二个 `dragover`，靠事件驱动会停在半路 |
| 「全部标签」下拉 | 右侧按钮只在真的溢出时出现；清单带滚动条，当前项 ✓、脏项 ● |

**当前标签必须自动滚进视野**：新建的排在最后，不滚过去，界面上就是「点了新建没反应」。
判定用 rAF 合并，`renderTabs` 与 `resize` 各调一次。

### 2.5 状态栏

`行列 · 行数 · 字数 · 字符数 · 类型徽章 · [右] 换行符 · 编码`

**没有「草稿状态」这一格**：`已保存` / `草稿已同步` 这类信息几乎永远成立，写在那儿只是
在提醒用户「注意这里」，而真正需要他知道的事（磁盘满、文件被占用）根本塞不进这一格。

- 字数统计口径：中日韩单字各算 1，ASCII 连续段算 1；行数 = 换行数 + 1。**单趟扫描**，
  10 MB 文档 39 ms（旧实现 `split('\n')` + 两次全局正则要 125 ms）。
- 类型徽章跟着当前标签变，不再是「打开第一个文件时算出来的那个」。
- 编码与换行符是**按钮**：点一下就能改，不用去菜单里找。
- **行列只在源码模式显示**：另两种模式没有「第几行第几列」这回事，整格收起来
  （`hidden`），不摆一个 `—` 让用户猜它是什么。
- 字数与字符数是**两条独立条目**（`3 920 字`、`5 128 字符`），不再用「·」把两个数粘成
  一个字符串 —— 中点既不是中文标点也不该出现在数据里。

### 2.6 菜单栏

**顺序：文件 / 编辑 / 格式 / 插入 / 视图 / 工具 / 设置 / 帮助 / 速记 / 对比。**

排序依据是频率与性质，不是字母：

| 位置 | 内容 | 为什么在这儿 |
|---|---|---|
| 前 6 项 | 文件 / 编辑 / 格式 / 插入 / 视图 / 工具 | 编辑器惯例顺序，肌肉记忆 |
| 设置 | 单独一级、点一下直接开面板 | 它不属于「处理文本」 |
| 帮助 | 快捷键一览 / 关于 | 惯例放最后 |
| 速记 | **动作项**，点一次直接打开 | 高频；不套「打开速记」 |
| 对比 | 文本 / 文件夹 / 三向合并 | 高频；固定最右，伸手就到 |

两条硬规则：

1. **一级菜单只有两种形态：下拉，或动作。** 动作项点一次就执行，不能先展开再让人点第二下。
   键盘左右键要**跳过**动作项，否则光标会停在「没有面板」的项上，看着像卡死。
2. **同一个命令不在两处各列一遍。** 所以「工具」里不再有文本 / 文件夹 / 三向合并；
   命令面板仍然全部收得到，它是从菜单树现抽的。

还有两条文字层面的约定（看着琐碎，但每条都对应过一次「用户以为点了会弹框」）：

3. **省略号 `…` 只表示「点了会先弹一个框让你填东西」。**
   | 有 `…` | 没有 `…` |
   |---|---|
   | 打开… / 打开文件夹… / 另存为… / 查找… / 替换… / 跳转到行… / 链接… / 图片… / 表格（自定大小）… / 目录… / 命令面板… / 文本对比… | 导出 PDF / 导出网页（HTML）/ 历史版本 / 在文件夹中显示 / 清空速记 / 重新载入 / 关闭标签 |

   反例说明为什么值得管：`导出 PDF` 曾经带 `…`，用户点下去以为会先问「存哪儿」，
   结果系统保存框直接弹出来（其实一样），但同一排的 `导出网页` 没有 `…` 却也弹框 ——
   两个挨着的项、两种写法，用户只能挨个试。现在按「是否先弹框」统一，不再按「是否碰文件」猜。
4. **「在文件夹中显示」紧跟「打开文件夹…」，且对任何打开着的文件都有效**（不限于速记）。
   它回答的是同一句话「这个文件在磁盘的哪儿」，所以放在一起；速记不再单独拥有一份。

菜单内部的表达手段：

| 手段 | 用途 | 例子 |
|---|---|---|
| 分组小标题 `head` | 一条线只说明「断了」，文字才说明「这是哪一组」 | 标题级别 / 文字 / 段落 |
| 一行多个 `row` | 互斥的单选题横排，当前项点亮 | 正文 / H1 / H2 / H3 |
| 按上下文隐藏 `hidden` | 不是变灰，是根本不渲染 | 不在表格里就不显示表格操作 |
| 说明行 `note` | 一句话解释「为什么这项是灰的 / 去哪儿找」 | 「标题与列表只在所见即所得模式下可用」 |
| 勾选 `checked` | 表达当前状态 | 大纲开着、主题是深色、双栏 |

**勾和图标共用一个 18px 槽**：有勾显示勾，没勾显示图标。否则带图标和带勾的两行，
文字左边缘会差一格，整列看起来是歪的。

### 2.7 右键菜单

右键菜单和主菜单共用一套渲染器，规则一致，另加：

- **定位必须量真实尺寸**：先以 `visibility:hidden` 挂上去，读 `offsetWidth/offsetHeight`，
  再四边夹取。早期按「项数 × 30」估高度，23 项的表格菜单估成 710px，窗口矮于 730 时
  `top` 被算成负数，菜单上半截永远在屏幕外——用户看到的是「靠上右键弹不出来」。
- 比窗口还高时给 `max-height` + 纵向滚动，不硬塞。
- **药丸**可以带 `checked`（点亮当前值）、`iconOnly`、`hint`（`title` 用完整说法，
  比如「本列取消对齐」）；`danger` 可以标在整行（`{lead:'删除', danger:true, row:[…]}`）。
- **关闭时机只有五种**：点别处（`document` mousedown 捕获）、Esc（捕获并阻止冒泡，
  防止同时触发「退出专注模式」这类全局 Esc）、滚动（捕获）、`resize`、`blur`。
  **鼠标移动永远不该关它**——曾经块菜单一挪鼠标就消失，根因是「菜单和按钮之间那 4px 缝」
  落在编辑区里，一次 `mousemove` 就把菜单收了。
- **锚在固定控件上的菜单要传 `stayOnScroll`**（标签条、工具栏）。滚动事件是排队派发的，
  「刚滚过标签条就点全部标签」会被迟到的 `scroll` 收掉，症状是「点了没反应」。

**两个右键菜单的成套项**（1.2.8）：

| 菜单 | 项目 | 规则 |
|---|---|---|
| 标签右键 | 关闭 / 关闭其他 / 关闭左侧 / 关闭右侧 | 三个方向按「其他 · 左 · 右」相邻；没有可关目标的项**置灰**，而不是点了没反应 |
| 标签右键 | 复制文件路径 / 在文件夹中显示 | 未命名文档没有路径，两项都置灰 |
| 文件树行右键 | 重命名… / 删除 / **历史版本**（仅文件）/ 复制文件路径 / 在资源管理器中显示 | 复制路径紧挨在「显示」之前；文件与目录都给，复制的是**被右键那一行**的完整路径（不是多选的整组）。「历史版本」按**被右键的路径**列快照，不要求该文件已打开 |

⛔ **复制路径只有一份实现**（`src/js/clipboard.js`，离屏 textarea + `execCommand('copy')`）。
WebView2 里 `navigator.clipboard.writeText` 会抛 `NotAllowedError`，旧版标签右键用了它却
无条件弹「路径已复制」——一个永远成功不了的假反馈。失败必须真的说「无法复制路径」。
⛔ **批量关闭不许静默丢数据**：三个方向统一先收脏标签、整批**只确认一次**（全部保存并
关闭 / 不保存并关闭 / 取消）。保存走各标签自己的 `t.content`（⛔ 不是 `readEditor`，那是
屏幕上活动标签的正文）；没有路径、存不进去的脏标签写进草稿，下次启动还能恢复；速记先
`flush`。以前这三个动作直接 `removeTab`，比单个「关闭」还不如。

### 2.8 对话框与设置面板

- 通用对话框：标题 + 正文 + 按钮（主按钮一个，其余为次要 / 危险）。
- **设置面板没有「确定」**：所有改动即时生效，底部只有「完成」。省掉「改完忘了点确定」
  这一类挫败。
- 设置分四页：**外观 / 界面 / 文件 / 快捷键**，左侧分类、右侧内容，宽 760px。
  切页只切显隐，所有控件留在原处，不会因为切页丢焦点。
- Esc 关闭；点遮罩关闭（正在输入的重命名框除外）。
- **对话框内不要用 `document.getElementById` 找还没挂载的节点**：`box` 还没 append 到
  `#dlgBody` 时，全局查询拿不到，报 `Cannot set properties of null`；一律 `box.querySelector`。

### 2.9 空状态

空状态不是「没内容」，是「告诉用户下一步点哪儿」：

| 位置 | 文案 |
|---|---|
| 没有标签 | 自动建一份「未命名.md」（欢迎文档只在首次启动出现） |
| 侧栏文件页未选文件夹 | 「还没有打开文件夹」+「选择文件夹」按钮 |
| 大纲为空 | 按文件类型分别说明：md「用 # 写标题就会出现在这里」；txt「只识别章节标记，不会猜」；data「表格数据不提取大纲」 |
| 搜索无结果 | 「没有找到匹配的内容」+ 当前搜索范围 |
| 对比窗口未打开文件 | 两个空白编辑区 + 提示「把两段文本分别粘到左右两侧，或点上面的文件名打开文件」 |

**空状态里不放插画**。这个程序的用户是来干活的，一张大图只会让「正文从哪儿开始」更难判断。

**统计口径**（`countStats`，一次线性扫描，不建中间数组）：

| 类 | 规则 |
|---|---|
| 词 | 中日韩统一表意文字（`0x4E00`–`0x9FA5`）**一字一词**；ASCII 连续 `0-9 A-Z a-z _ - '` 算一词；其它字符只做分隔 |
| 字符 | `text.length`——**含空格、含换行**（不做任何过滤） |
| 行 | 每个 `\n` 计一次 + 1，所以末尾有换行的文件会多出一行空行 |
| 显示 | 原样数字，**不做「万」缩写**；两条独立条目：`{词} 字`、`{字符} 字符` |

⚠️ 统计的是**内存里的 `\n` 文本**，不是屏幕上折行后的行数，也不是 CRLF 的字节数。

**坑**：
- ⛔ 字数在**输入路径上**不能算全篇。打字时只更新 `#stPos`；`#stLines`/`#stWords`
  走 `refreshStats()`，由防抖（约 250ms）触发。
- ⛔ **别再往状态栏加「已保存 / 同步中」这类几乎永远成立的状态**（2026-11-09 删掉了
  `#stDraft`）。它平时不提供任何信息，出事时又说不清原因——那种情况要走对话框。
- ⛔ 字数与字符数别拼成一个串。**没有分隔符可用**（中点被明令禁止，顿号读起来像并列的
  两类东西），两个数就是两个条目。

**验收**：手测——打开 10MB 文件看数字是否在 1s 内出现；改一个字看是否变「未同步」。

## 3. 文件、标签与数据安全

这一章的所有规则都服务同一个目标：**用户的东西不能丢，也不能在用户不知道的时候被改。**

### 3.1 新建

- 入口：`Ctrl+N` / 文件 → 新建 / 标签行 `+`。
- 先弹**类型网格**（**28 种**：md / txt / json / jsonl / yaml / csv / js / ts / py / html /
  css / sh / go / rs / java / kt / cs / c / cpp / php / rb / lua / sql / xml / toml / ini /
  vue / diff），点一下直接开，回车开上次用过的类型（`settings.lastNewExt`）。
- 网格末尾是**自定义**：填任意扩展名（`r`、`kt`、`jsonl`、`foo`）→ 建 `未命名.<ext>`。
  输入合法之前「创建」按钮是灰的，回车只认这一格（不会被对话框的全局回车抢走）。
  认不出的扩展名按纯文本处理，不会因为「不在列表里」拦住用户。
- 网格最多 56vh 高、可滚；自定义那行**吸在底部**，类型变多以后不会被挤出可视区。
- 未命名文档自动编号：「未命名.md」「未命名 2.md」……连开三个不该都叫一个名字。
- 新建不写磁盘。第一次 `Ctrl+S` 才问路径。
- 新建完**立即可打字**：焦点自动落进编辑区，空文档的光标钉在第一个位置，
  不用先点一下正文。所见即所得是空段落首位，非 md 是 CM6 的偏移 0。

**类型的唯一真源是 `src/js/langs.js`**：一个扩展名对应哪门语言、哪套着色、哪个格式化
引擎、哪种预览方式，都写在那张表里。新建网格、编辑区着色、预览分流、格式化选引擎
四处都查它 —— 以前四处各写一份，于是 `.jsonl` 没高亮、`.kt` 也没有。

**为什么先选类型**：新建一个 `.py` 却先得到 `未命名.md`、再让用户去另存为改扩展名，
是把自己的实现顺序（先有标签、后有类型）摊给用户看。

**坑：焦点不会自己回编辑区。** `setMode()` 只负责把内容画出来，从不接管焦点；
「新建文档」的类型网格是 `dialog()`，关窗只给遮罩加 `hidden`，焦点仍留在那个
`display:none` 的格子上，浏览器不会把它自动转交给编辑区。所以焦点必须在
`newTab()` 末尾按 `t.mode` 显式交出去，且**只给空文档摆光标** —— 打开已有文件、
恢复草稿的 `caret` / `scrollTop` 归 `setMode()` 管，抢着摆会把视口拽回顶部。
验收：`test/run-app.mjs` §6b、`test/probe-app.mjs`「新建完光标与焦点」段。

### 3.2 打开

| 入口 | 规则 |
|---|---|
| 对话框 | 过滤器覆盖 md / txt / 常见代码 / 数据文件；可多选，一次开多个标签 |
| 拖入 | 走 Tauri 原生拖放通道，拿得到**真实路径**；图片复制进 `assets/`，其它当文档打开；多选开多个 |
| 命令行 / 文件关联 | 双击文件或 `EZNotepad.exe a.md b.md`；已有实例时把路径交给它（单实例） |
| 最近打开 | 文件菜单里最多 6 条；localStorage 存 12 条，超出丢弃最旧 |
| 文件树 | 单击预览？不——单击即打开；多选后可「比较这两个文件」 |

**拖入必须是原生通道**（`dragDropEnabled: true`）。HTML5 `drop` 拿得到字节但**拿不到路径**，
而没有路径就没法「打开这个 md」。代价是从别的程序拖一段选中文字进来也会失效
（wry 会关掉外部拖放），这个取舍是明知且接受的。

### 3.3 类型与模式矩阵

| 类型 | 可用模式 | 默认 |
|---|---|---|
| Markdown（md / markdown） | 所见即所得 / 编辑 / 预览 | 所见即所得 |
| 其它一切（txt、json、csv、代码、日志…） | 编辑 / 预览 | 编辑 |

- 非 md 文件**不提供**所见即所得：它的结构不是 Markdown，硬套块模型只会改坏文件。
- 「预览」对非 md 不是「渲染成网页」，而是按类型分流：JSON 格式化 + 错误定位、
  代码语法高亮、CSV 按表格看、其余纯文本。
- 状态栏的类型徽章、预览分流、格式化策略、大纲提取策略，用的是同一套类型判定，
  不允许各写一份。

### 3.4 读盘：编码、BOM、换行、二进制

| 项 | 规则 |
|---|---|
| 编码探测 | UTF-8（含 BOM）→ 否则按 GB18030 尝试 → UTF-16LE/BE 按 BOM 认 |
| BOM | 读到就记住；保存时原样写回（不替用户「顺手去掉」） |
| 换行 | 读入后内存统一 `\n`，同时记住原文件是 LF 还是 CRLF，保存时还原 |
| 二进制 | 内容里出现 NUL 字节即判二进制，**拒读**并提示，不当文本硬解 |
| PDF 文件 | **按扩展名**在打开入口分流给系统默认阅读器，不进编辑器；给一条明确的 toast |
| 新文件 | 默认 UTF-8 / 无 BOM / LF |

PDF 是唯一按扩展名判的例外：它是二进制，走 `read_text_file` 只会得到「这是二进制文件」，
而硬塞进标签更糟 —— `t.content` 会跟着草稿 / localStorage、保存、格式化、查找、
外部改动重载一路走，每一处都得为它开特例。所以在 `openPath()` 一处分流，
文件树、拖放、命令行、「最近打开」全部自动生效；「打开文件」对话框的过滤器里
加一项 PDF 才点得到。**明确不做**：程序内嵌 PDF 阅读器（WebView2 的内置 PDF viewer
受 Edge 策略控制、不同机器行为不一致，用 pdf.js 自绘则要新增渲染引擎与 worker）。
打开后不建标签、不进会话、不记草稿，只进「最近打开」。

**内存统一 LF 是硬规则**：不统一的话，一个 CRLF 文件打开就「已修改」（DOM 里的 `\n` 与
磁盘的 `\r\n` 不等），用户按一次 `Ctrl+S` 会把整个文件的行尾翻一遍，diff 里全是噪音。

### 3.5 保存

- **原编码、原 BOM、原换行写回**：用户没要求转码，编辑器就不该转。
- 写盘用「临时文件 + 替换」的原子策略，避免写一半断电留下半个文件。
- 「另存为」之后，标签指向新路径。
- 外部生成的内容（对比结果、合并结果）没有原路径，保存时必须问路径，不能默默写到某个
  默认位置。
- 编码可以手动改（状态栏编码按钮 / 工具 → 文件编码）：UTF-8 / GBK / UTF-16LE 三选，
  另有「保存时写入 BOM」开关。改完提示「保存后生效」——它只影响下一次写盘，不立刻转码。

### 3.6 自动保存

| 项 | 规则 |
|---|---|
| 默认 | **开** |
| 生效范围 | 只对**已经有磁盘路径**的文件 |
| 时机 | 停手约 1.2 秒；连续输入会不断重置计时 |
| 提示 | 静默，不 toast、不闪状态 |
| 保存前 | 再比一次磁盘 `mtime`，被别人改过就先问（见 §3.7） |

未命名文档不自动保存：静默写盘会让文件管理器里凭空多出一堆 `未命名.md`。
它们走草稿（§3.8），退出时仍然有兜底。

### 3.7 外部改动

别的程序（或生成脚本）改了同一个文件，我们再保存就会把对方的改动默默抹掉 ——
这是记事本类软件最伤数据的一种 bug。

| 环节 | 规则 |
|---|---|
| 监听 | `notify` 只监听**文档所在目录的一层**（NonRecursive）；事件里拿文件名比对名单，不在名单里直接丢 |
| 事件过滤 | 只看 Modify / Create / Remove；`Access` 一律跳过（我们自己 stat/读文件也会产生） |
| 合并 | 前端 300 ms 合并一次变更，再等 250 ms 处理（Windows 上一次保存会拆成「截断 + 写 + 改属性」好几个事件） |
| 自激 | 保存成功后立刻同步 `t.mtime`，事件回来时时间相同即返回 |
| 内容未变 | 静默重载，不打扰 |
| 内容变了，且本标签没改 | 前台：提示「文件在磁盘上被修改，已重新载入」；后台：不弹窗，标签上冒琥珀点 |
| 内容变了，本标签也改了 | **必须问**：重新载入（丢本地改动）/ 保留我的（下次保存覆盖磁盘） |
| 保存前 | 无条件再比一次 `mtime`，包括自动保存 |

琥珀点和蓝点必须能分开看：蓝点是「我没存」，琥珀点是「别人改了」。两个都用蓝点，
用户会以为自己记错了。

### 3.8 会话恢复与草稿

两个不同的东西，别混：

- **会话**（`snp.session`）：上次开了哪些标签、各自什么模式、滚动到哪、光标在哪。
  只记路径，不记内容。
- **草稿**（`snp.drafts`）：所有**脏标签**的内容快照，用于「上次没保存就关了」的兜底。

规则：

| 项 | 规则 |
|---|---|
| 会话范围 | 全部标签（速记除外），按顺序重开，再回填模式/滚动/光标 |
| 草稿范围 | 只存脏标签；**干净标签不会清掉别人的草稿**（早期实现会 `LS.del('draft')`，一份干净标签就能抹掉所有未保存内容） |
| 容量 | 预算 4 MB，**从最新的脏标签往回分配**，最近改的一定保得住 |
| 恢复时判定 | 草稿与磁盘内容一致（都按 LF 比）→ 不算脏，不恢复；未命名文档必须**有字**才留 |
| 恢复交互 | 一个确认框，列出文件名与时间，二选一：全部恢复 / 丢弃 |
| 恢复后的脏状态 | 与**磁盘**比，不与草稿自己比；否则一恢复就是「已保存」，关窗也不再提醒 |
| 清空时机 | 恢复完立刻删草稿键，再写一次会话，避免下次重复询问 |
| 速记 | 不进会话、不进草稿、不进最近打开（见 §7） |

### 3.9 退出

关闭窗口有三条路：右上角 ×、Alt+F4、任务栏关闭。**三条都要拦**，所以守卫装在
`onCloseRequested`，不是装在按钮上。

有脏标签时三选：

| 选项 | 行为 |
|---|---|
| 全部保存并退出 | 逐个保存；有未命名文档就问路径；任何一个取消则中止退出 |
| 不保存退出 | 直接退，不写草稿，且用 `discardOnQuit` 标志挡住 `beforeunload` / `visibilitychange` 的草稿兜底（否则关窗瞬间又把草稿写回去，功能等于没做） |
| 取消 | 留在原地 |

**三个按钮都带单键快捷键，键帽直接印在按钮上**：`Y` = 全部保存并退出、
`N` = 不保存退出、`Esc` = 取消。关标签时的「保存 / 不保存 / 取消」、对比窗口关窗
确认条的「保存并关闭 / 不保存 / 取消」用同一组键；`Enter` 仍等于主按钮（保存）。
弹层里带输入框、正在组字或按着 Ctrl / Alt / Meta 时，字母键归输入框自己，
不会因为敲了个 `y` 就把确认框关掉。

**不再提供「存为草稿并退出」**：它和「全部保存」在用户心里是同一件事（都是「别丢」），
却要用户判断「我这次到底想不想留在磁盘上」。未命名文档本来就有草稿兜底。

### 3.10 文件树上的写操作

| 动作 | 规则 |
|---|---|
| 新建文件 / 文件夹 | 在当前目录下建；名字里的非法字符由后端拒绝并回错误码 |
| 重命名 | 就地输入；成功后**同步改掉所有打开着的、指向旧路径的标签** |
| 删除 | 进系统回收站（不是永久删除）；目录**只删空目录**；删之前确认，确认框里写清路径 |
| 删除后 | 关掉指向它的标签；如果标签有未保存改动，先问 |
| 刷新 | 监听事件驱动增量刷新，保留展开状态与滚动位置 |

### 3.11 最近打开

- 存 12 条，菜单只显示 6 条（超出的没有入口，纯属冗余）。
- 打开成功才记录；打开失败不写。
- 提供「清除最近记录」。
- 速记永远不进这个列表 —— 它是「随时能回去的地方」，不是「上次打开的文件」。

### 3.12 落地：落盘与读写

#### 草稿、会话、历史、外部变更

| 机制 | 存什么 | 存哪 | 何时 | 上限 |
|---|---|---|---|---|
| **会话** | 打开过哪些文件、哪个是当前、每个的滚动位置与模式 | `localStorage` 键 `snp.session` + `snp.sessionActive` | 标签/文件变化时 | 不设 |
| **草稿** | **未保存的正文** | `localStorage` 键 `snp.drafts` | 停手 **1200ms** | **4MB** |
| **历史快照** | 每次保存前的旧内容；**自动保存按 10 分钟合并窗口只留会话起点那一版**，`Ctrl+S` 每次都记 | `history/<fnv1a(绝对路径)>/<毫秒戳>.txt` | 保存成功前 | **60 份 / 20MB**，单份 > 2MB 不记 |
| **外部变更** | 磁盘上的 mtime 有没有变 | 内存 + 文件监听 | 监听 **300ms** 防抖，前端 **250ms** 防抖 | — |

**草稿预算算法**（`saveDraft`，这是最容易做错的一段）：

```
1. 只收「脏」标签（quickNote 不算脏，永不进草稿）
2. 从最新的往回装，累计 JSON 大小；超过 4MB 就**整份跳过**（⛔ 不截断内容）
3. 一份都没装下 → **删掉这个键**（否则下次启动读到一个空数组，白解析一次）
```

⛔ **不截断**是硬要求：截一半的草稿恢复出来是「半个文件」，比没有更糟——用户会以为
自己的内容丢了，然后又保存了一次。

**恢复六步**（`restoreDrafts`）：

1. 读 `snp.drafts`，坏 JSON 直接丢弃并删键；
2. 逐条与磁盘现状比：文件不在了 → 只留草稿（标记 `external = true`）；
3. 磁盘内容与 `savedContent` 相同 → 不恢复（草稿是多余的）；
4. 磁盘内容不同 → 恢复草稿，并**把 `savedContent` 设为磁盘上的那份**，这样标签显示为脏；
5. 恢复后光标与滚动位置按草稿里的记录摆；
6. 恢复完弹一次「恢复了几份草稿」的提示，**不逐个弹窗**。

⚠️ 第 4 步的 `savedContent` 必须设成**磁盘内容**而不是 `''`。设成 `''` 会让「放弃保存」
变成「清空文件」，用户点一下就把原文件写没了。

**历史快照**（`write_history_snapshot`）：
- 目录名是 `fnv1a(绝对路径)`——路径变（移动/改名）就断成两串历史，这是已知代价。
- 文件名是**毫秒时间戳**，天然按时间排序。
- **空内容不写**、**单份超过 2MB 不写**（否则一份大文件就能把 20MB 总额吃光）、**与上一份相同不写**（去重）。
- **自动保存走 10 分钟合并窗口**：窗口内不再新增，连续打字那几十次写盘共用一份。
  我们存的是「即将被覆盖的旧版」，合并必须**跳过**，⛔ 不是拿新内容覆盖最后一份——
  覆盖会丢掉这段编辑开始前的那一版，而那正是用户想回退的版本。
- **`Ctrl+S` 是显式里程碑**，不受合并窗口限制，每次都记；清空速记同理。
- 60 份 / 20MB 两个条件**同时生效**，超了从最老的删——但**长期检查点代表不删**：
  1 / 3 / 7 / 10 / 20 / 30 / 60 / 90 / 120 / 360 天，每个检查点年龄之后最近的
  那一份永远保留（会超 60 份，故意的）。没有它，几个月前的「样子」会被
  连续编辑一点一点挤光，等想找回时已经没了。

**为什么不是「1 分钟一版」**：自动保存是停手 1200ms 就写盘，比一分钟密得多。
如果每次写盘都留一份，60 份上限几分钟就会被逐秒的半成品填满，真正有用的
「改之前那一版」反而被挤掉。VS Code 的 Local History 用 `mergeWindow`（默认 10s）
合并、JetBrains 用「保留期 + 手动标签」；这里取的是同一条思路，窗口按「一段编辑会话」
放到 10 分钟，时间维度上按检查点留代表（近期密、远期疏的极简版）。语义标签与
diff 视图暂不做，60 份 + 合并窗口 + 检查点已足够。

⚠️ 沙箱化的 macOS 移植会在这里翻车：security-scoped bookmark 下同一个文件的路径可能
变成 `/private/var/...` 的另一串，历史会断成两段。见《实现规格》§10.5。

**外部变更**（`checkExternalChange` / `syncWatches`）：
- 监听**一层目录**，前端 300ms 防抖合并事件；
- 变化时只比 `mtime` + `size`，不同才标记 `.tab.stale`（琥珀点 5×5）；
- 用户切到那个标签时才提示「磁盘上的文件已改变，重新载入 / 保留我的」。

**坑**：
- ⛔ `localStorage` 在 WebView2 里**延迟落盘**（实测 6s 后杀进程仍可能丢）。所以
  「启动期行为」不能靠「写入后立刻杀进程再启动」来验，要用 `run-units.mjs` 读源码断下标。
- ⛔ 草稿键用 JSON 整体读写，别改成一条一个键：几十个键的读写会明显拖慢启动。
- ⛔ `quickNote` 永远不进会话、不进草稿。它靠磁盘文件自己回来。

**验收**：`test/probe-app.mjs` 的草稿/会话/外部变更用例；手测——改一个字不保存，
10 秒后 `taskkill`，重开看内容在不在、标签是否显示为脏。

#### 文件读写

| 顺序 | 判据 | 结果 |
|---|---|---|
| 1 | UTF-8 BOM（`EF BB BF`） | UTF-8，`bom = true` |
| 2 | UTF-16LE BOM（`FF FE`） | UTF-16LE |
| 3 | UTF-16BE BOM（`FE FF`） | UTF-16BE |
| 4 | 严格 UTF-8 校验通过 | UTF-8，`bom = false` |
| 5 | 以上都不成立 | **GB18030**（中文环境兜底，比 GBK 宽） |

⚠️ 第 4 步必须**严格**：宽松解码会把 GB18030 的中文解成乱码「锟斤拷」，然后再按
UTF-8 写回去，原文就彻底毁了。
⚠️ 顺序不能换：UTF-16 的文件常常也能「碰巧」通过宽松的 UTF-8 校验。

**写回**（`save_text_file`）：按读入时的 `encoding` + `bom` 原样写；单文件上限 **512MB**。
**换行符**由 `detect_eol` 记下（`\r\n` 占多数就是 CRLF），保存时按它写回；
内存里统一 `\n`。

**二进制判定**：读前 8192 字节，含 `0x00` 就当二进制，**拒绝以文本打开**并说明原因。

**图片**：
- 「插入图片」默认**复制到文档同级的 `assets/`**，名 `stem-1.png`（同名递增，上限 **999**）；
- 保存剪贴板图片用 `img-<时间戳>`，上限 **64MB**，扩展名白名单；
- 引用写成相对路径，导出时转 base64（§15）。

**坑**：
- ⛔ 行尾检测不能只看第一个换行：混合行尾的文件（Git 合并留下的）要按**多数**判。
- ⛔ 文件名校验 `check_simple_name` 拦 **9 个**非法字符（`\ / : * ? " < > |` + 控制字符）。
  写文件前必须过这一关，否则 Windows 上会静默失败。
- ⛔ 「二进制」不按扩展名判，只按内容判。`.md` 里塞了二进制照样要拒。

**验收**：`test/run-units.mjs` 的编码/行尾用例；手测——造一个 GB18030 的 `.txt` 打开
看中文是否正常、保存后 `file` 命令是否仍是 GB18030。

## 4. 视图模式与显示

### 4.1 三种模式

| 模式 | 快捷键 | 看见什么 | 数据形态 |
|---|---|---|---|
| 所见即所得 | `Ctrl+1` | 排版后的样子，直接改字 | 块 DOM ⇄ Markdown |
| 编辑模式 | `Ctrl+2` | 源码 + 行号 + 语法高亮 | 字符串 ⇄ 字符串（CodeMirror 6） |
| 预览模式 | `Ctrl+3` | 只读渲染结果 | Markdown → HTML |

- **默认**：md 进所见即所得，其余进编辑模式。
- `lastMode` **只记忆用户手动切换过的模式**。自动落位不写入 —— 早期把自动落位也存进去，
  导致「默认值」在第一次打开时就被粘滞成 `edit`，之后再改默认对老用户永远无效。
- 切标签、切文件后按类型回填上次模式；类型不支持该模式时回落到首个可用模式。
- 双栏（`Ctrl+Shift+L` 切换单/双栏）时，左边是当前编辑模式，右边固定是预览。

### 4.2 专注模式（F9）

- 隐藏：标签行、菜单栏、侧栏、状态栏。
- **保留标题栏**（无边框窗口没有标题栏就没法拖、没法关），但品牌与窗口按钮压到
  `opacity: .28`，悬停恢复。曾经设成 0，结果连关闭按钮都找不到。
- 正文宽度在用户设定值基础上再收 8%（`calc(var(--rw) * .92)`），长行更好读。
- `Esc` 退出。若查找条开着，先关查找条，再退专注 —— 一次 Esc 只做一件事。

### 4.3 行显示模式（soft wrap）

| 项 | 规则 |
|---|---|
| 开关 | `settings.wrap`，**默认换行** |
| 生效范围 | 编辑 / 预览 / 所见即所得 / 对比窗口，**一个开关管四处** |
| 入口 | 视图菜单（自动换行 / 不换行，互斥）、编辑区右键、所见即所得右键、预览右键、对比窗口工具栏 + 两栏右键 |
| 保存 | 进 localStorage，跨窗口共用 |

实现上的三条约束（用户看不见，但破坏任何一条都会丢数据或丢位置）：

1. **CSS 只写「不换行」这一侧**（`body[data-nowrap]`）。换行是浏览器默认行为，正面写
   `white-space: normal` 会和既有的 `pre-wrap` / `pre` 打架。
2. **CodeMirror 用 `Compartment` 热替换**，绝不重建 `EditorState` —— 重建等于把撤销历史
   和选区一起扔掉，用户只是改了显示方式，`Ctrl+Z` 却撤不回去。
3. **切换时保住视口顶部那一行**：先记 `rowAtY(scrollTop)`，重排后滚回 `rowTop(keep)`。
   在 2000 行文档的第 21 行上打开换行，屏幕跳到第 2 行，用户会以为文件被改了。
4. **编辑区行号槽必须是不透明纸面**（`--bg-panel`）。CodeMirror 把 `.cm-gutters` 做成
   `sticky + zIndex:200`，不换行横向滚动时长行会从它底下经过；背景透明就把文字透出来，
   看着像正文跑到了行号左边。行号槽要盖住这一条，颜色仍走 CSS 变量，明暗主题自动跟随。

### 4.4 字号与正文宽度

| 项 | 规则 |
|---|---|
| 字号 | 默认 13.5px；`Ctrl+=` / `Ctrl+-` / `Ctrl+0`；设置面板显示当前 px |
| 正文宽度 | 默认 800px；范围 560–1600，步进 40；显示 px 不显示 rem（rem 要心算 16 倍） |
| 生效 | 宽窗口下正文居中收窄；窗口或分栏不够宽时自动退回两侧 54px 留白；专注模式再收 8% |

正文宽度用 `padding-left/right: max(54px, calc((100% - 宽)/2))` 居中，**不包一层
`max-width`**：包了以后滚动条会离开窗口右边缘，贴在正文框上，长文档横向找位置很别扭。

### 4.5 双栏

- 单栏（默认）/ 双栏，`Ctrl+Shift+L` 切换。
- 双栏 = 左编辑 + 右预览，中间可拖拽调宽。
- **预览侧不做视口化**：6.4 MB 文档双栏时预览会渲染约 220 万个节点，切布局/改宽度/换主题
  都会触发全树重排（实测 12.8 秒）。⚠️ 已知设计债，大文档建议单栏。

### 4.6 落地：三种模式的取值

**取值表**：

| 模式 | `data-mode` | 承载 | 可编辑 |
|---|---|---|---|
| 所见即所得 | `wysiwyg` | `#wysiwyg`（`contenteditable`），一行一个 `.w-block` | 是 |
| 编辑（源码） | `edit` | `#editor`（CodeMirror 6） | 是 |
| 预览 | `preview` | `.preview-body`（`renderMarkdown` 输出） | 否 |

正文排版（三处共用同一组变量）：

| 项 | 值 |
|---|---|
| 正文宽 | `--rw`，默认 **800px**；专注模式 `calc(var(--rw) * .92)` |
| 两侧最小留白 | `--read-gutter: 54px` |
| 所见即所得字体 | `--font-read` 15px / 行高 **1.75** / `letter-spacing: .008em` |
| 预览行高 | **1.8**（比编辑态略松，因为只读时不追行） |
| 编辑区上内边距 | **32**（`padding-top`） |
| 编辑区下内边距 | **40vh**（让最后一行能滚到屏幕中间，不被底边卡住） |

**坑**：
- ⛔ 模式切换必须 `flush` 当前编辑态到 `content`（所见即所得块模型 → Markdown），
  否则切过去看到的是上次的文本。反向也一样。
- ⛔ `lastMode` 要在**设置**里记一份（下次新建标签用它），但它与 `tab.mode` 是两件事：
  后台标签的 `isDirty` 判断只看 `content` 与 `savedContent`。
- ⛔ 预览模式下块手柄必须隐藏（`lastMode` 不是 wysiwyg 时手柄不出现），否则会
  在一个只读视图上浮出可点的编辑入口。

**验收**：`test/run-units.mjs` / `run-editor.mjs` 离线用例；手测——打字 → 切预览 →
切回 → 光标还在原处、撤销还能退回三步之前。

## 5. 所见即所得

这一章是整个产品的核心，也是最容易「看起来能用、实际处处别扭」的地方。所有规则围绕一句话：
**编辑器的行为要和人写纸稿时的直觉一致** —— 回车是换行、退格是往回删、方向键是往那个方向走。

### 5.1 模型：一行一块

| 规则 | 说明 |
|---|---|
| 一行 = 一个 `.w-block` | 块是最小编辑单元，块内不再有「段落」概念 |
| **空行不是块** | 空行是序列化概念，由块间分隔符表达；把空行建模成空块会污染结构（可被光标命中、可被退格合并） |
| 源文本是唯一真相 | DOM 只是 `t.content` 的投影；任何 DOM 改动都要落账（flush）成 Markdown |
| 块是只读记录 | 大文档下块记录视为只读，改动换新对象（撤销快照靠这一点零成本） |

**连续两个以上空行**才折算成 `n-1` 个空段落 —— 那才是用户真的按了两次回车想留空档。
文档开头的空行直接丢。

**渲染层一行一块，操作层以「逻辑块」为单位。** 引用（含提示块）的一组连续行在 DOM 里
仍是多个 `.w-block`（序列化、虚拟滚动、光标偏移都靠这个，不动），但**对用户它就是一个块**：

| 规则 | 说明 |
|---|---|
| 手柄 | 整组只有一个 `⋮⋮`，钉在组首；续行不许再冒一个 |
| 转换类型 | 光标落在组内任意一行，都把整组一起转，不许留下没有 `[!x]` 头的半截引用 |
| 删除 | 整组一起删（普通块 / 表格 / 代码块则删自己那一块） |
| 组边界 | `bqStart` 只打在「空行断出的独立引用」上；「前一块是引用且自己没标记」就是续行 |
| 块内退格 | **仍按行**：续行行首退格并回上一行。块级语义不伸进块内去改退格 |

删除与转换的入口各两处：行首 `⋮⋮` 的「转换这一块」面板底部、所见即所得右键菜单。
表格内右键已有「整表」项，不重复摆。面板里的删除项是**破坏性操作，只留鼠标点击这一条路径**：
既不给盲打选择键（`0`~`9`/`w`/`d`/`s` 都是一次按键就执行的键），也**不进
↑↓ / Home / End / Enter 的键盘导航序列** —— 用户按 `End` 想跳到最后一个转换类型，
若末项是「删除这一块」，再按一下 `Enter` 就平白少一整块。它仍在面板里、仍有 hover
反馈，只是不会被键盘盲按选中；鼠标移上去时还会清掉别处残留的高亮，避免 Enter 误执行
那个「别处的项」。

### 5.2 块类型总表

| 块 | Markdown 形态 | 可编辑位 | 特殊规则 |
|---|---|---|---|
| 段落 | 纯文本 | 整块 | 默认落点 |
| 标题 | `#` … `######` | 标题文字 | 哈希把手 `###` 是 `contentEditable=false`，只在退格时亮出来；空标题自动退回正文 |
| 无序列表 | `- 项` | 项文字 | 最多 6 层缩进；标记不参与编辑 |
| 有序列表 | `1. 项` | 项文字 | 编号由序号重排，不手改 |
| 任务列表 | `- [ ]` / `- [x]` | 文字 + 勾选框 | 勾选直接改模型，不用进源码 |
| 引用 | `> 行` | 整行 | 连续引用行 = 一个引用组；组首行打 `data-bq-start` |
| 提示块 | `> [!info] 标题` + `> 正文` | 正文；标题单独存 | 四型 + 别名；标题不进正文文本 |
| 代码块 | 三反引号 + 语言 | 整段原文 | 语言条 + 复制按钮；块内没有「行」概念（文本 + `<br>`） |
| 公式块 | `$$ … $$` | TeX 原文 | `$$` 用 CSS 伪元素画，不进 DOM |
| 表格 | GFM 表格 | 单元格 | 单元格是唯一编辑位；对齐存 `data-aligns` |
| 分割线 | `---` | 不可编辑，但**整块可选中** | 点一下就选中这根线（浅橙底 + 块手柄）；`Delete` / `Backspace` 删整块，`Enter` 或打字在下方开一行。⛔ 插入后不垫空段落 |
| 图片 | `![](path)` | 无 | 行内元素，独立成块时居中 |

**块类型只在编辑区里存在**。切到编辑模式看到的是原始 Markdown，切到预览看到的是渲染结果，
两边不共享 DOM。

### 5.3 输入即转换（打字就把块变过去）

在行首敲标记，当前块原地变成对应类型，不用去菜单：

| 输入 | 变成 | 备注 |
|---|---|---|
| `# ` … `###### ` | 对应级别标题 | 空格是触发键 |
| `- ` / `* ` / `+ ` | 无序列表 | 三种符号等价，序列化统一成 `-` |
| `1. ` | 有序列表 | 数字不必是 1，序列化按位置重排 |
| `- [ ] ` / `- [x] ` | 任务列表 | 逐字升级：敲到 `[` 就已经是待办 |
| `> ` | 引用 | 紧跟已有引用时打 `data-bq-start`（否则会粘进上面的框） |
| `[!info] ` 等 | 提示块 | 在引用行里敲也生效，光标后的文字当标题 |
| 三个反引号 | 代码块 | 后面跟的语言名进语言条 |
| `---` | 分割线 | 要求整行只有它（后面还有字不算） |
| `$$` | 公式块 | 回车后成为块级公式 |

三条判据细节：

1. **看「光标之前这一小段」，不看整行**。所以三种写法等价：先打标记再写字 / 写完回行首补标记 /
   把普通文字原地升级成标题。早期判据是「整行 = 标记」，只有空行上先打 `#` 才行，
   用户在已有文字前补 `##` 只会得到两个井号。
2. **前缀超过 16 个字符不判**：那更可能是一行正常文字里恰好有 `-`，不是想建列表。
3. **光标不在行首时不触发**（`- ` 打在句子中间就是普通字符）。

**转换是原地改属性/类名，不是 `replaceWith`**：换节点会让光标、块下标、撤销记录一起错位。
光标后的内容用 `Range.extractContents()` 搬 DOM 片段，不用 `textContent` —— 否则加粗、链接、
行内代码会在转换时被削平。

#### `/` 起插入面板（手不离键盘）

手柄的 `+` 要鼠标。键盘这条路是**在行首或空白之后敲 `/`**：

| 敲 | 结果 |
|---|---|
| `/` | 光标处弹出插入面板，和「点 + 号」完全同一张（18 项） |
| `/` + `0`–`9` | 正文 / H1 / H2 / H3 / 无序 / 有序 / 任务 / 引用 / 代码块 / 信息提示块 |
| `/` + `w` `d` `s` | 警告 / 危险 / 成功提示块（warning / danger / success，能盲打） |
| `/` + `t` `T` | 表格 3×3 / 表格自定大小（`T` 要按 Shift） |
| `/` + `i` `l` `-` | 图片 / 链接 / 分割线 |
| `Esc`、点别处、滚动、敲了没分配的键 | 面板关闭，**那个 `/` 原样还回正文** |

编号**不连号**，按语义分段：`0` 是「归零」，`1`–`3` 标题，`4`–`6` 三种列表，`7`–`8` 引用与
代码，`9` 起是提示块。数字只有十个，硬连号会把后面三项挤成 `a`/`b`/`c` —— 那三个字母没有
任何语义，每次都得看菜单找，等于白做。面板右侧显示的就是选择键；全局快捷键（`Ctrl+K` 等）
退到悬停提示里，两个挤一行会把「表格（自定大小）…」顶到换行。

三条必须守住的判据：

1. **只在「行首或空白之后」触发**。`2026/11/05`、`a/b`、`1/2` 里的斜杠是正文，弹面板
   等于打断输入。判据看光标之前那一小段，只认末字符是空白（或这一段为空）。
   **「空」要按块读**：把一行里最后一个字删掉之后，Chromium 会把光标上提到 `.w-block`
   本身（`.w-text` 里只剩 `<br>`），那不是空行又是什么？早期按 `.w-text` 严格读偏移，
   得到 -1 就直接放弃了 —— 症状正是「新行里打了字再删掉，接着敲 `/` 唤不出面板」。
2. **代码块 / 公式块 / 表格单元格里不触发**——那里的 `/` 是注释符、除号、路径分隔符。
3. **没选就关，斜杠必须回来**。它从头到尾没进过正文（按键被拦下），所以关闭时按**原偏移**
   插回去，不是按当前光标；光标若还停在原处就推到斜杠后面接着打。用户想打一个 `/`，
   最多只多闪一下面板。

**空段落里 `/` + `1` 是原地变标题**，不是「在下面新增一个标题」——后者会留下一个空行，
用户看到的是「斜杠没了，标题跑到下一行」。

### 5.4 回车：每种块都有自己的「下一行」

| 块 | 回车做什么 |
|---|---|
| 段落 / 标题 | 在光标处拆成两块；空标题回车退回正文 |
| 无序 / 有序 / 任务列表 | 续一个同类型、同缩进的新项，编号接上；**空项回车 = 退出列表**，变回普通段落 |
| 引用 | 续一行同组引用；**空行回车也在下面续一行空引用**（不再退化成普通段落） |
| 提示块 | 续行仍属于这个提示块（打 `data-co-follow`，视觉同框）；空行同样续行，不退出 |
| 代码块 / 公式块 | **永远换行**，没有例外 —— 连按几次回车就是几个空行，不会被弹出去 |
| 表格 | 格内 `Shift+Enter` 插 `<br>`；普通回车在当前格换行？不 —— 回车在单元格里只做一件事：整行全空时退出表格，否则留在格内 |
| 分割线 | 在它下方开一个段落 |

**代码块这条规则改过两次**：最早是「光标在末尾就出块」，用户写完一行想换行就被弹出去；
后来按 Typora 的「空末行再回车才出块」，仍然有同一个毛病 —— 想空一行，第二下就被弹出去了。
现在的规矩一句话：**块内回车永远只是换行**。出块交给方向键（→ / ↓ 在块末），
那是一条独立的、只用按一下的路。

### 5.5 退格与删除

| 场景 | 行为 |
|---|---|
| 空段落 / 空标题 | 与上一块合并（光标落在接缝处）；**合并结果若仍是空块，必须补回占位 `<br>`** |
| 表格 / 代码块 / 公式块后的空段落行首 | **删掉这个空段落**，光标退回块末；非空段落仍只送光标，先把字删完再轮到删行 |
| 标题行首退格 | **第一下只亮出 `###`，不降级**；第二下起每按一次删一个 `#`：h3 → h2 → h1 → 正文；标记消失后回正文 |
| 空标题 | 自动降级为正文（原地改类型，不换节点）；但正在亮标记时不降级 |
| 列表项行首 | 并回上一行；已是组首行则退回普通段落 |
| 引用行行首 | 同上；提示块的续行并回上一行，只有组首行退回段落 |
| 代码块行首 | 一次退格吃掉行尾的零宽空格 + `<br>`（两个节点），不能按两次 |
| 有选区 | **只删选区，绝不合并行**。三击选中一行后按退格，锚点在行首，早期实现会把整行并进上一行，选中的内容一点没删 |
| 标题里只有图片 | 不算空，不降级 |

**两个容易一起犯的退格错**：①两个空段落合并时，双方的占位 `<br>` 都会被搬节点的循环
跳过，结果 `.w-text` 一个子节点都不剩、行盒塌成 0 高 —— 用户看到「一次删了两行」，
下一次退格还会因为光标无处落脚被甩进更前面的块（标题里就表现为光标跑进标题）。
②表格 / 代码块后面那个空段落是给「块内没有尾位」垫的落脚行，行首退格原来只把光标送回块末、
不删块，那一行永远删不掉。两者都要量**真实行高**验收：只看 DOM 块数看不出来（块还在，只是没高度）。

**为什么标题退格要分两步**：在 `### 标题` 这一行按退格，用户想的是「把标题级别降一格」，
不是「删掉这个标题」。先亮出 `###` 是在告诉用户「这里有一个标记，下一下删的就是它」——
和 Obsidian 的实时预览同一个思路。标记是纯视觉层（`contentEditable=false` 的兄弟节点），
绝不进正文文本，序列化时不参与。

### 5.6 方向键：走到头就出去

| 位置 | ↓ / → | 说明 |
|---|---|---|
| 普通段落、标题 | 浏览器默认 | 段落本身就是出口的落点 |
| 代码块 / 公式块末行 | **出块** | 只移动光标，文档一个字都不改 |
| 表格最后一格 | **出块** | 表格右下角必须有出口，否则只能动鼠标 |
| 引用 / 提示块的组末行 | **出块** | 组内还有下一行时交给浏览器（它会处理折行与滚动） |
| 列表最后一项 | **出块** | 同上 |
| 分割线上一行末尾 | **穿过分割线** | 分割线自己放不了光标；文末那条 `---` 否则是一道墙 |

**方向键绝不改文档**。出块时按优先级取第一个成立的落点：

1. 块后已经是空段落 —— 直接停进去，不重复开行；
2. 块后还有能站人的块 —— 光标落到它**开头**，同时记下一次性的「块后待插入」；
3. 块后什么都没有，或紧跟着没有光标位的分割线 —— 光标保持不动，同样记下「块后待插入」。

第 2/3 条只是移动光标：标签不脏、撤销栈不多一条、连按方向键也不会越按越长。
用户**按下回车、开始打字（含输入法组字）或粘贴**时，才在块与下一块之间插入一个真空段落、
把光标放进去并 `flush()`。这一下才是「在这块后面接着写」，插入时机由用户决定。

**「下一块是什么」不改变这套契约**。下一块也是带边界的块（表格后紧跟表格 / 代码块 / 引用，
代码块后紧跟引用 / 表格 / 另一个代码块……）时，回车同样必须在两块之间插一个空段落。
这一条是硬约束：若让回车按光标落点走默认行为，它就只会在那个块**内部**加行 —— 表格加一行、
代码块内换行、引用续一行 —— 用户要的「回车插一个空段落」根本做不到。所以「块后待插入」
要在 `handleKey` 里把这一下回车接管过来，不能只把光标送过去就算完。

「块后待插入」是一次性状态：点击、其它方向键、Tab / 退格 / 快捷键、失焦、重渲染都让它
立即作废，绝不残留到别的操作上。用「临时占位块」或把 Range 悬在子节点间隙假装有一行都
不是正路：前者会在窗口化重铺 / 切标签时悄悄消失，后者在 WebView2 里回车会被吞、打字会被
吸回表格最后一格。

#### 出去还要能回来：↑ 的入口（1.2.9 后）

↓/→ 的出口修好之后，反方向还留着一个洞：光标停在**代码块后一行**按 ↑，会跳过整个
代码块落到它**前面**那个块，而不是进代码块。根因和出口是同一个：code / math 正文是
`white-space: pre-wrap`，用户在块内末行留过一次回车时，正文末尾那个裸 `\n`
**不生成可点击的行**。浏览器往回找「上一行」找不到落点，就把整个块跳过去了。
没有尾随换行时实测浏览器本来就能正常进块，所以这不是「一律接管 ↑」的理由。

| 条件 | ↑ 的行为 |
|---|---|
| 前一块是代码块 / 公式块、末尾有那条不可见尾行，光标在当前块**第一视觉行** | **接管**：把光标放进前一块的**最后一个可见行**，按屏幕 x 对齐列 |
| 前一块末尾没有尾行 | 交给浏览器（本来就对，不抢） |
| 前一块是普通段落 / 引用 / 表格 / 分割线 | 交给浏览器 |
| 光标在折行长段落的第二行及以后 | 交给浏览器 —— ↑ 只是留在原块内上移一行 |
| `Shift+↑` / `Ctrl+↑` / `Alt+↑` / `Cmd+↑` | 不接管：扩选区与组合键各有自己的语义 |

⛔ 与出块一样，**↑ 只移动光标，文档一个字都不改**：`preventDefault()` + 摆光标，
不 `flush()`、不插段落；`gapAfter` 由 `handleKey` 按非写入键清掉。
⛔ 不许为了绕开这条尾行去改 `.w-code` 的 textContent —— 那个回车是文档内容，
删掉就成了「按一下方向键悄悄改了文件」。

「最后一个可见行」与「光标在不在末尾」必须读**同一份判据** `visibleEnd()`；
出口（`isCaretAtEnd`）与入口（`arrowIntoBlock`）各写一份剥尾逻辑，迟早又会
出现「出得去、回不来」。折行的代码块里「最后一个可见行」可能只是折出来的
第二行，别拿整段源码当一行去对齐。

#### 插入点必须看得见（1.2.9）

方向键零改动是对的，但「块后待插入」原来是个**隐形状态**：文末时光标还在原位，后面有块时
光标落进那个块里，界面上没有任何东西说「按回车会在这儿开一行」——用户判定「不知道可以换行」。
参考 Notion 的块间插入线，把插入点变成一个可见对象：

| 反馈 | 规则 |
|---|---|
| 常驻插入线 | `gapAfter` 存在期间，在**出块那一块的底边**画一条线，右端标「按 Enter 在此插入一行」；纯视图层，不进序列化、不改文档 |
| 光标跑进下一块 | 线仍钉在两块之间的**接缝**，不跟着光标走 —— 插入点由线决定，不由光标决定 |
| 状态作废 | 回车 / 打字 / 粘贴兑现、点击、其它方向键、Tab / 退格 / 快捷键、失焦、重渲染，线与状态同生共死 |
| 与 hover 线 | 两条线是**两个元素**；鼠标移动触发的 hover 线不许把常驻线擦掉 |
| 视觉 | 线用强调色（这是「待插入」状态，不是装饰）；标签走中性字色 + `--bg-panel` 底 + 1px `--line`，深浅色都可读；`pointer-events:none` |

**`Ctrl+Enter` 强制插入新行**（Typora 式）：不依赖方向键、不依赖 `gapAfter`，一步到位在块后
保证有一个可写空段落并把光标放进去。块后已有空段落就复用，不连开两行。

| 位置 | Ctrl / Cmd + Enter |
|---|---|
| 代码块 / 公式块末行、表格右下角一格、引用组末行、列表末项的**最后一个可编辑位置** | **插入**：块后已有空段落就复用，否则新建并 `flush()` |
| 带边界块的中间 | **不触发**：连浏览器默认行为一起拦掉，绝不把代码块劈成两段 |
| 普通段落 / 标题 | **不触发**：那里按回车本来就能开行，无需「强制」 |

⛔ 这条命令**只在结尾触发**：「结尾」指块内最后一个可编辑位置（表格是右下角那一格，
引用 / 列表是整组的末行），**不是文档末尾**。块后还有内容时照样在两块之间插行。

**块手柄「+」面板**第一项是「插入空行」（选择键 `n`，title 提示 `Ctrl+Enter`），给不碰方向键
的人一条点得到的路。它永远在下方真开一行，不走 `/` 面板的「空块复用」——否则在空段落里
按 `/` 选它会看起来什么都没发生。`kbd` 只是提示，⛔ 不注册成全局快捷键：全局那条会被
编辑模式、查找框一起吃到，而且没法做「只在块末尾」的判定。

**↓ 和 → 在块内最后一个位置做同一件事不是偷懒**：走到头的下一步就是出去。让 `→` 在表格
右下角原地打转，才是违背直觉的。

**「走到头」按眼睛看到的算，不按 `textContent.length` 算**。这有三层：

- 代码块末行、空单元格末尾垫的**零宽空格**不算内容，否则第一下只是跨过那个看不见的字符，
  用户读到的是「按 → 没反应，得按两下」；
- 代码块 / 公式块正文末尾那个 **`\n` 也不算**：`pre-wrap` 下它不生成可点击的行，浏览器
  把行尾点击映射到它前面。把它算进 `end`，则末尾留过一次回车的代码块永远判成「不在末尾」，
  ↓ / → 不接管、浏览器直接把光标甩进下一块 —— 表现为「代码块后面有内容时出不了块，
  别的块都行」。只忽略末尾这**一个**换行：再往前的每个 `\n` 都对应一条看得见的空行，
  全剥掉会让用户在倒数第二行就被弹出去。表格 / 引用 / 列表的正文没有裸 `\n`，不受影响；
- 组内还有下一行时（`data-bq-tail` / 后面还是 `li`）不接管，交给浏览器处理折行与滚动。

**分割线只是「穿过」**：线下面有正文就直接落进去，不为此插空行把后文顶下去；线在文末
只记下「线后待插入」，回车才在线下开一行。它自己没有光标位，语义不是「在线后面接着写」。

### 5.7 鼠标

| 动作 | 行为 |
|---|---|
| 点字 | 光标落在点的位置 |
| 点块内空白（表格右侧、代码块下方留白） | 光标落到该块最后一个可写位置 |
| 点文末空白 | **把光标送回文末**，不是加一行。只有代码块 / 公式块 / 表格 / 分割线垫底时才补一行（它们把光标包在结构里），其余 `placeCaretEnd(末块)` |
| 拖选跨块 | 保留选区，不许在松手时被当成「点空白」 |
| 拖到窗口边缘 | 自动滚动并继续扩选 |
| 双击 | 选词 |
| 三击 | 选一行 |

**跨块拖选有个隐蔽陷阱**：`mousedown` 与 `mouseup` 落在不同元素上时，`click` 派发给两者的
**最近公共祖先**。选到两行以上，公共祖先就是编辑区根节点，和「点了正文空白」长得一模一样。
必须两道闸：①选区非空直接返回；②真要按空白处理时用 `elementFromPoint` 问一下这一点命中谁，
命中任何块就按「点在字上」处理。只做①，「从空白拖到空白」仍会误判。

#### 块手柄

行首悬停出现两个按钮：`⋮⋮`（换块类型）和 `+`（在下方插入）。

| 规则 | 说明 |
|---|---|
| 位置 | 挂在编辑区外层（`position:relative`），按当前块的矩形定位，**不能放进块里** —— 会被当成正文吸进去 |
| 常驻 | 锚点是「最后确定的那一行」，鼠标移到行间空隙、页边距、编辑区外都不消失；只有真的换到另一行才跟着挪 |
| 滚动 | 滚出视野只隐藏元素，不丢锚点，滚回来还是它 |
| 菜单关闭 | 只有点别处 / Esc / 滚动三种；**鼠标移动永远不关**（手柄和菜单之间有 4px 缝，落在编辑区里，一次 `mousemove` 就会收掉） |
| 键盘 | ↑↓ 环绕、Home/End、Enter 执行、Esc 关闭；字母 / 空格 / Tab / ←→ 收起菜单且不拦事件（焦点始终留在编辑区，打字才是意图） |
| 高亮 | 当前项用 `.hot` 类，不给真焦点（给焦点会丢正文选区） |
| `+` 的语义 | 在**下方**插一个新块；表格 / 图片 / 链接 / 分割线自己知道往哪插，不走这条路 |

菜单里每个图标要和「点了会发生什么」对得上：标题用 heading-1/2/3，表格用 table，链接用 link，
引用用 text-quote。曾经三级标题都画同一个 `type` 图标，一列看下来分不出谁是谁。

#### 块尾插入指示线

鼠标在最后一块下方空白移动时，显示一条细线，预告「点这里会多一行」。

- **只在真的会补行时亮**：判据和「点空白」共用 `needsLineBelow()`；
- 指示线挂在编辑区外层，不挂进块容器（否则会被遍历成幽灵空段落）；
- 点一下只补一行；补出来的空段落立刻成为新末块，再点也不会继续长。

### 5.8 粘贴：先看落在哪个宿主

同一个 `paste` 事件，落到不同块上语义完全不同：

| 落点 | 处理 | 不这么做的后果 |
|---|---|---|
| 普通段落 / 空行 | 多行 → 解析成块，顶替空行或插在块后 | 从别处粘一段带标题的笔记，结构全丢 |
| 列表项 / 引用行 | **在容器里续行**：每行等价于一次回车，li 续同 kind 同缩进、ol 编号接上、task 仍是待办 | 按段落插在块后会拦腰截断容器：`- 第二项` 之后冒出三个普通段落、每段还隔一个空行 |
| 表格单元格 | 只取第一行 | 多行会把表格结构塞进一个格 |
| 代码块 / 公式块 | **原文插入**：换行落 `<br>`、末尾垫零宽空格、先摘掉占位 `<br>` | 走 Markdown 解析时，空代码块会被整块替换（粘一段 JSON，块凭空消失），非空块则把段落插到块外面 |
| 图片（剪贴板里是位图） | 存进 `assets/`，回填 `![](assets/…)` | 不处理就是静默吞掉 |
| 文件（资源管理器拖入） | 图片复制进 `assets/`，其它当文档打开 | — |

代码块的三个细节必须一起做，少一个都会出现「光标跑错行」：

1. **换行用 `<br>`，不往文本节点塞 `\n`**：Chromium 下一次输入会把行尾那个 `\n` 吃掉，
   光标漂到换行前面；
2. **末尾垫零宽空格**：否则以换行结尾的粘贴会让光标停在 `<br>` 上，接着打字跑回上一行；
3. **先摘掉空块的占位 `<br>`**：不然粘进来的内容前面多一个空行。

**粘贴期间不逐行落账**：`splitBlock` 有批量模式，粘贴时置 `silent`，末尾统一 flush 一次。
逐行 flush 在万块文档上是一次几百毫秒的全量序列化。

**空行不占列表项**：空的 li / bq 在模型里存不住（序列化直接丢），造一个只会留下看不见的空位。
代价是「粘多段文本进引用会并成一个引用组」，这个代价接受。

### 5.9 拖放

- 走 Tauri 原生拖放通道（`dragDropEnabled: true`），拿到真实路径。
- 图片：复制进文档同目录的 `assets/`，保留原名，重名加 `-1`。
- 其它文件：直接开标签，多选开多个。
- 拖入期间显示一个提示层（`.drop-hint`）；原生通道下页面收不到 `dragover`，只能由 Rust 的
  enter / leave 事件驱动。
- 页面内拖拽标签换位走 HTML5 DnD，不受影响。

**未保存的文档拒绝插入图片**，提示「请先保存文档」。没有「同目录」可放 —— 存到临时目录
再让 Markdown 指过去，换台机器图就全断。

### 5.10 图片

| 规则 | 说明 |
|---|---|
| 存储 | 文档同目录 `assets/`；Markdown 里写**相对路径** |
| 双地址 | `data-src` 存原始相对路径（序列化用它），`src` 存 `convertFileSrc` 后的绝对地址（WebView 只认这个） |
| 尺寸语法 | `![说明\|300x200](assets/x.png)`；只写宽度也可以 |
| 拖拽改宽 | 右下角 14px 见方才可拖；只写 `width`、删 `height`（高度按比例）；最小 24px，上限正文宽 |
| 撤销 | 一次拖拽 = 一步撤销（拖拽期间不落账，松手才 flush） |
| 原生拖动 | `draggable="false"` + `dragstart` 拦一道，别和浏览器「把图拖出去」抢指针 |

**为什么 Markdown 里存相对路径**：整个目录拷到别处、提交进 git、换台机器打开，图都还在。
存绝对路径当场能看，文件一移动就全断。

### 5.11 表格

| 项 | 规则 |
|---|---|
| 插入 | `Ctrl+Shift+T` 插 3×3；「表格（自定大小）…」可以输行列 |
| 编辑 | 光标进格子直接改；`Tab` 下一格、`Shift+Tab` 上一格；末格 `Tab` 加一行 |
| 光标上下 | `↑` / `↓` **一律只在同一列上下走**：格内用 `Shift+Enter` 换过行的先走格内那几行，走完才到相邻表格行；**表头算第 0 行**，`↑` / `↓` 都能进出；到上下边界停住（最后一格末尾 `↓` 除外，见「出口」）。这两个键在表格里**全部由编辑器接管，绝不交给浏览器默认行为**；`Shift+↑/↓` 同样只做纵向扩选 |
| 光标左右 | `←` / `→` 在格内逐字走，走到边缘交给浏览器跨格 —— 和上下是两套逻辑，不许混 |
| 单元格内换行 | `Shift+Enter` 插 `<br>`；序列化与解析都按 `<br>` 往返，空单元格不写占位 |
| 行列操作 | 右键：上方/下方插行、左侧/右侧插列、删行、删列 |
| 对齐 | 右键药丸：左 / 中 / 右 / 取消；当前列的对齐会点亮 |
| 出口 | 最后一格末尾 `↓` 或 `→` 出表（见 §5.6） |
| 转换 | 表格**不参与**「换块类型」（没有可搬的文本），也不可拖拽 |
| 空行退出 | 一整行所有格子都空时按回车 = 退出表格，在下面开段落 |
| 行内格式 | 加粗 / 斜体 / 行内码 / 删除线 / 高亮**都能用在单元格里**，条件是选区落在**同一格**；跨格一律不动（会把 `<td>` 搬进 `<mark>`，表格当场散架） |

**「表格里的字选得中，却加不了粗也高亮不了」**：`toggleInline` / `toggleMark` 原先见到单元格就
整条返回（当年为了保结构），用户读到的却是「选中了没反应」。现在改成只拦跨格选区：
`selInOneCell()` 用两个端点是否都在同一 `cell` 里判定，单格内的 `**张三**`、`==张三==`
照常往返（解析 `inlineHtml` 与序列化 `inlineToMd` 两头本来就认）。

**表格的阅读态与编辑态不同**：预览用完整 1px 网格（和所见即所得一致），编辑态保留极淡的
竖线用来定位光标。曾经预览用「横线表」（只留下边框），切到预览格子边界全消失，用户以为
边框没画。

**坑：空格子里的 `<br>` 是光标占位，不是一行。** `mkCell()` 给没有文字的单元格垫一个
`<br>`，序列化时也不写它（`tableToMarkdown()` 按「格子里有没有文字」判）。早期实现用
「格内 `<br>` 数 + 1」算行数，空格子被判成「还有下一行」，于是把 `↑`/`↓` 放行给浏览器；
浏览器在 `contenteditable` 表格里走的是**阅读顺序**，光标停在占位 `<br>` 前按 `↓` 会跳到
右边一格。更隐蔽的是同一个空格子：`setCaretOffset()` 把光标落在 `<br>` **之后**（这一支
接管），点格子左侧或删空一格则落在 `<br>` **之前**（这一支放行），症状就成了「有时候上下、
有时候左右」。现在 `cellLines()` 丢掉最后一个空段，`arrowInCell()` 无条件 `preventDefault()`
自己算落点；`test/run-app.mjs` 用真实按键覆盖空表头、空数据格、占位 `<br>` 前后、格内两行
与上下边界 —— 换回旧实现会红 3 条，不是假绿。

**上下键必须自己接管**：单元格没有自己的「行」，浏览器把整张表当一溜行内盒子，默认的
`↓` 落到的是**阅读顺序的下一格** —— 从中间格按 `↓` 会往右跑，和 `→` 一模一样（用户报的
就是这个）。所以 `↑`/`↓` 一律自己算目标格并把默认行为拦掉；只有格内还有 `Shift+Enter`
换出来的行时才让浏览器先走完那几行。

### 5.12 链接

- `Ctrl` / `⌘` + 点击才打开，直接点仍是定位光标 —— 否则想改链接文字就下不了手。
- 外链交给系统浏览器；站内锚点（`#标题`）在文档内跳转。
- 相对路径按文档所在目录解析；`http(s)` / `mailto` 直接放行。

### 5.13 数学公式

| 项 | 规则 |
|---|---|
| 行内 | `$ … $` |
| 块级 | `$$ … $$`，独立成块，跨行也吃成一个 |
| 渲染 | KaTeX，**懒加载**：文档里没有公式就一分钱不付 |
| 往返 | 行内公式必须存**含 `$` 的完整匹配**，否则切回编辑模式 `$` 就丢了，公式退化成普通文字 |
| 下标 | `a_i` 里的 `_` 不能被当成斜体标记（先提公式，再处理行内语法） |
| 体积 | 只 vendor `katex.min.js` + `auto-render` + 一份 CSS + 20 个 woff2，合计约 546 KB；CSS 里 woff/ttf 的 url 必须删掉，否则字体三份副本撑到 1.2 MB |

**顺序死记**：行内处理必须先提行内代码、再提公式，最后统一转义。公式里 `<` 要原样进 KaTeX，
提前转义成 `&lt;` 就废了。

### 5.14 提示块（callout）

语法：`> [!info] 可选标题` + `> 正文`。

| 类型 | 别名（GitHub 命名收编） | 视觉 |
|---|---|---|
| info | note | 蓝 |
| success | tip | 绿 |
| warning | important | 琥珀 |
| danger | caution | 红 |

- 未知标记保持普通引用（不猜）。
- 标题存在 `data-callout-title`，不在正文里；标题行是 `contentEditable=false` 的独立节点
  （和代码块语言条同一套路），序列化时单独输出。
- 续行染同色（`data-co-follow`），视觉上是一个框；空行退出。
- **相邻两个提示块之间必须有空行**，否则会并进同一段引用，第二个 `[!xx]` 在预览里退化成
  普通文字 —— 这是「相邻 callout 往返丢类型」的根因。
- 把提示块转成别的块（或取消提示块）时，**标题文字要放回正文**，否则「我的标题」凭空消失。
- 没写标题时用四型的**默认标题**（信息 / 警告 / 危险 / 成功），它属于界面文案，
  **跟着界面语言走**：切到英文显示 Info / Warning / Danger / Success，所见即所得与预览
  两侧都要跟着变。用户自己写的标题是正文，切语言不许翻译或覆盖。
  ⚠️ 默认标题必须在**渲染时**取词（`CALLOUT_TYPES[x].label` 是 getter，不是模块加载时
  算好的字符串）；所见即所得里已画出来的标题，换语言时由 `relabelCallouts()` 就地改文本节点，
  不整篇重画（会丢光标和撤销栈）。

### 5.15 换块类型

「插入新块」和「换类型」是两种语义。菜单「段落」组里的都是后者，五个入口全部走
`convertBlock()`：

- 能互转的是「一行文本」的块：段落 / H1–H6 / 列表项 / 引用 / 代码块 / 公式块；
- 表格与分割线没有可搬的文本，返回 false，调用方另起新块；
- **搬运取 Markdown 源**，不取 `textContent` —— 后者会把 `**加粗**` 削成纯字；
- 代码块 / 公式是多行的：转成逐行块要按 `\n` 拆开、一行一块（末尾空行是「空末行」的产物，
  丢掉）；反方向则整段塞进一块；
- 引用组边界双向都要管：自己转成引用时前一块是引用 → 自己打组首标记；后一块是引用且没标记
  → 给它打上（否则转完被紧凑规则吸成一个框）；
- **引用整组一起转**：先把 `currentBlock()` 用 `bqGroupOf()` 归一到组首，源文本取组内各行拼起来，
  替换时整组一起摘掉。光标落在续行上转换也作用于整组 —— 否则第二行单独变成标题，留下半截引用。

**块级删除**是同一套模型：`deleteBlock()` 从组首或续行都回溯到整组，删完光标落到相邻块末尾，
删光了补一个空段落并站进去。它和「块内退格按行」是两条独立的路，互不干扰（见 §5.1、§5.5）。

**为什么必须统一**：以前每个命令各写一套「只认某几种源类型」的判断，于是「在代码块上点引用」
静默无反应，「引用转代码块」在下面多出一个空代码块，换标题会把行内格式削平。同一个动作
在不同块上表现不一致，用户只能靠试。

### 5.16 序列化与幂等

| 规则 | 说明 |
|---|---|
| 两条实现 | DOM → md（`blocksToMd`）与记录 → md（`recordsToMd`）必须**逐字节一致** |
| 块间分隔 | 列表项之间、引用行之间用 `\n`（空行会让列表变 loose、把引用拆成两段）；其余用 `\n\n` |
| 空段落 | 自己就是空行，不再额外补一行 |
| 文末 | 只留一个换行；文档开头不留空行 |
| 改块类型 | 两个序列化函数 + 两个解析入口要同时改，这是最容易漏的一处 |

**每次改序列化都要验幂等**：读回来再写一遍，结果必须相同。否则每保存一次文件就漂一点，
几天后整篇文档的空行结构全变。

### 5.17 撤销

| 文档 | 快照 | 上限 |
|---|---|---|
| < 1 MB | 记录型快照 | 200 条 |
| ≥ 1 MB | `records` 数组浅拷贝（块对象写时复制） | 8 MB 总字节 |

- **入口唯一**：`Ctrl+Z`、工具行箭头、编辑菜单、命令面板，全部落到同一条 `editCmd('undo')`，
  按模式分派到各自的历史栈。
- **禁止 `document.execCommand('undo')`**：它操作浏览器原生栈，而所见即所得的 DOM 是受控
  重绘的，两套栈各记各的，混用会退到谁也没预期的位置（内容退一半、光标乱跑）。
- 纯文本走 CodeMirror 自己的历史；同一文档内替换内容（格式化、转大小写）保留历史，
  切换文档则重建 state，旧文档的历史不串到新文档。
- 到栈底按钮变灰。「点了没反应」是最差的反馈 —— 用户分不清是软件坏了还是自己记错了。

### 5.18 查找与替换

一个浮层，四个模式开关，替换行可折叠（IDEA 式）：

| 元素 | 规则 |
|---|---|
| 呼出 | `Ctrl+F` 只聚焦，**不收起**已展开的替换行；`Ctrl+H` 直接展开 |
| 折叠箭头 | 在输入框左侧，点一下展开/收起替换行 |
| 模式 | `Aa` 区分大小写 / `.*` 正则 / `全词` / `选区` |
| 整词 | **只在查询串两端是 ASCII 单词字符时加边界**。中文没有词边界，「标题」匹配到「副标题」是正常的，硬套 `\b` 会让中文查询永远匹配不到 |
| 多行 | 输入框是 `textarea`，`↵` 或 `Ctrl+Enter` 插换行，自动长高到四行 |
| 跨行命中 | 所见即所得里整篇一份索引、块间插 `\n`；显式分隔符保证不带换行的查询不会匹配「上段结尾 + 下段开头」 |
| 高亮 | CSS Custom Highlight API，不往 contenteditable 里插 `<mark>`（会毁行内结构与光标） |
| 替换一处 | 命中在同一文本节点内 → 就地改 + 落账；跨了加粗/链接等格式 → 问「切到编辑模式继续替换？」 |
| 全部替换 | 从后往前改（前面的偏移不失效）；跨格式的单独计数并如实告知 |
| 计数 | 「当前 / 总数」；无匹配时显示 `0/0`，不弹窗 |
| 关闭 | Esc；`Esc` 在专注模式下先关查找条（一次只做一件事） |

**选区模式只在真的选了东西时可用**：没选区时勾上也会自动取消，避免「勾了却搜整篇」的困惑。

### 5.19 一键格式化

快捷键 `Ctrl+Alt+L`（避开 Windows 繁改简的 `Ctrl+Shift+F`，系统级热键拦不住）。

**格式化规则全部来自 prettier**（打进 `src/vendor/format.js`，2.2 MB，第一次按 `Ctrl+Alt+L`
时才加载）。项目里不写任何缩进 / 折行 / 引号规则 —— 以前那套「全角引号改半角、删尾逗号、
删注释」的正则补丁已经删掉：它只在见过的那几种坏法上有效，改错了还是静默改坏用户数据。

**「不标准」不再等于「拒绝」**：一键格式化三级尽力而为，任何一级都不会弹
「无法格式化」把人挡在门外。

| 级 | 路径 | 结果 |
|---|---|---|
| ① 严格 | 语言表指定的 parser | 正常格式化，无额外提示 |
| ② 宽松 | 同族更宽容的 parser：JSON 失败试 `json` → `jsonc` → `json5`，JS / TS 失败试 `babel-ts` | 正常格式化，提示「已按宽松规则」；带注释、尾逗号、单引号、无引号键都在这里被接住 |
| ③ 兜底 | 全部解析失败 → `format-loose.js` 只重排空白（按括号深度缩进、结构边界换行） | 仍给出排版结果，提示「原文有语法错误，仅调整空白」+ 错误行列 |

只有**格式化引擎本身加载失败**才弹框（那是故障，不是文本的问题）。语法错误的行列只报出来、
不 `gotoLine` —— 重新排版后行号已经变了，把光标送过去反而误导。

| 类型 | parser | 说明 |
|---|---|---|
| Markdown | `markdown` | 标题 / 列表 / 表格 / 围栏重新排版；`proseWrap: preserve` —— 中文段落按用户自己的换行，不重排 |
| JSON | `json-stringify` | 严格 JSON；尾逗号 / 单引号 / 无引号键实测也能过（会自动规范化） |
| JSON 的宽松回退 | `json` / `jsonc` / `json5` | 允许注释与尾逗号；⚠️ 语言表目前**未登记** `.jsonc` / `.json5` 扩展名，这两个后缀按纯文本处理，宽松 parser 只用于 `.json` 解析失败时 |
| JavaScript / JSX | `babel` | |
| TypeScript / TSX | `typescript` | |
| CSS / SCSS / Less | `css` / `scss` / `less` | ⚠️ 不是 `postcss` —— 那是**插件名**，`prettier/plugins/postcss` 导出的是 `css` / `less` / `scss` 三个 parser。写成 `postcss` 会报 `Couldn't resolve parser`，CSS 格式化一直弹「无法格式化」 |
| HTML / Vue | `html` | |
| YAML | `yaml` | 缩进就是层级；解析失败时兜底**只做保守清理**，不重排缩进 |
| Markdown（解析失败） | `markdown` | 同上：四空格缩进是代码块，不能当空白随手改 |
| 其余代码（Python / Go / Rust / SQL / Shell / C 系 …） | —— | **保守清理**：统一 LF、去行尾空格、压缩连续空行。不动缩进、不动语法 —— 靠缩进定语法的语言重排缩进会改语义，不能为了「看起来整齐」去赌 |
| CSV / TSV | —— | 不格式化（列对齐不是「修文本」，是「重排数据」） |

公共选项：`printWidth 100`（默认 80 会把一行放得下的配置折成三行）、`tabWidth 2`、
`endOfLine lf`。

兜底排版的硬边界（`format-loose.js`）：**输出里增删的只能是 ASCII 空白**，字符串 / 模板串 /
注释内部原样保留（连行尾空格都不碰）；出口有硬校验「去掉空白后与原文逐字符相同」，
不满足就原样返回；超过 30 万字符直接放弃排版。词法判断失误最多让排版难看，
不会像正则补丁那样静默改坏数据。

格式化的三条原则：**不丢内容、可撤销、语法错误时尽力排版而不是拒绝**。

### 5.20 大文档（≥ 1 MB）

超过 100 万字符换一条路径：

| 项 | 规则 |
|---|---|
| 真相 | `records` 数组（每块存 Markdown 原文切片 + 结构标记） |
| DOM | 只放视口附近约 4 屏、上限 600 块；窗口外高度用前后伪元素撑出 |
| 不能用 padding | `clientHeight` 含 padding，会把滚动容器自己撑高 |
| 滚动锚定 | 必须 `overflow-anchor: none`，否则浏览器的锚定与自己的偏移补偿各补一次 |
| `Ctrl+A` | 走逻辑全选（标记整篇 + 拦截输入/复制/剪切）；原生全选只覆盖窗口，随后打字会把窗口外几万块当未选中删掉 |
| 载入 | 分段解析（512 KB 一段，围栏 / `$$` / 松散列表 / 连续空行 / 引用前五处不切），首段先显示，其余一次插入 |
| 分段失败 | 整篇重载兜底，绝不留半截文档 |
| 载入中 | 禁止把半截 DOM 序列化回 `t.content`（载入中途切标签或失焦会把残篇写进标签，自动保存再覆盖磁盘） |

实测 10.8 MB / 7.8 万块：打开约 1.14 秒、DOM 48 块、堆内存 32 MB、击键 1 ms、往返逐字节一致。
这些数字是这条路径存在的理由；如果某次改动让它掉到几百毫秒，先查是不是又退回了整篇渲染。

### 5.21 代码块：高亮、识别、复制、全选

| 能力 | 规则 |
|---|---|
| 着色引擎 | **highlight.js 11**（`src/vendor/syntax.js`，注册 54 门语言）。项目里没有一行分词正则；加语言只改 `src/js/langs.js` + 打包入口，重跑 `scripts/build-syntax.mjs` |
| 编辑态高亮 | **不改 DOM**：用 CSS Custom Highlight API 给文本区间上色（区间由 `highlight()` 的输出换算成源码偏移）。往 `.w-code` 插 `<span>` 会同时毁掉光标、撤销记录和序列化 |
| 着色一致 | 预览、导出 HTML、编辑态三方共用同一个 `highlight()` 输出，没有第二套实现 |
| class 映射 | hljs 的 `hljs-keyword` 等几十个 scope 收敛到主题的 9 个类（`tok-key/str/num/comment/punc/fn/tag/attr/type`），多余 scope 落到最接近的一档 —— 不为「精确」再造十个颜色变量 |
| 偏移换算 | `<br>` 占一位但没有文本节点；零宽空格有文本位但源码里没有 —— 必须逐字符记位置，用 `textContent.length` 硬算会整体错位 |
| 重算 | `MutationObserver` + 120 ms 防抖；单块超过 4 万字符放弃着色（流畅比彩色重要；hljs 是完整分词器，40k 约 40 ms） |
| 自动识别 | `hljs.highlightAuto`，**候选集剔除** CSS/SCSS/Less 与 dart/kotlin/csharp/scala/objc（这几门「长得像任何代码」，会把 TypeScript 判成 CSS、Python 判成 dart）；**≥ 8 分才认**，不够就老实不上色；JSON 先 `JSON.parse` 验算 |
| 识别时机 | **停手 500 ms 后才认**，且只看前 2000 字符。打分要跑几十门语法（2KB≈150ms），挂在每次输入上就是打字卡顿；结果按前缀缓存，在块尾打字不重算 |
| 短片段 | 三四行代码打分常在 2~7 分乱跳，一律不认。这是刻意的：错色比无色难查，还会让语言条显示错名字 |
| 识别写回 | **绝不写回 Markdown**。往用户文件里补一句语言名会让首次打开就标脏，存一次就改了人家的文件 |
| 语言条 | 显示 `data-lang` 或识别结果；没认出来显示 `code` |
| 复制 | 语言条右侧按钮，点一下整块进剪贴板，图标变对勾。走 textarea + `execCommand('copy')`（WebView2 里 `clipboard.writeText` 不可靠） |
| 块内 `Ctrl+A` | 第一次选**这一块**，第二次选整篇，第三次仍是整篇 |
| 复制按钮的焦点 | `pointerdown` 要 `preventDefault`，否则焦点被抢走，复制完光标不在原处 |

**`Ctrl+A` 为什么不由浏览器做**：实测「已选中一个内联块」之后再触发全选，WebView2 会把选区
整个吃掉（`execCommand('selectAll')` 返回 true，而选区是空的）。所以两步都自己算：第一下
用文本节点边界圈住本块，第二下自己从首块铺到末块。

#### 5.21.1 ```mermaid：把代码块画成图

写 Markdown 时用 ` ```mermaid ` 围起来的块，在**预览、导出 HTML、导出 PDF** 里会画成图
（所见即所得编辑区仍显示源码 —— 那里要能改字符，塞一张 SVG 进去光标就没法用了）。

| 项 | 值 |
|---|---|
| 引擎 | **mermaid 12**（`src/vendor/mermaid.js`，5.12 MB，**懒加载**） |
| 加载时机 | 文档里真的出现 ` ```mermaid ` 才 `import()`；没有图的文档一个字节都不读 |
| 支持语法 | 流程图 / 时序图 / 类图 / 状态图 / ER / 甘特 / 饼图 / 思维导图 / 时间线 / 象限图 / gitGraph / C4 等（mermaid 官方全集） |
| 配色 | 跟随主题：`theme: 'default' | 'dark'`，换主题时缓存作废重画 |
| 安全级别 | `securityLevel: 'strict'`（标签里的 HTML 过滤、`click` 绑定不执行） |
| 缓存 | 按「源码 + 主题」存 SVG，上限 **80** 张。预览每次输入都重渲染整篇，没缓存的话每敲一个字都要重跑一次布局（流程图 50–200 ms） |
| 画布 | `.mermaid-fig`（`--bg-soft` 底 + 1px 内描边）；SVG `max-width:100%; height:auto` |
| 出错 | 源码**原样留着**，下面一行红字说明原因。不静默、不吞掉 |

**三条必须做对的**：

1. **缓存按「源码 + 主题」**。图是异步画出来的，而预览是每次输入重渲染整篇 ——
   没有缓存，一篇带 5 张图的文档每敲一个字就要重排 5 次。
2. **异步回来要核对节点还挂着**。这几十毫秒里用户可能又敲了一个字，容器已经重渲染；
   旧结果贴进作废的节点=「图闪一下又没了」。
3. **画不出来要留证据**。错误信息 + 源码都留在原处，用户才知道改哪一行。

**成本（实测，见 §18.5）**：首次进入带图的文档多花 **+21 MB** JS 堆
（引擎 + 布局 + 两张图的 DOM），单张图渲染 50–200 ms；没图的文档 **0 额外成本**。

代价在**安装包**上，而且不小：引擎要进产物（前端是编译期内嵌的），所以
**主程序 5.1 → 7.6 MB、setup.exe 2.63 → 4.58 MB、便携 zip 3.07 → 5.01 MB**。
这是本项目体积上最大的一次增长，记在这里防止下次有人以为它白拿。
**但不打算收回去**：体积预算已经从「≤ 8 MB」改成「20 MB 以内都算小」（§1.3 / §1.5），
用户明确 20 MB 都不算大。理论上还有两条收法 —— ① 只注册常用的几种图
（流程图 / 时序 / 类 / 状态 / ER / 甘特 / 饼图），ELK 布局单独就占 1.5 MB；
② 不做成内嵌、改成按需下载 —— 两条都只是在为「已经不算问题的问题」付复杂度，
第 ② 条还会动到「不联网」这条承诺，所以都不做。

**「画」的边界**：支持**写** mermaid（自动出图），不做拖拽式的图形编辑器 ——
那是一个独立的画布应用，和「记事本」不是一件事。

### 5.23 文字高亮与重复行

两件事都是「标出来让我看见」，但一个改文档、一个不改，视觉上也必须分得开。

| 项 | 规则 |
|---|---|
| 语法 | `==文字==` → `<mark>`。预览、所见即所得、导出 HTML 三处同一个标签 |
| 往返 | `md → <mark> → md` 必须回到一模一样的 `==文字==`；改 `<span style>` 就等于把纯文本文件变成 HTML |
| 不认的地方 | 行内代码里不算（`a == b` 原样保留）；没成对的 `a == b` 也不算 |
| 触发 | 右键「高亮 / 取消高亮」（文案跟着选区状态换）、格式菜单「高亮」 |
| 取消的判据 | 所见即所得看**选中文字**是否等于 `<mark>` 的文字，而不是端点落在哪个元素：拖选一个高亮词时起点常停在前一个文本节点的末尾 |
| 只选中半块 | 什么都不做 —— 拆一半出来会留下 `====` |
| 颜色 | `--mark-bg`：浅色 `#ffe9a3`、深色半透明黄。⛔ 不能跟 `--sel-bg` 同族，那是「你刚选中」，这个是「文档里本来就标着」 |
| 重复行 | 工具菜单「高亮重复行」是个开关，打勾表示正在标；再点一次清掉 |
| 重复行只在视图上 | 编辑区用 CM6 的 `Decoration.line`（`.cm-dup`），所见即所得给 `.w-block` 加 `.w-dup`；**一律不碰文档内容** |
| 为什么按块 | 所见即所得里代码块是「一块十行」，行级标记在 DOM 里落不下去 |
| 文档一改就作废 | 行号会漂，重新映射只会越标越错：CM6 侧 `docChanged` 直接清空，所见即所得在 `flush()` 里清 |
| 切模式也算作废 | 切模式会整篇重渲（`_render` / `plain.load`），标记连节点一起消失。**所以开关状态只从 DOM 读**（块上还有没有 `.w-dup`），不另存布尔量 —— 另存的那份会跟 DOM 说两套 |
| ⛔ 别在 `_render` 里补重绘 | 它同时也是「整篇替换」的入口（大段粘贴、撤销文本快照），在那里重绘等于内容都变了还把重复标记贴回去 |
| 视觉区分 | 重复行是「更淡的底 + 左侧 2px 竖线」，和 `==文字==` 的整块黄底不是一回事 |
| 非 md 文件 | `==` 在 `.txt` / 代码 / 数据文件里只是两个等号，**绝不写进文件**。高亮按钮改用 CM6 的 `.cm-view-mark` 视图装饰（仍是 `--mark-bg` 黄底），区间存在标签的 `t.viewMarks`，随正文编辑 `map`，切标签各归各 |
| 非 md 的取消判据 | 只看 `t.viewMarks` 有没有覆盖当前选区。⛔ 不能扫源码里的 `==`：`a == b` 会被判成「已高亮」，再点一次什么都没发生 |
| md 文件不变 | 所见即所得仍写 `<mark>`、编辑模式仍写 `==文字==`；分流只按 `detectKind(t.name)`，一处判断管右键与格式菜单两个入口 |

当前行与「选区匹配」是**第三种东西**：既不是文档高亮，也不是重复行，而是跟着光标走的临时视图提示。三者的颜色必须分得开，否则用户分不清「我标过的」「我选中的」「光标停在哪」。

**选区本身**属于「当前选中」这一状态，不是视图提示：浅色直接用 `--accent-soft`，和大纲选中项
同一层浅橙；深色用暗一档的番茄底，⛔ 不交给系统高亮色（深色下发白刺眼、浅色下发蓝）。
所见即所得 / 预览也必须显式写 `::selection`，不能只覆盖编辑模式那一个容器。

| 提示 | 编辑模式 | 所见即所得 | 底色 |
|---|---|---|---|
| 当前行 | `.cm-activeLine` | 不画整行底 | `--active-line-bg` |
| 选中一段文字后，把全文里相同的文字一并标出 | `@codemirror/search` 的 `highlightSelectionMatches`，落在 `.cm-selectionMatch` | `selmatch.js` 注册 `sn-same`（CSS Custom Highlight API） | `--sel-match-bg` |
| 非 md 的高亮按钮 | `StateField` + `Decoration.mark` 的 `.cm-view-mark` | 无（非 md 不进所见即所得） | `--mark-bg` |

| 取值 | 数 | 为什么 |
|---|---|---|
| 当前行混合比 | 浅色 3% / 深色 5% 的 `--fg` | 原来是 `--accent` 7%，深色下成了一条橙红横杠；**强调色只表示状态** |
| 选中匹配混合比 | 明暗都取 `color-mix(--accent-soft 62%, --bg-panel)` | 它是「选中」的延伸，跟选区同族但再淡一档；⛔ 不再用 `--fg` 的半透明白 —— 深色下那是一块发白的灰，用户报「太白刺眼」。仍不跟 `==` 的黄、查找命中的琥珀抢语义 |
| 匹配最小长度 | 1 个字符 | 中文单字也要能标；写 2 会把「红」挡掉 |
| 匹配上限 | 两种模式各 300 处 | 满屏灰底反而看不出哪一处是刚选中的 |
| 所见即所得的闸门 | 选区 ≤ 64 字、全文 ≤ 200,000 字 | `selectionchange` 是高频事件，超长选区 / 大文档直接不算，别在里头跑全文扫描 |
| 折叠 / 点空白 / 选到正文外 | 立刻清掉 `sn-same` | 光标一走还留着灰底，会被当成「文档里标过」 |

**坑**：

- `@codemirror/search` 的参数叫 `minSelectionLength`，不是 `minLength`；写错不报错，只是单字不生效。它的 `baseTheme` 自带一层亮绿 `.cm-selectionMatch`，必须用 `editor/theme.js` 的 `var(--sel-match-bg)` 盖掉，否则深色下冒出一条荧光绿。
- 两种模式的**命中数口径不同**：CM6 的 `getDeco` 只装饰选区之外的命中（主选区那处由选区底色自己画），所见即所得的 `sn-same` 把选中那处也算进去。三个「红」选第一个：编辑模式 2 处、所见即所得 3 处，视觉上都是三处有反馈。⛔ 别拿同一个数字卡两边，更别为凑数给选区再叠一层装饰。
- `selmatch.js` 要跳过 `.w-code` / `.w-tex` / `pre` / `code` / `.katex`：那里已有代码着色，再叠一层灰会糊成一团。跨多个文本节点的命中必须拆成多个 `Range`，不能拿首末节点硬拼一个。
- `CSS.highlights` 是**全局注册表**，`sn-same` 不跟着 DOM 走：`_render()` 与 `clearView()` 都得删掉它，否则切标签后旧文档的灰底还挂在别处。
- 非 md 的视图高亮用 `StateField` + `Decoration.mark`，`docChanged` 时 `deco.map(tr.changes)`；`plain.load()` 会重建 state，所以 `setMode()` / `activate()` 之后要按 `t.viewMarks` 重放一次。⛔ 别把它写进 `t.content`，那等于把视图状态存进文件。
- 改 `cm6-entry.js` 要重跑 `pnpm build:cm6` 并提交 `src/vendor/cm6.js`；`editor/theme.js` 是运行时源码，改它不重生成 vendor，但两种改法都要 `cargo build` 重新内嵌前端。

**验收**：`test/run-units.mjs` 的 `==` 四条 + 源码级视图约定 8 条、
`test/editor.html` 的当前行 / 选区匹配 / 视图高亮 14 条（含量 computed 底色）、
`test/wysiwyg.html` 的 `sn-same` 8 条（含 `İ` 这类大小写折叠变长字符不涂错位置）、
`test/run-app.mjs` 的非 md 高亮 8 条（不写 `==`、`a == b` 不误判、切标签不串、md 仍写 `==`）、
`test/probe-app.mjs` 真机 WebView2 的 11 条；
真机看深色下黄底不能把字色逼成黑字（正文颜色一变，整段阅读节奏就断了）。

## 6. 侧栏与导航

### 6.1 侧栏两页

- 「大纲」与「文件」两个页签，宽度可拖拽；当前页记在 `settings.side`，重开还原。
- **没有齿轮图标**：设置是软件级的，放在侧栏顶部会被读成「这一栏的设置」。
- 页签右边是一个**定位按钮**（`locate` 准星图标），把当前标签对应的文件在文件树里找出来。
- 侧栏可整体隐藏（`Ctrl+Shift+O`），专注模式下自动隐藏。

#### 定位当前文件（照 IDEA 的 Select Opened File）

| 场景 | 行为 |
|---|---|
| 文件在树里，折叠着 | 把从根到它父目录的每一层都展开，再滚到可见处 |
| 已经在当前文件 | 照旧闪三下 —— 「知道是它，但想看清它在树的哪儿」正是这个按钮的用途 |
| 侧栏被隐藏 | 先叫出来，再切到「文件」页，最后才展开定位（顺序不能换：行要在可见之后才有高度） |
| 标签还没存盘 / 没打开文件夹 / 文件不在这个文件夹 | 各给一句 toast，不静默失败 |

闪烁只改背景，不动尺寸与位置（一抖就说明改错了属性）；三下约 1 秒后自动收掉。

### 6.2 大纲：只反映结构，不猜内容

| 类型 | 认什么 |
|---|---|
| Markdown | `#` ~ `######`（跳过围栏代码块内的 `#`）；Setext 的 `===` / `---`（文字在上一行） |
| 纯文本 | `#` / Setext / `【章节】` / `第X章·节·条` / 多级编号（点号段数 = 层级） |
| JSON | 缩进层级里的键 |
| 代码 | 函数 / 类 / 接口定义 |
| CSV / TSV | **不提取**（一行一条记录，提取出来就是几千行噪音） |

**单级编号必须「空行断组后只剩它一条」才算章节**：一份 `1. 2. 3.` 的清单不该把每行都变成
大纲；文件首尾天然缺一边邻居，所以不能按「前后都有空行」判。收完做一次「不跳级」归一化，
避免 h3 上面没有 h1/h2 时缩进悬空。

| 交互 | 规则 |
|---|---|
| 点击 | 标题**顶边贴基准线**（容器顶 + min(96, 高 × 0.3)），不是滚到视口中央 —— 滚到中央时高亮判据还停在上一节，用户会看到「点 A 亮了 B」 |
| 跟随 | 编辑 / 预览 / 所见即所得三套滚动容器各接一条路；CodeMirror 用 `lineAtViewportY()`，**不许自己累加行高**（折行会算错） |
| 滚到底 | 高亮让给最后一个标题（否则最后一节永远高亮不到） |
| 空状态 | 按文件类型分别说明，见 §2.9 |
| 大纲内定位 | 二分查找（标题位置单调递增） |

**大纲必须窗口化**：3 万个标题全铺，每次重排要 `classList.toggle` 4 万项，会把主文档的
视口渲染一起拖垮。只铺可见段（行高 28px、上下各多铺 12 行），未铺部分用**子元素 div 占位**
（绝不能用 padding，`clientHeight` 含 padding，会把盒子越撑越高）。首帧 `clientHeight`
不可信（可能等于内容高度），只采信 `(40, 4000)` 区间，超范围用 rAF 重试。

**换文档 = 换一份数据，滚动位置与窗口游标必须一起归零**：列表的 `scrollTop` 属于上一份
文档；新文档只有 3 条却拿旧的 8000px 去算窗口，`start` 会落到 `end` 之后，
`new Array(end - start)` 拿到负数当场抛异常、DOM 原封不动 —— 表现就是「切了文件大纲
还是旧的，滚回顶部才刷新」。判据用**标签 id**（不是大纲签名）：同一文档里增删标题不该
把正滚在中间的用户拽回顶部。无论哪条路径，`start/end` 都要按当前条目数 `n` 收口
（`end >= start`，且 `scrollTop <= n × 28 - 视口高`），⛔ 不许让窗口区间越界。

窗口化之后有三件事必须配套，少一条就会出现「算对了但看不见」：

- **重铺要保住 `scrollTop`**。`replaceChildren` 会先把子节点全摘掉，容器高度瞬间归零，
  浏览器顺手把 `scrollTop` 夹到 0，再把内容插回来也不会自动复原。不手动恢复，列表每
  重铺一次用户就跳回顶部 —— 跟随高亮时表现为「索引明明到了第 30 节，却永远亮在第一屏」。
- **高亮项必须在渲染窗口内**。`paintOutlineActive` 只给已铺出来的节点加类，当前章节落在
  窗口外时（长文档 + 矮窗口必现）要先滚列表再点亮，否则等于给 `null` 加类。还要当心它
  的 `cur === outlineActive` 提前返回：高亮一旦因为重铺丢了类，这个判断会让它永不重试。
- **滚动定位要二次校正**。CM6 首屏用的是估算行高，滚一次才把视口外的行测出来 ——
  120 行的文档实测一次长高近 500px。只按第一次的量算落点会差一整行，点「第 22 节」
  高亮停在第 21 节。`revealOffset` 在下一帧按新布局再校一次。

还有一件不属于「三件事」但同样会让面板变白板：**空态那句话不许被重铺清掉**。切到一个
没有结构的文件时，列表内容变短、`scrollTop` 从几百被夹回 0，浏览器顺手补一个 scroll，
那个 rAF 里的重铺走进空分支、一句 `replaceChildren()` 就把刚写好的「未发现章节标记」
抹了 —— 用户看到的是一整块空白，分不清「这个文件没有结构」还是大纲坏了。现在空分支
只把窗口化游标归零：`outlineItems` 只有 `updateOutline` 能改，它为空时 DOM 必然已经是
空态，重铺没有资格再动节点。

**矮窗口是大纲的照妖镜**：620×420 的下限尺寸下侧栏只装得下二十来项，上面三条一条都
藏不住。探针跑大纲一律先确认侧栏停在大纲页 —— 切到文件页后 `#outlineList` 高度是 0，
既滚不动也点不亮。

### 6.3 文件树

| 项 | 规则 |
|---|---|
| 打开文件夹 | 菜单 / 设置面板 / 命令行；一个文件夹一个根 |
| 懒加载 | 展开时才读这一层（`read_dir_shallow`），不递归；展开状态在刷新后保留 |
| 排序 | 目录在前、文件在后，同类按名称（中文按拼音） |
| 单击 | 打开文件；已打开则切到那个标签（不重复开） |
| 双击 | 同单击（没有「预览 vs 打开」两态，别让用户猜） |
| 右键 | 文件：重命名… / 删除（进回收站）/ **历史版本** / 复制文件路径 / 在资源管理器中显示；目录：再加「新建文件…」「新建文件夹…」；空白处：根目录的新建两项 + 刷新 |
| 多选 | `Ctrl` 点加选、`Shift` 点连选；选两个文件后可「比较这两个文件」 |
| 选中态 | `.active` = 当前编辑区文件；`.sel` = 显式多选。**单选必须跟着标签切换搬走**，⛔ 当前行不许再叠 `.sel`（那圈 accent 边框 + 灰底看起来就是「鼠标还悬在旧文件上」）；显式多选 ≥ 2 时不被标签切换打断 |
| 与标签联动 | 重命名 / 删除后同步已打开的标签；删除有未保存改动的标签先问 |

### 6.4 侧栏搜索：只搜不改

| 项 | 规则 |
|---|---|
| 范围 | 当前打开的文件夹，递归 |
| 模式 | 字面 / 正则；`Aa` 区分大小写；改开关要**立即重跑**并把按钮状态说清 |
| 结果 | 按文件分组，显示命中行；点击跳到该文件的那一行 |
| 上限 | 200 条；到了就明说「只显示前 200 条」 |
| 跳过 | 二进制（含 NUL）、大于 4 MB 的文件 |
| 替换 | **不提供**。文件侧栏只回答「在哪儿」，改内容回编辑区 |
| 空态 | 「没有找到匹配的内容」+ 当前范围与模式 |

⛔ **跨文件替换整体删除**（后端命令、`plan_replace`、面板行一起删）。这类功能一次误点改几十
个文件，撤销要按文件翻历史快照，而真实需求几乎不存在。侧栏搜索的价值是「定位」，
不是「批量手术」。

### 6.5 跳转

- `Ctrl+G` 跳转到行：输入行号，光标落到该行行首，视口把该行放到中央。
- 目录（`Ctrl+Shift+T` 之外的「插入 → 目录…」）按当前文档的标题生成锚点列表；锚点 slug
  由渲染和生成**共用同一个函数**，差一点链接就跳不过去。
- 站内链接 `#标题` 同样走 slug 匹配；重名标题按出现顺序加后缀，两边算法一致。

### 6.6 落地：侧栏 / 文件树 / 大纲的取值

#### 侧栏（大纲 / 文件两页）

**取值表**：

| 元素 | 值 |
|---|---|
| `.outline` 宽 | 220（min **140** / max **420**） |
| 侧栏头 `.side-head` | 高 **38**，`padding: 0 8px 0 10px` |
| 页签 `.side-tab` | 高 24，字号 12，`padding: 0 8px`；`.active` 底 `--bg-panel` |
| `.pane-head`（详情页用） | 高 **34**，字号 11 / 600 / `--fg-faint` |
| 分隔线 `.splitter` | 宽 **5**，线画在 `left: 2px`、`0.5px` 宽；hover 换 `--accent` |
| 大纲项 | 高 **28**（固定，见下），`padding: 5px 10px`；字号 **13**（h1 同号、靠 600 加粗）；缩进按级 18/30/42/54 |

**坑**：
- ⛔ 大纲项行高必须与 `OUTLINE_ROW` 常量严格一致。行高不齐时「第几条 × 28」的定位
  会越往下偏越多，出现「点第 30 条跳到第 27 条」。
- ⛔ 侧栏是**灰面**（`--bg-side`），正文是纸面，分界本身就有底色差；`.splitter::after`
  那条 0.5px 线只是「收边」。**不要**再给 `.outline` 加 `border-right`，否则 5px 的
  拖拽区里会同时出现两条线。
- ⛔ 大纲项的**行高必须与 `OUTLINE_ROW` 严格一致**（固定 `height: 28px` + `border-box`），
  字号变化不许带动高度 —— 一行算错，往下越滚越偏。

**验收**：手测——拖分隔线到 140 / 420 两个极限；大纲 300 条时滚动是否跟手、点击是否落对行。

#### 文件树与文件夹内搜索

**取值表**：

| 元素 | 值 |
|---|---|
| 搜索框 `.ft-search` | 高 **27**，`margin: 0 8px 6px`，`inset 0 0 0 1px var(--line)` |
| 开关 `.ft-tog` | 高 19，字号 10.5，等宽字体；开着时 `--accent` 边框 |
| 路径行 `.ft-path` | 字号 11.5；「选择…」按钮高 21 |
| 树行 `.ft-row` | 高 **24**，字号 12.5，`padding-right: 6` |
| 折叠箭头 `.ft-caret` | 12×12 固定槽位，`open` 时 `rotate(90deg)` |
| 图标 `.ft-ico` | 14×14 |
| 命中行 `.ft-hit` | `padding: 3px 6px 3px 21px`（让开文件名那级的缩进） |
| 文件名行 `.ft-hit-file` | 字号 12 / 600，`margin-top: 4` |
| 空态 `.ft-empty` | `padding: 18px 14px`，行高 1.7 |

**两种选中态并存**（这是这里最容易做错的地方）：

| 状态 | 样式 | 含义 |
|---|---|---|
| `.ft-row.active` | `--accent-soft` 底 + `--accent` 字 + 600 | **编辑区里打开的就是它** |
| `.ft-row.sel` | `--bg-hover` 底 + `inset 0 0 0 1px var(--accent)` | 多选（挑两个文件做对比） |
| 两者同时 | `--accent-soft` 底 + 描边 | 既打开又被选 |

实底强调只能有一个，所以「多选」只加一圈描边——否则同时选中三个文件时，看不出来
哪个在编辑区里。

**坑**：
- ⛔ 「大小相同 = 文件相同」在文件夹对比里必须读内容（§13）。这里同理：搜索命中数
  不能靠缓存的文件大小判断。
- ⛔ 一层监听意味着：用户在看 `docs/` 时，`docs/sub/` 里新建的文件**不会**触发刷新。
  这是故意的（递归监听百万文件会拖垮进程），但界面上不能假装自己在递归监听。
- ⛔ 树行高度固定 24，文件夹与文件的行首图标必须在同一列对齐（`.ft-caret` 占固定
  12px 槽位就是为了这个）。

**验收**：`test/probe-filetree.mjs` 31 条；手测——搜一个必定 0 命中的词，看是否给出
「没有找到」而不是空白。

#### 大纲

**取值表**：

| 元素 | 值 |
|---|---|
| 列表容器 | `padding: 0 8px 16px`，`min-height: 0`（**必须有**，见坑） |
| 项高 | **28**（`box-sizing: border-box`，`line-height: 18`） |
| 基准字号 | **13.5**（比正文小一档，但不再压到 12.5 那么费眼） |
| `h1` | 字号 **14** / 600 / `--fg` |
| `h2`–`h6` 缩进 | `padding-left: 18 / 30 / 42 / 54`，字号 13 |
| hover | 底 `--bg-hover`，左沿 2px `--line-strong` |
| 当前节 | 底 `--accent-soft`，字 `--accent`，左沿 2px `--accent`，600 |
| 上限 | **300** 条，文本截 **80** 字 |
| 空态 | `padding: 16`，字号 12，行高 1.7 |

**坑**：
- ⛔ 列表容器缺 `min-height: 0` 时，几万条大纲的上下 padding 会把 flex 盒子自己撑到
  几十万像素高——窗口化等于没做。这是 flex 项 `min-height: auto` 的老陷阱。
- ⛔ hover 的左沿是**变色不加位移**。加位移（比如 `padding-left + 2px`）会让指针扫过时
  整行文字左右抖。
- ⛔ 当前节的判断不能「谁的标题在视口顶部谁亮」，那样两节之间会闪；用「最后一个
  顶部不超过视口 1/3 的标题」。

**验收**：手测——打开一份 300 条大纲的文档，滚动时高亮是否连续、跳转是否准到节。

## 7. 速记

### 7.1 它是什么

一份固定在 `<app_data_dir>/quicknote.md` 的普通 Markdown 标签。不选位置、不按保存 ——
用来接住「先记一下，回头再整理」的那类内容。

### 7.2 与普通标签的三处不同

| 普通文档 | 速记 |
|---|---|
| 脏标记 = 内存 ≠ 磁盘 | **永远算干净**（`isDirty` 直接放行）—— 它没有「保存」这个动作 |
| 关窗时逐份问「要保存吗」 | 不问；关标签 / 退出前先 `flushQuickNote()` |
| 进「最近打开」、进会话恢复、进草稿 | 都不进 |

**「永远算干净」和「关前必须 flush」是一对**：打字到落盘是 350 ms 防抖，打完最后一个字就
关窗，`content` 里可能还差几个字。正因为不显示脏点、不弹确认框，沉默丢字的窗口必须由代码
自己关掉 —— 否则「不用保存」就成了「悄悄丢」。

### 7.3 只有一份

- 身份看标签上的 `quickNote` 标记，**不靠路径比较**（路径比较要在每个用到的地方重新问后端）。
- `openPath()` 命中速记路径时改道 `openQuickNote()`；文件树、拖放、最近打开都会走到这里。
- 两个标签写同一个文件，后保存的会把先保存的盖掉 —— 所以只允许一份。

### 7.4 「另存为」= 导出副本

对速记执行另存为，**不改 `t.path`**。改了之后自动保存会跟着副本跑，速记本身从此不再更新。

### 7.5 入口

- 菜单栏最右的「速记」是一个**动作项**，点一次直接打开。
- **没有「速记」小节**。原来那四行（插入当前时间 / 在文件夹中显示 / 复制路径 / 路径提示）
  2026-11-05 撤掉了，逐条理由：
  | 原来那行 | 为什么撤 |
  |---|---|
  | 插入当前时间 | 正文里自己打 `2026-11-05 20:11` 更快，也不会插错位置 |
  | 在文件夹中显示 | 它对**任何**打开着的文件都成立，挪到「打开文件夹…」下面了（§2.6） |
  | 复制文件路径 | 标签右键里本来就有，同一个命令不该列两遍 |
  | 「保存在 …\quicknote.md」 | 前半段被截成 `…`，用户根本认不出在哪；而且上一条已经能直接把人带到那个文件夹 |
- 剩下的「清空速记」留在「文件」菜单里（`关闭标签` 下面一行、不带分区头）：它**没有别的入口**。
- `Ctrl+Shift+M` 打开。
- 清空前先存一份历史快照，给「手滑清空」留一条后路。
- ⛔ **清空只清速记**。判断方法是「速记标签此刻是否正显示着」：不显示就只更新它的
  `content`，绝不去碰编辑器 —— 碰了就是清掉用户正在看的那一篇（§3 的不变量）。

### 7.6 落地：速记的取值

**取值表**：

| 项 | 值 | 说明 |
|---|---|---|
| 文件路径 | 应用数据目录 / `quicknote.md` | `quickNotePath()`；探针用 `EZNOTEPAD_QUICKNOTE` 指到 `%TEMP%` |
| 自动落盘 | 停手 **350ms** | `scheduleQuickSave` |
| 标签名 | 「速记」 | `tabLabel()` 固定 |
| 未保存点 | **不显示** | `isDirty` 对 `quickNote` 放行 |

**八条规则**：
1. **只允许一份**。已开着就切过去（`openQuickNote` 先 `tabs.find(t => t.quickNote)`），
   否则两个编辑器会互相覆盖同一个文件。
2. **不进会话恢复**。`restoreSession` 过滤掉 `quickNote`；它靠磁盘文件自己回来。
3. **关标签 / 退出前必须 `flushQuickNote()`**，返回值 `false` 时要拦住关闭。
4. **贴盘失败只说一次**（`quickWarned`），磁盘满/被占用时沉默才是真的伤人。
5. **另存为只导出副本，不动 `t.path`**。改了路径，之后的自动保存会写到副本上，
   速记本身从此不再更新。
6. **清空之前先存快照**（`clearQuickNote` 先 `write_history_snapshot`），这是唯一能反悔的地方。
7. **打开时如果文件在但读不出来**（二进制/无权限），要明说并**放弃打开**：继续写下去
   等于把用户原来的笔记盖掉。文件不存在则不是错误——空着开。
8. **一级菜单「速记」是动作**（`action`），点一次直接开，不再套一层「打开速记」。

**坑**：
- ⛔ 编辑器的 `flush` 是防抖的：`flushQuickNote` 里必须先 `t.content = readEditor(t)`，
  否则「打完最后一个字就关窗」会丢掉最后几个字。
- ⛔ 速记标签的内容永远算干净，所以**它不会出现在草稿里**——这是设计，不是漏洞。
  反过来说，任何「凭脏标记决定要不要落盘」的逻辑都不能用在它身上。

**验收**：`test/probe-quicknote.mjs` 28 条（含「开着别的文档时清空速记」）；手测——打 20 个字，0.5s 后 `taskkill`，
重开看最后几个字在不在。

## 8. 设置

### 8.1 四页

| 页 | 内容 |
|---|---|
| 外观 | 主题（跟随系统 / 浅色 / 深色）、字号（步进 + 当前 px + 重置）、正文宽度（560–1600，步进 40，默认 800 + 重置） |
| 界面 | 语言（跟随系统 + 9 种）、显示侧栏、双栏 |
| 文件 | 自动保存、监听外部修改、工作文件夹 |
| 快捷键 | 说明一句 + 全部命令的键位列表 + 逐条「更改」 |

**复选框文案只写「开关什么」，不写机制**：`自动保存` 不写「停手约 1 秒写盘」，
`监听外部修改` 不写「别的程序改了文件时提示」。这些是实现的细节，写在设置面板里
既占位置又逼用户读一遍才知道要不要勾。要解释就在帮助文档里解释一次。

**「重置」逐条给，不叫「实际大小 / 默认」**：两处复位做的是同一件事（回到 `DEFAULTS`），
名字也必须一样；「实际大小」还会让人以为是缩放 100%，其实只是字号回 13.5。

「行显示模式」不在设置里 —— 它放在**视图菜单**和右键菜单，因为改的是「此刻怎么显示」，
不是一次性配置。

### 8.2 即时生效

面板没有「确定」按钮，改哪一项立刻生效并写 localStorage。底部只有「完成」。
省掉「改完忘了点确定」这一类挫败。

### 8.3 默认值与迁移

| 项 | 默认 |
|---|---|
| 主题 | 跟随系统 |
| 语言 | 跟随系统 |
| 字号 | 13.5 px |
| 正文宽度 | 800 px |
| 行显示 | 自动换行 |
| 布局 | 单栏 |
| 自动保存 | **开** |
| 磁盘监听 | 开 |
| 侧栏 | 显示，停在大纲页 |

**改默认值必须 bump `__v`**：老用户的 localStorage 里存着旧默认，光改 `DEFAULTS` 对他们无效。
当前 `__v = 4`，迁移做过四件事：布局回单栏、自动保存回开、清掉被粘滞的 `lastMode`、
语言回「跟随系统」。

**新增设置键不需要 bump**：`Object.assign({}, DEFAULTS, stored)` 会自动补上缺失的键。
bump 会顺带重跑上面那几条重置，属于误伤。

### 8.4 恢复默认

- 确认框写清「主题、字号、正文宽度、布局、自动保存都会回到出厂状态，文件夹设置也会清空」。
- 实现是 `Object.assign(settings, DEFAULTS, { keymap: {}, lastMode: {} })` —— 手抄字段
  加一项必漏；`keymap` / `lastMode` 必须换新对象，否则改动会污染 `DEFAULTS`。
- 测试或脚本要钉死设置时，写入的对象必须带 `__v: 4`，否则会被迁移改写。

### 8.5 自定义快捷键

- 设置 → 快捷键 → 某条命令「更改」→ 直接按新组合键。
- 没有自定义键的行不画那个灰掉的「恢复」：几十行灰按钮就是一片噪声。位置留着
  （`visibility: hidden`），这样每行的「更改」才竖着对齐。
- 规则：必须带 `Ctrl` / `Alt`，或单用 `F1–F12`；`Esc` 取消。
- 自定义键位优先于默认键位；冲突时后设的覆盖前设的，并在列表里标出冲突。
- 存在 `settings.keymap`（`{ 'mod+shift+k': 'commandId' }`），与平台无关的 `mod` 在匹配时
  映射到 `Ctrl` / `⌘`。

### 8.6 落地：设置面板的取值

**取值表**：

| 元素 | 值 |
|---|---|
| 模态框 | 宽 **760**（`.modal.wide`），`max-height: calc(100vh - 80px)` |
| 网格 `.set-panel` | `grid-template-columns: 156px 1fr`，`min-height: 240` |
| 分类按钮 `.set-tab` | 高 **30**、`padding: 0 10`，字号 12；`.on` 底 `--bg-well` + 600 |
| 底部「恢复默认设置」 | 高 **30** 与标签行同高，`padding: 0 10` **左对齐**，色 `--fg-faint`（hover 提亮）。`.mini` 默认 `justify-content: center`，不覆盖就会飘到中间、与上面四条错开半个词 |
| 内容区 `.set-body` | `gap: 18`、`padding-left: 20`、`max-height: 58vh` |
| 组内 `gap` | 8；组标签 12 / 600 / `--fg-faint`（**不加字距**：中文一加就散） |
| 分段控件 `.set-seg` | 外框 `padding: 4`、`gap: 4`、外圆角 **8**；按钮高 **26**、内圆角 **4**（8 − 4，同心）；轨道 `--bg-well`、选中项 `--bg-raised` |
| 步进按钮 `.set-step` | **28×26**，字号 15，底 `--bg-well` |
| 数值 `.set-value` | `min-width: 62`，居中，`tabular-nums` |
| 复位链接 `.set-link` | 字号 12，`--fg-soft`（**不用强调色**：它是个动作，不是状态） |
| 下拉 `.set-select` | 宽 **220**、高 **28**，`0.5px --line-strong` 边，底 `--bg-well`，焦点环 `--ring` |
| 路径框 `.set-folder` | 高 **26**（与右侧 `.mini` 同高，否则一行里两个高度对不齐），底 `--bg-well` |
| 提示文字 `.set-hint` | 字号 12，`--fg-faint`，行高 1.6 |

**取值范围**：

| 项 | 范围 | 步长 | 默认 |
|---|---|---|---|
| 字号 `fontSize` | **11 – 24** | **0.5** | 13.5 |
| 正文宽 `readWidth` | **560 – 1600** | **40** | 800 |
| 主题 `theme` | `auto` / `light` / `dark` | — | `auto` |
| 语言 `lang` | `auto` + 9 种 | — | `auto` |
| 布局 `layout` | `single` / `split` | — | `single` |

**坑**：
- ⛔ 迁移判据用 `!==` 而不是 `<`：用户可能装了更新版又退回旧版，`<` 会漏掉。
- ⛔ **新增键不要 bump `__v`**；**改默认值必须 bump**（否则老用户的旧默认值永远不更新）。
- ⛔ 面板里的文案一律 `data-i18n` + 中文兜底，末尾 `applyDom(box)` 统一翻。这样
  换语言时开着的面板能就地刷掉，不用关掉重开。
- ⛔ 切分类只是 `hidden` 切换，**不要重建 DOM**：重建会让用户刚改的控件回到上次渲染值。

**验收**：`test/probe-app.mjs` 的设置相关断言；手测——字号调到 24 再恢复默认，
看重启后是否真的回到 13.5。

## 9. 历史版本

| 项 | 规则 |
|---|---|
| 何时留 | **每次写盘之前**，把上一版磁盘内容留一份。内容为空 / 单份 > 2MB / 与最新一份相同 → 不留 |
| 自动保存 | **10 分钟合并窗口**内不新增：连续打字只留「这段编辑开始前的那一版」。`Ctrl+S` 是显式里程碑，每次都记（清空速记也算） |
| 位置 | `<app_data_dir>/history/<fnv1a(路径)>/<时间戳>.txt`；目录里另存 `name.txt` 供人辨认 |
| 上限 | 每个文件最近 60 份，再按总量 20 MB 兜一道；**长期检查点代表不删**（1/3/7/10/20/30/60/90/120/360 天各保年龄之后最近的一份，可超 60 份） |
| 面板入口 | ①「文件 → 历史版本…」（当前文件）；②**文件树右键 → 历史版本**（被右键那个文件，不要求它已打开） |
| 面板 | 列出时间（今天 / 昨天 / 月日 + 时分）与大小 |
| 动作一 | 在**只读标签**里打开这一版（可以对照、复制，不会误覆盖当前文件） |
| 动作二 | 写回编辑器（**不落盘**）—— 要不要保存由用户决定；**只有被查看的文件正是当前活动标签时才给这个按钮** |
| 不动作 | ⛔ 绝不「一键回滚并覆盖磁盘」；⛔ 未打开的文件不给「恢复」（写回编辑器必须落到明确的标签上） |

**为什么回滚不直接覆盖**：历史快照是兜底，不是版本控制。一键覆盖会让「我只想看一眼旧版」
变成「我的新版没了」。所有对比 / 合并 / 历史功能的共同原则是：**结果先落在编辑器里，
落不落盘由用户按一次 `Ctrl+S` 决定。**

## 10. 导出（不提供打印）

### 10.1 导出网页（HTML）

- 单个 `.html` 文件，样式内联，双击即可看。
- 图片转 `data:` URI —— 不转的话另存到别处就只剩一堆断链。
- 单张图片超过 4 MB 不内嵌，保留原相对路径，并在完成提示里说明「有几张图没有内嵌」。
- 非 md 文件按当前类型的预览结果导出（JSON 高亮、代码高亮）。

### 10.2 导出 PDF（不提供打印）

- `Ctrl+P` / 文件 → 导出 PDF；**只导出文件，不调打印机**。
- 选完保存路径后：把内容渲染进 `#printRoot`，等版面和图落地，由 Rust 侧调
  **WebView2 的 `PrintToPdf`** 直接写成 PDF。
- 导出期间整屏盖一层「正在生成 PDF…」，主题临时切成浅色（深色底打成 PDF 既费墨也没法看），
  结束一定还原。
- 复用预览的渲染结果：Markdown 的标题、表格、代码高亮、公式、```mermaid 图都在里面。
- **整篇分页导出**，不是只出第一页。打印媒体要把屏幕布局的
  `height:100%` / `overflow:hidden` / `display:flex` 三条一起撤销，否则 `html/body`
  仍锁在一个视口高，长文档被裁成 1 页（用户原话：「只能导出一页，后面内容没了」）。
- 失败给对话框（错误码 `pdf.failed`），不静默。

**验收**：90 节的长 Markdown 导出后，PDF 里的 `/Type /Page` 对象数 **≥ 3**；
只改 CSS 不真的导出是抓不到这个 bug 的（`test/probe-app.mjs` 同时量打印媒体下的
`body` 布局与真实 PDF 页数）。

**为什么不是「打印」**：WebView2 **没有实现**浏览器的打印面板。原来那版是
`window.open('') + win.print()`，在真机上既不弹框也不报错 —— 用户看到的正是「点了没反应」。
嵌入式 WebView 里根本不存在 `window.print()` 那条路径，所以不是「修一下」，是换机制。
`PrintToPdf` 是 WebView2 自己的接口：按 `@media print` 渲染当前页面、直接落盘，
不需要打印机、不需要系统对话框、也不弹第二个窗口。

⚠️ **这条只做了 Windows**。macOS 的 WKWebView 有 `createPDF` 但接口不同，
目前 `export_pdf` 在非 Windows 上返回错误码 `pdf.unsupported`（见《实现规格》§10.4 C1）。

### 10.3 落地：导出的取值

**取值表**：

| 项 | 值 |
|---|---|
| 导出 HTML 正文宽 | **46rem**（≈736px，比屏幕上的 `--rw` 窄，因为要打印与阅读） |
| 单张图片上限 | **4MB**（超过不内嵌，保留原路径） |
| MIME 支持 | **9** 种（png/jpg/jpeg/gif/webp/svg/bmp/avif/ico） |
| PDF 纸张 | **A4**（8.27 × 11.69 英寸，`PrintSettings`） |
| PDF 页边距 | 交给 `@page`：上下 **16mm**、左右 **15mm**；`PrintSettings` 的四边是 **0**（两处都给会挤成窄条） |
| PDF 底色 | `ShouldPrintBackgrounds = true`（代码块、引用条的浅灰靠它） |
| PDF 内容容器 | `#printRoot`，平时 `display:none`，`@media print` 只显示它 |
| PDF 导出耗时 | 一页带图 ≈ **1.8 s**（含 mermaid 布局） |
| PDF 大小 | 纯文字页 ≈ 3 KB；带一张流程图 ≈ 30–70 KB（矢量） |
| 分页保护 | `page-break-after: avoid` 给标题、`page-break-inside: avoid` 给表格、图片、代码块 |
| 版面就绪判据 | `document.fonts.ready` + **两帧 rAF** + mermaid 渲染 promise 落地 |

**坑**：
- ⛔ `window.print()` 在 WebView2 里是**空实现**：不弹框、不报错、不返回错误。别再用。
- ⛔ `#printRoot` 之外的东西**一律不会进 PDF**（`body > *:not(#printRoot)` 被隐藏）。
  谁在别处渲染「打印专用」内容，都会在 PDF 里凭空少一块，而屏幕上看不出来。
- ⛔ 主题必须在导出期间切成浅色：深色主题的 `--bg` 是 #1a1d23，打出来整页黑。
  切换外面盖了遮罩，用户看不到这一下闪烁。
- ⛔ 导出前要把编辑态 `flush` 到 `content`，否则导出的是上一次的文本。
- ⛔ mermaid 图必须**等 SVG 落地**再序列化，否则 PDF 里是一段没人渲染的源码。
- ⛔ 导出 HTML 里的相对图片路径要按**文档所在目录**解析，不是按应用目录。

**验收**：`test/probe-app.mjs`（真机导出到 `%TEMP%`，断言 `%PDF-` 头、文件 > 2KB、
导出后主题/遮罩/容器都复原）；手测——导一篇带图、带表格、带代码块的文档，
用系统 PDF 阅读器打开，看分页有没有把表格切断、代码有没有被截掉右半边。

## 11. 文本对比窗口

对比是这款软件的第二条腿。它的设计目标不是「功能对标 Beyond Compare」，而是
**「打开就能看、看完就能改、改完就能存」**。

### 11.1 形态与生命周期

- 独立窗口（`compare.html`），有自己的最大化 / 关闭；窗口标题带两侧文件名。
- 入口：菜单「对比 → 文本对比…」、`Ctrl+D`、文件夹对比里点一行、命令行 `--compare 左 右`。
- **窗口复用**：已经开着就推新数据（`compare:load` 事件），不再开第二个。
  因此「打开一对新文件」必须先把两侧重置干净（见 §11.3）。
- 关闭走 `onCloseRequested`，× / Alt+F4 / 任务栏三条路都过这里（见 §11.12）。
- **窗口尺寸**：最小 760×460，出生即铺满工作区；无边框，标题栏自绘（`.cmp-top` 34px）。

四条形态决策与它们否决掉的替代方案：

| 决策 | 做法 | 否决了什么 |
|---|---|---|
| 独立窗口，不是标签页 | 另一个 `WebviewWindow`（label `compare`） | 塞进主窗口当标签 → 对比要占满屏，和编辑器抢宽；切标签还会丢对比状态 |
| 不共享内存 | 只通过两条通道通信：建窗时的 `CompareRequest` 状态、后续的 `compare:load` 事件 | 把两边的行模型塞进同一个进程 → 窗口崩溃互相带死 |
| 已开着就复用 | `get_webview_window("compare")` 命中就 `emit("compare:load", …)` | 再开一个同名窗口 → 两个窗口抢同一个 label，第二个静默失败 |
| 铺满工作区 | `create_tool_window` 按主窗口所在屏的 `rcWork` 建 | 用 `SPI_GETWORKAREA` → 只认主屏，副屏上点「对比」窗口跑到主屏 |

⚠️ **建窗命令必须是 `async fn`**。同步命令里 `get_webview_window` 拿不到刚创建的窗口，
表现是「点了没反应，也不报错」。
⚠️ **新窗口的 label 必须写进 `capabilities/default.json` 的 `windows` 数组**。不写的话
页面照常渲染、数据照常出来，但 `plugin:window|close` / `dialog:default` / `start-dragging`
全部**静默失败**——截图完全看不出来，只有真点一下才发现。

### 11.2 打开时给什么

| 情况 | 界面 |
|---|---|
| 什么都没带 | **两个空白编辑区**，光标在左侧第一行，`Ctrl+V` 就能用；顶部一行提示「把两段文本分别粘到左右两侧，或者点上面的文件名打开文件」 |
| 带一个文件 | 另一侧补成空白文本，两侧都能写 |
| 带两个文件 | 两侧都加载，直接进可写状态 |
| 一侧读失败 | 那一侧**清成空白可写区**，并说明失败原因；绝不保留上一轮的旧内容 |

**为什么不再有「选择左侧 / 选择右侧 / 粘贴两段文本」的浮层**：三个入口等于逼用户先选模式，
而最常见的用法就是贴两段文本比一比。直接给两个空白框，想比文件就点槽位上的文件夹图标
（有图标才看得出那里能点）。

**失败侧必须清空**：否则「新的超大文件没读进来」时，界面会拿旧左栏比新右栏，给出一个
看起来完全正常的错误结论。

### 11.3 上限

| 项 | 上限 | 超限表现 |
|---|---|---|
| 单文件大小 | 8 MB | **先问 `file_size`，超限不读**；正文上方可关闭的提示条写明文件名、实际值、上限、建议 |
| 单文件行数 | 50 000 行 | 同上 |
| 文件夹列举 | 20 000 个文件 | 提示已截断 |

引擎本身很快（5 万行约 160 ms），卡的是读入、每行一个对象的模型和导出报告。所以限制放在
**读之前**，不是读完再放弃。

### 11.4 行模型与对齐

- 两侧各是一个行数组；并排视图把两侧对齐成一张「对齐行表」，每行有左侧行号 / 右侧行号 /
  类型（相同 / 修改 / 仅左 / 仅右）。
- 短的一侧补**占位行**（`row.l` 或 `row.r` 为 `null`）。
- 占位行不是空白，是「这一侧缺了几行」的位置（见 §11.7）。
- 行级 diff 分档：段内 `n × m ≤ 4M` 走精确 LCS；更大就按「两侧都唯一出现的行」当锚点
  （LIS 保持顺序）切开递归；兜底只能报「整段替换」。
- **绝不允许输出 `same` 而某一侧行号无效**：这会让整栏空白、新增全堆到文末，用户拿到的
  是一个看似正常的错误结论。

### 11.5 差异怎么画

| 元素 | 规则 |
|---|---|
| 修改行 | 只有 `inlineDiff` 算出的那几段字变红；行本身不加底色、不加边框 |
| 仅左 / 仅右 | 整行文字红（行号也红） |
| 预览条 | 每一条差异行一根 1px 细红线，画在 22px 轨道正中；差异太密（每行不足 2.5px 或超过 4000 行）时退回按段合并 |
| 底色 | **一律不铺** |
| 删除线 | 不用（删除由「仅左」表达，不需要再把字划掉） |

**为什么只红字**：一屏几十处差异时，铺底色会让整页发红，反而看不出是哪几个字变了。
差异要一眼看见，但**看见的应该是字**。

### 11.6 预览条

| 项 | 规则 |
|---|---|
| 尺寸 | 栏宽 34px，槽宽 22px |
| 起点 | 对齐**滚动区顶部**，不是预览条自身顶部（每栏顶上还有 26px 的文件名条） |
| 高度 | `min(可视高度, 内容高度)`，短文档时只有几行高 |
| 颜色 | 只有两种：红 = 这一行有差异；灰框 = 正在看的范围 |
| 当前这一处 | **不额外上色**。差异位置本来就靠红线的疏密看出来，多一种颜色只会让人问「蓝色是什么」 |
| 视口框 | 内容只比一屏多一点时不画（否则整条轨道被染灰，像没画差异） |
| 交互 | 点击 / 拖动定位，换算与绘制共用同一个几何函数 |
| 说明 | 三种含义写进 `title`，九种语言 |

宽度从 22px 加到 34px 是因为「三样东西抢十来个像素，点起来像瞄靶」——用户的原话是
「预览条太窄，很不好用」。丢给正文 12px 换这些划算。

### 11.7 编辑

打开即可写，只读是主动选择。

| 项 | 规则 |
|---|---|
| 宿主 | 每行一个 `contenteditable="plaintext-only"` 单元 |
| 单行内编辑 | 交给浏览器（保住原生撤销粒度） |
| 行首退格 / 行尾删除 | 自己算：合并行（`mergeUp` / `mergeDown`） |
| 回车 | 在光标处拆行 |
| Tab / Shift+Tab | 行首插 / 删缩进 |
| 有选区时按退格 | **只删选区，绝不合并行**（三击一行的锚点在行首，只看锚点会把「选中一行」误判成「光标在行首」） |
| 占位行 | 可写；写下去 = 在**这一侧插入一行** |
| 占位行点击 | 按**对齐索引**定位，不按行号（空行号 `+'' === 0` 会被夹成第 1 行） |
| 视觉 | 占位行编辑态画极淡斜纹 + 行号位 `·`；只读时不画（不该暗示可写） |

#### 跨行选区

Blink 的选区**不许跨出一个 `contenteditable` 宿主**：拖到第二行就停住，`range` 设进去也会
被掐回第一行（实测设 201 行，读回来只剩 17 个字）。所以编辑态的跨行选区由我们自己管：

1. **先摘掉这一侧每行的 `contenteditable`**（`stripSide()`），文本仍可选，但 Blink 不再
   拿某一行当编辑宿主；
2. `Ctrl+A` 全选这一侧，拖选与 Shift+点击也走同一条路；
3. 接管期间渲染**只补行不重建**，否则选中节点会跟着 `innerHTML` 一起被摘掉；
4. 跨行选区上的按键自己落进模型：删除 → 删选区；打字 → 替换选区；粘贴 → 替换选区；
5. 下一次点击、切编辑态或重建 DOM 时惰性恢复可写属性。

重建选区一律用 `setBaseAndExtent(anchor, focus)`，**不要手工 `setStart` / `setEnd`**：后者只
表达正向区间，向上扩的那一次会把锚点悄悄换到点击处，再按 Shift+点击就扩不动了。

**Shift+点击**：从已有锚点直接扩到点击处，等价于「一次到位的拖选」。锚点必须在恢复可写
**之前**读 —— 一恢复可写，Blink 就把跨行选区掐回一行。

#### 粘贴

**不能自己读剪贴板。** `navigator.clipboard.readText()` 在 WebView2 里既不 resolve 也不
reject（1.2 秒后仍在等），用户看到的是「按了没反应」。唯一不依赖权限的读法是 `paste` 事件
里的 `clipboardData`，可没有编辑宿主浏览器根本不派发 `paste`。

所以两步接上：

1. `keydown` 里记下 `pendingPaste` 的区间 → 恢复可写 → 把光标摆到选区起点 →
   **放行这次按键**（拦了就没有 `paste` 事件）；
2. `document` 上的 `paste` 监听 `preventDefault()`，用 `clipboardData.getData('text/plain')`
   落进模型。

剪切同理，只是复制那一步交给 `execCommand('copy')`（选区是真的，不需要编辑宿主）。

### 11.8 复制到另一侧

| 项 | 规则 |
|---|---|
| 单位 | **一处差异**（不是一行，也不是整个文件） |
| 键盘 | `Alt+←/→` 推这一处；`Ctrl+Alt+←/→` 推完并跟到下一处（连续合并） |
| 方向 | 箭头指向哪一侧就推到哪一侧；键盘的方向看**光标所在侧** |
| 按钮 | 长在中间那道 26px 的缝里，跟着当前差异块上下走；只在「编辑态 + 两侧都有内容 + 真有差异」时出现 |
| 箭头跟谁走 | **点哪一处差异行，就挪到哪一处**（行内、行号、行尾空白、行下方空白都算；点在两侧相同的行上取**最近**一块）。之后再滚屏，交回「视口中心落在哪一块」 |
| 目标侧缺行 | 插到该对齐位置（用 `recompute()` 算好的插入点） |

**为什么箭头在缝里**：这是用得最多的动作，放在顶部等于让鼠标从正文跑回顶上再跑回来。
**为什么按钮方向固定、不随光标翻转**：一个按钮说两件事，两边都说不清；键盘的组合键已经
表达了方向。

### 11.9 撤销 / 重做

| 项 | 规则 |
|---|---|
| 粒度 | 打字 700 ms 内合并成一步；换行 / 合并 / 缩进 / 删选区 / 粘贴这些结构性编辑一次一步 |
| 落哪一侧 | 光标所在侧 → 最近一次改动侧（`lastSide`）→ 左边 |
| 同步之后 | 先试光标侧，没历史就落到另一侧（`undoEither`）——否则「刚同步完按 Ctrl+Z 没反应」 |
| 光标 | 先记位置再换内容；实时选区 → `lastCaret` 备份 → 第 1 行 |
| 滚动 | **不主动滚视口**；光标行不在屏幕上时夹到视口中央那一行 |
| 按钮 | 可用性从**真实历史栈**算（两侧 undo/redo 长度 + 排序快照），只读态一律灰 |
| 监听 | 挂在 `document` 上，不挂在画布上 —— 点过工具栏后焦点在按钮上，画布收不到按键 |

`focus()` 本身会把元素滚进视野，必须 `focus({ preventScroll: true })`，否则前面「不滚」白做。

### 11.10 折叠（只看差异）

- 默认开。相同行收起来，每处差异前后各留 3 行；2000 行 20 处改动 → 49 行。
- **进编辑态自动关掉折叠**（要改的地方得看得见）。
- 折叠时两个特例必须保留：**光标所在行**、**当前查找命中行**。把左边改成和右边一样，
  这一行就从「修改」变成「相同」、随即被折掉，光标当场消失，表现为「键盘不管用了」。
- 折叠后「哪一行在哪、有多高」一律走**可见行表**，不许再拿原始行数组的下标当行位。

### 11.11 查找与差异清单

**查找（`Ctrl+F`）**：

- 浮在文件名条那一行，不遮正文；`Enter` 下一个、`Shift+Enter` 上一个、`Esc` 关闭。
- **命中按对齐行去重**：同一条对齐行可能两侧都有，不去重的话「下一个」会在两栏之间原地打转。
- 高亮只做**行级**：差异行的内部已经是 `inlineDiff` 的高亮 HTML，再插 `<mark>` 会互相踩。
- 命中色是蓝、当前命中加左侧竖线，和差异红刻意分开 ——「哪里不一样」和「你找的词在哪」
  是两件事。

**差异清单**：

- 把每个差异块摊成一行：位置 / 类型 / 行数 / 摘要。
- 表头三列都能点，同一列再点切换升降序；第二排序键恒为位置升序（否则「按类型排」时
  同类型内部会反序）。
- 筛选：全部 / 修改 / 仅左 / 仅右。
- 超过 300 条只渲染前 300 条并明说「用 F8 继续浏览」，不假装全列出来。

### 11.12 保存、脏标记、关闭

| 项 | 规则 |
|---|---|
| 保存 | `Ctrl+S` 写回磁盘；没有磁盘目标（纯粘贴）时提示「这份内容还没有路径」，引导另存 |
| 脏标记 | 每侧与**打开时/存盘时的基线**逐行比（`slice()` 让未改的行共享字符串，8 MB 也不多存一份） |
| 撤销回原样 | 「未保存」必须自己消失，`Ctrl+S` 变灰 |
| 关闭守卫 | `onCloseRequested` 里先 flush 再判 `dirtySides()`；三选：保存并关闭 `Y` / 不保存 `N` / 取消 `Esc`，键帽印在按钮上 |
| 无磁盘目标 | **不显示「保存并关闭」** —— 给一个按了也没用的按钮比没有按钮更糟；此时 `Y` 也不生效 |
| 二次拦截 | 确认后置 `forceClosing = true` 再关，否则会被自己拦第二次 |

### 11.13 排序

- 把两侧的行按**字典序**重排，空行沉到末尾，行数不变。
- 比较器 `Intl.Collator('zh-CN', { numeric: true })`：中文按拼音（李 < 王 < 张），`a9` 在
  `a10` 前。码位序下中文既不可读，`a10` 还会跑到 `a9` 前面。
- 排序键跟着「忽略空白 / 忽略大小写」走，否则 diff 说相同的两行会被排到两处。
- 只读态点排序会**先自动进入编辑态**（否则内容变了但保存是灰的）。
- `Ctrl+Z` 一次还原**两侧**（只还原一侧会留下「一边排好一边没排」的中间态）。
- 排序后打字再撤销，不能跳回排序前把字一起抹掉 —— 任何写入模型的路径都要先清掉排序快照。

### 11.14 工具栏

`统计 · 当前序号 · 忽略空白 · 忽略大小写 · 只看差异 · 自动换行 · 上一处 · 下一处 ·
差异清单 · 查找 · 排序 · 撤销 · 重做 · 编辑 · 保存 · 导出报告`

- 单行 flex，**按真实溢出量降级**：先去掉两级文字（`.tight` 按钮只留图标，`.tighter`
  勾选项也收成方框），每次量 `scrollWidth > clientWidth`。
- **不按窗口宽度猜阈值**：九种语言宽度差 100px 以上，按像素猜的阈值必然在某种语言下把
  最右边的按钮静默裁掉（760px 窗口下「导出报告」曾经就这么消失过）。
- 调用时机：`resize`、`document.fonts.ready`（字体没就绪时量出来偏窄）、`updateMeta()`
  （统计文字长度会变）。
- 统计与当前序号允许收缩 + 省略号：**信息和动作抢地方时，动作优先**。

### 11.16 行显示模式

对比窗口和主窗口共用 `settings.wrap`。它原来是**固定行高虚拟滚动**（满篇「下标 × 行高」），
换行后行高不等，于是全部改成前缀和几何：

- `S.y`（每行顶边，长度 = 行数 + 1）、`S.hh`（每行高）、`rowAtY()`（在 `S.y` 上二分）、
  `rowTop()` / `rowH()` / `totalHeight()`；全站收口到这几个函数。
- **折几行靠算不靠量**：等宽字体 + `word-break: break-all` + `overflow-wrap: anywhere`，
  一行能放几个字只取决于宽度；一次算好每行的半角单元数（全角算 2），「可用宽 ÷ 字符宽」
  向上取整就是折行数。
- 不许逐行 `getBoundingClientRect()`：滚动路径每帧都要行位，5 万行量一次就是几千次强制重排，
  而且虚拟滚动只摆一屏、屏幕外的行根本没有元素可量。
- 切换换行、改字号、改栏宽、切折叠 —— **凡是改变行高的动作都不能沿用像素偏移**，
  先记视口顶部那一行，重排后滚回它。

#### 行模型与对齐

**一句话**：两边的差异行对齐成一张「左格 + 右格」的表，缺的那一侧是**占位行**。

```
S.rows[i] = { l: {no, text} | null, r: {no, text} | null, kind: 'same'|'chg'|'add'|'del' }
S.view    = 屏幕上真正摆出来的行（值是 S.rows 的下标）—— 折叠后与 S.rows 不同长
```

| 概念 | 说明 |
|---|---|
| `kind = chg` | 两侧都有行，但内容不同（`l` 与 `r` 都在） |
| `kind = add` | 只有右侧有（左侧是占位行 `l === null`） |
| `kind = del` | 只有左侧有 |
| `kind = same` | 两侧一样 |
| 占位行 | `l` 或 `r` 为 `null`。**必须可写**：写下去 = 在该侧插一行 |
| 行位 | 一律用 `vposOf(模型下标)` 换算成 `S.view` 的下标，**不要**拿 `S.rows` 下标当行位 |

⚠️ 折叠打开时，`S.rows` 的下标和屏幕上的第几行**不是一回事**。渲染、滚动、`focusAt`、
覆盖层、预览条比例、`gotoBlock`、点击兜底——所有地方都必须走 `S.view` + `vposOf()`。
漏一处的表现是「行号跳了但位置没跳」。

#### 四类行的视觉（⛔ 差异只标红字）

| 类 | 样式 | 说明 |
|---|---|---|
| `k-add` / `k-del` | 整行 `.cmp-tx` 字色 `--cmp-red` | 增删行整行都是差异 |
| `chg` | 只把**差异片段**包进 `<mark>`，`mark` 无底色、字色 `--cmp-red` | 改行只红变了的那几个字 |
| `.diff`（有差异的行） | 行号列字色 `--cmp-red` | 让人一眼看到行号 |
| `same` | 正常 `--fg` | |

**底层色、边框、删除线一律没有**。理由写在 `compare.css` 的注释里：一屏几十处差异时
铺底色会让整页发红，反而看不出是哪几个字变了——而这正是对比窗口唯一要说的事。
删除线看似能区分「删掉的」和「补上的」，但它让这一行读起来像已经被删了。

```css
.cmp-tx mark { background: none; color: var(--cmp-red); padding: 0; }
```

**其它装饰**：

| 元素 | 值 | 用途 |
|---|---|---|
| 占位行斜纹（仅编辑态） | `repeating-linear-gradient(-45deg, var(--cmp-void-band) 0 1px, transparent 1px 10px)` | 「位置在这里，内容不在这里」 |
| 占位行行号 | 行号列 `::after { content: '·' }` | 提示可以点 |
| 折叠缝 `.gap::before` | 顶部 1px **虚线**：`repeating-linear-gradient(90deg, var(--line-strong) 0 4px, transparent 4px 8px)` | 行号在这里跳了一段 |
| 折叠缝 `⋮` | 行号列左上 `left: 5; top: -3`，字号 10 | 「上面被折掉了一段，不是行号算错」 |
| 查找命中 `.hit` | 整行底 `--cmp-hit` = `rgba(51,102,240,.14)` | |
| 当前命中 `.hit-cur` | 底 `rgba(51,102,240,.24)` + `inset 2px 0 0 var(--accent)` | |

⚠️ **红与蓝的分工**：红 = 这一行有差异；蓝 = 你找的那个词在这里。同一行可以既是差异
又是命中，两种颜色叠在一起仍然分得清，因为红在字上、蓝在底上。

#### 预览条（最容易被做坏的地方）

**一句话**：右边缘一条 34px 的竖槽，把全文的差异密度画成一条条 1px 红线，
再用一个灰框标出「你现在看的是哪一段」。

**取值表**（`--cmp-ruler-w` 与 `drawRuler()`）：

| 项 | 值 | 为什么是这个数 |
|---|---|---|
| 栏宽 | **34px** | 16px 时差异段只有 5px 宽；22px 也只到「能看见」，点起来像瞄靶 |
| 轨道宽 | `clamp(w - 12, 10, 22)` = **22px**，居中 | 给三段（差异 / 视口 / 留白）各留位置 |
| 轨道底 | `rgba(127,127,127,.12)`，圆角 **4** | 中性灰，不带任何语义 |
| 差异线宽 | **10px**，**1px** 高，`--cmp-red`，居中画 | 铺满 22px 会让连续几行粘成一根红柱，像滚动条影子 |
| 视口框填充 | `SOFT`（`--fg-soft` = `#8a8a8a`）`alpha .12`，`roundRect(tx-2, y, tw+4, vh, 4)` | |
| 视口框描边 | `SOFT` `alpha .5`，`lineWidth 1` | |
| 视口框上沿 | `SOFT` `alpha .75`，1px 实线，宽 `tw+4` | 滚动时它比半透明框更容易被眼睛抓住 |
| 视口框最小高 | `clamp((viewH/contentH)*h, 14, h)` | 太薄就点不着 |
| 视口框抑制 | `contentH <= viewH * 1.12` 时**不画** | 装得下一屏时整条轨道就是视口，画框只是把轨道染灰 |
| 悬停底色 | `rgba(127,127,127,.07)` | |
| 悬停浮标 | 字号 11.5，底 `--bg-float`，`right: calc(100% + 8px)` | 内容：`12 ⇄ 15 · 修改` |
| 逐行绘制条件 | 每行平均 **≥ 2.5px** 且差异行总数 **≤ 4000** | 否则按段并成一条 |
| 轨道高度 | `min(可视高度, 内容高度)` | 短文档时预览条只有几行高 |
| 起点 | 对齐**滚动区顶部**，不是预览条自身顶部 | 正文区顶部即滚动区顶部（原先中间还隔着 26px 的栏头） |

**⚠️ 只有两种颜色**：红 = 这一行有差异；灰框 = 你正看着的这一屏。**不许**再给「当前
这一处」加第三种颜色——同一个 22px 槽里出现两种蓝，用户第一反应是「蓝色是什么意思」。

**⚠️ 逐行标记画的是「1px」，不是「这一行有多高」**：折行之后一行可能有 80px 高，
按高度画就成了粗柱子，把「这是几行」糊掉了。同理，具体 y 位置一律按 `S.y` 换算，
不能按「平均每行像素」画——折行会让整体错位。

**⚠️ 绘制全部在 canvas 上**，Canvas 颜色必须从 CSS 变量读（`getComputedStyle` 取
`--cmp-red` / `--fg-soft`），否则切主题时预览条不会跟着变。

**交互**：

| 操作 | 行为 |
|---|---|
| 点击轨道 | `rulerRatio()` 得 0..1 → `jumpToRatio()` 把目标行居中 |
| 按住拖动 | `pointerdown` + `setPointerCapture`，`pointermove` 持续跳 |
| 滚轮在预览条上 | 转给正文滚动（不是缩放） |
| 悬停 | 浮标显示「两侧真实行号 + 改动类型」；行号按 `rowAtY()` 反查，**不按格子均分** |
| 指针在轨道外（短文档下半截空白） | `rulerRatio()` 返回 `null`，什么都不做 |

**坑**：
- ⛔ 滚动时几何没变，`rulerGeom()` / `diffMarks()` 必须走缓存（`rulerCache` /
  `markCache`，键含 `S.ver` 与 `LAYOUT_VER`）。每帧重算几万条会让滚动发黏。
- ⛔ 折叠状态变化必须让 `markCache` 失效（`S.ver` 要跟着涨），否则预览条还在画
  被折掉的行。

#### 编辑态

**一句话**：点「编辑」后两栏直接可写，写完 `Ctrl+S` 落盘；打开窗口时两侧就是两个
**空白编辑区**，可以直接粘。

| 决策 | 做法 | 否决了什么 |
|---|---|---|
| 打开即两个空白编辑区 | `startPairText()` / `blankSide()` 预先放一对空段落 | 「选左侧 / 选右侧 / 粘两段文本」三个入口 → 等于逼用户先选模式 |
| 不弹浮层引导 | 工具栏统计位置直接写「把两段文本分别粘到左右两侧」 | 引导层挡住正文，还得点掉 |
| 跨行选区自己管 | 见下 | 依赖浏览器原生拖选 → Blink 不许选区跨出 `contenteditable` 宿主 |

**跨行选区为什么必须自己管**：Blink 不允许选区跨出当前 `contenteditable` 宿主，
所以 `Ctrl+A` 只能拿一屏、拖到第二行就停。做法：

1. `stripSide()` 先摘掉 `contenteditable` 属性；
2. 拖动由 `dragMove()` 重建 range，按键走 `crossSelKey()` → `replaceSpan()` 落模型；
3. 拖动期间 `renderRows()` **只 `growRows()` 补行，绝不重建**（重建会摘掉选区）；
4. 补行判定挂在 `document` 上——指针到边缘时落在滚动条上，画布收不到事件；
5. `dragstart → preventDefault()`，否则 Blink 会起 OS 拖动会话吞掉后续 `mousemove`；
6. Shift+点击走同一条路（`dragBegin(e, anchor)`，锚点必须在 `restoreEditables()` **之前**读）；
7. 重建选区用 `sel.setBaseAndExtent()`。手工 `setStart/setEnd` 会把锚点换到点击处，
   往回扩一次就扩不动了。

**粘贴为什么不能用 `navigator.clipboard.readText()`**：WebView2 里它既不 resolve 也不
reject（1.2s 后仍挂着），表现就是「一边改完另一边全选粘贴没反应」。正解：

```
keydown(Ctrl+V) → 记 pendingPaste + 恢复可写 + 光标移到选区起点
                → ⛔ 不 preventDefault（拦了就没有 paste 事件）
                → document 的 paste 监听读 e.clipboardData → replaceSpan()
```

**替换的边界按字符偏移，不按行号**。`replaceSpan()` 先把两端换成「本侧正文里的字符
偏移」再拼接，占位行取紧邻的行界（尾部占位 = 正文末尾）。这不是实现偏好：一侧粘进来
的行**比对面多**的时候，对面在对齐表尾部会多出一串占位行，全选时选区末端正好落在
占位行上 —— 按行号取就会「两端都必须有本侧行号」而整段放弃，表现正是「先改的一边
成功，另一边全选后粘贴没反应」。占位行的位置已经有现成的 `fL`/`fR`（建模时算好的
「这一行若填上会排第几行」），换算偏移直接用它们即可。

剪切用 `execCommand('copy')` + 删选区（同一条 replaceSpan 路径）。

**其它编辑态细节**：

| 项 | 值 / 行为 |
|---|---|
| `blur` 时 | **只 flush 不重绘**（同步 render 会把正要被点中的行摘掉） |
| `flush()` | 必须 `clearTimeout(onInput.timer)`，否则 300ms 后 applyEdit 把光标拽回旧行 |
| 输入防抖 | 300ms 后 `applyEdit` |
| 占位行可写 | 写下去 = 在该侧插一行；点击按**对齐索引** `focusRowIdx` 聚焦（按行号会因 `+'' === 0` 落到第 1 行） |
| 撤销 | `undoEither()` 先光标侧、再另一侧；每侧各自一个栈 |
| 脏标记 | 顶部槽位的小圆点 `.cmp-dot.on`（5×5，`--cmp-red`） |
| 保存 | `Ctrl+S` 写回各侧自己的路径，编码与 BOM 沿用读入时的 |

#### 中缝箭头

**一句话**：两个箭头常驻在中间那道缝里，纵向位置跟着当前差异块走，点一下把这一处
推到另一侧。

**为什么这样**：这是对比窗口里用得最多的动作。「复制到另一侧」原来在工具栏上，
鼠标得从正文跑回顶上再跑回来——而判断「推到哪边」还要低头看。

| 元素 | 值 |
|---|---|
| 缝宽 | **26**（两侧正文各让 13px——1px 的缝放不下可点的东西） |
| 箭头 | **20×18**，圆角 `--r-1`，底 `--bg-float`，`border: var(--bw) solid var(--line-strong)`（线归线，不再画进 `box-shadow`） |
| 两个箭头间距 | `gap: 2`（中间不留缝） |
| 定位 | `left: 50%` + `translateX(-50%)`，纵向由 `syncGutter()` 跟当前块 |
| 当前块从哪来 | **点击 > 滚屏中心 > 第 1 处**（`pinCurAt()` 在 `mousedown` 里定，`followScroll()` 兜底） |
| 方向语义 | 箭头指向**目标侧**：`Alt+←` 推到左侧、`Alt+→` 推到右侧 |
| 禁用 | 目标侧不存在（比如这一处只在左边）时 `disabled`，`opacity: .45` |

⚠️ 背景必须用 `--bg-float` 而不是透明：中间那道 1px 竖线会从箭头里穿过去，
看着像箭头被切成两半。

⚠️ **「当前这一处」必须在 `mousedown` 里更新，且只有 `S.cur` 一份。** 曾经只有滚屏
会算它（判据是视口中心），于是窗口一打开箭头永远停在正中那块，点别的差异行毫无反应。
三个不许：⛔ 别放在 `click`（晚一步，`focusAt` 可能已经滚过，箭头会先跳别处再跳回来）；
⛔ 别给箭头单独一个 `anchor`（会出现「箭头画在第 5 块、`Alt+→` 推了第 3 块」）；
⛔ 别为了让箭头听话去改 `followScroll` 的中心判据（滚到第 5 处、状态栏就得写第 5 处）。

⚠️ 「同步到另一边」的单位是**一处差异**（`pushBlock`），不是「一行」。方向读**文档
选区**——`lastSide` 在「只放光标不写字」时不更新，不要指望它。

#### 折叠（只看差异）

#### 工具栏与窄窗口降级

工具栏是 `overflow: hidden` 的单行 flex。窗口一窄，最右边的按钮被**静默裁掉**——
用户看到的是「导出报告不见了」，没有任何提示（760px 窗口下实测被裁）。

降级由 `fitTools()` 按**真实溢出量**决定，不按窗口宽度猜阈值：同一份布局在九种语言下
宽度差 100px 以上，猜出来的阈值必然在某种语言下裁掉东西。

| 级 | class | 效果 |
|---|---|---|
| 0 | — | 全部文字可见 |
| 1 | `.cmp-tools.tight` | 按钮文字隐藏（`.cmp-btn > span`），只留图标（图标有 `title` 兜底） |
| 2 | `.cmp-tools.tighter` | 勾选项也收成方框（`.cmp-chk > span` 隐藏，`gap: 0`） |

#### 对比窗口的坑（按代价排序）

1. ⛔ **折叠后拿 `S.rows` 下标当行位**：行号跳了位置不跳，点哪行都不是那行。
2. ⛔ **`blur` 里重绘**：会摘掉正要被点中的行，表现为「点一下没反应，得点两下」。
3. ⛔ **`flush()` 忘 `clearTimeout`**：300ms 后 `applyEdit` 把光标拽回旧行。
4. ⛔ **占位行按行号聚焦**：`+'' === 0` 让所有占位行都落到第 1 行。
5. ⛔ **拖动期间重建行**：`renderRows()` 一重建就摘掉选区，拖到第二行就断。
6. ⛔ **给预览条加第三种颜色**：见 §12.5。
7. ⛔ **按「平均行高」画预览条**：折行后整体错位。
8. ⛔ **把「行底淡红」写进注释**：`compare.js` 开头的注释还留着「行底淡红 / 行内深红 /
   行号栏红竖条」的旧描述，那是**早期设计**，现在只有红字。看注释不看 CSS 会被带偏。

**验收**：`test/probe-compare.mjs` **167** 条（含预览条颜色语义与细线、差异只标红字、
占位行可写、跨行选区、两侧各自全选粘贴、折叠、查找、关窗守卫、窗口落屏）。
改动这一块必须整组跑一遍——单测覆盖不到「点两下才生效」这类手感问题。

## 12. 文件夹对比

### 12.1 为什么是独立窗口

浮层只有一栏「状态 / 路径 / 大小」，看不出左右两侧各自是什么，也点不进两侧目录。
独立窗口里**左右各列自己那一侧的文件**，同一行就是同一对，一行行看过去就是
「谁多了、谁少了、谁改过」。

### 12.2 布局规则

| 决定 | 理由 |
|---|---|
| **一个滚动区里的两列**（`1fr 1fr`），不是两个各自滚动的列表 | 对齐是这扇窗存在的唯一理由；两边各滚一下就全错位了 |
| 中缝用一条渐变画到底 + 每行一条底边 | 只有几行时中缝不会断在半空 |
| 行内只存索引（`data-i`），路径不进 `data-*` | 路径里的 `& < "` 要转义好几层，索引是唯一不会出错的做法 |
| 单侧存在的格子画 -45° 淡斜纹 | 与文本对比窗口「这一侧没有内容」用同一套语言 |
| 差异只红字 | 与文本对比一致 |
| 行数超过 4000 截断并明说 | 2 万行 DOM 会卡住半秒，而「能不能看全」用户得知道 |

### 12.3 「相同」必须读内容

早期判据是「大小 + 修改时间（±1.5 秒）」。把「一」改成「二」字节数一样、时间又挨着，
于是被判成「相同」；而「只看差异」默认勾着，**改动直接从界面上消失**。

现在用 `compare_file_pairs` 整批比对内容（一次 IPC、256 KB 分块、首个不同块就返回），
**修改时间从判据里彻底删掉**。这是那扇窗里最要紧的一条规则。

### 12.4 点一行

| 情况 | 动作 |
|---|---|
| 两边都有 | 开文本对比窗口（复用） |
| 只有一边 | 在主窗口打开这个文件 |
| 目录 | 展开 / 收起？不 —— 不做递归逐层展开，用系统文件管理器 |

这扇窗只回答「差在哪儿」，改内容交给各自该在的地方。

⛔ 刻意不做：批量同步、三栏合并、目录递归逐层展开。做深了，维护成本会和「打开看一眼」
的价值迅速失衡。

### 12.5 落地：文件夹对比的取值

| 元素 | 值 |
|---|---|
| 中缝 | `background-size: 1px 100%`，按可视区高铺，**不跟内容滚** |
| 表头 `.fcmp-head` | `position: sticky; top: 0`，两列 `1fr 1fr`，`padding: 6px 12px`，字号 11.5 |
| 行 `.fcmp-row` | `grid: 1fr 1fr`，下边线 `inset 0 -1px 0 var(--line)` |
| 格子 `.fcmp-c` | `padding: 3px 12px`，字号 12.5 / 行高 1.5，`gap: 8` |
| 文件名 `.fcmp-nm` | 省略号，`--fg`；目录名 `--fg-faint` |
| 大小 `.fcmp-sz` | 字号 11，`tabular-nums`，`--fg-faint` |
| 占位格 `.void` | 与对比窗口同一套 -45° 淡斜纹（`--cmp-void-band`，1px / 10px） |
| 差异 | 只标红字（`--cmp-red`）：文件名 + 那一侧的大小 |
| 行上限 | **4000**（`MAX_ROWS`），超出显示「只显示前 4000 条」 |

**交互**：点一行——两侧都有 → 打开**文本对比窗口**比这一对；只有一侧 → 在主窗口打开
那一个文件。`.` 隐藏行（同样的 `.DS_Store` 之类）不计入统计。

**坑**：
- ⛔ 中缝用背景线按可视区铺，不画在行上。画在行上时，只有几行文件的话左右边框会断在
  半空，两栏看着像「各写各的」。
- ⛔ 只显示前 4000 条时必须**明说**。截断而不提示，用户会以为「文件夹里就这些」。
- ⛔ 占位格斜纹是对比窗口的同一套语言（`.cmp-row.void`），不要另发明一种。

**验收**：`test/probe-fcmp.mjs` 24 条；手测——造两个目录，一个有 4001 个文件看截断提示；
一个「大小相同但内容差一个字」看是否报「已修改」。

## 13. 三向合并

- 输入：基准版本 + A 侧 + B 侧。
- 输出：自动合并结果 + 冲突清单；结果**另存为新文件**，绝不覆盖任何原文件。
- 不做四栏可视化合并器 —— 复杂交互交给已有的两栏对比，这里只解决「先合一遍看看」。
- 三个文件缺一个就不让开始，提示「请先选择基准、A 侧、B 侧三个文件」。
- 合并算法与行级 diff 共用（`merge3`），冲突块按「基准里的位置」排序，便于逐条看。

### 13.1 落地：三向合并的取值

**取值表**：

| 项 | 值 |
|---|---|
| 入口 | 菜单「工具 → 三向合并…」，模态框 |
| 三个选择器 | 基准版本 / A 侧 / B 侧，各「选择文件」+ 文件名 |
| 结果区 | `#mergeResult`，列出合并统计与冲突条数 |
| 输出 | `pickSavePath()` 选的**新路径** |

**算法**（`merge3(base, a, b)`，详见《实现规格》§7.3）：

```
1. base → a 求一次 ops，base → b 求一次 ops
2. 按「区间」把 ops 分组成 hunk（连续改动算一处）
3. 每个 hunk：只有一侧改 → 取那一侧；两侧都改且结果相同 → 取任意一侧；
   两侧都改且结果不同 → 记一处冲突，输出取 A 侧
4. 逐 hunk 拼出结果，末尾清掉多余空行
```

**坑**：
- ⛔ 绝不能输出「两个版本拼在一起」的长文件却不报告冲突条数——用户会拿它当结果直接发出去。
- ⛔ `base` 与 `a`/`b` 的行尾必须统一成 `\n` 再比。CRLF 参与 diff 会让每一行都算改动。
- ⛔ 侧边文件读不出来时要**中止整个合并**，不能当空文件继续——那会把 A 侧整篇当新增。

**验收**：`test/run-units.mjs` 的 merge3 用例（含「两侧改成一样」「两侧改成不同」
「A 删 B 改」三种组合）。

## 14. 快捷键体系

### 14.1 设计原则

1. **不碰系统级热键**。`Ctrl+Shift+F`（繁简切换）、截图、虚拟桌面这些由系统/输入法先截走，
   `preventDefault()` 根本轮不到我们。格式化因此改成 `Ctrl+Alt+L`。
2. **不碰窗口级热键**。`Ctrl+Shift+T/N/W` 在浏览器和很多应用里是标签操作，尽量不用。
3. **跟随编辑器惯例**：`Ctrl+N/O/S/W`、`Ctrl+Z/Y`、`Ctrl+F/H/G`、`Ctrl+1/2/3` 切模式。
4. **匹配用 `mod`**（`Ctrl` 或 `⌘`），展示文案目前写 `Ctrl`（⚠️ 见 §21）。
5. **功能键留给全局**：`F9` 专注、`F11` 全屏、`F3` 查找下一个、`F7/F8` 对比窗口专用。

### 14.4 自定义

- 设置 → 快捷键 → 「改」→ 按新组合。
- 必须带 `Ctrl` / `Alt`，或单用 `F1–F12`；光按字母会误吞输入，直接忽略。
- `Esc` 取消；`Backspace` 清空回默认。
- 自定义优先于默认；冲突时列表标红并提示被谁占用。

### 14.5 落地：菜单与快捷键的取值

|---|---|---|

  里按 `Ctrl+A` 会去全选正文。
- ⛔ 菜单项的快捷键提示文字必须和实际绑定同源（`setKeysList()` 一份数据），
  写死在文案里迟早对不上——对比窗口的「编辑（E）」就是这么留下的债：文案写了 E，
  代码里没有绑定。
- ⛔ 拼音输入法组合期间（`e.isComposing`）不处理任何单键快捷键。

**验收**：`test/run-menu.mjs` 27 条；手测——把九种语言逐个切一遍，看菜单一级项宽度
变化时是否会溢出（一级项不折行、不省略）。

## 15. 多语言与文案

### 15.1 九种语言

简体中文（源）、繁体中文、英、日、韩、法、德、西、葡。默认跟随系统：

- 读 `navigator.languages`，取第一个匹配；
- `zh` 按地区判：`TW` / `HK` / `MO` → 繁体，其余 → 简体；
- 没有匹配 → 英文。

### 15.2 词条结构

| 文件 | 角色 |
|---|---|
| `i18n-dict-src.js` | **唯一手写源**。键 = 简体中文原文，值 7 列（en/ja/ko/fr/de/es/pt） |
| `i18n-dict.js` | 生成物，**不许手改**。繁体列由 `tools/build-i18n-dict.py` 用 OpenCC `s2twp` 生成 |
| `i18n.js` | `tt()` 取词、`applyDom()` 刷静态文案、`detectLang()` |

- 键用中文原文（gettext 思路），代码里 `tt('保存')` 一眼知道上下文。
- 取词函数必须叫 `tt`，不能叫 `t` —— `t` 是「当前标签」，会被局部变量遮住。
- 带 `tt()` 的**顶层常量必须写成函数**（`const menuTree = () => [...]`），否则模块加载那一刻
  就求值了，切语言不生效。
- 新增词条后跑 `node test/run-i18n.mjs`：查覆盖率、列数、占位符、缺键回退。

### 15.3 不能挂 `data-i18n` 的节点

凡是 JS 会赋值 `textContent` 的节点，**绝不能**挂 `data-i18n`，否则切语言那一刻会被刷回
静态词。已知名单：对话框标题、草稿状态、文件树路径、对比窗口的两侧文件名与统计、预览标题。

切换语言的流程是「就地刷新」，不是重建界面：

```
setLang → applyDom → 菜单 update（不是重建，重建会叠 document 监听）
        → 模式标签 / 预览标题 / 大纲 / 状态栏 / 文件树 / 预览重排
```

### 15.4 错误文案

后端只说三样东西：`code`（稳定错误码）、`vars`（模板参数）、`detail`（系统原文）。
前端 `errors.js` 把码映射成一条**完整句子**：

| 规则 | 原因 |
|---|---|
| 整句做成一条词条，**不用「前缀 + 冒号 + 细节」拼** | 中日全角冒号、法语冒号前有空格，拼接每种语言都错 |
| `detail` 原样透传 | 它本来就是 Windows 按自己的语言给的，不归我们翻 |
| 未知码显示 `[io.foo] detail` | 宁可露出来，也不静默吞掉 |
| 翻过的 `Error` 不再翻第二遍 | 判据是「有 message、没有 code」 |

`run-i18n` 做双向对账：`ERR_TEXT` 的每条模板都在词条表里；Rust 里出现的每个错误码前端都有
模板。新增错误码不补文案，测试会红。

### 15.5 语气

- **说清后果，不吓人**：「上次关闭时还有没保存的内容：a.md、b.md。是否全部恢复？」
- **给下一步**：「替换需要编辑模式。这一处匹配跨越了加粗、链接这类格式……切到编辑模式继续？」
- **不甩锅**：不说「非法输入」「操作失败」，说「文件名里不能有 `\`」「文件已被其他程序修改」。
- **不用感叹号**。这个程序不激动。
- 数字与路径用 `<b>` 突出，长列表用「、」连接。

### 15.6 术语表（跨语言必须一致）

| 中文 | 英文 | 说明 |
|---|---|---|
| 速记 | quick note | 固定位置、不用保存的那份 |
| 对比 | compare | 文本对比窗口 |
| 提示块 | callout | `> [!info]` |
| 大纲 | outline | 侧栏结构导航 |
| 正文宽度 | reading width | 设置项，不是「页面宽度」 |
| 行显示模式 | soft wrap / no wrap | 统一用 soft wrap，不用 word wrap |
| 只看差异 | differences only | 折叠开关 |
| 差异清单 | difference list | 不是「变更列表」 |
| 换块类型 | change block type | 不是「转换」 |
| 一键格式化 | format document | — |

### 15.7 落地：语言的取值

| 项 | 说明 |
|---|---|
| 语言 | `zh-CN` `zh-TW` `en` `ja` `ko` `fr` `de` `es` `pt`（`LANGS`） |
| 自动 | `auto` 按系统语言；`zh` 系再按 `TW/HK/MO/Hant` 细分到繁体 |
| 取词 | `tt('中文原文', { 参数 })`，**不叫 `t`**（`t` 到处是 tab 变量） |
| 回退链 | 当前语言 → `zh-CN` → 原文 |
| 字典 | `i18n-dict-src.js`（7 列）→ `python tools/build-i18n-dict.py` → 生成物**不许手改** |
| DOM 翻译 | `applyDom(root)` 处理 `data-i18n` / `data-i18n-title` / `data-i18n-ph` / `data-i18n-aria` |

**坑**：
- ⛔ 带 `tt()` 的顶层常量必须写成函数，否则语言切换后不更新。
- ⛔ 繁体不是简体的字对字替换：`s2twp` 之后要把加粗项换回「繁體中文」这类固定写法。
- ⛔ 新增文案只改生成物不改源，下一次构建就被覆盖。

## 16. 视觉与交互规范

### 16.1 两层底色：纸面与灰面

界面只有**两种底色**，靠明度分区，不靠线条画框：

| 面 | 谁在上面 | 浅色 | 深色 |
|---|---|---|---|
| **纸面** `--bg-panel` | 正文 / 预览 / 编辑区（全窗唯一的「纸」） | slate-1 `#fcfcfd` | slate-2 `#18191b` |
| **灰面** `--bg-side` | 侧栏、标签行、状态栏、工具行 | slate-2 `#f9f9fb` | slate-1 `#111113` |

- ⛔ 正文、代码块、引用块**不许上灰面**：「能写字的地方」= 纸面，这条比「好看」优先。
- ⚠️ **深色下两个面的方向是反的**（Radix 暗色第 1 步最暗）：纸面取第 2 步、灰面取第 1 步，
  才能保住「纸面比侧栏亮」。照抄浅色的步号会让两块糊成一片。
- 区域分界仍然可以有一条 `--line-strong`，但它的职责是「收边」，不是「分区」。

### 16.2 浮层：线归线，影归影

- 浮层 = **0.5px `--line-strong` 边框** + **一层**淡影（`--shadow-float`）。
- ⛔ 不再把边框画进 `box-shadow`（旧写法 `0 0 0 1px` 既是线又是影，改一处另一处跟着歪）。
- 深色下浮层比纸面**亮一档**（第 3 步），否则菜单和正文同色，只能靠阴影硬撑。
- 菜单、下拉、右键、查找条、弹窗、对话框全部用同一套。
- ⛔ 浮层上的控件**不能再取浮层那一步**：深色下它们会整块消失（只剩一圈线）。
  凹进去的输入框走 `--bg-well`，凸起来的按钮走 `--bg-chip`。

### 16.3 圆角：两档 + 同心

只有两个值：`--r-1: 4px`（控件）/ `--r-2: 8px`（浮层、代码块、图片）。圆形只用于圆点。

- **嵌套时内层 = 外层 − 内边距**：菜单 8 − `padding: 4` → 菜单项 4；分段控件外层 8 +
  `padding: 4` → 内层 4。两层弧线要平行，否则一眼看出「里面套了个方框」。
- ⛔ `.tab` 恒为 `0`：标签之间共享竖线，圆角会在接缝处露出缺口。
- ⛔ 引用块、公式块、大纲项、拖放指示线保持 `0`。
- ⛔ 不再出现「左直角右圆角」这类写法。

**目标不是「现代感」，是「硬朗但顺手」**：这个程序每天开几十次，圆角是给手指的，
不是给眼睛的。第四档圆角一旦出现（6 / 10 / 12），说明有人开始凭手感调参数了。

### 16.4 排版

| 项 | 值 |
|---|---|
| 字号阶梯 | h1 1.9em / h2 1.42em / h3 1.16em |
| 段距 | 0.85em（早期 0.32em，段落粘在一起） |
| 标题上边距 | 1.5–1.85em（给足「新一节开始」的呼吸） |
| 中文 `letter-spacing` | **0**（加了就散架；要区分层级用字重与颜色） |
| 界面字号 | 只有三档：12 / 13 / 15，**12 是下限**；编辑器字号是用户设置 |
| 正文行宽 | `--read-measure`，默认 800px，专注模式 ×0.92 |
| 正文左边距 | `max(54px, calc((100% - 宽)/2))`，不包 `max-width` |

h2 不加下划线：中文里那条横线会把标题压成「分节条」，显旧。

### 16.5 颜色语义

色板全部来自 **Radix UI Colors**：中性灰 `slate`，强调色 `tomato`（与图标那支橙红同族）。
组件里只引语义令牌，**不写裸色值**。

| 颜色 | 含义 | 不许用于 |
|---|---|---|
| 橙红（accent） | **当前态**：激活标签、当前章节、焦点、未保存点、主按钮、**选区与选中相同文本** | 悬停底色、装饰、普通链接 |
| 红 | 差异（修改片段、增删行）、危险操作 | 普通强调 |
| 琥珀 | 外部改动提示、警告提示块、查找命中 | 未保存（那是标签上那颗橙点） |
| 绿 | 成功提示块 | 「已保存」（那不需要说） |
| 灰阶 | **其余一切，含所有悬停与当前行这类视图提示** | — |

- ⛔ **强调色只表示状态**。悬停与「光标停在哪」的当前行仍走灰阶 —— 满屏橙条会让
  「哪个是当前」这个信息直接失效。选区是**选中态**，走强调浅底（浅色与大纲选中项同色、
  深色用暗番茄底），⛔ 不许退回系统高亮色。
- 同类颜色不重叠：预览条里红 = 差异、灰框 = 视口，**不给「当前差异」第三种颜色**。
- ⛔ 原生复选框 / 单选框不写 `accent-color` 就会被系统刷成**蓝色**，那是整套界面里
  唯一不来自色板的颜色。

### 16.6 图标

- 全部来自 Lucide（ISC），只 vendor 用到的；`scripts/build-icons.mjs` 编译成内联 sprite。
- 引用 `<svg class="ico"><use href="#i-x"/></svg>`；**绘制属性（fill/stroke/线宽）由 CSS 给**，
  symbol 里只留路径，天然跟随 `currentColor`。
- 图标尺寸 13–16px；**16px 下默认 1.75 的线宽只有 1.17px**，需要更实的图标（抓手、提示块）
  要单独把 `stroke-width` 提到 2–3，否则六个圆点糊成一层灰。
- 新图标下载后要验证内容（`grep` 路径数）；曾经 `curl` 没跟随 302，把「Redirecting…」
  当 svg 编译进 sprite，表现为所有图标隐形。

### 16.7 正文光标

系统 I-beam 只有 1px，且 Chromium 会按背景明暗自动翻色（深底白、浅底黑）——两种配色都细，
浅色底翻白时几乎看不见。

- 自绘 SVG：2px 竖线 + 1px 对比晕，热区必须在竖线正中（`7 12`），否则点击落点偏移。
- 只写在容器上靠继承（`.wysiwyg` / 预览正文 / CodeMirror 内容 / `textarea` / 文本框），
  **不要写 `*`**，否则会盖掉链接、复选框、拖拽把手自己的 cursor。
- `cursor: var(--cur-text), text`：变量里只放 `url(...) 7 12`，`text` 兜底留在规则里，
  图加载失败也不会变箭头。

### 16.8 动效

- **只有「浮层出现」有动画**：`250ms` + `ease-out`（`cubic-bezier(0,0,.2,1)`）。
- 悬停、切换、折叠、换主题一律**瞬变**，没有 `transition`。工具类界面里，延迟反馈
  只会让人觉得卡 —— 鼠标已经到下一个按钮了，上一个还在淡出。
- 滚动、输入、切标签不做过渡：编辑器里任何延迟都会被读成「卡」。

- 圆角两档：`--r-1: 4px` / `--r-2: 8px`，嵌套时内层 = 外层 − 内边距。
- 边框只有 `--bw: 0.5px`；浮层 = 0.5px 边框 + 一层淡影。
- accent 只给「状态」，**悬停与选中一律灰阶**。
- ⛔ 编辑区的四种底不许互相借色：当前行最淡（3% / 5% 中性灰）、选区匹配次之（10% / 14%）、`==文字==` 是黄底、真选区是 `--sel-bg`。越靠「用户刚做的动作」越明显，越靠「常驻提示」越淡；accent 一律不参与。
- ⛔ 强调色与语义色撞车时改语义色，不改强调色：info 跟 accent 走橙红之后，
  `--co-warn` 从橙棕 `#b45309` 挪到暗金 `#96650a`（否则两个橙并排分不出）。

  「找到的」和「不一样的」。
- ⛔ 卡片式识别不再靠「左沿一条 2–3px 彩边」（引用、提示块、JSON 校验条、块公式、
  重复行、大纲当前项都已去掉）；分类改用「底色 + 标题字色」。
- `.ico` 是 sprite `<use>`，`stroke: currentColor`；描边宽度随尺寸调（11px 图标用 2.1，
  16px 用 1.7，21px 的六点抓手用 **3**）。

**坑**：
- ⛔ `--read-measure: var(--rw)` 与专注模式的 `calc(var(--rw) * .92)` 是**两个变量**。
  同一个变量自引用（`--rw: calc(var(--rw) * .92)`）会被浏览器判为无效。
- ⛔ 深色主题要给 `color-scheme: dark`，否则复选框、滚动条是刺眼的白块。
- ⛔ Canvas（预览条）不会自动跟随 CSS 变量，必须显式读一次再重绘。

**验收**：`test/run-i18n.mjs` 45 条；手测——九种语言逐个切一遍看工具栏是否溢出（§12.12
的降级应该自动生效）。

## 17. 数据、隐私与安全

### 17.1 数据落在哪

| 数据 | 位置 | 说明 |
|---|---|---|
| 设置 / 草稿 / 会话 / 最近打开 | `localStorage`（前缀 `snp.`） | 由 WebView 的 profile 目录承载 |
| 历史快照 | `<app_data_dir>/history/<hash>/*.txt` | 一个文件一个目录，目录名是路径哈希；`name.txt` 存原名 |
| 速记 | `<app_data_dir>/quicknote.md` | 固定一份 |
| 粘贴 / 拖入的图片 | `<文档目录>/assets/` | 相对路径引用，换机器不断链 |
| 临时探针数据 | `%TEMP%\eznotepad-probe` | 只在测试时；绝不碰用户真实数据 |

`app_data_dir` 由 Tauri 按平台给出，代码里没有硬编码路径。

### 17.2 不联网

- 没有账号、没有遥测、没有自动更新检查、没有 CDN 依赖（KaTeX、CodeMirror、图标全部
  vendor 进仓库）。
- 打开外链是唯一会发起网络请求的动作，且由用户显式点击（`Ctrl+点击`）。
- 这条不是「暂时没做」，是产品承诺：断网、内网、隔离环境里必须完整可用。

### 17.3 删除

- 文件树删除、清理速记等**一切删除进系统回收站**（Windows `SHFileOperationW` +
  `FOF_ALLOWUNDO`），不是永久删除。
- 目录只删空目录。
- 删除前确认，确认框写清路径与「进回收站」。
- ⚠️ 非 Windows 分支目前是 `fs::remove_file`（永久删除），与产品语义不符（见《实现规格》§10.4 B1）。

### 17.4 数据保护的分层

| 层 | 防什么 |
|---|---|
| 自动保存 + 草稿 | 忘记保存 / 崩溃 |
| 退出三选 | 关窗时丢掉未保存内容 |
| 保存前比 `mtime` | 覆盖别人刚写的内容 |
| 历史快照（60 份 / 20 MB） | 保存错了还能找回上一版 |
| 原子写盘 | 写一半断电留下半个文件 |
| 对比窗口关闭守卫 | 改完直接 Alt+F4 |

**每一层都只解决一种失效**，不能互相替代。加新功能时先问：它会绕过哪一层？

### 17.5 测试与构建不留垃圾

用户对「回收站被构建产物塞满」有明确要求，所以定成硬约定：

- 测试代码里**一行删除都不写**：Chrome profile 按端口固定并复用、夹具覆盖写、不放 `unlink`；
- 探针的 WebView2 数据目录固定在 `%TEMP%`（安全软件不备份 TEMP），绝不写用户真实配置；
- 每次构建后跑 `.workbuddy/tools/purge-build-trash.ps1` 只清本项目 target 下的条目；
- 这条约定写在《构建说明》的「零垃圾约定」，有实测数字。

## 18. 性能预算与降级

### 18.1 指标

| 指标 | 目标 | 现状（Windows） | 怎么测 |
|---|---|---|---|
| 主程序 | 20 MB 以内都算小（原 ≤ 8 MB，见 §1.5） | 7.56 MB（含内嵌的 mermaid 5.12 MB） | 二进制大小 |
| 安装包 | 同上，不做硬卡 | setup.exe 4.58 MB / 便携 zip 5.01 MB | 构建产物 |
| 冷启动 | < 1 s | 约 0.6 s | 人工 / 日志 |
| 单次击键（600 段） | < 12 ms | 9.1 ms | 页面内打点 |
| 常驻内存 | < 250 MB | 约 170 MB | `WorkingSetPrivate`（不是 `PrivateMemorySize64`，后者虚高 60 MB） |
| 大文档 | 10 MB 可编辑 | 10.8 MB / 7.8 万块可用 | 生成夹具 |

### 18.2 输入路径纪律

1. **禁止全量重算**：normalize 只扫光标块 ±1；
2. 大纲 250 ms 防抖 + 结构签名；
3. 标签栏先比签名，没变就返回；
4. 大纲定位用二分；
5. 判「结构变化」只看块类型，不看文本 —— 纯文本编辑不重排块间距；
6. 序列化按块缓存（签名校验），纯打字不 renumber；
7. 字数统计 150 ms 节流、单趟扫描。

这七条是「600 段文档从 18.6 ms/字降到 9.1 ms」留下的，任何一条被「顺手简化」都会退回去。

### 18.3 降级阶梯

| 触发 | 降级 |
|---|---|
| 文档 ≥ 100 万字符 | 视口渲染（records + 窗口 DOM） |
| 代码块 > 4 万字符 | 不上色 |
| 文档 > 5000 块 | 给容器加 `content-visibility: auto` |
| 对比单文件 > 8 MB 或 5 万行 | 拒绝加载，先提示 |
| 对比差异 > 4000 行 | 预览条按段合并 |
| 文件夹对比 > 4000 行 | 截断并明说 |
| 搜索命中 > 200 条 | 截断并明说 |
| 递归列举 > 2 万文件 | 截断 |
| 查找命中 > 5000 处 | 停止继续收集 |
| 大纲 > 数万标题 | 列表窗口化 |
| 预览双栏 + 大文档 | 不降级，⚠️ 已知会卡（12.8 秒） |

**降级的共同要求：用户必须知道。** 截断要说「只显示前 N 条」，拒绝加载要说上限和建议，
不上色不提示（它不影响正确性）但也不能报错。

### 18.4 主动放弃的优化

- **CM6 惰性加载**：省 49 ms，但 `plain` 有 30 处同步调用，异步就绪会让首次读取拿到空内容；
- **后台降频**：Chromium 已经节流，再叠一层会动到草稿保护与文件监听的边界；
- **滚动性能调优**：后台窗口 rAF 被节流，测出来的数不可信，不拿它当依据改 CSS。

### 18.5 资源占用：实测与结论

这一节回答的是「GPU 进程 290MB、一个标签页 100MB，正常吗」。结论先给：
**正常，没有明显浪费**；真正能省的只有一处（隐藏但未销毁的预览 DOM），已经做了。

先看「290MB 从哪来」。WebView2 不是一个进程，任务管理器里那一堆 `msedgewebview2.exe`
各管一摊，报的是**各自私有工作集**。1280×820 窗口实测（同一台机器，同一天）：

| 状态 | GPU 进程 | 页面进程（6 个合计） |
|---|---|---|
| 空文档，只开着界面 | 95 MB | 105 MB |
| 900 行 / 3.9 万字符，滚动中 | 96 MB（峰值 166 MB） | 124 MB |

三点判断依据：

1. **GPU 进程的基线是「窗口面积」而不是「文档大小」**。空文档就已经 95MB —— 那是
   整窗合成、字形图集（font atlas）、光栅缓存的固定成本。换一个更大的窗口，
   这个数会跟着涨；换一个更大的文档，它几乎不动（96MB）。所以 290MB 是**同一个基线上
   的峰值**：滚动、动画、大量文本重绘时，Chromium 会多分配几张中间纹理，
   而且**不主动归还给系统**（留着下次用）。停手一分钟后再看，通常会掉回 100MB 上下。
2. **文档内存的大头在页面进程，且与「块」数量线性相关**。605 行 / 3 万字符约 100MB，
   900 行 / 3.9 万字符约 124MB，增量与行数同阶 —— 每块一个 `.w-block` 元素 +
   一个记录对象 + 一段文本节点。这是「一行一块」这个模型的直接代价，
   换来的是光标、选区、撤销都能逐块定位（见《架构设计》§5.2）。把它降到「整篇一个
   文本节点」就等于换掉整个编辑器，不在优化预算内。
3. **合成层只有 4 层，其中 3 层是整窗尺寸**（1280×820 ≈ 105 万像素，每层 4 字节/像素
   ≈ 4 MB）。层数正常：多一层就多一份显存与一份合成开销，这里没有出现「每个标签页
   一层」或「每个代码块一层」这类失控。

**做过的那一处优化**：所见即所得模式下预览面板是 `display:none`，但节点仍然挂在 DOM 上
—— 900 行文档就是 6000+ 个没人看的节点。现在改成隐藏时清空（`dropPreviewDom()`），
切回来按签名重渲染（预览本来就有签名缓存，所以切回来几乎不耗时）。

**不做的事与理由**：

| 想法 | 为什么不做 |
|---|---|
| 关掉 GPU 合成（`--disable-gpu`） | 实测更糟：文本光栅全落到 CPU，滚动明显掉帧，整窗 100% CPU 尖峰。已固化的 `--disable-gpu-sandbox` 只是修全黑窗口，与性能无关 |
| 大文档改为「整篇一个文本节点」 | 等于换编辑器，且会失去逐块光标/撤销 |
| 主动 `gc()` / 定时清缓存 | 没有稳定收益，反而让「刚滚动过的地方」重新光栅化，表现是「越用越卡」 |
| 限制标签页数量 | 用户开了二十个标签说明他需要二十个，替他关是抢权；内存不够时系统会自己换页 |

⚠️ **量内存的纪律**：只用 `WorkingSetPrivate`，不用 `PrivateMemorySize64`（虚高 60MB）；
必须在「停手一分钟」后读一次稳态、在滚动中读一次峰值，两个数都记下来 ——
只报峰值会得出「必须优化」的错误结论，只报稳态又会漏掉真卡顿。

## 19. 平台差异

当前只正式支持 Windows。平台相关行为集中在四类，逐条后果与改法见《实现规格》§10.4：

| 类别 | Windows 做法 | 移植时要注意 |
|---|---|---|
| 窗口外观 | DWM 圆角（Win11）、无边框 + 自绘标题栏、最大化靠 `SetWindowPos` 铺满工作区 | macOS 用 `titleBarStyle: Overlay`；Linux 用 GTK 最大化 |
| 工作区 | `MonitorFromWindow` + `GetMonitorInfoW().rcWork`，按窗口所在屏算 | 三平台都要问「窗口在哪块屏」 |
| 删除 | 回收站 | 非 Windows 目前是永久删除（债） |
| 浏览器参数 | `additionalBrowserArgs`（`--disable-gpu-sandbox` 修全黑窗口） | wry 只在 Windows 编译该字段，其它平台忽略 |
| 拖放 | 原生通道拿真实路径 | macOS / Linux 需实测 |
| 文件关联 / 单实例 | 安装器注册 + 插件 | macOS 双击走 `RunEvent::Opened`，不是 argv |

**WebView 内核不同，性能数字不能照搬**：这三个平台上必须重测 §18.1，
尤其「10 MB 可编辑」和「GPU 进程内存」。

## 21. 已知设计债（产品视角）

结构与移植层面的清单在《架构设计》§13；这里只列**用户能感觉到**的：

1. **快捷键文案写死 `Ctrl`**（约 130 处）。macOS 上能用（匹配 `⌘`），但显示错。
2. **双栏 + 大文档会卡**：预览侧没有视口化，6.4 MB 文档切布局约 12.8 秒。
3. **视口模式的选区跨不出窗口**：10 MB 文档里拖选只能覆盖当前窗口内的块；
   全选走逻辑全选，但「拖到窗口外」不是。
4. **大文档撤销深度 = 1 步**（8 MB 历史上限，10 MB 文档一份快照就占满）。
5. **非 Windows 删除是永久删除**，与界面文案（进回收站）不符。
6. **打印依赖 `window.open`**，mac/Linux 待实测。
7. **标签的 `readonly` 字段基本没派上用场**：目前只在插入图片时检查，真正只读态在对比窗口。
8. **macOS 菜单会重复**（系统一套 + 自绘一套），移植时必须二选一。
9. **Mermaid / 孤儿图片清理 / 跨文件替换**是明确不做，不是欠账；但用户提起来时需要解释。
10. **对比窗口「编辑」按钮的 `title` 写了按 `E` 切换，代码里没有这个绑定**。要么补键位
    （但 `E` 是普通字母，得先判焦点不在可编辑行，容易误吞输入），要么把 `title` 里的
    「（E）」去掉。现在属于「文案承诺了、行为没做到」，优先改文案。

## 附录 C · 一次交互的完整状态（自查用）

改一个功能时，至少把这五件事过一遍：

1. **入口**：键盘、菜单、右键、按钮 —— 有没有漏一处？
2. **禁用态**：不可用时是变灰、隐藏，还是点了给提示？三种语义不能混。
3. **失败态**：读不到、写不进、格式不支持时，用户看到什么？下一步能做什么？
4. **持久化**：刷新 / 切标签 / 重启之后，这个状态还在吗？该在的要在，不该在的不能粘住。
5. **可撤销**：这一步改内容，`Ctrl+Z` 能回去吗？回去之后光标和视口在哪？
