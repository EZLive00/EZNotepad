# 功能详解

> 逐功能的设计意图与实现取值。**每一条都是「照着做就长这样」的程度**：颜色给到十六进制、
> 尺寸给到像素、阈值给到数字、交互给到分支。
>
> 与另外两份文档的分工：
> - 《功能设计.md》讲**对用户承诺什么**（不承诺什么、为什么不选另一种）；
> - 《实现规格.md》讲**算法怎么写**（解析器、几何、差异引擎的判据与伪代码）；
> - 这一份讲**每个功能由哪些零件拼成、每个零件取什么值**——是前两份之间那张对照表。
>
> 冲突时**以代码为准**，并顺手改掉文档（本轮就是这么发现「工具行是五个控件不是三个」的）。
> 改动之后要同步哪些地方，见 §20 与 `docs/README.md` 的「文档同步矩阵」。

## 0. 阅读方式

每个功能点固定六段，位置固定，方便跳读：

| 段 | 回答什么 | 写不好会怎样 |
|---|---|---|
| **一句话** | 这个功能对用户是什么 | 边界说不清，做出来是另一个功能 |
| **为什么这样** | 当年否决了哪几种做法 | 下一个人「优化」回被否掉的那条 |
| **取值表** | 尺寸 / 颜色 / 阈值 / 文案 | 移植时靠目测，差 2px 就不是同一个软件 |
| **实现** | 文件 · 函数 · 数据结构 | 改一处漏三处 |
| **坑** | ⛔ 已经踩过、不能重踩的 | 同一个 bug 修两遍 |
| **验收** | 怎么确认没坏（探针名 / 手测动作） | 只能靠「看起来对」 |

数值的口径统一：**CSS 像素**，运行在 100% DPI；125%/150% 缩放由 WebView2 自己按
`devicePixelRatio` 放大，不要按物理像素写死。**颜色一律走 CSS 变量**，硬写十六进制只在
CSS 变量表里允许（见 §18.2）。凡本文给出十六进制的，都是那份变量表里的浅色主题值，
深色主题的对应值在 §18.2 的同名行。

## 1. 主窗口骨架

**一句话**：一个无系统边框的窗口，从上到下六层——标题栏、标签行、侧栏＋正文、状态栏。

**为什么这样**：
- **无边框（`decorations: false`）**：Windows 原生标题栏在深色主题下永远是一块白条，
  且高度随系统版本变（40/48px 不等），正文区域会被顶得不稳定。代价是窗口按钮、拖拽区、
  双击最大化全要自己实现——这一条在移植章节里是最大的成本项。
- **同色平面**：标题栏、标签行、侧栏、正文、状态栏全部 `--bg`，区域之间只靠 1px
  `--line-strong` 分界。「分块浅灰底」的做法在这个程序里被否掉了——它让界面看着像
  五个独立面板，而不是一张纸。
- **标签与工具同行**：曾经是「标签栏 + 工具栏」两行，正文上方白占 30px。

**取值表**（`src/styles.css`）：

| 元素 | 高 | 其他 |
|---|---|---|
| `.titlebar` | **34** | `padding-left: 10`，`gap: 3` |
| `.brand-mark` | 22×22 | 底 `--accent`，图标 15×15 |
| `.menubar` 按钮 `.am-btn` | 26 | `padding: 0 9px`，字号 12.5，`gap: 1` |
| `.win-title` | — | 绝对定位居中，`max-width: min(46vw, 520px)`；窗口 < 820px 时隐藏 |
| 窗口按钮 `.wc` | **42×28** | 图标 11×11、`stroke-width: 2.1`；关闭键 hover `#e5484d` |
| `.tabbar` | **33** | 内容 32 + 上边线 1；`padding: 0 6px 0 8px` |
| `.statusbar` | **27** | 字号 11.5，`padding: 0 10px` |

⚠️ `tabbar` 写 33 而不是 32，是因为 12.5px 的字落在 31px 高的盒子里会压在半像素上发虚。
**这种「奇数高度」不是笔误，改之前先看这一行。**

**实现**：`src/index.html` 的固定骨架顺序 →
`.appbar`（`.titlebar` + `.tabbar`）→ `.workspace`（`.outline` + `.splitter` + `.editor-pane`）
→ `.statusbar`。窗口控制走 `getCurrentWindow().minimize()/toggleMaximize()/close()`，
拖拽靠 `data-tauri-drag-region` 属性（**不能**给整块 `.appbar` 加，否则菜单点不动）。

**坑**：
- ⛔ 给容器加 `data-tauri-drag-region` 会连带吃掉子元素上的点击。只能加在「确实是空白」
  的元素上（`.titlebar-fill`、`.brand`、`.win-title`）。
- ⛔ 窗口按钮的 `tabindex="-1"`：键盘用户按 Tab 时会先落到菜单，再落到窗口按钮会
  误关窗口。这是故意的。
- ⛔ 失焦态（`body.win-blur`）必须变淡：无边框窗口失去焦点时，用户没有任何系统提示，
  只能靠标题和按钮变淡来知道「现在打字是打到别的窗口里」。

**验收**：`test/probe-app.mjs` 的窗口尺寸/标题/状态栏断言；手测——拖动标题栏空白处能
移动、双击能最大化、拖菜单文字不会带动窗口。

## 2. 标签条

**一句话**：一排等高的标签，每颗只有左右两道竖线，激活态靠字重和全亮文字区分。

**为什么这样**：
- **上下不封口**：标签自己画四条边就会变成一排独立小方块，看着碎。现在高度靠
  `align-items: stretch` 撑满，上下边界直接借标签栏自己的两条线。
- **激活态不铺底色**：全域同色之后，底色差已经没有对比度可用，改靠 `font-weight: 600`
  + `--fg`。**代价**是加粗会让文字变宽、整排标签左右窜——解法见下面的 `::before` 占位。
- **最大 133px**：原来 200px，开五六个就顶满整行。

**取值表**：

| 元素 | 值 | 说明 |
|---|---|---|
| `.tab` 高 | 32（撑满） | `padding: 0 7px 0 11px`，`gap: 6` |
| `.tab` 最大宽 | **133** | `flex: 0 1 auto` |
| `.tab-name` 最大宽 | **100** | 超出省略号 |
| 相邻标签 | `margin-left: -1px` | 共享一条竖线，不出现双线 |
| 未保存点 `.tab-dot` | **7×7**，`--accent` | 与文件名间距 6 |
| 外部改动点 `.tab.stale` | **5×5**，`--chg-fg`（浅色 `#8a5a00`） | `::after`，`margin-left: 5` |
| 关闭键 `.tab-close` | 18×18，图标 13×13 / `stroke-width: 2.2` | 默认 `opacity: 0`，hover 或激活时 1 |
| 新建键 `.tab-add` | 26×26，图标 15×15 | |
| 拖拽落点 | 2px 竖线，`--accent` | `drop-before` / `drop-after` 各贴一侧 |

**两个点为什么不同色**：「没保存」是**你自己的待办**，「磁盘上被别的程序改了」是
**外部事件**。都画成蓝点的话，用户看到点不知道要不要先保存。

**实现**：
- 渲染 `renderTabs()` 重建整条（标签数量变化时才重建，切激活态只改 class）。
- 溢出检测 `syncTabOverflow()`：`tabs.scrollWidth > tabs.clientWidth` 时显示 `.tab-more`；
  滚轮在标签条上横向滚（`wheel` 里转 `scrollLeft`）。
- 加粗占位：
  ```css
  .tab-name::before { content: attr(data-bold); height: 0; overflow: hidden; font-weight: 600; visibility: hidden; }
  ```
  渲染时必须写 `data-bold="<同名文本>"`，否则占位不起作用、标签会左右跳。

**坑**：
- ⛔ 只改文字不加占位 → 激活切换时整排标签左右窜 1–2px，看着像抖动。
- ⛔ `.tabs` 的 `scrollbar-width: none` + `overflow-x: auto`：隐藏滚动条之后，
  若不给 `.tab-more` 入口，溢出的标签就**彻底不可达**（没有滚轮提示，也没有箭头）。
- ⛔ 首尾两颗不画外侧边线（`first-child` / `last-child` 的 `border-color: transparent`），
  否则标签区两端各多一根孤立的竖线。选择器要带 `.tabs` 前缀才盖得过 `.tab.active`。

**验收**：`test/probe-app.mjs` 标签渲染/切换/关闭；手测——开 8 个标签看是否出现
「全部标签」、拖拽换位时落点线是否贴在被拖标签边上。

## 3. 侧栏（大纲 / 文件两页）

**一句话**：左侧 220px 一栏，顶部两个页签，下面是列表；边界靠一条可拖的分隔线。

**为什么这样**：
- **两页而不是三个面板**：大纲和文件树不会同时看，一上一下摊开只会让两边都变矮。
- **设置入口不在这里**：侧栏页签曾经有第三个「设置」，结果是「设置」被当成第三个面板
  切来切去。现在设置只在顶部菜单（`设置` 一级项，`Ctrl+,`）。
- **宽度可拖**：`--` 固定 220 只是初值，`min 140 / max 420`。超出 420 的侧栏会把正文
  挤到 40 字以下，不值得。

**取值表**：

| 元素 | 值 |
|---|---|
| `.outline` 宽 | 220（min **140** / max **420**） |
| 侧栏头 `.side-head` | 高 **38**，`padding: 0 8px 0 10px` |
| 页签 `.side-tab` | 高 24，字号 11.5，`padding: 0 9px` |
| `.pane-head`（详情页用） | 高 **34**，字号 11 / 600 / `--fg-faint` |
| 分隔线 `.splitter` | 宽 **5**，线画在 `left: 2px`、1px 宽；hover 变 `--accent` 2px |
| 大纲项 | 高 **28**（固定，见下），`padding: 5px 8px` |

**实现**：
- 页签切换只切 `.hidden`，两页的滚动位置各自保留（不要重渲染）。
- 分隔线拖动改 `--` 元素 `style.width`，松手存进设置（`settings.sideWidth`）。
- 大纲列表按**固定行高 28** 窗口化（`app.js` 的 `OUTLINE_ROW`）：只渲染可视区 ± 若干条，
  未渲染部分用上下 padding 顶出来。

**坑**：
- ⛔ 大纲项行高必须与 `OUTLINE_ROW` 常量严格一致。行高不齐时「第几条 × 28」的定位
  会越往下偏越多，出现「点第 30 条跳到第 27 条」。
- ⛔ 侧栏和正文同色，分界只靠 `.splitter::after` 那条 1px 线。**不要**再给
  `.outline` 加 `border-right`，否则 5px 的拖拽区里会同时出现两条线。

**验收**：手测——拖分隔线到 140 / 420 两个极限；大纲 300 条时滚动是否跟手、点击是否落对行。

## 4. 文件树与文件夹内搜索

**一句话**：把打开的文件夹列成树，顶上一条搜索框能搜**内容**（不是搜文件名）。

**为什么这样**：
- **只搜不改**：跨文件替换已经整体删掉了（`replace_in_folder` / `plan_replace` 不复存在）。
  理由是「看不见全部命中的替换」风险太高——用户看不到的文件被改掉了，没有后悔的可能。
  替换只存在于**单个文件的编辑区**里。
- **搜索框里放 `Aa` / `.*` 两个小方格**：它们改的是「这一次搜索」的语义，不是全局设置，
  所以不该进菜单。
- **结果列表分「文件 → 命中行」两级**：只给一堆行，用户不知道自己在哪个文件里。

**取值表**：

| 元素 | 值 |
|---|---|
| 搜索框 `.ft-search` | 高 **27**，`margin: 0 8px 6px`，`inset 0 0 0 1px var(--line)` |
| 开关 `.ft-tog` | 高 19，字号 10.5，等宽字体；开着时 `--accent` 边框 |
| 路径行 `.ft-path` | 字号 11.5；「选择…」按钮高 21 |
| 树行 `.ft-row` | 高 **24**，字号 12.5，`padding-right: 6` |
| 折叠箭头 `.ft-caret` | 12×12 固定槽位，`open` 时 `rotate(90deg)` |
| 图标 `.ft-ico` | 14×14 |
| 命中行 `.ft-hit` | `padding: 3px 6px 3px 21px`（让开文件名那级的缩进） |
| 文件名行 `.ft-hit-file` | 字号 12 / 600，`margin-top: 4` |
| 空态 `.ft-empty` | `padding: 18px 14px`，行高 1.7 |

**两种选中态并存**（这是这里最容易做错的地方）：

| 状态 | 样式 | 含义 |
|---|---|---|
| `.ft-row.active` | `--accent-soft` 底 + `--accent` 字 + 600 | **编辑区里打开的就是它** |
| `.ft-row.sel` | `--bg-hover` 底 + `inset 0 0 0 1px var(--accent)` | 多选（挑两个文件做对比） |
| 两者同时 | `--accent-soft` 底 + 描边 | 既打开又被选 |

实底强调只能有一个，所以「多选」只加一圈描边——否则同时选中三个文件时，看不出来
哪个在编辑区里。

**实现**：
- 后端：`list_dir_recursive`（上限 **20000** 项、深度 **24**）、`search_in_folder`
  （最多 **300** 条命中）、`watch_files`（**只监听一层目录**，不递归）。
- 前端：`renderFileTree()` 只展开已展开的目录（懒加载），`renderSearchResults()` 按
  `file → hits[]` 分组。
- 搜索走 `buildRegex(query, {case, regex})`：`regex` 开着时不当普通字符串处理，
  非法正则要**当场提示且不查**（不是静默返回 0 条）。

**坑**：
- ⛔ 「大小相同 = 文件相同」在文件夹对比里必须读内容（§13）。这里同理：搜索命中数
  不能靠缓存的文件大小判断。
- ⛔ 一层监听意味着：用户在看 `docs/` 时，`docs/sub/` 里新建的文件**不会**触发刷新。
  这是故意的（递归监听百万文件会拖垮进程），但界面上不能假装自己在递归监听。
- ⛔ 树行高度固定 24，文件夹与文件的行首图标必须在同一列对齐（`.ft-caret` 占固定
  12px 槽位就是为了这个）。

**验收**：`test/probe-filetree.mjs` 31 条；手测——搜一个必定 0 命中的词，看是否给出
「没有找到」而不是空白。

## 5. 三种编辑模式

**一句话**：同一个文件可以在「所见即所得 / 原始 Markdown / 只读预览」之间切，切的是
**视图**，不是文件。

**为什么这样**：
- **三模式而不是两栏对照**：双栏（左边源码右边预览）在宽屏上正文只剩一半宽，
  而 90% 的时间只想要其中一种。需要对照时用「视图 → 双栏」临时开。
- **模式是每个标签各自记的**（`tab.mode`），不是全局开关：一个 `.json` 通常想看源码，
  一篇 `.md` 想看渲染结果，全局模式会让每次切换都要重设。
- **切模式不重新读文件**：内存里始终是那份 `content`，三种视图只是同一份数据的
  三种投影。这条保证了「编辑到一半切去看预览」不会丢光标与撤销栈。

**取值表**：

| 模式 | `data-mode` | 承载 | 可编辑 |
|---|---|---|---|
| 所见即所得 | `wysiwyg` | `#wysiwyg`（`contenteditable`），一行一个 `.w-block` | 是 |
| 编辑（源码） | `edit` | `#editor`（CodeMirror 6） | 是 |
| 预览 | `preview` | `.preview-body`（`renderMarkdown` 输出） | 否 |

正文排版（三处共用同一组变量）：

| 项 | 值 |
|---|---|
| 正文宽 | `--rw`，默认 **800px**；专注模式 `calc(var(--rw) * .92)` |
| 两侧最小留白 | `--read-gutter: 54px` |
| 所见即所得字体 | `--font-read` 15px / 行高 **1.75** / `letter-spacing: .008em` |
| 预览行高 | **1.8**（比编辑态略松，因为只读时不追行） |
| 编辑区上内边距 | **32**（`padding-top`） |
| 编辑区下内边距 | **40vh**（让最后一行能滚到屏幕中间，不被底边卡住） |

**实现**：
- `setMode(mode)`：切 `hidden`、恢复各自的滚动位置与光标（`tab.scrollTop` /
  `tab.previewScroll` / `tab.caret`）。
- CodeMirror 的换行开关走 `Compartment` 热替换（`wrapComp`），**绝不重建 EditorState**
  —— 重建会同时丢掉撤销历史与选区。
- 预览区渲染有节流：编辑时不实时重渲染，切到预览才渲染。

**坑**：
- ⛔ 模式切换必须 `flush` 当前编辑态到 `content`（所见即所得块模型 → Markdown），
  否则切过去看到的是上次的文本。反向也一样。
- ⛔ `lastMode` 要在**设置**里记一份（下次新建标签用它），但它与 `tab.mode` 是两件事：
  后台标签的 `isDirty` 判断只看 `content` 与 `savedContent`。
- ⛔ 预览模式下块手柄必须隐藏（`lastMode` 不是 wysiwyg 时手柄不出现），否则会
  在一个只读视图上浮出可点的编辑入口。

**验收**：`test/run-units.mjs` / `run-editor.mjs` 离线用例；手测——打字 → 切预览 →
切回 → 光标还在原处、撤销还能退回三步之前。

## 6. 富文本块编辑（所见即所得）

**一句话**：Markdown 的每个块在编辑区里就是一个可编辑的盒子，左边留白处浮出手柄，
点开是块类型菜单。

**为什么这样**：
- **一行 = 一个块**，不是「一整篇 contenteditable」。整篇可编辑的话，浏览器的
  回车/粘贴/选区行为会把 Markdown 结构啃得七零八落，而且光标一移动就要重排全文。
- **手柄挂在编辑流之外**（`.edit-wrap` 上绝对定位），不是块的子元素。挂在块里会被
  浏览器选中、被退格删到、被「扫游离节点」的逻辑吸进正文——`.w-hash` 踩过这个坑。
- **手柄常驻可见**，不是 hover 才出。它是这个编辑器**唯一的块级入口**，藏起来等于没有。

**取值表**：

| 元素 | 值 | 说明 |
|---|---|---|
| 手柄按钮 `.wh-btn` | **21×22**，图标 16×16 | 颜色 `--fg`（不是 `--fg-soft`，试过，六个点看着像一层灰） |
| 抓手图标线宽 | `stroke-width: 3` | 六段零长度线段靠 `linecap: round` 画点；24→16 缩放后 1.75 只剩 1.17px，糊 |
| 块菜单 `.w-bmenu` | `min-width: 190`，`padding: 6` | `max-height: calc(100vh - 24px)`，「插入」有 **14** 项 |
| 菜单项 `.bm-item` | `padding: 6px 8px`，字号 **13** | `gap: 8`，图标 14×14 |
| 菜单分组头 `.bm-head` | 10.5 / 600 / `letter-spacing: .07em` / 大写 | |
| 菜单快捷键 `.bm-kbd` | 字号 11，`margin-left: auto`，`padding-left: 18` | |
| 拖入提示 `.drop-hint` | `inset: 8`，1px 虚线 `--accent` | 中间浮层 `padding: 12px 20px` |
| 新建文档类型网格 | 2 列，`gap: 6` | 项 `padding: 7px 10px`，`b` 13 / `small` 11 |

标题与段落的排版（`src/styles.css` 末尾）：

| 块 | 字号 | 字重 | 上下外边距 | 行高 | 字距 |
|---|---|---|---|---|---|
| `.w-h[data-type=h1]` | **1.9em** | 680 | `1.5em / .5em` | 1.28 | `-.022em` |
| `h2` | **1.42em** | 660 | `1.85em / .55em` | 1.32 | `-.012em` |
| `h3` | **1.16em** | 650 | `1.55em / .45em` | 1.4 | — |
| `h4`–`h6` | 1.02em | 650 | `1.35em / .35em` | — | — |
| `.w-p` | 15px | — | `.85em 0` | 1.75 | — |

⚠️ `h2` **不画下边框**。中文标题下面那条横线会把它压成「分节条」，显旧；分段靠
「上方 1.85em 的大间距 + 字号差」就够了。
⚠️ 第一个块强制 `margin-top: 0`，否则正文顶部的呼吸感全被标题自带的边距吃掉。

**实现**：
- 解析：`parseMarkdown()` → 块记录数组（字段见《实现规格》§2.3），每块 `md` 存**原文切片**。
- 渲染：`_materialize(rec)` 建一个 `.w-block`；装饰层（`mkCode` 的复制按钮、`mkMath`、
  `mkCell`）**不进 `.w-text`**，否则会被序列化当成内容。
- 转换：`convertBlock(block, type)` 是唯一入口，四个调用点（菜单 / 快捷键 / 输入即转换 /
  粘贴）都走它。
- 序列化：`blocksToMarkdown()` 按块 `sig` 指纹增量缓存，`sig = dataset 关键字段 +
  子节点数 + 行内标签计数 + textContent`。
- 大文档：`> 5000` 块加 `.cv-auto`；`> 1,000,000` 字符走 `_windowAt()` 窗口化，
  上下用 `::before/::after` 的 `--vpad-top/bot` 顶高度（**不是 padding**，见下）。

**坑**：
- ⛔ 占位高度**不能用 padding**：`clientHeight` 含 padding，几百万像素的 padding 会把
  滚动容器自己撑高，滚动条直接失效。伪元素还有个好处——不进 `root.children`，
  块下标、序列化、光标恢复的假定全都不受影响。
- ⛔ 窗口化必须 `overflow-anchor: none`。浏览器自带的滚动锚定会和 `_windowAt()`
  自己补的 delta 叠加，每搬一次窗口 scrollTop 就被顶前一两千像素。
- ⛔ 用 `content-visibility: auto` 时 `contain-intrinsic-size: auto 28px` 要给，否则
  未渲染块高度按 0 算，滚动条会先短后长地跳。
- ⛔ 只在**非窗口化**那一档开 `cv-auto`，且载入期间临时摘掉 `contenteditable`
  ——每次 DOM 变异 Chromium 都要整理一次选区。

**验收**：`test/run.mjs`（headless，5s，改完先跑这个）；真机 `test/probe-app.mjs` 93 条。
手测——粘一篇带表格和代码块的文章，看块手柄是否只浮在当前行、菜单「插入」14 项是否可滚。

## 7. 查找与替换

**一句话**：右上角浮出一条查找框，一个箭头展开成「查找 + 替换」两行；命中用
CSS Custom Highlight API 上色，**不往正文里插 `<mark>`**。

**为什么这样**：
- **浮层而不是占一行**：查找是「临时用一下」，占掉一行会让正文在开合之间跳一下。
  同理，替换行默认折叠，点箭头才展开。
- **不插 `<mark>`**：往 `contenteditable` 里插标记会毁掉行内结构与光标位置，撤销栈也会
  被污染。`::highlight()` 只在渲染层上色，DOM 一个节点都不动。
- **四个模式开关做成小方格**：「区分大小写 / 正则 / 全词 / 选区」各占一格塞在输入框
  右侧。单独占一行的复选框会把整条撑高一个行高，还会折行。

**取值表**：

| 元素 | 值 |
|---|---|
| 查找条 `.findbar` | `top: 8`、`right: 16`，`padding: 6px 8px`，`gap: 5` |
| 输入框 | **168×26**，`padding: 3px 21px 3px 8px`，字号 12.5 / 行高 20 |
| 输入框换行按钮 `.fb-mini` | 18×18，`right: 2` |
| 模式方格 | 高 **26**，`min-width: 26`，字号 11.5；开 `--accent` 边框 + `--accent-soft` 底 |
| 计数 `.find-count` | `min-width: 42`，字号 11.5，格式 `n/m`；空查询显示 `0/0` |
| 按钮 `.fb` | 26×26（纯图标），`padding: 0 7px`（带字） |
| 替换行 `.fb-replace-row` | `padding-left: 30`（让开箭头那一格，与查找框左对齐） |
| 其它命中 | `rgba(255, 196, 0, .28)` |
| 当前命中 | `#ffb020`，字色 `#241a00` |
| 深色：其它 / 当前 | `rgba(255,196,0,.18)` / `#ffc247` + `#1a1300` |

**行为表**：

| 输入 | 动作 |
|---|---|
| `Ctrl+F` | 打开（已开则聚焦并全选输入框） |
| `Ctrl+H` | 打开并展开替换行 |
| `Enter` / `Shift+Enter` | 下一个 / 上一个命中 |
| `Ctrl+Enter` | 在输入框里插入真正的换行（多行查找） |
| `Alt+C` / `Alt+R` / `Alt+W` | 切大小写 / 正则 / 全词 |
| `Alt+A` | 全部替换（**先弹确认**，给出条数） |
| `Esc` | 关闭并清掉高亮 |
| 替换行 `Enter` | 替换当前这一处，并跳到下一处 |

**实现**：
- `buildRegex(q, {case, regex, word})`：`word` 只在**两侧是 ASCII 词字符**时加
  `(?<!\w)` / `(?!\w)`；中文不加——中文没有词边界，加了就永远匹配不上。
- 命中集合一次性算好（当前文档全文），`findNext()` 只移指针。
- 高亮两个名字：`sn-find`（全部）与 `sn-find-cur`（当前），在 `CSS.highlights` 里换。
- 替换在原位做：先定位 range → 再改模型 → 再重渲染，避免「边替换边让命中集失效」。

**坑**：
- ⛔ 「选区」开关在没选中文字时必须 `disabled`（`opacity: .42`），否则用户勾上了
  却什么也搜不到。
- ⛔ 输入框是 `textarea` 而不是 `input`：要多行查找就得让它自己长高，最多 4 行再内部滚。
  用 `input` 的话换行会被吃掉。
- ⛔ 关闭查找要**清高亮**（`CSS.highlights.delete`），否则高亮会留在正文上，
  用户以为那是语法着色。
- ⛔ 全部替换不给确认就是灾难。条数、是否可撤销都要在确认框里说清。

**验收**：`test/run.mjs` 的查找用例 + 真机手工：搜 `\n`（正则）看是否跨行命中；
替换后立刻 `Ctrl+Z` 看是否整批撤回。

## 8. 大纲

**一句话**：侧栏第一页，按文档结构列标题，点一条跳到那一节，读的时候有一个「你在这」的高亮。

**为什么这样**：**只反映结构，不猜**。曾经用「像标题的行」启发式，结果一份带序号的
清单让每行都成了大纲，层级还全被压平。提取规则（Setext / `#` / `【】` / `第X章` /
编号）在《实现规格》§6.5，这里只讲界面。

**取值表**：

| 元素 | 值 |
|---|---|
| 列表容器 | `padding: 0 8px 16px`，`min-height: 0`（**必须有**，见坑） |
| 项高 | **28**（`box-sizing: border-box`，`line-height: 18`） |
| `h1` | 字号 **13** / 600 / `--fg` |
| `h2`–`h6` 缩进 | `padding-left: 18 / 30 / 42 / 54`，字号 12 |
| hover | 底 `--bg-hover`，左沿 2px `--line-strong` |
| 当前节 | 底 `--accent-soft`，字 `--accent`，左沿 2px `--accent`，600 |
| 上限 | **300** 条，文本截 **80** 字 |
| 空态 | `padding: 16`，字号 12，行高 1.7 |

**实现**：`extractOutline(kind, text)` 按类型分四路（Markdown / JSON / 代码 / 纯文本）；
渲染走固定行高窗口化，`OUTLINE_ROW = 28` 与 CSS 严格一致；滚动时用「离滚动位置最近的
标题」点亮 `.active`。

**坑**：
- ⛔ 列表容器缺 `min-height: 0` 时，几万条大纲的上下 padding 会把 flex 盒子自己撑到
  几十万像素高——窗口化等于没做。这是 flex 项 `min-height: auto` 的老陷阱。
- ⛔ hover 的左沿是**变色不加位移**。加位移（比如 `padding-left + 2px`）会让指针扫过时
  整行文字左右抖。
- ⛔ 当前节的判断不能「谁的标题在视口顶部谁亮」，那样两节之间会闪；用「最后一个
  顶部不超过视口 1/3 的标题」。

**验收**：手测——打开一份 300 条大纲的文档，滚动时高亮是否连续、跳转是否准到节。

## 9. 状态栏

**一句话**：底部 27px 一行，左边是你现在在哪、文档多大，右边是文件怎么存、草稿存没存。

**为什么这样**：**常看的在左，偶发的在右**。行列位置、行数、字数每秒都在变；编码和
换行符一天改一次。中间用 `flex: 1` 的空白隔开，右侧三项靠右贴边。

**取值表**（顺序＝DOM 顺序，从左到右）：

| # | 元素 | 内容 | 样式 |
|---|---|---|---|
| 1 | `#stPos` | `行 12，列 5`；没有光标时 `—` | 11.5，`tabular-nums` |
| 2 | `#stLines` | `320 行`；渐进载入时 `载入中…` / `载入中 42%` | 同上 |
| 3 | `#stWords` | `6213 字 · 7420 字符` | 同上 |
| 4 | `#fmtBadge` | `Markdown` | 10.5 / `letter-spacing: .04em` / 底 `--bg-active` / `1.5px 8px` |
| 5 | 空白 | — | `flex: 1` |
| 6 | `#stEOL` | `LF` / `CRLF` | 按钮，`padding: 2px 7px`，可点（切换行符） |
| 7 | `#stEncoding` | `UTF-8` / `UTF-8 BOM` / `GB18030` | 按钮，可点（改编码重存） |
| 8 | `#stDraft` | `已保存` / `未保存` | `--fg-faint`；未保存时 `--chg-fg`，`transition: color .3s` |

⚠️ 第 1 项用的是**全角逗号**「，」，与后面的「字 · 字符」共享同一套中文标点约定。
英文语境下由 `tt()` 换成 `Line 12, Col 5`——不要在 JS 里拼标点。

**统计口径**（`countStats`，一次线性扫描，不建中间数组）：

| 类 | 规则 |
|---|---|
| 词 | 中日韩统一表意文字（`0x4E00`–`0x9FA5`）**一字一词**；ASCII 连续 `0-9 A-Z a-z _ - '` 算一词；其它字符只做分隔 |
| 字符 | `text.length`——**含空格、含换行**（不做任何过滤） |
| 行 | 每个 `\n` 计一次 + 1，所以末尾有换行的文件会多出一行空行 |
| 显示 | 原样数字，**不做「万」缩写**；格式 `{词} 字 · {字符} 字符` |

⚠️ 统计的是**内存里的 `\n` 文本**，不是屏幕上折行后的行数，也不是 CRLF 的字节数。

**坑**：
- ⛔ 字数在**输入路径上**不能算全篇。打字时只更新 `#stPos`；`#stLines`/`#stWords`
  走 `refreshStats()`，由防抖（约 250ms）触发。
- ⛔ 草稿状态只有**两态**（`已保存` / `未保存`）。**保存失败不进状态栏**——那要走对话框
  说清原因（磁盘满、文件被占用），状态栏塞不下原因，只会变成一句没人看得懂的红字。
- ⛔ `#stDraft` 是**噪音级**信息（`--fg-faint`），别用 accent。它平时不该抢注意力；
  只有确实有未保存内容时才升到 `--chg-fg`。

**验收**：手测——打开 10MB 文件看数字是否在 1s 内出现；改一个字看是否变「未同步」。

## 10. 设置

**一句话**：一个 760px 宽的模态框，左侧四个分类，改任何一项**立即生效**，没有「确定」。

**为什么这样**：
- **没有确定/取消**：设置项都是可逆的（再改回去就行），加个确定按钮只会让用户点
  「取消」之后发现尺寸已经不听话地变回去了。即时生效 + 「恢复默认设置」是更诚实的模型。
- **左分类右内容**：原来八组竖着排，面板比一屏还长，「快捷键」要滚三屏才看得见。
  分类之后每页三组以内，面板高度稳定，切换不跳。
- **四个分类**：外观（主题/字号/正文宽）、界面（语言/布局）、文件（写入/工作文件夹）、
  快捷键。

**取值表**：

| 元素 | 值 |
|---|---|
| 模态框 | 宽 **760**（`.modal.wide`），`max-height: calc(100vh - 80px)` |
| 网格 `.set-panel` | `grid-template-columns: 156px 1fr`，`min-height: 320` |
| 分类按钮 `.set-tab` | 高 **30**，字号 12.5；`.on` 底 `--bg-soft` + 600 |
| 内容区 `.set-body` | `gap: 18`、`padding-left: 20`、`max-height: 58vh` |
| 组内 `gap` | 8；组标签 11 / 600 / `letter-spacing: .04em` |
| 分段按钮 `.set-seg` | 外框 `padding: 3`、`gap: 4`；按钮高 **26** |
| 步进按钮 `.set-step` | **28×26**，字号 15 |
| 数值 `.set-value` | `min-width: 62`，居中，`tabular-nums` |
| 下拉 `.set-select` | 高 **28**，`1px --line-strong` 边，底 `--bg-soft` |
| 提示文字 `.set-hint` | 字号 11，`--fg-faint`，行高 1.6 |

**取值范围**：

| 项 | 范围 | 步长 | 默认 |
|---|---|---|---|
| 字号 `fontSize` | **11 – 24** | **0.5** | 13.5 |
| 正文宽 `readWidth` | **560 – 1600** | **40** | 800 |
| 主题 `theme` | `auto` / `light` / `dark` | — | `auto` |
| 语言 `lang` | `auto` + 9 种 | — | `auto` |
| 布局 `layout` | `single` / `split` | — | `single` |

**实现**：
- schema 与迁移在 `src/js/state.js`：`settings.__v` 当前 **4**。
- 「恢复默认设置」要清空 `keymap` 与 `lastMode`——只重置颜色和字号是半成品：
  用户点「恢复默认」时想的是「把我改过的东西都还回去」。
- 快捷键页由 `setKeysList()` 渲染，点「改」后直接按新组合键；自定义键位优先于默认键位。

**坑**：
- ⛔ 迁移判据用 `!==` 而不是 `<`：用户可能装了更新版又退回旧版，`<` 会漏掉。
- ⛔ **新增键不要 bump `__v`**；**改默认值必须 bump**（否则老用户的旧默认值永远不更新）。
- ⛔ 面板里的文案一律 `data-i18n` + 中文兜底，末尾 `applyDom(box)` 统一翻。这样
  换语言时开着的面板能就地刷掉，不用关掉重开。
- ⛔ 切分类只是 `hidden` 切换，**不要重建 DOM**：重建会让用户刚改的控件回到上次渲染值。

**验收**：`test/probe-app.mjs` 的设置相关断言；手测——字号调到 24 再恢复默认，
看重启后是否真的回到 13.5。

## 11. 速记

**一句话**：一个固定路径的临时记录本，一个标签，写完自动落盘，关掉程序也还在。

**为什么这样**：临时记东西时，「新建文件 → 起名 → 选目录 → 保存」四步就把念头丢了。
速记把这些全省掉：路径固定、不进会话恢复、**永远算干净**（标签上没有未保存点）。

**取值表**：

| 项 | 值 | 说明 |
|---|---|---|
| 文件路径 | 应用数据目录 / `quicknote.md` | `quickNotePath()`；探针用 `EZNOTEPAD_QUICKNOTE` 指到 `%TEMP%` |
| 自动落盘 | 停手 **350ms** | `scheduleQuickSave` |
| 标签名 | 「速记」 | `tabLabel()` 固定 |
| 未保存点 | **不显示** | `isDirty` 对 `quickNote` 放行 |
| 时间戳格式 | `YYYY-MM-DD HH:MM` | `insertStamp()` |

**八条规则**：
1. **只允许一份**。已开着就切过去（`openQuickNote` 先 `tabs.find(t => t.quickNote)`），
   否则两个编辑器会互相覆盖同一个文件。
2. **不进会话恢复**。`restoreSession` 过滤掉 `quickNote`；它靠磁盘文件自己回来。
3. **关标签 / 退出前必须 `flushQuickNote()`**，返回值 `false` 时要拦住关闭。
4. **贴盘失败只说一次**（`quickWarned`），磁盘满/被占用时沉默才是真的伤人。
5. **另存为只导出副本，不动 `t.path`**。改了路径，之后的自动保存会写到副本上，
   速记本身从此不再更新。
6. **清空之前先存快照**（`clearQuickNote` 先 `write_history_snapshot`），这是唯一能反悔的地方。
7. **打开时如果文件在但读不出来**（二进制/无权限），要明说并**放弃打开**：继续写下去
   等于把用户原来的笔记盖掉。文件不存在则不是错误——空着开。
8. **一级菜单「速记」是动作**（`action`），点一次直接开，不再套一层「打开速记」。

**坑**：
- ⛔ 编辑器的 `flush` 是防抖的：`flushQuickNote` 里必须先 `t.content = readEditor(t)`，
  否则「打完最后一个字就关窗」会丢掉最后几个字。
- ⛔ 速记标签的内容永远算干净，所以**它不会出现在草稿里**——这是设计，不是漏洞。
  反过来说，任何「凭脏标记决定要不要落盘」的逻辑都不能用在它身上。

**验收**：`test/probe-quicknote.mjs` 25 条；手测——打 20 个字，0.5s 后 `taskkill`，
重开看最后几个字在不在。

## 12. 对比窗口

这是全程序细节最多的一个窗口：一个像素的偏移、一种颜色的语义，都直接决定「能不能看出
哪几个字变了」。所以这一节按**零件**拆，每个零件给全值。

### 12.1 为什么是独立窗口

| 决策 | 做法 | 否决了什么 |
|---|---|---|
| 独立窗口，不是标签页 | 另一个 `WebviewWindow`（label `compare`） | 塞进主窗口当标签 → 对比要占满屏，和编辑器抢宽；切标签还会丢对比状态 |
| 不共享内存 | 只通过两条通道通信：建窗时的 `CompareRequest` 状态、后续的 `compare:load` 事件 | 想把两边的行模型塞进同一个进程 → 窗口崩溃互相带死 |
| 已开着就复用 | `get_webview_window("compare")` 命中就 `emit("compare:load", ...)` | 再开一个同名窗口 → 两个窗口抢同一个 label，第二个静默失败 |
| 铺满工作区 | `create_tool_window` 按主窗口所在屏的 `rcWork` 建 | `SPI_GETWORKAREA` → 只认主屏，副屏上点「对比」窗口跑到主屏 |

**窗口尺寸**：最小 **760×460**，出生即铺满工作区。无边框，标题栏自绘（`.cmp-top` 34px）。

⚠️ 建窗命令必须是 `async fn`。同步命令里 `get_webview_window` 拿不到刚创建的窗口，
表现为「点了没反应，也不报错」。
⚠️ 新窗口的 label 必须写进 `capabilities/default.json` 的 `windows` 数组。不写的话
页面照常渲染、数据照常出来，但 `plugin:window|close` / `dialog:default` /
`start-dragging` 全部**静默失败**——截图完全看不出来。

### 12.3 行模型与对齐

**一句话**：两边的差异行对齐成一张「左格 + 右格」的表，缺的那一侧是**占位行**。

```
S.rows[i] = { l: {no, text} | null, r: {no, text} | null, kind: 'same'|'chg'|'add'|'del' }
S.view    = 屏幕上真正摆出来的行（值是 S.rows 的下标）—— 折叠后与 S.rows 不同长
```

| 概念 | 说明 |
|---|---|
| `kind = chg` | 两侧都有行，但内容不同（`l` 与 `r` 都在） |
| `kind = add` | 只有右侧有（左侧是占位行 `l === null`） |
| `kind = del` | 只有左侧有 |
| `kind = same` | 两侧一样 |
| 占位行 | `l` 或 `r` 为 `null`。**必须可写**：写下去 = 在该侧插一行 |
| 行位 | 一律用 `vposOf(模型下标)` 换算成 `S.view` 的下标，**不要**拿 `S.rows` 下标当行位 |

⚠️ 折叠打开时，`S.rows` 的下标和屏幕上的第几行**不是一回事**。渲染、滚动、`focusAt`、
覆盖层、预览条比例、`gotoBlock`、点击兜底——所有地方都必须走 `S.view` + `vposOf()`。
漏一处的表现是「行号跳了但位置没跳」。

### 12.4 四类行的视觉（⛔ 差异只标红字）

| 类 | 样式 | 说明 |
|---|---|---|
| `k-add` / `k-del` | 整行 `.cmp-tx` 字色 `--cmp-red` | 增删行整行都是差异 |
| `chg` | 只把**差异片段**包进 `<mark>`，`mark` 无底色、字色 `--cmp-red` | 改行只红变了的那几个字 |
| `.diff`（有差异的行） | 行号列字色 `--cmp-red` | 让人一眼看到行号 |
| `same` | 正常 `--fg` | |

**底层色、边框、删除线一律没有**。理由写在 `compare.css` 的注释里：一屏几十处差异时
铺底色会让整页发红，反而看不出是哪几个字变了——而这正是对比窗口唯一要说的事。
删除线看似能区分「删掉的」和「补上的」，但它让这一行读起来像已经被删了。

```css
.cmp-tx mark { background: none; color: var(--cmp-red); padding: 0; }
```

**其它装饰**：

| 元素 | 值 | 用途 |
|---|---|---|
| 占位行斜纹（仅编辑态） | `repeating-linear-gradient(-45deg, var(--cmp-void-band) 0 1px, transparent 1px 10px)` | 「位置在这里，内容不在这里」 |
| 占位行行号 | 行号列 `::after { content: '·' }` | 提示可以点 |
| 折叠缝 `.gap::before` | 顶部 1px **虚线**：`repeating-linear-gradient(90deg, var(--line-strong) 0 4px, transparent 4px 8px)` | 行号在这里跳了一段 |
| 折叠缝 `⋮` | 行号列左上 `left: 5; top: -3`，字号 10 | 「上面被折掉了一段，不是行号算错」 |
| 查找命中 `.hit` | 整行底 `--cmp-hit` = `rgba(51,102,240,.14)` | |
| 当前命中 `.hit-cur` | 底 `rgba(51,102,240,.24)` + `inset 2px 0 0 var(--accent)` | |

⚠️ **红与蓝的分工**：红 = 这一行有差异；蓝 = 你找的那个词在这里。同一行可以既是差异
又是命中，两种颜色叠在一起仍然分得清，因为红在字上、蓝在底上。

### 12.5 预览条（最容易被做坏的地方）

**一句话**：右边缘一条 34px 的竖槽，把全文的差异密度画成一条条 1px 红线，
再用一个灰框标出「你现在看的是哪一段」。

**取值表**（`--cmp-ruler-w` 与 `drawRuler()`）：

| 项 | 值 | 为什么是这个数 |
|---|---|---|
| 栏宽 | **34px** | 16px 时差异段只有 5px 宽；22px 也只到「能看见」，点起来像瞄靶 |
| 轨道宽 | `clamp(w - 12, 10, 22)` = **22px**，居中 | 给三段（差异 / 视口 / 留白）各留位置 |
| 轨道底 | `rgba(127,127,127,.12)`，圆角 **4** | 中性灰，不带任何语义 |
| 差异线宽 | **10px**，**1px** 高，`--cmp-red`，居中画 | 铺满 22px 会让连续几行粘成一根红柱，像滚动条影子 |
| 视口框填充 | `SOFT`（`--fg-soft` = `#8a8a8a`）`alpha .12`，`roundRect(tx-2, y, tw+4, vh, 4)` | |
| 视口框描边 | `SOFT` `alpha .5`，`lineWidth 1` | |
| 视口框上沿 | `SOFT` `alpha .75`，1px 实线，宽 `tw+4` | 滚动时它比半透明框更容易被眼睛抓住 |
| 视口框最小高 | `clamp((viewH/contentH)*h, 14, h)` | 太薄就点不着 |
| 视口框抑制 | `contentH <= viewH * 1.12` 时**不画** | 装得下一屏时整条轨道就是视口，画框只是把轨道染灰 |
| 悬停底色 | `rgba(127,127,127,.07)` | |
| 悬停浮标 | 字号 11.5，底 `--bg-float`，`right: calc(100% + 8px)` | 内容：`12 ⇄ 15 · 修改` |
| 逐行绘制条件 | 每行平均 **≥ 2.5px** 且差异行总数 **≤ 4000** | 否则按段并成一条 |
| 轨道高度 | `min(可视高度, 内容高度)`，`margin-top: 26` 让开栏头 | 短文档时预览条只有几行高 |
| 起点 | 对齐**滚动区顶部**，不是预览条自身顶部 | 每栏顶上还有 26px 的栏头 |

**⚠️ 只有两种颜色**：红 = 这一行有差异；灰框 = 你正看着的这一屏。**不许**再给「当前
这一处」加第三种颜色——同一个 22px 槽里出现两种蓝，用户第一反应是「蓝色是什么意思」。

**⚠️ 逐行标记画的是「1px」，不是「这一行有多高」**：折行之后一行可能有 80px 高，
按高度画就成了粗柱子，把「这是几行」糊掉了。同理，具体 y 位置一律按 `S.y` 换算，
不能按「平均每行像素」画——折行会让整体错位。

**⚠️ 绘制全部在 canvas 上**，Canvas 颜色必须从 CSS 变量读（`getComputedStyle` 取
`--cmp-red` / `--fg-soft`），否则切主题时预览条不会跟着变。

**交互**：

| 操作 | 行为 |
|---|---|
| 点击轨道 | `rulerRatio()` 得 0..1 → `jumpToRatio()` 把目标行居中 |
| 按住拖动 | `pointerdown` + `setPointerCapture`，`pointermove` 持续跳 |
| 滚轮在预览条上 | 转给正文滚动（不是缩放） |
| 悬停 | 浮标显示「两侧真实行号 + 改动类型」；行号按 `rowAtY()` 反查，**不按格子均分** |
| 指针在轨道外（短文档下半截空白） | `rulerRatio()` 返回 `null`，什么都不做 |

**坑**：
- ⛔ 滚动时几何没变，`rulerGeom()` / `diffMarks()` 必须走缓存（`rulerCache` /
  `markCache`，键含 `S.ver` 与 `LAYOUT_VER`）。每帧重算几万条会让滚动发黏。
- ⛔ 折叠状态变化必须让 `markCache` 失效（`S.ver` 要跟着涨），否则预览条还在画
  被折掉的行。

### 12.6 编辑态

**一句话**：点「编辑」后两栏直接可写，写完 `Ctrl+S` 落盘；打开窗口时两侧就是两个
**空白编辑区**，可以直接粘。

| 决策 | 做法 | 否决了什么 |
|---|---|---|
| 打开即两个空白编辑区 | `startPairText()` / `blankSide()` 预先放一对空段落 | 「选左侧 / 选右侧 / 粘两段文本」三个入口 → 等于逼用户先选模式 |
| 不弹浮层引导 | 工具栏统计位置直接写「把两段文本分别粘到左右两侧」 | 引导层挡住正文，还得点掉 |
| 跨行选区自己管 | 见下 | 依赖浏览器原生拖选 → Blink 不许选区跨出 `contenteditable` 宿主 |

**跨行选区为什么必须自己管**：Blink 不允许选区跨出当前 `contenteditable` 宿主，
所以 `Ctrl+A` 只能拿一屏、拖到第二行就停。做法：

1. `stripSide()` 先摘掉 `contenteditable` 属性；
2. 拖动由 `dragMove()` 重建 range，按键走 `crossSelKey()` → `replaceSpan()` 落模型；
3. 拖动期间 `renderRows()` **只 `growRows()` 补行，绝不重建**（重建会摘掉选区）；
4. 补行判定挂在 `document` 上——指针到边缘时落在滚动条上，画布收不到事件；
5. `dragstart → preventDefault()`，否则 Blink 会起 OS 拖动会话吞掉后续 `mousemove`；
6. Shift+点击走同一条路（`dragBegin(e, anchor)`，锚点必须在 `restoreEditables()` **之前**读）；
7. 重建选区用 `sel.setBaseAndExtent()`。手工 `setStart/setEnd` 会把锚点换到点击处，
   往回扩一次就扩不动了。

**粘贴为什么不能用 `navigator.clipboard.readText()`**：WebView2 里它既不 resolve 也不
reject（1.2s 后仍挂着），表现就是「一边改完另一边全选粘贴没反应」。正解：

```
keydown(Ctrl+V) → 记 pendingPaste + 恢复可写 + 光标移到选区起点
                → ⛔ 不 preventDefault（拦了就没有 paste 事件）
                → document 的 paste 监听读 e.clipboardData → replaceSpan()
```

剪切用 `execCommand('copy')` + 删选区（同一条 replaceSpan 路径）。

**其它编辑态细节**：

| 项 | 值 / 行为 |
|---|---|
| `blur` 时 | **只 flush 不重绘**（同步 render 会把正要被点中的行摘掉） |
| `flush()` | 必须 `clearTimeout(onInput.timer)`，否则 300ms 后 applyEdit 把光标拽回旧行 |
| 输入防抖 | 300ms 后 `applyEdit` |
| 占位行可写 | 写下去 = 在该侧插一行；点击按**对齐索引** `focusRowIdx` 聚焦（按行号会因 `+'' === 0` 落到第 1 行） |
| 撤销 | `undoEither()` 先光标侧、再另一侧；每侧各自一个栈 |
| 脏标记 | 顶部槽位的小圆点 `.cmp-dot.on`（5×5，`--cmp-red`） |
| 保存 | `Ctrl+S` 写回各侧自己的路径，编码与 BOM 沿用读入时的 |

### 12.7 中缝箭头

**一句话**：两个箭头常驻在中间那道缝里，纵向位置跟着当前差异块走，点一下把这一处
推到另一侧。

**为什么这样**：这是对比窗口里用得最多的动作。「复制到另一侧」原来在工具栏上，
鼠标得从正文跑回顶上再跑回来——而判断「推到哪边」还要低头看。

| 元素 | 值 |
|---|---|
| 缝宽 | **26**（两侧正文各让 13px——1px 的缝放不下可点的东西） |
| 箭头 | **20×18**，圆角 `--r-sm`，底 `--bg-float`，`box-shadow: 0 0 0 1px var(--line-strong)` |
| 两个箭头间距 | `gap: 2`（中间不留缝） |
| 定位 | `left: 50%` + `translateX(-50%)`，纵向由 `syncGutter()` 跟当前块 |
| 方向语义 | 箭头指向**目标侧**：`Alt+←` 推到左侧、`Alt+→` 推到右侧 |
| 禁用 | 目标侧不存在（比如这一处只在左边）时 `disabled`，`opacity: .45` |

⚠️ 背景必须用 `--bg-float` 而不是透明：中间那道 1px 竖线会从箭头里穿过去，
看着像箭头被切成两半。

⚠️ 「同步到另一边」的单位是**一处差异**（`pushBlock`），不是「一行」。方向读**文档
选区**——`lastSide` 在「只放光标不写字」时不更新，不要指望它。

### 12.12 工具栏与窄窗口降级

工具栏是 `overflow: hidden` 的单行 flex。窗口一窄，最右边的按钮被**静默裁掉**——
用户看到的是「导出报告不见了」，没有任何提示（760px 窗口下实测被裁）。

降级由 `fitTools()` 按**真实溢出量**决定，不按窗口宽度猜阈值：同一份布局在九种语言下
宽度差 100px 以上，猜出来的阈值必然在某种语言下裁掉东西。

| 级 | class | 效果 |
|---|---|---|
| 0 | — | 全部文字可见 |
| 1 | `.cmp-tools.tight` | 按钮文字隐藏（`.cmp-btn > span`），只留图标（图标有 `title` 兜底） |
| 2 | `.cmp-tools.tighter` | 勾选项也收成方框（`.cmp-chk > span` 隐藏，`gap: 0`） |

### 12.13 对比窗口的坑（按代价排序）

1. ⛔ **折叠后拿 `S.rows` 下标当行位**：行号跳了位置不跳，点哪行都不是那行。
2. ⛔ **`blur` 里重绘**：会摘掉正要被点中的行，表现为「点一下没反应，得点两下」。
3. ⛔ **`flush()` 忘 `clearTimeout`**：300ms 后 `applyEdit` 把光标拽回旧行。
4. ⛔ **占位行按行号聚焦**：`+'' === 0` 让所有占位行都落到第 1 行。
5. ⛔ **拖动期间重建行**：`renderRows()` 一重建就摘掉选区，拖到第二行就断。
6. ⛔ **给预览条加第三种颜色**：见 §12.5。
7. ⛔ **按「平均行高」画预览条**：折行后整体错位。
8. ⛔ **把「行底淡红」写进注释**：`compare.js` 开头的注释还留着「行底淡红 / 行内深红 /
   行号栏红竖条」的旧描述，那是**早期设计**，现在只有红字。看注释不看 CSS 会被带偏。

**验收**：`test/probe-compare.mjs` **164** 条（含预览条颜色语义与细线、差异只标红字、
占位行可写、跨行选区、两侧各自全选粘贴、折叠、查找、关窗守卫、窗口落屏）。
改动这一块必须整组跑一遍——单测覆盖不到「点两下才生效」这类手感问题。

## 13. 文件夹对比

**一句话**：两个目录逐文件对齐，只在一侧存在的格子画斜纹，点一行就能看内容差异。

**为什么这样**：
- **一个滚动区里两列**，不是两个各自滚动的列表。左右对齐是这个窗口存在的唯一理由——
  两边各滚一下就全错位了。
- **「大小相同」必须读内容再判相同**（`compareFilePairs`，整批一次 IPC）。
  只比大小 + 修改时间会把「改了一个字」判成相同，而那是这个功能最容易骗人的地方。
- **读不了就按「已修改」报**，不按「相同」。宁可让用户多点开一次，也不能告诉他
  「这两个文件一样」。

**取值表**（`src/css/foldercmp.css`，外壳复用 `compare.css` 的 `.cmp-*`）：

| 元素 | 值 |
|---|---|
| 中缝 | `background-size: 1px 100%`，按可视区高铺，**不跟内容滚** |
| 表头 `.fcmp-head` | `position: sticky; top: 0`，两列 `1fr 1fr`，`padding: 6px 12px`，字号 11.5 |
| 行 `.fcmp-row` | `grid: 1fr 1fr`，下边线 `inset 0 -1px 0 var(--line)` |
| 格子 `.fcmp-c` | `padding: 3px 12px`，字号 12.5 / 行高 1.5，`gap: 8` |
| 文件名 `.fcmp-nm` | 省略号，`--fg`；目录名 `--fg-faint` |
| 大小 `.fcmp-sz` | 字号 11，`tabular-nums`，`--fg-faint` |
| 占位格 `.void` | 与对比窗口同一套 -45° 淡斜纹（`--cmp-void-band`，1px / 10px） |
| 差异 | 只标红字（`--cmp-red`）：文件名 + 那一侧的大小 |
| 行上限 | **4000**（`MAX_ROWS`），超出显示「只显示前 4000 条」 |

**交互**：点一行——两侧都有 → 打开**文本对比窗口**比这一对；只有一侧 → 在主窗口打开
那一个文件。`.` 隐藏行（同样的 `.DS_Store` 之类）不计入统计。

**坑**：
- ⛔ 中缝用背景线按可视区铺，不画在行上。画在行上时，只有几行文件的话左右边框会断在
  半空，两栏看着像「各写各的」。
- ⛔ 只显示前 4000 条时必须**明说**。截断而不提示，用户会以为「文件夹里就这些」。
- ⛔ 占位格斜纹是对比窗口的同一套语言（`.cmp-row.void`），不要另发明一种。

**验收**：`test/probe-fcmp.mjs` 24 条；手测——造两个目录，一个有 4001 个文件看截断提示；
一个「大小相同但内容差一个字」看是否报「已修改」。

## 14. 三向合并

**一句话**：给「基准版本 + A 侧 + B 侧」三个文件，自动合并成一份**新文件**，原文件一个
都不动。

**为什么这样**：
- **结果另存为新文件**：合并是个容易出错的动作，覆盖任何一侧都等于让用户失去对照。
- **不写冲突标记**（`<<<<<<<` / `=======` / `>>>>>>>`）：大多数人不用 git，看到那堆符号
  只会以为文件坏了。冲突的处置是**保留 A 侧**并在结果里列出「有 N 处冲突，已取 A 侧」。
- **按 hunk 分组而不是逐行**：逐行合并会产生「一半来自 A、一半来自 B」的碎行。

**取值表**：

| 项 | 值 |
|---|---|
| 入口 | 菜单「工具 → 三向合并…」，模态框 |
| 三个选择器 | 基准版本 / A 侧 / B 侧，各「选择文件」+ 文件名 |
| 结果区 | `#mergeResult`，列出合并统计与冲突条数 |
| 输出 | `pickSavePath()` 选的**新路径** |

**算法**（`merge3(base, a, b)`，详见《实现规格》§7.3）：

```
1. base → a 求一次 ops，base → b 求一次 ops
2. 按「区间」把 ops 分组成 hunk（连续改动算一处）
3. 每个 hunk：只有一侧改 → 取那一侧；两侧都改且结果相同 → 取任意一侧；
   两侧都改且结果不同 → 记一处冲突，输出取 A 侧
4. 逐 hunk 拼出结果，末尾清掉多余空行
```

**坑**：
- ⛔ 绝不能输出「两个版本拼在一起」的长文件却不报告冲突条数——用户会拿它当结果直接发出去。
- ⛔ `base` 与 `a`/`b` 的行尾必须统一成 `\n` 再比。CRLF 参与 diff 会让每一行都算改动。
- ⛔ 侧边文件读不出来时要**中止整个合并**，不能当空文件继续——那会把 A 侧整篇当新增。

**验收**：`test/run-units.mjs` 的 merge3 用例（含「两侧改成一样」「两侧改成不同」
「A 删 B 改」三种组合）。

## 15. 导出与打印

**一句话**：三种出口——导出 HTML（独立文件、图片内嵌）、导出 PDF（走系统打印）、
对比窗口导出 HTML 报告。

**为什么这样**：
- **PDF 不打包渲染库**：直接用系统打印引擎（「另存为 PDF」）。省 10MB 以上体积，
  字体也天然跟着系统走。
- **导出的 HTML 强制浅色**：深色主题的页面在别人机器上打开、或者打印出来，是一块黑。
  导出物的读者不是当前用户。
- **图片一律内嵌**（base64）：导出的 HTML 拷到别的机器上，图片不能丢。

**取值表**：

| 项 | 值 |
|---|---|
| 导出 HTML 正文宽 | **46rem**（≈736px，比屏幕上的 `--rw` 窄，因为要打印与阅读） |
| 单张图片上限 | **4MB**（超过不内嵌，保留原路径） |
| MIME 支持 | **9** 种（png/jpg/jpeg/gif/webp/svg/bmp/avif/ico） |
| 打印页面 | A4，上下 **18mm**、左右 **16mm**（`@page`） |
| 打印触发 | `win.onload` → **250ms** 后 `print()`；**800ms** 兜底再调一次 |
| 关闭打印窗口 | `afterprint` 后 **300ms** |
| 分页保护 | `page-break-after: avoid` 给标题、`page-break-inside: avoid` 给表格与代码块 |

**实现**：
- `exporthtml.js`：`collectImages()` 扫全文图片引用 → `buildImageMap()` 读盘转 base64
  （**失败就保留原路径，不要让整篇导出失败**）→ `inlineCss()` 内联样式 → 46rem 包壳。
- `pdf.js`：`buildPrintHtml(tab)` 复用预览渲染器，套一层打印专用 CSS，然后
  `window.open('', '_blank', 'width=900,height=1000')`。
- 对比报告：`saveReport()` 拼一张「左格 / 右格 / 类型」的表，文件名默认 `对比报告.html`。

**坑**：
- ⛔ `window.open` 被拦时**必须给对话框**。静默失败的表现是「点了导出，什么也没发生」。
- ⛔ 两次 `print()` 的兜底要 `try/catch`：用户已经手动点了打印时，第二次调用会抛异常。
- ⛔ 导出前要把编辑态 `flush` 到 `content`，否则导出的是上一次的文本。
- ⛔ 导出 HTML 里的相对图片路径要按**文档所在目录**解析，不是按应用目录。

**验收**：手测——导出一个带 3 张图 + 1 个表格的文档，用浏览器打开看图片在不在、
表格有没有被分页切断；打印预览看页边距。

## 16. 草稿、会话、历史、外部变更

这四个是一组：**都在回答「关掉之后东西还在不在」**，但存的是不同层次的东西。

| 机制 | 存什么 | 存哪 | 何时 | 上限 |
|---|---|---|---|---|
| **会话** | 打开过哪些文件、哪个是当前、每个的滚动位置与模式 | `localStorage` 键 `snp.session` + `snp.sessionActive` | 标签/文件变化时 | 不设 |
| **草稿** | **未保存的正文** | `localStorage` 键 `snp.drafts` | 停手 **1200ms** | **4MB** |
| **历史快照** | 每次保存前的旧内容 | `history/<fnv1a(绝对路径)>/<毫秒戳>.txt` | 保存成功前 | **60 份 / 20MB** |
| **外部变更** | 磁盘上的 mtime 有没有变 | 内存 + 文件监听 | 监听 **300ms** 防抖，前端 **250ms** 防抖 | — |

**草稿预算算法**（`saveDraft`，这是最容易做错的一段）：

```
1. 只收「脏」标签（quickNote 不算脏，永不进草稿）
2. 从最新的往回装，累计 JSON 大小；超过 4MB 就**整份跳过**（⛔ 不截断内容）
3. 一份都没装下 → **删掉这个键**（否则下次启动读到一个空数组，白解析一次）
```

⛔ **不截断**是硬要求：截一半的草稿恢复出来是「半个文件」，比没有更糟——用户会以为
自己的内容丢了，然后又保存了一次。

**恢复六步**（`restoreDrafts`）：

1. 读 `snp.drafts`，坏 JSON 直接丢弃并删键；
2. 逐条与磁盘现状比：文件不在了 → 只留草稿（标记 `external = true`）；
3. 磁盘内容与 `savedContent` 相同 → 不恢复（草稿是多余的）；
4. 磁盘内容不同 → 恢复草稿，并**把 `savedContent` 设为磁盘上的那份**，这样标签显示为脏；
5. 恢复后光标与滚动位置按草稿里的记录摆；
6. 恢复完弹一次「恢复了几份草稿」的提示，**不逐个弹窗**。

⚠️ 第 4 步的 `savedContent` 必须设成**磁盘内容**而不是 `''`。设成 `''` 会让「放弃保存」
变成「清空文件」，用户点一下就把原文件写没了。

**历史快照**（`write_history_snapshot`）：
- 目录名是 `fnv1a(绝对路径)`——路径变（移动/改名）就断成两串历史，这是已知代价。
- 文件名是**毫秒时间戳**，天然按时间排序。
- **空内容不写**、**与上一份相同不写**（去重）。
- 60 份 / 20MB 两个条件**同时生效**，超了从最老的删。

⚠️ 沙箱化的 macOS 移植会在这里翻车：security-scoped bookmark 下同一个文件的路径可能
变成 `/private/var/...` 的另一串，历史会断成两段。见《跨平台移植》§5。

**外部变更**（`checkExternalChange` / `syncWatches`）：
- 监听**一层目录**，前端 300ms 防抖合并事件；
- 变化时只比 `mtime` + `size`，不同才标记 `.tab.stale`（琥珀点 5×5）；
- 用户切到那个标签时才提示「磁盘上的文件已改变，重新载入 / 保留我的」。

**坑**：
- ⛔ `localStorage` 在 WebView2 里**延迟落盘**（实测 6s 后杀进程仍可能丢）。所以
  「启动期行为」不能靠「写入后立刻杀进程再启动」来验，要用 `run-units.mjs` 读源码断下标。
- ⛔ 草稿键用 JSON 整体读写，别改成一条一个键：几十个键的读写会明显拖慢启动。
- ⛔ `quickNote` 永远不进会话、不进草稿。它靠磁盘文件自己回来。

**验收**：`test/probe-app.mjs` 的草稿/会话/外部变更用例；手测——改一个字不保存，
10 秒后 `taskkill`，重开看内容在不在、标签是否显示为脏。

## 17. 文件读写

**一句话**：内存里的正文永远是 UTF-8 语义 + `\n` 行尾；编码与 BOM 只是「读进来怎么解、
写回去怎么存」。

**编码探测五步**（`decode_bytes`）：

| 顺序 | 判据 | 结果 |
|---|---|---|
| 1 | UTF-8 BOM（`EF BB BF`） | UTF-8，`bom = true` |
| 2 | UTF-16LE BOM（`FF FE`） | UTF-16LE |
| 3 | UTF-16BE BOM（`FE FF`） | UTF-16BE |
| 4 | 严格 UTF-8 校验通过 | UTF-8，`bom = false` |
| 5 | 以上都不成立 | **GB18030**（中文环境兜底，比 GBK 宽） |

⚠️ 第 4 步必须**严格**：宽松解码会把 GB18030 的中文解成乱码「锟斤拷」，然后再按
UTF-8 写回去，原文就彻底毁了。
⚠️ 顺序不能换：UTF-16 的文件常常也能「碰巧」通过宽松的 UTF-8 校验。

**写回**（`save_text_file`）：按读入时的 `encoding` + `bom` 原样写；单文件上限 **512MB**。
**换行符**由 `detect_eol` 记下（`\r\n` 占多数就是 CRLF），保存时按它写回；
内存里统一 `\n`。

**二进制判定**：读前 8192 字节，含 `0x00` 就当二进制，**拒绝以文本打开**并说明原因。

**图片**：
- 「插入图片」默认**复制到文档同级的 `assets/`**，名 `stem-1.png`（同名递增，上限 **999**）；
- 保存剪贴板图片用 `img-<时间戳>`，上限 **64MB**，扩展名白名单；
- 引用写成相对路径，导出时转 base64（§15）。

**坑**：
- ⛔ 行尾检测不能只看第一个换行：混合行尾的文件（Git 合并留下的）要按**多数**判。
- ⛔ 文件名校验 `check_simple_name` 拦 **9 个**非法字符（`\ / : * ? " < > |` + 控制字符）。
  写文件前必须过这一关，否则 Windows 上会静默失败。
- ⛔ 「二进制」不按扩展名判，只按内容判。`.md` 里塞了二进制照样要拒。

**验收**：`test/run-units.mjs` 的编码/行尾用例；手测——造一个 GB18030 的 `.txt` 打开
看中文是否正常、保存后 `file` 命令是否仍是 GB18030。

**图形约定**：
- 圆角只有四个值：`--r-sm: 0` / `--r-md: 2px` / `--r-lg: 3px` / `50%`（圆点）。
  `0` 会让描边在斜角处露锯齿，1–3px 是「刻意方正」而不是「渲染坏了」。
- 浮层**不写 border**，一律 `box-shadow: var(--shadow)`（一圈 1px 线）。
- accent 只给「当前态」，不给装饰。
- `.ico` 是 sprite `<use>`，`stroke: currentColor`；描边宽度随尺寸调（11px 图标用 2.1，
  16px 用 1.7，21px 的六点抓手用 **3**）。

**坑**：
- ⛔ `--read-measure: var(--rw)` 与专注模式的 `calc(var(--rw) * .92)` 是**两个变量**。
  同一个变量自引用（`--rw: calc(var(--rw) * .92)`）会被浏览器判为无效。
- ⛔ 深色主题要给 `color-scheme: dark`，否则复选框、滚动条是刺眼的白块。
- ⛔ Canvas（预览条）不会自动跟随 CSS 变量，必须显式读一次再重绘。

**验收**：`test/run-i18n.mjs` 45 条；手测——九种语言逐个切一遍看工具栏是否溢出（§12.12
的降级应该自动生效）。

## 19. 菜单与快捷键

**一句话**：自绘菜单栏，一级十项，每项要么是下拉、要么直接执行。

**一级顺序**（不许调换，位置本身就是记忆）：

```
文件 / 编辑 / 格式 / 插入 / 视图 / 工具 / 设置 / 帮助 / 速记 / 对比
```

- **速记**与**对比**放最右：高频入口，位置固定。
- **速记是动作**（`action`）：点一次直接开窗口，不再套一层「打开速记」。
- **设置也是动作**：直接开设置面板。
- 「工具」里**不再重复列**文本/文件夹/三向合并的入口（它们已经在一级里或各自的窗口里）。

**四种表达手段**（用错就会让人以为功能坏了）：

| 手段 | 用于 | 例子 |
|---|---|---|
| 打勾 `checked` | 可开关的状态 | 显示大纲、自动换行、专注模式 |
| 药丸 `pill` | 互斥的一组里当前那个 | 主题（跟随系统/浅/深）、模式（三选一） |
| 置灰 `disabled` | 现在不可用 | 没得撤销时的「撤销」 |
| 右侧说明文字 | 只读信息 | 最近打开的路径、当前文件夹 |

**关闭时机（五条）**：点菜单项 / 点面板外 / `Esc` / 窗口失焦 / 滚动。
⚠️ 锚在固定控件上的菜单（比如状态栏的编码按钮）必须传 `{stayOnScroll: true}`——
滚动事件是排队派发的，「刚滚过标签条就点按钮」会被迟到的 scroll 收掉菜单。

**快捷键**：

| 键 | 动作 | 备注 |
|---|---|---|
| `Ctrl+N` / `Ctrl+O` / `Ctrl+S` | 新建 / 打开 / 保存 | `Ctrl+Shift+S` 另存为 |
| `Ctrl+W` | 关闭标签 | ⚠️ `Ctrl+T` **没有绑定**（详见下面的债） |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | 下一个 / 上一个标签 | |
| `Ctrl+F` / `Ctrl+H` | 查找 / 替换 | `F3` / `Shift+F3` 下一个 / 上一个 |
| `Alt+A` | 全部替换 | **只在替换行展开时**生效 |
| `Ctrl+Z` / `Ctrl+Y` | 撤销 / 重做 | 对比窗口里 `Ctrl+Shift+Z` **仍是撤销** |
| `Ctrl+Alt+0/1/2/3` | 正文 / 一/二/三级标题 | 块级格式 |
| `Ctrl+Alt+L` | 格式化 | ⛔ 不用 `Ctrl+Shift+F`（撞 Windows 繁简切换，`preventDefault()` 管不着） |
| `Ctrl+Shift+7/8/9` | 有序 / 无序 / 任务列表 | 用 `e.code` 判，不用 `e.key`（Shift 下不同键盘布局的 `key` 不是数字） |
| `Ctrl+K` / `Ctrl+Shift+K` | 链接 / 代码块 | |
| `Ctrl+Shift+Q` / `X` / `T` | 引用 / 删除线 / 表格 | |
| `Ctrl+1` / `2` / `3` | 切三种模式 | |
| `Ctrl+Shift+O` / `L` | 显示大纲 / 双栏 | |
| `Ctrl+G` | 跳到行 | |
| `Ctrl+=` / `-` / `0` | 放大 / 缩小 / 实际大小 | 字号 11–24，步长 0.5 |
| `F9` / `F11` | 专注模式 / 全屏 | 无修饰键 |
| `Ctrl+,` | 设置 | |
| `Ctrl+Shift+M` | 速记 | |
| `Ctrl+D` / `Ctrl+Shift+N` | 文本对比 | 两个入口开同一个窗口 |
| `F8` / `Shift+F7` | 对比窗口：下一处 / 上一处 | 只在对比窗口里 |

**⚠️ 已知的两处「文案承诺了、代码没做到」**（优先级：改文案，不是加绑定）：

| 位置 | 文案 | 实际 |
|---|---|---|
| 主窗口「新建标签」按钮 | `Ctrl+T` | `app.js` 的 keydown 里**没有** `k === 't'` 分支（只有 `Ctrl+Shift+T` = 表格） |
| 对比窗口「编辑」按钮 | `（E）` | 只有点击绑定，没有 E 键 |

这两条属于设计债，不是「忘了写文档」。加新键位前先把它们改掉（改文案更省事），
否则下一次有人照着 `title` 写测试会假红。

**自己加键位的三条禁区**：系统级（繁简/截图/虚拟桌面）、窗口级（`Ctrl+Shift+T/N/W`）、
编辑器惯例（`Ctrl+B/I/U`、`Ctrl+←/→`）。

**坑**：
- ⛔ 快捷键分派要在 `keydown` 的**捕获阶段**判断「焦点是否在输入框里」，否则在查找框
  里按 `Ctrl+A` 会去全选正文。
- ⛔ 菜单项的快捷键提示文字必须和实际绑定同源（`setKeysList()` 一份数据），
  写死在文案里迟早对不上——对比窗口的「编辑（E）」就是这么留下的债：文案写了 E，
  代码里没有绑定。
- ⛔ 拼音输入法组合期间（`e.isComposing`）不处理任何单键快捷键。

**验收**：`test/run-menu.mjs` 27 条；手测——把九种语言逐个切一遍，看菜单一级项宽度
变化时是否会溢出（一级项不折行、不省略）。

## 20. 以后怎么维护这份文档

文档不是写完就完了。**改代码不更新文档，下一次改动就会照着错的文档改**——这一轮
写《实现规格》时抓到的四处错误（两层引用输出、首块缩进归零、斜体符号、工具行控件数）
全都是「代码改了、文档没跟」的后果。

### 20.1 改动类型 → 必须更新哪里

| 你改了什么 | 必须同步 |
|---|---|
| 用户能感知的行为（默认值、交互、文案） | 《功能设计》对应章节 + 本文对应小节 |
| 界面尺寸 / 颜色 / 图标 | 本文取值表 + `docs/实现规格.md` §11 常量表（如涉及阈值） |
| 解析器 / 序列化 / 差异算法 | 《实现规格》§4 / §7 + 附录 A、B 的测试向量（**改前跑一遍，改后再跑**） |
| 新增 IPC 命令 | 《架构设计》命令表 + 《实现规格》§1 原语表（若引入了新的宿主能力） |
| 新增设置项 | 《功能设计》§设置 + 本文 §10 + `state.js` 的 `__v` 判断 |
| 新增窗口 | 《架构设计》窗口表 + `capabilities/default.json` + 本文对应功能节 |
| 修一个「踩过的坑」 | 本文该功能的「坑」段 + `.workbuddy/memory/` 当日日志 |

### 20.2 新增一个功能的五步

1. **先在《功能设计》写「对用户承诺什么、不承诺什么」**——写不出来说明功能还没想清；
2. **在本文加一节**，按固定六段写（一句话 / 为什么这样 / 取值表 / 实现 / 坑 / 验收）；
   取值表里每一行都要能指出「这个数从哪来」；
3. **在《实现规格》补算法**（如果是新的计算逻辑），并把新常量登记进 §11；
4. **加验收**：离线进 `test/run-*.mjs`，真机进 `test/probe-*.mjs`，并在本文「验收」
   段写明探针名与条数；
5. **提交信息写清「为什么」**，一个功能一个提交。

### 20.3 这份文档的「不许」

- ⛔ **不许只写「应该好看一点」**这种无法验收的描述。要么给数，要么别写。
- ⛔ **不许把早期设计留在注释里**（`compare.js` 开头那段「行底淡红 / 行号栏红竖条」
  就是反例）。改设计时，注释和 CSS 一起改。
- ⛔ **不许在文档里写「见源码」了事**。文档的价值就在于不用翻源码。
- ⛔ **不许三份文档各说一套**。冲突时以代码为准，然后**同时**改掉三份。
