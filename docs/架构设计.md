# EZNotepad · 架构与设计

> 读者：接手维护的人、要把项目移植到 macOS / Linux 的人、准备动结构的人。
>
> 三份文档分工——本文讲「为什么这样搭、改动要守住什么」；《跨平台移植.md》讲
> 「换一个操作系统要动哪些地方」；《构建说明.md》讲「怎么装环境、怎么打包」。
> 「踩过的坑与结论」在《开发经验.md》，本文不重复叙事，只写结论性的结构约束。

---

## 0. 一句话概括

一个**单进程、双窗口、无边框、零 UI 框架**的 Tauri 桌面应用：前端是约 1.4 万行
原生 ESM，后端是约 1500 行 Rust，中间只靠 24 条命令说话。能力边界很清楚——

- **前端不知道文件在哪**：所有磁盘操作都过 Rust，前端只拿到字符串路径与内容。
- **后端不知道界面长什么样、说什么语言**：Rust 只回错误**码**，句子由前端拼。

这条边界是后面所有设计的前提。跨平台移植时它也是最大的帮手：**换操作系统主要是在
换「Rust 那 1500 行里的系统调用」和「窗口外壳」，业务逻辑一行不用动**。

## 1. 产品边界

目标用户是自己写 Markdown / 改配置文件 / 比对两段文本的人。产品赌注是
**启动快、体积小、不联网**，而不是功能多。

功能只分三类，新增功能必须先归到某一类：

| 类别 | 内容 | 对应模块 |
|---|---|---|
| **写** | 所见即所得、源码编辑、预览、格式化、查找替换、表格/公式/图片、大纲、多标签 | `wysiwyg.js` `plain-editor.js` `preview.js` `format.js` |
| **看** | 语法高亮、编码与换行识别、字数统计、历史快照、导出（HTML / PDF） | `highlight.js` `history.js` `exporthtml.js` `pdf.js` |
| **比** | 行级 + 字符级 diff、文件夹对比、三方合并、独立对比窗 | `diff.js` `diffpanel.js` `compare.js` `mergewizard.js` |

**明确不做**（不是没来得及，是不打算做）：图床、账号体系、云同步、插件市场、
多窗口拆分编辑、二进制对比。判断一个新需求该不该做，问三句：

1. 这个功能每天都会用到吗？
2. 能不能在不联网、不登录的前提下做完？
3. 它会不会让「打开一个 md」变慢，或让安装包明显变大？

任何一个答案是「否」，就不做。第 3 问是硬约束——体积和启动时间是这款软件的核心
卖点（见 §11）。

## 2. 技术选型

| 决策 | 选择 | 为什么 | 代价 |
|---|---|---|---|
| 运行时外壳 | Tauri 2（系统 WebView） | 不打包 Chromium，主程序 5MB | 三个平台的 WebView 内核不同，行为有差异（见《跨平台移植》） |
| 前端构建 | **无**（裸 ESM） | `frontendDist` 直接指向 `src/`，零构建配置 | 改前端必须 `cargo build`；第三方库要预先打成单文件入库 |
| UI 框架 | **无** | DOM 量可控（视口内 ≤600 块），手写比框架更快更小 | 没有响应式，所有刷新靠手写 `render*()` |
| Markdown 渲染 | 自研（`markdown.js`，469 行） | 只要 GitHub 风味子集；可控转义与图片路径解析 | 新语法要自己写解析分支 |
| 所见即所得 | 自研 contentEditable 块模型 | 没有现成库能同时满足「行=块 + 零延迟 + 大文件」 | 光标、退格、粘贴要自己兜（项目里最复杂的一块） |
| 代码/纯文本编辑 | CodeMirror 6（预打包成 `src/vendor/cm6.js`） | 语法高亮、缩进、撤销开箱可用 | 打包步骤多一步 `pnpm build:cm6` |
| 数学公式 | KaTeX（懒加载） | 只读渲染，不需要编辑期解析 | 首次渲染有 ~200KB 加载 |
| 多语言 | 自研 `tt()` + 生成式词条表 | 键=中文原文，代码里直接看得懂上下文 | 改文案要同步词条表（有测试兜底） |
| 打包 | Tauri bundler | 与 Tauri 一体 | 各平台产物格式不同（nsis / dmg / deb、AppImage） |

**为什么坚持不用打包器**：`src/` 里的每个文件都是运行期直接加载的模块，
`index.html` 里一行 `<script type="module" src="js/app.js">` 就是全部构建配置。
好处是 vendor 里的第三方库（Tauri API、CodeMirror、KaTeX、Lucide 图标）提交进仓库
后**永远可复现**，不怕上游改版或 CDN 挂掉；坏处只有一个：改完前端得重新编译，
因为资源是编译期内嵌进二进制的。

## 3. 运行时结构

### 3.1 进程与窗口

一个进程，最多两个窗口，靠 `tauri-plugin-single-instance` 保证全局只有一个实例
（第二个进程发现已有实例就把命令行里的文件交给它然后自己退出）。

```
进程 EZNotepad（单实例）
├── main 窗口（index.html）                        ← 双击文件 / 命令行参数进入
│   ├── WebView A：全部业务逻辑（29 个 JS 模块，约 1.4 万行）
│   └── Rust：文件 / 目录 / 监听 / 编码 / 窗口系统
└── compare 窗口（compare.html，按需创建）          ← 菜单「比较」/ Ctrl+Shift+N 进入
    └── WebView B：独立 JS 上下文（compare.js）
```

**两个 WebView 是两个互不相干的 JS 世界**：模块、全局变量、localStorage 之外的一切
都不共享。跨窗口只有三条路，项目里三条都用到了（各取所长）：

| 通道 | 用途 | 代码位置 | 注意 |
|---|---|---|---|
| Rust 状态 `Mutex<Option<T>>` + `take_*` 命令 | 打开对比窗时把「左/右文件路径」传过去 | `CompareRequest` / `take_compare_request` | **不要走 URL query**：中文路径双重编码后与磁盘路径对不上 |
| 窗口事件 `emit` / `listen` | 窗口已存在时推新数据（复用窗口） | `compare:load` | 事件名是契约，改名要两边一起改 |
| localStorage | 主题、语言、设置 | `state.js` 的 `LS` | 两个窗口各读一份，改设置后另一窗不自动刷新 |

### 3.2 主线程规则（血泪级）

> **凡是「建窗口 / 弹原生对话框」的命令，必须是 `async fn`。**

Tauri 的同步命令在主线程上执行，而 `WebviewWindowBuilder::build()` 要等 WebView
回调；主线程被自己占着，`build()` 卡到超时——症状极具迷惑性：**窗口壳子、标题、
尺寸全对，页面永远不加载，整扇窗纯白**。

命令行入口 `--compare 左 右` 那条路走 `setup()`，本来就在主线程外，所以同一份代码
一条路好、一条路坏——这也是当初排查花了最久的原因。

### 3.3 启动流程

```
main.rs → lib.rs::run()
  ├─ 装单实例插件（必须第一个：要在建窗口前认出「已经有一个在跑」）
  ├─ 装 dialog / opener 插件，注册 24 条命令，manage 两份状态
  ├─ setup()
  │   ├─ 给主窗口套系统圆角（仅 Windows 11）
  │   └─ 解析 argv：有 --compare 就直接开对比窗，主窗口不显示
  └─ app.run()（当前为空回调 —— 见《跨平台移植》A3，macOS 要在这里接文件打开事件）
```

命令行参数解析集中在两个纯函数（有单测）：`file_args()` 过滤掉开关与不存在的路径，
`compare_args()` 认出 `--compare 左 右` 并把这两个文件从「要开成标签」的列表里剔除。

### 4.1 模块地图

```
app.js（主控，3800 行，唯一装配点）
├── 数据    state.js  taborder.js
├── 外壳    ui.js  appmenu.js  win.js  icons.js  shortcuts.js
```

### 4.2 五条依赖规则（违反就会出诡异 bug）

| 规则 | 具体约束 | 破了会怎样 |
|---|---|---|
| **R1 CM6 独占** | 只有 `plain-editor.js` 能 import CodeMirror；其他模块只能调它暴露的 `value/selection/revealOffset` | CM6 状态是全局单例，两处各改一份 → 光标乱跳、撤销失效 |
| **R2 HTML 只从 `markdown.js` 出** | 任何要插进 DOM 的 HTML 字符串都必须经过 `escapeHtml` / `inline()` | 一处漏转义 = XSS（预览是 `innerHTML`） |
| **R3 invoke 只从 `backend.js` 出** | 别处不许直接 `invoke()` | 绕过 `localizeError()`，用户看到英文/错误码原文 |
| **R4 不许循环 import** | 裸 ESM 下循环引用会让 `const` 停在 TDZ，表现为 `Cannot access before initialization` | 小概率、难复现，且只在某个模块先加载时炸 |
| **R5 状态只经 `state.js`** | 全局只有一份 `tabs` / `settings` | 两份真相 = 保存时写错标签（这个坑真踩过，见 §5.2） |

### 4.3 app.js 的内部结构

`app.js` 是唯一「知道所有事情」的模块，内部按功能分成若干段落，读它的顺序就是
界面的装配顺序：

```
导入 → DOM 引用表 el → 状态与视图切换(setMode/activate)
     → 标签栏刷新 → 工具条/状态栏刷新 → 大纲
     → 命令表 commands{id: fn} → 菜单树 menuTree() → 快捷键 setupKeys()
     → 初始化：setupDrop / setupSplitters / setupKeys / restoreSession
```

**所有功能入口都归到 `commands` 一张表**：菜单项、快捷键、命令面板、右键菜单，
四者只产出命令 id，执行统一走 `commands[id]()`。加功能时只加一条命令 + 引用它的
菜单项 / 键位，不要各写一份逻辑。

## 5. 状态模型

### 5.1 标签（`state.js::createTab`）

| 字段 | 含义 | 谁写 |
|---|---|---|
| `id` | 自增整数，界面里的 `data-id` | `createTab` |
| `path` | 磁盘绝对路径，未保存为 `null` | 打开/另存为 |
| `name` | 显示名（未保存时是「未命名.md」） | 改名/保存 |
| `content` | **源文本**，就是磁盘上应该有的那串字符 | 编辑器落账 / 打开 / 撤销 |
| `savedContent` | 上次读写磁盘时的内容，只用来算脏 | 保存成功 / 打开 |
| `encoding` `bom` `eol` | 读盘时探测到的编码与换行；保存时原样写回 | 打开 |
| `mode` | 当前模式（`wysiwyg` / `edit` / `preview`），按扩展名自动决定 | `setMode` |
| `scrollTop` `caret` | 切回来时恢复位置 | 切标签前 |
| `readonly` | 只读（大文件、二进制误判、外部结果） | 打开 |
| `external` | 是否为外部生成（对比结果 / 合并结果），保存时要问路径 | 对比/合并 |
| `mtime` | 上次读写时的修改时间，用于发现「别的程序改了它」 | 保存/监听 |

### 5.2 源文本是唯一真相（本项目最容易搞错的一条）

`t.content` 是权威数据，编辑器的 DOM 只是它的**投影**。由此推出三条纪律：

1. **落账（flush）必须在正确的时机**：输入走 600ms 防抖 + 失焦兜底，结构性编辑
   （Enter/Backspace/Tab/粘贴）立即落账。**每加一条写路径，第一件要问的是「脏标记在哪」**——
   早期漏掉 `applyEdit` 的脏标记，导致 `Ctrl+S` 判定「无改动」直接丢数据。
2. **DOM 有归属**：`wysiwyg.ownerTabId` 在渲染时钉住「这块 DOM 属于哪个标签」，
   `onChange` 只写回自己的标签。少了它，切标签那一刻旧 DOM 的 blur 会把旧内容
   写进新标签（**跨标签内容串台**，真机抓了半天的 bug）。
3. **落账后要封口**：`markCommitted()` 清掉 `_edited` / 待执行的 flush 定时器，
   迟到的 blur 不再冲第二次。

还有一条反直觉的：**没有未落账的编辑时，绝不读回 DOM**。判断「脏」用的是
`content !== savedContent`，不是「DOM 和 content 像不像」——读回 DOM 会把
DOM 的规范化差异（软换行、空白）当成用户改动，产生假脏标记。内存里统一按 LF
比较（`toLF()`），否则 CRLF 文件一打开就是「已修改」。

### 5.3 设置与迁移

设置是 `localStorage['snp.settings']`，默认值在 `state.js::DEFAULTS`，**改默认值必须
bump `__v`**：老用户 localStorage 里存着旧默认值，光改 `DEFAULTS` 对他们无效；
`__v` 变了才按新默认覆盖一次（并顺手清掉已经变成「粘滞值」的键）。

当前 `__v = 4`。测试或脚本要钉死设置时，写入的对象必须带 `__v: 4`，否则会被迁移逻辑
改写（这是测试环境的经典陷阱）。

### 5.4 数据落盘位置

| 数据 | 位置 | 说明 |
|---|---|---|
| 设置 / 草稿 / 会话 | `localStorage`（前缀 `snp.`） | 由 WebView 的 profile 目录承载 |
| 历史快照 | `<app_data_dir>/history/<fnv1a(路径)>/*.txt` | 一个文件一个目录，目录名是路径的哈希（避免路径里的非法字符）；`name.txt` 存原始文件名方便人看 |
| 粘贴/拖入的图片 | `<文档所在目录>/assets/` | 用相对路径引用（`![](assets/x.png)`），换机器不断链。**未保存的文档直接拒绝**并提示先存盘——没有「同目录」可放 |

`app_data_dir` 由 Tauri 按平台给出（Windows `%APPDATA%`、macOS
`~/Library/Application Support`、Linux `~/.local/share`），**代码里没有任何硬编码路径**
——这是移植时少数不用管的地方。

### 5.5 撤销：两套实现，按文档大小分流

| 文档 | 快照内容 | 代价 |
|---|---|---|
| < 1MB（DOM 即模型） | 记录型快照（文本或块引用） | 每步约 60KB，上限 200 条 |
| ≥ 1MB（视口模式） | `records` 数组的浅拷贝 | **记录写时复制**，未变的块共享引用；8 万块约 304KB |

写时复制是这里的地基：`records` 里的块对象视为只读，`_syncWindow` 只在内容真变时
换新对象，于是 `records.slice()` 就是零成本快照。**绝不能往记录上挂 DOM 引用**
（`rec.el = el` 会让 COW 失效，快照退化成深拷贝）。

## 6. 渲染管线

### 6.1 三种模式

| 模式 | 适用 | 实现 | 数据流向 |
|---|---|---|---|
| `wysiwyg` | Markdown 默认 | `wysiwyg.js`（一行=一个 `.w-block`） | md → 块 DOM ⇄ md |
| `edit` | 纯文本 / 代码 / 想要源码视图 | `plain-editor.js`（CM6） | 字符串 ⇄ 字符串 |
| `preview` | 只读看渲染结果 | `preview.js` | md → HTML 字符串 |

md 文件默认落在 `wysiwyg`（`modesFor()` 的首项）；`lastMode` **只记忆用户手动切换过
的模式**，自动落位不写入——否则默认值首次启动就会被粘滞成别的模式。

### 6.2 md → 块

`parseMarkdown(md)` 产出 `DocumentFragment`，每个块带类型与元数据：

| 块 | class | 备注 |
|---|---|---|
| 标题 | `.w-h1`…`.w-h6` | 哈希把手 `.w-hash` 是 `contentEditable=false`，绝不进 `.w-text` |
| 段落 | `.w-p` | |
| 列表项 | `.w-li` | `gap` 标记空行、`li` 标记层级 |
| 引用 | `.w-bq` | 连续 `.w-bq` = 一个引用组，组首行打 `data-bq-start` |
| 提示块 | `.w-bq[data-callout]` | `> [!info] 标题`，标题行 `.w-co-head` |
| 代码块 | `.w-code` | 语言存 `data-lang` |
| 公式 | `.w-math` | 块级独立成块 |
| 表格 / 分割线 | `.w-table` / `.w-hr` | 表格不可拖拽、没有「转为其它块」 |

**空行不是块**：块之间的空行由序列化按类型生成。空标题原地降级（不 `replaceWith`，
否则光标错位）；正在敲 `###` 时不降级。

### 6.3 序列化

`blocksToMd()`（DOM → md）与 `recordsToMd()`（记录 → md）是两条独立实现，必须给出
**逐字节一致**的结果——所有 round-trip 测试断言的就是这件事。**改任何一个块类型，
两个序列化函数 + 两个解析入口（`parseMarkdown` / `parseRecords`）要同时改**，
这是本项目最容易漏的一处（提示块曾经在两条路径上行为不一致）。

### 6.4 预览

`renderPreview(kind, text, lang, target, docDir)` 按类型分流，绝不糅合：
md 走 `renderMarkdown`，json 走格式化 + 错误定位，代码走 `highlight.js`，其余纯文本。

`markdown.js::inline()` 的**顺序是有意的**：行内代码 → 公式 → 转义。先抽出代码与公式
（它们内部的字符不再参与 Markdown 解释），再统一转义，否则 `` `a<b` `` 会被吃掉。

**大纲提取**（`preview.js::extractOutline`）只看结构，不猜内容：md 认 `#`（跳过围栏代码），
json 认缩进层级，代码认函数/类定义；纯文本只认 `# `、Setext 下划线（`===`/`---`，标题在上一行）、
`【章节】`、`第X章/节/条`、以及多级编号（`1.1` 按点号段数分级）。**单级编号必须「空行断组后
只剩它一条」才算章节**——否则一份 `1. 2. 3.` 的清单会把每行都变成大纲，这正是旧实现的问题。
csv/tsv 一行一条记录，不提取。收完统一做一次「不许跳级」归一化，避免 h3 上面没有 h1/h2 时缩进悬空。

### 6.5 视口渲染（> 1MB）

超过 `BIG_DOC_CHARS = 1000 * 1000` 字符的文档换一条路径：

- **`records` 是唯一真相**（每块存 md 原文切片 + 标记），DOM 只放窗口内（约 4 屏，
  上限 600 块）。
- 窗口外的高度用 `.wysiwyg.virtual::before/::after` + `--vpad-top/bot` 撑出来。
  **绝不能用 `padding`**：`clientHeight` 含 padding，会把滚动容器自己撑高。
- 必须 `overflow-anchor: none`：浏览器的滚动锚定会和自己的 delta 补偿各补一次。
- 视口模式下 `Ctrl+A` 走**逻辑全选**（标记整篇 + 拦截 beforeinput/copy/cut），
  原生全选只覆盖窗口内容，随后打字会把窗口外几万块当「未选中」删掉。
- `_render()` 里任何分流分支**结尾必须补 `silent = false`**，漏了会让编辑不进
  `tab.content`、不变脏、不自动保存。

### 6.6 性能纪律（写进代码注释的硬约定）

1. **输入路径禁止全量重算**：normalize 只扫光标块 ±1。
2. 大纲 250ms 防抖 + 结构签名（签名没变就不重建）。
3. 标签栏刷新前先比签名，没变就返回。
4. 大纲定位用二分（标题位置单调递增）；`syncOutline` 同理。
5. 判「结构变化」只看块类型（`typeFrom`/`typeTo`），不看文本——纯文本编辑不算结构变化。

## 7. 前端 ↔ Rust 契约

24 条命令（`lib.rs::generate_handler!`）。**加命令时必须同步**：①这里 ②
`backend.js` 包装 ③`capabilities/default.json`（若涉及新权限）。

| 命令 | 入参 | 返回 / 用途 |
|---|---|---|
| `read_text_file` | path, encoding? | `{path, name, content, encoding, bom, eol}`；自动探测编码，含 NUL 字节判为二进制并拒读 |
| `save_text_file` | path, content, encoding, bom | 按原编码写回（含原子替换策略） |
| `file_stat` | path | size / mtime / 是否存在 |
| `read_dir_shallow` | path | 单层目录（文件树懒加载） |
| `list_dir_recursive` | path, max_files? | 递归列举（文件夹对比），默认上限 2 万 |
| `search_in_folder` | path, query, opts | 全目录搜索（字面 / 正则） |
| `replace_in_folder` | path, query, replacement, opts | 仅处理能按 UTF-8 读通的文件 |
| `write_binary_file` / `read_file_base64` / `save_image_bytes` | path / bytes | 图片粘贴与导出 |
| `copy_image_to_assets` | src, 文档目录 | 把拖入的图片复制到文档旁 |
| `file_mtime` | path | 监听比对用 |
| `watch_files` | paths | 只监听文档所在目录的**一层**（NonRecursive） |
| `create_entry` / `rename_entry` / `delete_entry` | path… | 新建 / 改名 / 删除（删除进回收站，见移植文档） |
| `initial_files` | — | 启动时的命令行文件列表 |
| `save_history` / `list_history` / `read_history` / `clear_history` | path… | 历史快照 |
| `open_compare_window` | left?, right? | **async**：建/复用对比窗口 |
| `take_compare_request` | — | 新窗口取一次待处理请求（取完即清） |
| `compare_set_fullscreen` | fill | 对比窗的「最大化 / 还原」（实质是两个矩形） |

设计约束：

- **命令只做一件事，参数与返回都是可序列化的简单类型**（字符串、数字、`Vec`、结构体）。
  不传回调、不传句柄。
- **文件名校验在 Rust 做**（`name.path_sep` 之类的错误码），前端只负责显示。
- **长时间操作不做进度回调**：搜索/替换是同步返回结果，超时靠上限（2 万文件）兜住。

## 8. 错误模型

后端**不说人话**，只说三样东西：

```rust
AppError { code: "io.read", vars: {"name": "a.md"}, detail: "系统原始报错" }
```

- `code` 是稳定错误码（`io.read` / `entry.exists` / `name.path_sep` / `recycle.failed` …），
  一旦发布就不能改语义。
- `vars` 是模板参数，供前端填空。
- `detail` 是 `std::io` / Win32 原文——**它本来就是系统按自己的语言给的，不归我们翻**。

前端 `errors.js::ERR_TEXT` 把码映射到词条键（键里带 `{detail}` `{name}` 占位符），
`localizeError()` 拼整句；`backend.js` 的 invoke 出口统一过一道，**调用方 catch 到的
一定是带人话 `message` 的 `Error`**。

三条纪律：

- **冒号不拼接**：`前缀 + '：' + 细节` 这种拼法每种语言都错（中日全角、法语冒号前有空格）。
  整句（含冒号）做成一条词条。
- **防二次翻译**：`localizeError` 产出的 `Error` 带 `message` 无 `code`，天然不会再被翻一遍。
- **没收录的码要露出来**：宁可显示 `[io.foo] boom`，也不要静默吞掉。
  `test/run-i18n.mjs` 做双向对账：`ERR_TEXT` 的每条模板都在词条表里；Rust 里出现的
  每个 `AppError::code` 前端都有模板。

## 9. i18n

- **键 = 简体中文原文**（gettext 思路），代码里 `tt('保存')` 一眼知道上下文。
- 词条源 `i18n-dict-src.js` 是 **7 列**（英/日/韩/法/德/西/葡），**繁体不手写**，
  由 `tools/build-i18n-dict.py` 用 OpenCC `s2twp` 生成 → 产物 `i18n-dict.js` **只读**。
- 静态 HTML 用 `data-i18n` / `-title` / `-ph` / `-aria`，`applyDom()` 统一刷。
- **JS 会赋值 `textContent` 的节点绝不能挂 `data-i18n`**（对话框标题、草稿状态、文件名…），
  否则切语言那一刻会被刷回静态词。
- 带 `tt()` 的**顶层常量必须写成函数**（`const modeMeta = () => ({...})`），否则在模块
  加载那一刻就求值了，切语言后不生效。
- 取词函数叫 `tt` 不叫 `t`——`t` 是「当前标签」，会被局部变量遮住。
- 后端错误码的词条要显式登记进词条表（`ERR_TEXT` 里的键同样受覆盖率检查）。

新增文案后的固定动作：`node test/run-i18n.mjs`（查覆盖率、列数、占位符）。

## 10. 关键不变量

移植、重构、升级依赖时，这些行为**必须原样保住**。每一条都对应过至少一个真实 bug。

| # | 不变量 | 破了的表现 |
|---|---|---|
| 1 | `t.content` 是唯一真相，DOM 只是投影 | 保存写错内容、跨标签串台 |
| 2 | 落账后 `markCommitted()` 封口 | 同一份编辑冲两次，撤销变乱 |
| 3 | 无未落账编辑时不读回 DOM | 打开 CRLF 文件立刻「已修改」 |
| 4 | 内存里统一 LF 比较 | 假脏标记、`Ctrl+S` 反复写盘 |
| 5 | 每条写路径都要标脏 | `Ctrl+S` 判无改动 → 丢数据 |
| 6 | 大文档 `_render` 分支结尾 `silent = false` | 编辑不进 content、不自动保存 |
| 7 | 视口模式 `overflow-anchor: none` | 滚动时内容被顶走一两千像素 |
| 8 | 视口模式 `Ctrl+A` 走逻辑全选 | 打字删掉窗口外几万块 |
| 9 | 块是只读的，改动要换新对象 | 撤销快照退化成深拷贝，切标签卡顿 |
| 10 | 记录/块上不挂 DOM 引用 | 同上，且内存泄漏 |
| 11 | `recordsToMd` 与 `blocksToMd` 逐字节一致 | round-trip 丢格式 |
| 12 | 引用组首行必须打 `data-bq-start`（四个入口都要） | 两个引用框粘成一个、空行丢失 |
| 13 | 提示块转走/取消时把标题字放回正文 | 标题文字凭空消失 |
| 14 | 换块类型只走 `convertBlock()` | 「代码块上点引用没反应」 |
| 15 | 建窗口命令必须 `async fn` | 窗口纯白、页面永不加载 |
| 16 | 新窗口必须在 `capabilities` 里登记 | `core:window:*` 静默失败 |
| 17 | 跨窗口传参走 Rust 状态，不走 URL | 中文路径对不上 |
| 18 | `.w-hash` 等 `contentEditable=false` 元素不进 `.w-text`，且 sweep 白名单要含它 | 标题退级时字被吃 |
| 19 | JS 会写 `textContent` 的节点不挂 `data-i18n` | 切语言后被刷回静态词 |
| 20 | 改 `src/` 后必须重新编译 | 看到的还是旧界面（最容易浪费时间的假象） |
| 21 | 大纲只反映**结构**：md 认 `#`，纯文本只认 `#`/Setext/`【】`/`第X章`/多级编号 | 「每行都是大纲」——清单、日志逐行进面板，面板失去导航意义 |
| 22 | 块菜单浮层不抢焦点，当前项靠 `.hot` 类 | 菜单一开正文选区就没了，Esc 回去光标无处落脚 |
| 23 | 差异算法可以牺牲精度，**不许输出假相同**：`same` 行必须两侧行号都有效 | 2000 行对 2000 行的文件整页右栏空白，新增全堆到文末（旧实现的 `b=-1`） |

## 12. 平台边界在哪

代码里所有 `#[cfg(target_os = ...)]` 与前端所有平台相关判断，集中在**四类**：

| 类别 | 位置 | 说明 |
|---|---|---|
| 系统窗口行为 | `lib.rs`：圆角、工作区矩形、铺满、`compare_set_fullscreen` | 全 Windows 专属，非 Windows 有回落分支 |

## 13. 已知设计债

按「什么时候会咬人」排序：

1. **快捷键文案写死 `Ctrl`**（约 130 处）。匹配逻辑是 `ctrlKey || metaKey`，所以 macOS 上
   **能用但显示错**。移植前应统一成 `mod+` 存储 + 按平台渲染。
2. **`app.run(|_, _| {})` 是空回调**。macOS 必须在这里接文件打开事件，否则「双击 md
   打开」在 mac 上完全不通。
3. **菜单在 macOS 上会重复**：Tauri 默认会给 macOS 建一套系统菜单栏（App/File/Edit/…），
   而应用又自绘了一份 —— 窗口里一套、屏幕顶上一套。移植时要么改用原生菜单承接所有命令，
   要么 `enableMacosDefaultMenu: false` 后自己补最小 App 菜单（⌘Q / ⌘H 仍需归属）。
4. **打印依赖 `window.open` + `win.print()`**。Windows（WebView2）可行，macOS（WKWebView）
   很可能不行，Linux（WebKitGTK）待实测。需要一层抽象。
5. **`delete_file_impl` 的非 Windows 分支是永久删除**，与产品语义（进回收站）不符。
6. **构建配置写死 `bundle.targets: ["nsis"]`**，在 mac / Linux 上构建会直接失败。
7. **测试工具链分两层，一半是 Windows 专属**：离线套件（CDP + headless Chrome）可移植；
   真机套件（UIA + SendInput + PrintWindow 截图）是 Windows 专用 PowerShell，需要重写。
9. **无边框窗口的「最大化」是自己算矩形**：`tao` 的 `maximize()` 在无边框窗口上不可用
   （标志位先写后跳过），现在靠 `SPI_GETWORKAREA` + `SetWindowPos` 手动铺满，
   还要按 DWM 隐形边框外扩。这套绕法只在 Windows 上验证过，mac / Linux 应换成
   各自的正规做法（macOS 的 `toPhysical`/`setFrame`、Linux 的 GTK 最大化）。
10. **i18n 词条里含着快捷键文案**（`i18n-dict-src.js` 15 条），改了键位要连带改词条。
