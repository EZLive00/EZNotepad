# EZNotepad · 构建说明

> 一个 5MB 的桌面小工具，把 Markdown 写作、文本读写、文件对比收在一起。
>
> 本文只讲「怎么把代码变成能跑的东西」。结构设计见《架构设计.md》，
> 换平台要改什么见《实现规格.md》§10，踩过的坑见《架构设计.md》。

## 一、环境准备

| 平台 | 需要安装 |
|---|---|
| **Windows** | [Node.js 18+](https://nodejs.org)、[Rust](https://rustup.rs)、[Microsoft C++ 生成工具](https://visualstudio.microsoft.com/visual-cpp-build-tools/)（勾选「使用 C++ 的桌面开发」） |
| **macOS** | Node.js 18+、Rust、Xcode Command Line Tools（`xcode-select --install`） |
| **Linux** | Node.js 18+、Rust、`build-essential` `pkg-config` `libwebkit2gtk-4.1-dev` `libgtk-3-dev` `libayatana-appindicator3-dev` `librsvg2-dev`（Ubuntu 22.04 / Debian 12 起） |

装好 Node 后，在项目目录执行一次：

```bash
npm install -g pnpm
pnpm install
```

> 依赖安装脚本默认被 pnpm 12 拦着，放行清单写在 `pnpm-workspace.yaml` 的 `allowBuilds`。
> 仓库的**唯一锁文件是 `pnpm-lock.yaml`**，不要再用 npm 生成 `package-lock.json`——
> 两份锁文件漂移过，直接导致 CI 装出空壳依赖。

### Windows 环境自检

双击 **`环境检查-Windows.bat`**，逐项检查并给结论：

| 检查项 | 缺失后果 |
|---|---|
| Windows 版本 | — |
| Node.js ≥ 18 | `pnpm` 无法运行 |
| pnpm | 会自动帮你 `npm i -g pnpm` |
| Rust + MSVC 工具链 | `cargo` 无法编译；工具链非 msvc 会报 `link.exe not found` |
| Visual Studio C++ 生成工具 | 报 `error: linker 'link.exe' not found`（**最常见**，只装 VS Code 不算） |
| WebView2 运行时 | 不影响打包，但本机无法运行程序 |

不想跑脚本也行，用官方自检命令（能列出 Tauri 视角下的完整环境）：

```bash
pnpm tauri info
```

卡在 `Downloading NSIS` 是 GitHub 下载超时。手动下载
[Tauri NSIS 包](https://github.com/tauri-apps/binary-releases/releases) 放到
`%LOCALAPPDATA%\tauri\` 后重试，或临时开代理。

## 二、三条铁律

这三条弄错，会得到「改了没反应」或「CI 莫名失败」这类最难查的问题。

**1. `src/` 是编译期内嵌的。** `tauri.conf.json` 的 `frontendDist` 指向 `../src`，
HTML/CSS/JS 在 `cargo build` 时被打进二进制。**改完前端不重新编译，跑起来还是旧界面。**
开发时用 `pnpm tauri dev`（带热重载），验证构建产物时必须 `cargo build` 后再启动。

**2. `src/vendor/` 必须入库。** Tauri API、CodeMirror（`cm6.js`）、KaTeX、Lucide 图标
全在里面。打包时**不跑 npm**——没有这些文件，前端就 import 不到。
`.gitignore` 里没有它们，别手贱加进去。

**3. 版本号只有一个源。** `src-tauri/tauri.conf.json` 的 `version` 是权威值：
关于对话框走 `be.appVersion()`（Tauri `getVersion()`）读它，CI 的标签名也从它推出来。
`package.json` / `Cargo.toml` 里的同名版本仅作留档，改的时候三处一起改，但**判断以
`tauri.conf.json` 为准**。

### 零垃圾约定（重要）

**这台机器上删除的文件会进回收站**（不是 `rm` 那种直接抹掉；钩子来自深信服的
`SGuard64X` / `SGuardSvc64X`）。所以测试里每删一个临时目录，就是往回收站塞几百条：
一个 Chrome 用户目录约 190 个文件，以前每套测试「新建 profile + 用完即删」，
跑一轮七套测试就是上千条垃圾。

现在的规矩是 **测试代码一行删除都不写**：

- Chrome 用户目录按调试端口固定（`node_modules/.tmp/chrome-prof-<端口>`），
  **反复复用、永不删除**。总共 4 个，各约 6MB
- 复用会带进旧缓存，所以静态服务统一发 `Cache-Control: no-store`
- 探针夹具（`probe-cmp`）每轮 `writeFileSync` 覆盖，不删目录
- 探针一批只起一次应用（`test/run-probe.mjs`），应用退出先 `WM_CLOSE` 再兜底强杀
  —— 硬杀会让 WebView2 下次启动清理一遍缓存
- 探针的 WebView2 数据目录固定在 `%TEMP%\eznotepad-probe`（`WEBVIEW2_USER_DATA_FOLDER`，
  可用 `APP_PROFILE` 覆盖），不碰用户的真实配置目录
- **速记也要隔离**：探针会往速记里打字，而速记默认落在应用数据目录（用户真正的笔记）。
  `test/lib/appctl.mjs` 用 `EZNOTEPAD_QUICKNOTE` 把它指到
  `%TEMP%\eznotepad-probe-note\quicknote.md`（`APP_QUICKNOTE` 可覆盖）——
  同样是覆盖写、不删除

最后一条不只是卫生问题，也是**测试正确性**问题：探针以前共用的
`%LOCALAPPDATA%\com.simple.notepad\EBWebView` 是用户的真实配置，探针往里写
localStorage/settings，残留状态让断言假红（`probe-app` 的「默认停在大纲页」就是
这么红的）。另外 Chromium 每次会话都要重建 `Session Storage`
（`LOCK`/`CURRENT`/`MANIFEST-000001`/`LOG`）和 `Code Cache` 索引，SGuard 会把这类
删除重定向进回收站 —— 共用真实目录时**一次 10 条**。

**SGuard 对 `%TEMP%` 下的删除不做重定向**：同一个 `%TEMP%` 数据目录连续启动 4 次，
实测 0 条。所以探针的数据目录放在那里，既干净又零垃圾。

实测（2026-11-03，按回收站条目计数）：

| 动作 | 新增条目 |
|---|---|
| 七套离线测试跑一轮 | **0** |
| 一批七个真机探针（598 条断言） | **0**（改 `%TEMP%` 数据目录之前是 10/次） |
| 一次 `cargo build` 重编 | 约 500（cargo 删旧产物，构建本身避免不了） |

构建产生的那些仍然会进回收站，用完跑 `.workbuddy/tools/purge-build-trash.ps1` 清掉；
`-WhatIf` 可以先看范围（`-Root` 可临时换过滤路径，例如清探针旧数据目录的遗留）。

> **别把这 10 条算在「测试制造垃圾」头上**：正常双击启动一次应用、再关掉，同样是
> 10～13 条（debug 10、release 13，都实测过），与测试无关。
>
> 但也不是「所有 Chromium 应用都这样」——本机回收站里 Chrome / Edge 的条目是 **0 条**，
> 而 Chrome 此刻有十来个进程在跑。差别在于那两个是签名的知名程序，我们的是
> `NotSigned`：安全软件对**未签名进程**的删除做「备份进回收站」，这是防勒索的常规策略。
> 顺着这条线只有两个出路——给 exe 做代码签名，或在安全软件里给
> `%LOCALAPPDATA%\com.simple.notepad` 加排除。探针那条之所以能归零，是因为数据目录
> 挪进了 `%TEMP%`（安全软件对 TEMP 不备份）。

### 真机验证（仅 Windows）

界面上真的点下去、系统对话框真的弹出来，这类问题只有真机能暴露：

```bash
node test/probe-app.mjs
node test/probe-compare.mjs      # 对比窗口（夹具写到 node_modules/.tmp，覆盖写不删除）
node test/probe-bmenu.mjs
node test/probe-ctx.mjs
node test/probe-undo.mjs
node test/probe-quicknote.mjs
node test/probe-fcmp.mjs       # 文件夹对比窗口（夹具同样写 node_modules/.tmp）
```

一次跑完七个：`pnpm test:probe`（约 3 分钟，只起一次应用，零重建）。

**不需要改配置、不需要为探针重新构建。** 探针会自己起应用（`test/lib/appctl.mjs`）：
用 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS` 把 `--remote-debugging-port=9333` 注入进去，
等主窗口的 `document.readyState === 'complete'` 且 `window.__snp` 挂上才算就绪，
跑完用 `taskkill /T` 连树收掉。端口上已经有应用时会直接复用，不会起第二个。

为什么要这么绕：以前是临时改 `tauri.conf.json` 的 `additionalBrowserArgs` 和
`lib.rs::spawn_compare_window` 两处再全量重编，测完再撤销重编 —— 一轮两次
`cargo build`（前端内嵌，各 50~100s）。WebView2 的环境变量是**进程级**的，
主窗口和随后打开的对比窗口都会带上，于是这条路径可以完全省掉。

几个约束：

- 环境变量会**覆盖**窗口级参数，所以 `appctl.mjs` 里把 `tauri.conf.json` 那串
  `--disable-features=... --disable-gpu-sandbox` 原样带着；漏掉沙箱那个开关会重新踩到
  WebView2 崩溃
- 端口冲突用 `CDP_PORT=9344 node test/probe-compare.mjs` 覆盖
- 想自己先起应用再跑探针，设 `NO_LAUNCH=1`；换产物用 `APP_EXE=<路径>`
- **多个 page 目标时只能按 `!url.includes('compare.html')` 区分主窗口与对比窗口**，
  只写 `type === 'page'` 会随机挑到对比窗口，断言全落在错误页面上（踩过一次）
- 探针读的是**已构建产物**里的前端，改完 `src/` 仍然要 `cargo build` 才生效

工具链在 `test/real/`（PowerShell + UIA + SendInput），用例生成器是 `gen-*.mjs`。
方法论与结论见 `test/real/TEST-PLAN.md`、`RESULTS.md`。

## 五、CI 与发版

`.github/workflows/release.yml` 当前只构建 Windows，产出两个 artifact：

| 文件 | 说明 |
|---|---|
| `EZNotepad_<版本>_x64-setup.exe` | NSIS 安装包（未签名，首次运行会被 SmartScreen 拦一次） |
| `EZNotepad_<版本>_x64-portable.zip` | 免安装版打包（Tauri 在 Windows 上没有 portable 目标，裸 exe 即便携版） |

本机发版前 checklist（1.2.9 起固化，顺序别倒）：

1. 四处版本号一起改：`package.json` / `tauri.conf.json` / `Cargo.toml` /
   `Cargo.lock` 里 `name = "simple-notepad"` 那一处（`Cargo.lock` 还有一堆依赖版本，别误改）。
2. `cargo build --release --manifest-path src-tauri/Cargo.toml` —— **debug 能编不等于
   release 能编**，这一步不能省。
3. `pnpm exec tauri build --bundles nsis`，核对 exe 与 setup 的 `FileVersion` 都是新版本号；
   图标改动还要按 PNG blob 字节确认 exe 内嵌的是新帧（截图看不出来）。
4. `APP_EXE=src-tauri/target/release/EZNotepad.exe CDP_PORT=9355 node test/run-probe.mjs`
   —— **用最终 release 产物**跑真机七组，不能拿 debug 结果顶替。端口固定 9355 是给
   release 产物留的，跑前先 `taskkill /IM EZNotepad.exe /F /T`，否则会复用旧进程假绿。
5. 最后一次性提交 `chore(release): <版本>`，打附注 tag，推 main 与 tag。

发版流程（**标签是唯一触发源**）：

```bash
git tag -f -a v1.0.2 -m "v1.0.2"
git push -f origin v1.0.2
```

两个细节：

- **`-f` 是必需的**：重发同一版本号时要重新钉标签到当前 HEAD，否则 CI 跑的还是旧提交。
- 标签名从 `tauri.conf.json` 的 `version` 推出来（workflow 里有「读取版本号」步骤），
  不要在 workflow 里再写一遍数字，写死必然脱节。

构建失败时，错误行会以 `::error::` 注解打到日志里——**Actions 的完整日志需要管理员
令牌，注解不需要**，这是无人值守排障的正路。同理，构建与发布拆成了两个显式步骤，
而不是用 `tauri-action` 一把梭（它把输出吞在自己的步骤里，失败就是黑箱）。

三种平台的 CI 矩阵写法见《实现规格.md》§10.6。

## 六、构建期资源

### CodeMirror 6 怎么打包

纯文本 / 代码编辑区用 [CodeMirror 6](https://codemirror.net)（MIT）。它不是单个文件，
而是几十个 npm 包互相 `import`，而本项目是**裸 ESM、没有打包器**——浏览器直接加载会 404。
所以在开发机上预先打成**一个**文件：

```
src/js/editor/cm6-entry.js      ← 只 re-export 用到的 API（按 import 裁剪体积）
        ↓  esbuild bundle --format=esm --minify
src/vendor/cm6.js               ← 约 1.16 MB，已入库，必须提交

src/js/vendor-entry/syntax.js   ← highlight.js core + 54 门语言
        ↓
src/vendor/syntax.js            ← 约 208 KB

src/js/vendor-entry/prettier.js ← prettier standalone + 7 个 parser 插件
        ↓
src/vendor/format.js            ← 约 2.2 MB（运行时懒加载，不进启动路径）

src/js/vendor-entry/mermaid.js  ← mermaid 全套图类型
        ↓
src/vendor/mermaid.js           ← 5.12 MB（懒加载：文档里没有 ```mermaid 就永不 import）
```

```bash
pnpm build:cm6               # 只在这一步需要 node_modules
pnpm build:syntax            # 着色引擎 + 格式化引擎，一次打两个文件
pnpm build:mermaid           # diagram.js 用的 mermaid（单文件、不分包）
```

⚠️ `src/vendor/mermaid.js` **5.12 MB 必须入库**，但它只在 `diagram.js` 真正需要时
才 `import()`。所以它不影响冷启动，也不进 `index.html` 的加载路径 —— 想验证这一点，
在 DevTools 控制台跑 `performance.getEntriesByName` 看有没有 `mermaid.js`：
打开一份不含图的文档应该一条都没有，一旦插入 ` ```mermaid ` 才会出现。

| 要改什么 | 怎么做 |
|---|---|
| 升级 CM6 | `pnpm update @codemirror/*` 后重跑 `pnpm build:cm6` |
| 升级 highlight.js / prettier | `pnpm update highlight.js prettier` 后重跑 `pnpm build:syntax` |
| 升级 mermaid | `pnpm update mermaid` 后重跑 `pnpm build:mermaid`；体积变化超过 1MB 要重新评估「默认集成」这个决定 |
| **加一门语言** | ① `src/js/langs.js` 加一条（扩展名 → hljs 名 / CM 名 / prettier parser）② 预览侧：`vendor-entry/syntax.js` 注册语法 ③ 编辑区：`cm6-entry.js` export + `plain-editor.js` 的 `CM` 表加一行 ④ 重跑两个打包脚本 |
| 改配色 | 不用重打包。改 `styles.css` 的 `--tok-*` 变量，编辑器和预览同时生效 |
| 改外观（行高、行号、内边距） | 改 `src/js/editor/theme.js`，也不用重打包 |

分层约定：**只有 `plain-editor.js` 认识 CM6**，`app.js` 拿到的只是一组「读写文本 +
字符偏移」的方法。将来换编辑器只动这一层。同理，**只有 `highlight.js` 认识 hljs**、
**只有 `format.js` 认识 prettier**，其余模块只看到「HTML 片段 / 格式化后的文本」。

### 界面图标、应用图标与 KaTeX

```bash
pnpm icons          # Lucide 子集 → index.html 的 icon-sprite 生成区
pnpm icons:app      # 品牌标 + 应用图标：app-icon.svg、#i-brand、17 份位图一次出齐
pnpm build:katex    # 生成 src/vendor/katex/（只在升级 KaTeX 时跑）
```

**改程序图标只有 `pnpm icons:app` 一个入口**：几何、配色、22/16 比例都写在
`scripts/app-icon.mjs` 里，脚本同时生成 `src-tauri/icons/app-icon.svg` 与

⛔ 不要手改这两份产物，也不要单独跑 `tauri icon` —— 那样标题栏和任务栏又会变成

### 多语言

界面文案全部走 `tt('简体中文原文')`，词条表是 `src/js/i18n-dict-src.js`（7 列：
英/日/韩/法/德/西/葡）。**繁体不手写** —— 由 OpenCC `s2twp` 从简体转出：

```bash
python tools/build-i18n-dict.py    # 需要 pip install opencc-python-reimplemented
node test/run-i18n.mjs             # 校验：列数、覆盖率、占位符、缺键回退
python tools/i18n-find-left.py     # 收尾：列出还没被 tt() 包住的中文字面量
```

两条纪律：

- **`i18n-dict.js` 是生成物，不要手改**，改 `i18n-dict-src.js` 再跑脚本。
- 新写的界面文字要么包 `tt()`，要么在 HTML 上打 `data-i18n`；两种情况 `run-i18n.mjs`
  都会查「表里有没有这条」。忘了会红，不会静默显示英文。

静态 HTML 用 `data-i18n` / `data-i18n-title` / `data-i18n-ph` / `data-i18n-aria`，
启动和切换语言时由 `applyDom()` 统一刷。**但文字由 JS 赋值的节点不能挂**
（对话框标题、草稿状态、文件名……），否则切语言那一刻会被刷回静态词。

## 八、Windows 上窗口全黑 / 白屏的诊断

启动后窗口正常出现但**客户区全黑、点什么都没反应**，先看 WebView2 自己的日志：

```bat
set WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--enable-logging --v=1
"%LOCALAPPDATA%\com.simple.notepad\EBWebView\chrome_debug.log"
```

日志里出现下面三行就中了：

```
ERROR:gpu_process_host.cc:1103  GPU process exited unexpectedly: exit_code=7
WARNING:gpu_process_host.cc:1571  The GPU process has crashed N time(s)
FATAL:gpu_data_manager_impl_private.cc:408  GPU process isn't usable. Goodbye.
```

意思是 **GPU 进程的沙箱在这台机器上起不来**，Chromium 连续崩溃 N 次后直接中止浏览器进程，
窗口就只剩一片黑（页面其实已经加载完了）。这不是前端代码的问题。

`tauri.conf.json` 里已固化兜底参数：

```json
"additionalBrowserArgs": "--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection --disable-gpu-sandbox"
```

`--disable-gpu-sandbox` 只关掉 GPU 进程的沙箱，渲染沙箱与主进程沙箱仍然保留。
某些机器上连这个也不管用，可退一步改用 `--in-process-gpu`。

> 这个字段是 WebView2 专属，mac/Linux 上会被忽略，不会报错。

## 十、常见故障

| 现象 | 原因 / 处理 |
|---|---|
| 改了 CSS/JS 没生效 | 忘了重新 `cargo build`（前端是编译期内嵌的） |
| `cargo build` 报「拒绝访问 (os error 5)」 | 残留进程占着产物：关掉正在跑的 EZNotepad 再构建 |
| 构建产物不消失，回收站暴涨 | 本机有文件系统过滤驱动把所有删除转进回收站，跑 `.workbuddy/tools/purge-build-trash.ps1`（`-WhatIf` 先看量） |
| `link.exe not found` | 只装了 VS Code，没装 VS 生成工具的 C++ 工作负载 |
| CI 报 `Cannot find module '@tauri-apps/cli-win32-x64-msvc'` | 锁文件被 npm 污染过，`pnpm install --frozen-lockfile` 会暴露出来 |
| 窗口纯白、页面不加载 | 建窗口的命令写成了同步 `fn`，主线程被 `build()` 卡死 |
| 窗口按钮点了没反应 | `capabilities/default.json` 缺对应的 `core:window:allow-*` |
| 测试报 `找不到 Chrome / Edge` | 用 `CHROME_PATH` 指定浏览器可执行文件 |
| 真机探针里**几何类断言一起变红**（大纲项数、滚动高亮、拖选坐标、工具栏折叠、窗口铺满） | 当前会话是「断开」的（`qwinsta`），WebView2 只拿到 `screen 640×480 / dpr=1`，显卡仍报 1920×1200。用改动前的产物跑同一探针做对照：`APP_EXE=src-tauri/target/release/EZNotepad.exe CDP_PORT=9355 node test/probe-app.mjs`；旧前端也红就是环境。回到活动桌面会话重跑，⛔ 别改系统显示设置、别用视口模拟糊过去（详见《架构设计》§15 第 55 条） |
