# EZNotepad · 构建说明

> 一个 5MB 的桌面小工具，把 Markdown 写作、文本读写、文件对比收在一起。
>
> 本文只讲「怎么把代码变成能跑的东西」。结构设计见《架构设计.md》，
> 换平台要改什么见《跨平台移植.md》，踩过的坑见《开发经验.md》。

## 一、环境准备

| 平台 | 需要安装 |
|---|---|
| **Windows** | [Node.js 18+](https://nodejs.org)、[Rust](https://rustup.rs)、[Microsoft C++ 生成工具](https://visualstudio.microsoft.com/visual-cpp-build-tools/)（勾选「使用 C++ 的桌面开发」） |
| **macOS** | Node.js 18+、Rust、Xcode Command Line Tools（`xcode-select --install`） |
| **Linux** | Node.js 18+、Rust、`build-essential` `pkg-config` `libwebkit2gtk-4.1-dev` `libgtk-3-dev` `libayatana-appindicator3-dev` `librsvg2-dev`（Ubuntu 22.04 / Debian 12 起） |

装好 Node 后，在项目目录执行一次：

```bash
npm install -g pnpm
pnpm install
```

> 依赖安装脚本默认被 pnpm 12 拦着，放行清单写在 `pnpm-workspace.yaml` 的 `allowBuilds`。
> 仓库的**唯一锁文件是 `pnpm-lock.yaml`**，不要再用 npm 生成 `package-lock.json`——
> 两份锁文件漂移过，直接导致 CI 装出空壳依赖。

### Windows 环境自检

双击 **`环境检查-Windows.bat`**，逐项检查并给结论：

| 检查项 | 缺失后果 |
|---|---|
| Windows 版本 | — |
| Node.js ≥ 18 | `pnpm` 无法运行 |
| pnpm | 会自动帮你 `npm i -g pnpm` |
| Rust + MSVC 工具链 | `cargo` 无法编译；工具链非 msvc 会报 `link.exe not found` |
| Visual Studio C++ 生成工具 | 报 `error: linker 'link.exe' not found`（**最常见**，只装 VS Code 不算） |
| WebView2 运行时 | 不影响打包，但本机无法运行程序 |

不想跑脚本也行，用官方自检命令（能列出 Tauri 视角下的完整环境）：

```bash
pnpm tauri info
```

卡在 `Downloading NSIS` 是 GitHub 下载超时。手动下载
[Tauri NSIS 包](https://github.com/tauri-apps/binary-releases/releases) 放到
`%LOCALAPPDATA%\tauri\` 后重试，或临时开代理。

## 二、三条铁律

这三条弄错，会得到「改了没反应」或「CI 莫名失败」这类最难查的问题。

**1. `src/` 是编译期内嵌的。** `tauri.conf.json` 的 `frontendDist` 指向 `../src`，
HTML/CSS/JS 在 `cargo build` 时被打进二进制。**改完前端不重新编译，跑起来还是旧界面。**
开发时用 `pnpm tauri dev`（带热重载），验证构建产物时必须 `cargo build` 后再启动。

**2. `src/vendor/` 必须入库。** Tauri API、CodeMirror（`cm6.js`）、KaTeX、Lucide 图标
全在里面。打包时**不跑 npm**——没有这些文件，前端就 import 不到。
`.gitignore` 里没有它们，别手贱加进去。

**3. 版本号只有一个源。** `src-tauri/tauri.conf.json` 的 `version` 是权威值：
关于对话框走 `be.appVersion()`（Tauri `getVersion()`）读它，CI 的标签名也从它推出来。
`package.json` / `Cargo.toml` 里的同名版本仅作留档，改的时候三处一起改，但**判断以
`tauri.conf.json` 为准**。

## 三、开发与测试

```bash
pnpm tauri dev            # 开发（热重载，前端改动秒见）
pnpm test                 # 所见即所得行为回归（浅色）
THEME=dark pnpm test      # 深色（顺带核对样式）
```

### 测试矩阵

全离线：Node 起一个静态服务，用 headless Chrome 打开测试页，通过 CDP 跑断言。
零依赖，Node 22+ 的全局 `WebSocket` 就够；Chrome 路径不对时用 `CHROME_PATH` 指定。

| 命令 | 覆盖 | 规模 |
|---|---|---|
| `pnpm test` | md 引擎：往返保真、语法糖、Tab 缩进、退格语义、表格、预览结构 | 262 |
| `pnpm test:units` | 纯函数：diff、格式化、路径、命名 | 42 |
| `pnpm test:editor` | 纯文本编辑区（CM6） | 38 |
| `pnpm test:menu` | 自绘菜单栏结构与交互 | 27 |
| `pnpm test:i18n` | 词条覆盖率、列数、占位符、错误码双向对账 | 45 |
| `pnpm test:filetree` | 文件树、多选、搜索替换 | 31 |
| `pnpm test:app` | 真机探针（需要先开调试端口，见下） | 29 |

数字会随用例增加，以实际输出为准。**改 `wysiwyg.js` / `markdown.js` / `diff.js`
必须跑 `pnpm test`；改文案必须跑 `test:i18n`。**

### 真机验证（仅 Windows）

界面上真的点下去、系统对话框真的弹出来，这类问题只有真机能暴露：

# 2) 重新构建并启动
# 3) 另一个终端跑探针

## 四、打包

### Windows（在 Windows 机器上执行）

```bash
pnpm build            # = tauri build
```

产物：

- `src-tauri/target/release/bundle/nsis/EZNotepad_<版本>_x64-setup.exe` —— 安装版
- `src-tauri/target/release/EZNotepad.exe` —— **免安装单文件**（前端与图标都编进二进制）

> `bundle.targets` 目前是 `["nsis"]`，只出 exe 安装包，不出 msi。
> 这也意味着**在 macOS / Linux 上 `tauri build` 会直接失败**，见《跨平台移植.md》A1。

### macOS（在 Mac 上执行）

```bash
# Apple 芯片（M1 及以后，推荐）
pnpm tauri build --target aarch64-apple-darwin

# Intel
pnpm tauri build --target x86_64-apple-darwin

# 通用包（两种芯片都能跑，体积约翻倍）
rustup target add x86_64-apple-darwin aarch64-apple-darwin
pnpm tauri build --target universal-apple-darwin
```

产物：`bundle/dmg/*.dmg`（拖进「应用程序」即装）、`bundle/macos/EZNotepad.app`（免安装）。

**首次打开提示「无法验证开发者」**：右键 → 打开 → 确认；或 `xattr -cr /Applications/EZNotepad.app`。
要分发给他人不出现该提示，需要 Apple 开发者账号签名 + 公证，配置在
`bundle.macOS.signingIdentity`（证书别提交进仓库，走 CI secrets）。

### Linux

```bash
pnpm tauri build --bundles deb,appimage
```

产物：`bundle/deb/*.deb`、`bundle/appimage/*.AppImage`。
`bundle.linux.deb.depends` 现在是空数组，**发布前要补上 `libwebkit2gtk-4.1-0` 等运行时依赖**，
否则用户装完双击没反应。

### 一键脚本

- `打包-Windows.bat` —— 检查环境 → 装依赖 → 构建 → 打开产物目录
- `打包-macOS.command` —— 同上（双击运行）

## 五、CI 与发版

`.github/workflows/release.yml` 当前只构建 Windows，产出两个 artifact：

| 文件 | 说明 |
|---|---|
| `EZNotepad_<版本>_x64-setup.exe` | NSIS 安装包（未签名，首次运行会被 SmartScreen 拦一次） |
| `EZNotepad_<版本>_x64-portable.zip` | 免安装版打包（Tauri 在 Windows 上没有 portable 目标，裸 exe 即便携版） |

发版流程（**标签是唯一触发源**）：

```bash
git tag -f -a v1.0.2 -m "v1.0.2"
git push -f origin v1.0.2
```

两个细节：

- **`-f` 是必需的**：重发同一版本号时要重新钉标签到当前 HEAD，否则 CI 跑的还是旧提交。
- 标签名从 `tauri.conf.json` 的 `version` 推出来（workflow 里有「读取版本号」步骤），
  不要在 workflow 里再写一遍数字，写死必然脱节。

构建失败时，错误行会以 `::error::` 注解打到日志里——**Actions 的完整日志需要管理员
令牌，注解不需要**，这是无人值守排障的正路。同理，构建与发布拆成了两个显式步骤，
而不是用 `tauri-action` 一把梭（它把输出吞在自己的步骤里，失败就是黑箱）。

三种平台的 CI 矩阵写法见《跨平台移植.md》§8。

## 六、构建期资源

### CodeMirror 6 怎么打包

纯文本 / 代码编辑区用 [CodeMirror 6](https://codemirror.net)（MIT）。它不是单个文件，
而是几十个 npm 包互相 `import`，而本项目是**裸 ESM、没有打包器**——浏览器直接加载会 404。
所以在开发机上预先打成**一个**文件：

```
src/js/editor/cm6-entry.js   ← 只 re-export 用到的 API（按 import 裁剪体积）
        ↓  esbuild bundle --format=esm --minify
src/vendor/cm6.js            ← 约 724 KB，已入库，必须提交
```

```bash
pnpm build:cm6               # 只在这一步需要 node_modules
```

| 要改什么 | 怎么做 |
|---|---|
| 升级 CM6 | `pnpm update @codemirror/*` 后重跑 `pnpm build:cm6` |
| **加一门语言** | ① 装 `@codemirror/lang-xxx` ② 在 `cm6-entry.js` 里 export ③ 在 `plain-editor.js` 的 `LANGS` 表加一行 ④ 重打包 |
| 改配色 | 不用重打包。改 `styles.css` 的 `--tok-*` 变量，编辑器和预览同时生效 |
| 改外观（行高、行号、内边距） | 改 `src/js/editor/theme.js`，也不用重打包 |

分层约定：**只有 `plain-editor.js` 认识 CM6**，`app.js` 拿到的只是一组「读写文本 +
字符偏移」的方法。将来换编辑器只动这一层。

（已知缺口：CM6 官方没有 java / c / cpp / shell / ini 的语言包，这几种目前只有基础高亮。）

### 界面图标与 KaTeX

```bash
pnpm icons          # 把 src/vendor/icons/lucide/*.svg 编译成内联精灵图写进 index.html
pnpm build:katex    # 生成 src/vendor/katex/（只在升级 KaTeX 时跑）
pnpm tauri icon src-tauri/icons/app-icon.svg   # 应用图标（exe / 安装包 / .icns）
```

页面里用 `<svg class="ico"><use href="#i-搜索图标名" /></svg>` 引用，颜色/粗细/尺寸
统一由 `.ico` 控制（跟随 `currentColor`，深浅主题自动适配）。

### 多语言

界面文案全部走 `tt('简体中文原文')`，词条表是 `src/js/i18n-dict-src.js`（7 列：
英/日/韩/法/德/西/葡）。**繁体不手写** —— 由 OpenCC `s2twp` 从简体转出：

```bash
python tools/build-i18n-dict.py    # 需要 pip install opencc-python-reimplemented
node test/run-i18n.mjs             # 校验：列数、覆盖率、占位符、缺键回退
python tools/i18n-find-left.py     # 收尾：列出还没被 tt() 包住的中文字面量
```

两条纪律：

- **`i18n-dict.js` 是生成物，不要手改**，改 `i18n-dict-src.js` 再跑脚本。
- 新写的界面文字要么包 `tt()`，要么在 HTML 上打 `data-i18n`；两种情况 `run-i18n.mjs`
  都会查「表里有没有这条」。忘了会红，不会静默显示英文。

静态 HTML 用 `data-i18n` / `data-i18n-title` / `data-i18n-ph` / `data-i18n-aria`，
启动和切换语言时由 `applyDom()` 统一刷。**但文字由 JS 赋值的节点不能挂**
（对话框标题、草稿状态、文件名……），否则切语言那一刻会被刷回静态词。

## 八、Windows 上窗口全黑 / 白屏的诊断

启动后窗口正常出现但**客户区全黑、点什么都没反应**，先看 WebView2 自己的日志：

```bat
set WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--enable-logging --v=1
"%LOCALAPPDATA%\com.simple.notepad\EBWebView\chrome_debug.log"
```

日志里出现下面三行就中了：

```
ERROR:gpu_process_host.cc:1103  GPU process exited unexpectedly: exit_code=7
WARNING:gpu_process_host.cc:1571  The GPU process has crashed N time(s)
FATAL:gpu_data_manager_impl_private.cc:408  GPU process isn't usable. Goodbye.
```

意思是 **GPU 进程的沙箱在这台机器上起不来**，Chromium 连续崩溃 N 次后直接中止浏览器进程，
窗口就只剩一片黑（页面其实已经加载完了）。这不是前端代码的问题。

`tauri.conf.json` 里已固化兜底参数：

```json
"additionalBrowserArgs": "--disable-features=msWebOOUI,msPdfOOUI,msSmartScreenProtection --disable-gpu-sandbox"
```

`--disable-gpu-sandbox` 只关掉 GPU 进程的沙箱，渲染沙箱与主进程沙箱仍然保留。
某些机器上连这个也不管用，可退一步改用 `--in-process-gpu`。

> 这个字段是 WebView2 专属，mac/Linux 上会被忽略，不会报错。

## 九、Git 约定

仓库默认分支 `main`，每完成一个功能提交一次，不攒批。

**提交信息一律英文**（约定式前缀）：

| 前缀 | 用途 |
|---|---|
| `feat:` | 新功能 |
| `fix:` | 修复问题 |
| `refactor:` | 不改行为的重构 |
| `style:` | 只动样式 / 版式 |
| `docs:` | 文档 |
| `chore:` | 构建、依赖、杂务 |

例：`feat(compare): multi-select compare from the file tree, paste texts directly`

其它约定：

- **远程地址是 `git@github-ezlive:EZLive00/EZNotepad.git`**（走 `~/.ssh/config` 的
  Host 别名 + 专用密钥）。别改成 `git@github.com`，那会切到另一个账号。
- **换行统一 LF** —— 本机系统级 `core.autocrlf=true`，由 `.gitattributes` 的 `eol=lf` 覆盖。
- 已忽略（不进仓库）：`node_modules/`、`src-tauri/target/`、`src-tauri/gen/schemas/`、`.workbuddy/`。

## 十、常见故障

| 现象 | 原因 / 处理 |
|---|---|
| 改了 CSS/JS 没生效 | 忘了重新 `cargo build`（前端是编译期内嵌的） |
| `cargo build` 报「拒绝访问 (os error 5)」 | 残留进程占着产物：关掉正在跑的 EZNotepad 再构建 |
| 构建产物不消失，回收站暴涨 | 本机有文件系统过滤驱动把所有删除转进回收站，跑 `.workbuddy/tools/purge-build-trash.ps1`（`-WhatIf` 先看量） |
| `link.exe not found` | 只装了 VS Code，没装 VS 生成工具的 C++ 工作负载 |
| CI 报 `Cannot find module '@tauri-apps/cli-win32-x64-msvc'` | 锁文件被 npm 污染过，`pnpm install --frozen-lockfile` 会暴露出来 |
| 窗口纯白、页面不加载 | 建窗口的命令写成了同步 `fn`，主线程被 `build()` 卡死 |
| 窗口按钮点了没反应 | `capabilities/default.json` 缺对应的 `core:window:allow-*` |
| 测试报 `找不到 Chrome / Edge` | 用 `CHROME_PATH` 指定浏览器可执行文件 |
